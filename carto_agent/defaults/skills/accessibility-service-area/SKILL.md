# 可达性与服务区分析

## 概述

本 skill 描述跨智能体协作的可达性分析流程，评估设施的服务范围和覆盖能力。适用于公共设施布局评估、应急响应范围分析、商业选址等场景。

## 前置条件

- 路网矢量数据已准备（线要素，需具备连通性）
- 设施点位数据已准备（点要素）
- 如需覆盖统计，需准备人口/设施等统计数据
- 路网数据使用投影坐标系

## 工作流步骤

### 1. 需求确认 [orchestrator]

- 确认设施点位和路网数据
- 确认服务半径或时间阈值（如 5/10/15 分钟，或 1/3/5 公里）
- 确认需统计的覆盖指标（人口/设施数/面积等）
- **阈值设置指南**：
  - 步行可达：5 分钟（约 400m）、10 分钟（约 800m）、15 分钟（约 1200m）
  - 驾车可达：5 分钟、10 分钟、15 分钟、30 分钟
  - 距离阈值：根据设施类型确定（如社区服务 1km，医院 3km）
- **数据传递**：将设施图层名、路网图层名、阈值列表传递给后续步骤
- **判断标准**：数据齐全，阈值合理

### 2. 数据准备 [data_processing]

- 加载路网、设施点和统计数据
- 统一 CRS（所有数据必须同一投影坐标系）
- **路网连通性检查**：
  - 用 `check_validity` 检查路网几何有效性
  - 用 `fix_geometries` 修复无效几何
  - 检查路网是否存在断头路或悬挂节点（影响路径计算）
- 检查速度/成本字段：
  - 如有速度字段（km/h），可用于时间成本计算
  - 如无速度字段，使用默认速度（如步行 5km/h，驾车 40km/h）
- **数据传递**：输出预处理后的路网和设施图层
- **判断标准**：路网几何有效，CRS 一致，速度字段可用

### 3. 服务区计算 [vector_spatial]

- 单设施点：使用 `service_area_from_point`
- 多设施点：使用 `service_area_from_layer`
- 关键参数：
  - 成本类型：距离（米）或时间（秒）
  - 阈值：可设置多级（如 300, 600, 900 秒）
  - 速度字段：指定路网中的速度字段名
- 多级服务区会生成嵌套的等时圈/等距圈
- **数据传递**：输出服务区面图层（含阈值等级字段）
- **判断标准**：服务区面图层已生成，各级别范围合理

### 4. 覆盖统计 [vector_spatial]

- 使用 `analysis_point_in_polygon` 统计各级服务区内的设施/人口
- 计算覆盖率：覆盖人口 / 总人口 × 100%
- 识别服务缺口：不在任何服务区内的区域
- 按需使用 `extract_by_location` 提取未覆盖区域
- **数据传递**：输出覆盖统计表和服务缺口图层
- **判断标准**：覆盖率计算完整，缺口区域已识别

### 5. 成果制图 [cartography_layout]

- 用 `cartography_graduated_style` 渲染等时圈（渐变色表示可达性递减）
- 推荐配色：深绿（最近）→ 浅绿 → 黄 → 橙 → 红（最远）
- 标注服务覆盖率
- 导出可达性分析报告

## 常见问题处理

- 服务区形状异常（如只沿一条路延伸）→ 路网连通性不足，检查是否有断头路
- 服务区范围过大或过小 → 检查阈值单位（米 vs 秒）和速度字段值
- 覆盖统计结果超过 100% → 检查统计数据是否有重叠或重复
- 计算耗时过长 → 裁剪路网到分析区域附近，减少计算量

## 输出检查清单

- [ ] 路网连通性良好
- [ ] 服务区各级别范围合理
- [ ] 覆盖率统计完整
- [ ] 服务缺口已识别
- [ ] 可达性专题图已导出
