### 4.2 迁移规则（T13 实现，读取时自动迁移，保存时写 v2）

1. `version` 改为 `"2.0"`。
2. `runtime.global.skill_packages`：`project-state`、`runtime-control` 丢弃（系统基础包自动挂载）；`build-capability-awareness` 丢弃（Plan 自动挂载）；其余按 §1 表映射为工具包后放入 `runtime.shared_tool_packages`；映射为流程的加入 `flows.enabled`。
3. 每个 runtime 角色：
   - `skill_packages` 中的每个编号按 §1 表处理：保留类、系统类 → 对应工具包编号；并入类 → 目标工具包编号；流程类 → 流程编号加入 `flows.enabled`，同时把该流程需要的工具包加入该角色（见 §4.3）；资源类 → 对应工具包（cartography-styling-standard → cartography-styling，print-layout-standard → print-layout）；删除类 → 丢弃。
   - 结果去重后写入 `tool_packages`，系统基础包不写入。
   - 无法识别的编号写入 `legacy_unresolved_packages`，界面显示为警告，不静默丢弃。
   - 角色名为 `knowledge_engineer`，或 `skill_packages` 中包含 `marching-route-knowledge-tools` 的角色 → `kind: executor`、`executor: route_knowledge`、`flow_only: true`，`tool_packages` 置空，`static_instructions` 原样保留作为兜底规则。这是全仓唯一允许按角色名判断的地方，只存在于迁移代码中，并在 removal_ledger 登记。
   - 其他角色 → `kind: agent`。
   - `workflow_package` 字段丢弃，并记录警告（试点功能下线）。
4. `plan.global` 与 `plan.agents` 按同样规则处理，写入 `tool_packages`。
5. 没有找到任何流程类编号时，不写 `flows`（表示全部启用）。
6. 首次以 v2 保存时，在同目录写一次 `agent.yaml.v1.bak`，之后不再覆盖。
7. 提供 `POST /api/agent-configs/{name}/migrate` 供手动迁移和预览（`dry_run=true` 时只返回迁移结果和警告）。
