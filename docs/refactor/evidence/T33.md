# T33 知识抽取专用执行器

## 结论

实现完成，专项验证通过。知识角色按 `kind=executor`、`executor=route_knowledge` 构造，角色名称不参与运行时分支；通用角色即使仍叫 `knowledge_engineer` 也使用通用工厂。`flow_only` 角色不进入编排委派列表或提示词中的可委派角色说明，但可由流程明确构造。

任务卡原始全量 Go 命令**未全绿**：6 个 deepagent、8 个 config 旧方案/目录断言仍失败，具体见下文；未通过跳过或修改断言来宣称完整验收通过。新增 10 项 Go 测试及其竞态检测通过；精确排除上述 14 个已知失败后的其余五个包全部通过。

## 工厂与流程交接接口

- 新增 `deepagent.BuildRoleAgent(ctx context.Context, cfg *Config, roleName string) (adk.Agent, error)`。从原 `createSubAgents` 提取完整角色创建逻辑，保留授权工具过滤、独立 provider/model 及预算、提示词、技能中间件、运行时 handlers 和旧 workflow 包分支。`createSubAgents` 复用该函数，并跳过 main、disabled、flow_only。
- `kind=executor` 仅接受已支持的 `route_knowledge`。角色配置、模型、抽取契约或编译工具不足时直接报错；没有按角色名回退。静态规则可为空，供流程步骤传入本次规则。通用角色配置 executor、执行器配置旧 workflow 包或未知 kind/type 均拒绝。
- `flowrun.NewRouteKnowledgeExecutor() ExecutorAdapter` 返回 `RouteKnowledgeExecutor{}`，`Type()` 为 `route_knowledge`。接入方通过现有注册表 `registry.Register(flowrun.NewRouteKnowledgeExecutor())` 注册；本卡没有改动其他代理拥有的控制器/注册表文件。
- `BuildInput` 只取本步明确引用的输入和资源；要求已提供的 `conversation_text` 引用，输出 `source_ref=current_user_message`。原文继续由运行上下文提供，输入消息不复制原文，也不复制原文哈希。只有引用的、名称为“重新抽取”的 boolean 输入决定 force_refresh，没有时为 false。
- 引用的 symbols 资源转为 `symbol_assets_dir` 与实际 CSV/XLSX 对照表路径；route_style 转为 `route_style_table`。对照表发现顺序与资源校验一致。T23 后续补入的 executor_default 引用已兼容：ResolvedPath 是目录时发现对照表，是 CSV/XLSX 文件时直接使用该表及其父目录；两个文件入口增加独立子例并通过定向测试。未知资源键、未解析路径、同类型多资源歧义均报错；没有引用时保持编译器默认行为。
- `ToReceipt` 严格解析现有执行器 `success/data` JSON，把 dataset_dir 映射到本步第一个 dataset 产出名称，保留 artifact_id、task_id、task_graph_file、counts/table_counts、validation、warnings；失败回包返回失败回执。缺少成功标识、数据集或产出声明直接报错，不调用模型修补回执。

## 本次规则、资源与恢复

`knowledge_agent.go` 新增严格字符串输入 rules、route_style_table、symbol_table。本步非空 rules 优先于角色 static_instructions；省略时回退静态规则，不修改共享角色对象。rules 只用于抽取契约，不传给 Python 编译器；有效规则进入现有抽取缓存与已确认审查的兼容性哈希。资源路径保留在审查 CompileArgs 中，验证与恢复编译均使用原资源，不因中断丢失。

`knowledge_executor_test.go` 实际运行 Eino Runner、checkpoint、现有知识审查 StatefulInterrupt、带签名审查校验、ReviewStore Claim 和 ResumeWithParams。模型与工具传输使用确定性替身，审查/缓存/坐标处理/恢复逻辑为真实生产实现：确认前没有编译，确认后仅编译一次且没有再次调用抽取模型，产生的原生 success/data 经适配器变成流程回执。测试还覆盖规则改变后重新抽取、兼容规则复用已确认结果、静态规则回退与实例不被污染。该测试验证运行协议，不宣称真实外部模型或真实 Python 编译器参与了此 Go 进程；Python 编译器与 QGIS 另行验证。

## 获授权的 XLSX 交接补齐

T22 资源校验已接受 XLSX，T43 知识编译器此前只读 CSV。按主代理明确扩展范围，首张工作表读取逻辑从 data_loading_support 移至纯 Python `table_io.read_xlsx_rows/read_table_rows`，数据加载保留兼容包装并映射原错误码；知识视觉资源复用同一解析器，没有另造第二份 XLSX 读取器。处理共享字符串、inline strings、稀疏单元格及已有公式缓存，拒绝工作表错误值；不引入第三方依赖。

新增测试在临时目录把内置符号 CSV 同数据写成 XLSX，目录自动发现和显式 XLSX 路径均执行实际六表编译，六份 CSV 与修改前冻结夹具逐字节一致。内置 CSV 默认行为未改变。两个工具 YAML 仅同步参数说明为 CSV/XLSX。
