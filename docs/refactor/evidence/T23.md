# T23 流程编译器、体检与缓存

## 结论与范围

实现 `flow-plan/v1`、确定性绑定与体检、受限模型推断、中文 BM25 候选、按方案缓存及 HTTP 编译/预览。新增 16 个顶层测试（含表驱动子用例），三个规范示例与完整语义夹具一致；真实资产目录、资源库和 HTTP 路由联调通过，模型回复使用固定 JSON，未调用外部模型服务。

所有改动在 `enio2`；原 `Eino`、用户数据与默认方案文件未改。不安装、部署或调用真实制图工具。测试运行目录为项目内独立 `autocarto_data/test-t23*`，各用例写入各自临时目录；没有读取或输出秘钥。

## 计划与编译规则

- 新建 `carto_agent/internal/flow/plan.go`、`executors.go`、`compile.go`、`compile_llm.go`、`bm25.go`、`diagnose.go`、`cache.go`。结构遵循 02 §6，并增加有序 `roles` 快照及步骤 `completion` 原文；分别供自动选角和步骤消息/回执使用。
- 角色依次按显示名精确、编号、显示名包含匹配；不特判角色 ID。保留禁用角色和歧义的错误；用户/人工为确认步骤，空/系统自动为自动步骤，专用执行器按角色元数据绑定。
- 生产环境读取真实 `AssetCatalogService` profile 与正式 `category` 工具包。共享、角色显式、系统和声明式自动挂载共同生成实际工具集合，复用 `subagents.AutoMountedPackageNames`。离线 QGIS 不会导致把静态存在的正式工具误报为系统缺失。
- 候选为角色全部实际工具，加其他包中中文名/说明/关键词 BM25 得分大于零的前 20 项；中文字符二元组、固定参数和名称决胜保证排序稳定，不用不相关工具凑满 20 项。
- 每流程一次、每步骤一次模型调用，温度为 0、无工具，要求单个 JSON 对象；输出经过严格字段、类型、候选、约束与条件校验。非法 JSON、未知工具、无效产出类型、无效条件、额外字段及 `null` 冒充数组都反馈一次并重试；最多两次。仍失败则警告并丢弃辅助部分，保留原文和确定性回退，不阻止仅有警告的计划运行。
- 输入 key、类型、选项、触发词和约束可推断，但显式必填、默认值、是/否、选项和二选一声明有最终决定权；显式产出和确定性条件不被模型覆盖。没有模型仍产生 `input_1` 等 key 与规范要求的回退类型。
- 在产出推断完成后重新绑定引用，避免保留已经解决的未解析引用；条件中的输入换成 key，复合条件递归校验，前向步骤引用报错。专用执行器的必需输入须被本步实际引用，仅全局声明不足以通过。
- 诊断级别、代码与修复动作遵循 02 §9/01 §5。另外增加 `FLOW_EXECUTOR_NOT_FOUND` 错误，阻止方案中未注册的执行器类型进入运行。

## 资源身份与执行器默认资源

显式资源 key 使用 `resource_` 加 `sha256(type + NUL + label)` 的前 12 位十六进制。key 由声明身份决定，不由模型或列表序号决定：重排资源声明不会把已保存的基准目录错套给其他资源。更改资源类型或名称产生新 key，需要重新绑定；前端读取 `plan.resources[].key`，不按名称或序号拼接。

执行器默认资源通过 `ExecutorSpec.DefaultResources` 声明。`route_knowledge` 的元数据指定 `styles/route-defaults.json` 及 `symbol_table/route_style_table` 键；通用编译器不写业务图层或场景名称。本步没有显式引用同类型资源时，把实际默认文件/条目加入 `plan.resources`（`origin=executor_default`）和步骤资源引用，同时纳入默认配置、表格与图片的指纹；显式引用始终优先。

必要联调修正：`internal/resource/resolve.go` 的符号解析兼容直接 CSV/XLSX 对照表路径，以该表父目录解析相对图片，原目录模式保留。原因是专用执行器配置的 `symbol_table` 指向实际表文件，不能擅自换成同目录其他表。继续严格限制资源内路径、无符号链接、SVG/PNG；没有全局放宽 JPEG。

三示例真实资源检查曾发现公共“图例”CSV 引用 JPEG，与 04 的符号格式不符。资源负责方已另存像素一致的 PNG 并更新 CSV；原 JPEG 保留兼容入口。最终三示例资源体检通过；本卡没有降低校验来掩盖该问题。

## 缓存与运行边界

- SHA256 包含 FLOW 正文、包内附件、解析后资源清单及文件内容、外部清单条目存在性/内容、基准目录绑定、方案与能力修订及快照、编译器版本、模型身份。按确定顺序流式哈希，支持取消，不跟随符号链接。
- 默认缓存位于 `$AUTOCARTO_HOME/data/flow_cache/<flow-id>/<scheme>/<hash>.plan.json`，临时文件写入后同步并原子替换。相同 key 的并发编译合并；缓存损坏、身份或结构不符会重建。
- `Inspect` 只读且不调用模型；旧计划带 `FLOW_PLAN_STALE`，没有计划也明确未编译。`EnsureCompiled` 重新核对指纹并自动编译，错误诊断返回携带完整计划的 `ValidationError`，禁用流程返回 `ErrFlowDisabled`。模型生成期间内容或方案变化返回 `ErrPlanChanged`，旧快照不进入执行。
- `AvailablePlans(ctx, scheme)` 用于主编排摘要：过滤当前方案未启用或有错误的流程；单包损坏跳过；根目录读取、方案环境和取消失败返回错误。提示词装配层只摘取名称、编号、适用场景和输入，不重复注入完整 FLOW 正文。

公开接口：`NewCompiler(CompilerOptions)`、`Compile(ctx,id,scheme,force)`、`Inspect(ctx,id,scheme)`、`EnsureCompiled(ctx,id,scheme)`、`AvailablePlans(ctx,scheme)`、`Enabled(ctx,id,scheme)`、`ResourceKey(type,label)`。HTTP/运行装配共享 `API.FlowCompiler()`；测试可用 `SetFlowCompiler` 注入固定模型。

## HTTP

- `POST /api/flows/{id}/compile` 接收 `{scheme?,force}`，返回计划与诊断，有体检错误仍返回 200 供修复。
- 列表按方案返回启用状态与错误/警告/提示计数；详情返回计划、诊断和 stale。GET 不调用模型。
- 新建、保存、导入、复制和基准目录绑定后自动重新编译；资源文件修改由指纹使旧计划失效。原有资源预览路由保留。
- 只装配 Store 的离线嵌入模式仍可编辑，明确返回解析诊断和未编译状态；显式 compile 缺少方案服务返回结构化不可用错误。生产通过现有 `internal/llm` 模型注册创建聊天模型，方案主角色的提供方优先，未单独指定时使用当前提供方；初始化或输出失败走规范回退。
