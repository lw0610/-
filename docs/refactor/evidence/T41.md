# T41 样式资源化与国标底图样式集

## 结论

完成。11 份 QML 由真实 QGIS 调用冻结的旧构造器导出；三个旧预设工具改为读取资源，保留原参数、错误回包、符号及选择性继承标注的行为。新增 `style_set_apply`，路线黄金样例的 `new` 驱动已用它处理底图样式。

最终样式专项 **41 passed**，其中 30 项实际使用独立 QGIS；既有专题样式 **5 passed、12 subtests passed**；完整黄金样例 **10 passed**。原始 T01 基线与比较阈值未修改，未使用样式哈希豁免。所有改动仅在 `enio2` 副本实施。

## 改动摘要

- 新增 `autocarto/resources/system/styles/国标底图样式/`：11 份实际 QML、UTF-8 BOM 的 `对照表.csv`、`presets.json` 兼容索引与说明。覆盖地级/县级驻地点、铁路、高速公路、国道、省界、河流线/面、县域/市域/省域面。具体图层名、别名、颜色、字号、字体及预设复制策略位于资源文件。
- 新增 `_shared/presets/export_basemap_styles.py`：冻结资源化前的 7 个构造函数，独立 QGIS profile 中生成资源，只保存符号和标注类别。以 AST 比较冻结前保存的源码，7 个函数体全部保持一致。该脚本仅供开发导出和回归，运行时模块没有导入它。
- 重写 `_shared/basemap_presets_impl.py` 的三个旧预设入口：克隆资源符号，并按资源声明选择性复制标注。点预设仍继承已有字体/颜色等设置而覆盖字号；面预设保留已有其他标注属性；非河流线不重置标注；河流线保留旧默认字段和沿线合并行为。旧兼容 facade 的通用线符号构造辅助函数仍可调用。
- 新增 `_shared/style_set_support.py` 与 `_shared/style_set_impl.py`：中文/英文列名、主名称优先于别名的精确匹配、重名图层要求 ID、严格模式预检、相对 QML 路径和项目根路径解析、缺文件/字段/不兼容几何/未知渲染器诊断、失败回滚。空标注字段保留 QML，`无` 关闭标注，显式字段覆盖保留规则标注及其过滤表达式。
- 新增 `cartography/style_set_apply.yaml`、`cartography/handlers/style_sets.py`，挂载到“符号与标注”工具包。新工具中文名称、关键词和参数说明遵循 T10；T11/T12 正文只修正本工具真实回包字段。旧三个 YAML 仅在本卡补充读取 QML 与推荐样式集的说明，参数与绑定不变。
- `golden/run_golden.py` 的 `compose=True` 路线底图分支调用新样式集；`legacy` 仍调用旧预设入口。排版部分保留 T44 实现，路线/点/注记绘制仍待 T43 替换。
- 新增 `test_style_set.py` 与 `test_style_set_qgis.py`。实际 authority manifest 调用新 handler，另验证现有单图层 QML 保存/加载入口的点、面往返。

## 真实符号、标注与图片验证

逐项比较全部 11 类旧构造与新兼容包装的渲染器 dump、符号 XML、完整标注 XML、实际 QFont 回退列表、启用状态及 400×300、96 DPI 实际渲染图片；每对图片像素完全一致。再将同一批 11 类图层用新样式集应用，与旧构造结果逐项、逐像素比较，并验证再次应用保持状态一致。

另以预先存在的自定义字体、斜体、颜色、缓冲、优先级、距离、数据定义字号及图层透明度，验证全部 11 类预设的选择性继承；非点工具还验证省略标注字段的旧行为。13 组无效旧参数回包逐字典比较。兼容 facade 的通用线符号辅助构造也实际调用并比较结果。

QML 内自动生成的符号层 UUID（含转义的嵌套 callout 符号 XML）不作为视觉属性比较；标准 `families` XML 节点是字体回退列表的序列化载体，其实际 QFont 列表另行严格比较，未忽略实际字体。隐式空字体列表按其有效单一字体归一化。除这些序列化细节外，符号和标注结构不放宽；实际图片要求像素完全相同。

实测发现 QGIS 3.44 在导出时不会自动把旧 QFont 内的多字体回退列表写入标准 QML `families`，读取该标准字段后也不会自动恢复 Qt 绘制所用的 QFont 列表。仅直接保存再加载时，省域面等标注的实际像素发生变化。本卡导出时保存标准 `families`，加载时恢复实际 QFont，保留该标准元数据以供后续保存。为保证用户用现有单图层工具加载生成资源也得到同样结果，`style_basic_impl.py:load_style_handler` 在成功读取后增加同一恢复调用，未改变参数、保存接口或错误结构。专项测试以点和省域面实际保存→加载→符号/标注/像素比较验证此行为。

另发现未知 QGIS 矢量渲染器的 QML 可能返回加载成功而没有应用目标渲染器，新工具在修改前检查渲染器注册表。失败回滚同时保存原生 renderer/labeling 克隆及启用状态，避免仅用序列化备份再次丢失字体回退列表。回滚用例仅模拟第二个文件在预检后无法加载；第一个图层的真实 QGIS 应用与恢复均实际执行。
