# T22 资源库与资源解析

## 结论

实现完成；新增资源功能及相关回归通过。任务卡要求的 API 全包仍有 4 组既有失败，与 T20 在 Git 初始基线独立复现的结果一致，未把它们计为通过。所有修改仅在 `enio2` 副本实施。

## 改动摘要

- 新增 `carto_agent/internal/resource/`：资源库列举、按类型/名称查找、用户资源优先、导入、只读保护、删除及解析器。支持数据清单、数据文件夹、QML 样式、样式集、路线样式表、QPT/内置 YAML 版式、SVG/PNG 符号集、Markdown/TXT/PDF 文档。
- 新增 `internal/resource/bindings/`：流程和公共资源共享的绑定配置读写、按配置文件共享并发锁、原子保存、符号链接拒绝。项目内目录保存为相对路径，项目外目录保留绝对路径；解析统一调用 T47 的项目根路径 helper，切换工作目录不改变结果。空基准目录值表示清除绑定。
- 修改 `internal/flow/bindings.go`，让 T20 的流程绑定入口转发到同一绑定实现；原有 YAML 键格式保持不变。
- 新增 `internal/shared/xlsx/`：从知识注记导入提取通用 OOXML 文件/关系/共享文本/工作表/单元格读取，保留压缩包、XML、行和单元格限额，不计算公式、不跟随外部关系、不解压到磁盘。知识层保留原有表头匹配、工作表优先级及图片锚点业务逻辑。
- 新增 `internal/shared/diagnostic/`，流程和资源用类型别名共享诊断结构，避免后续流程编译器导入资源包时形成循环依赖。
- 新增 `internal/api/handlers_resource.go` 与集成测试，在既有 `/api`、envelope 和控制面版本校验下注册资源及绑定接口。
- 新建 `autocarto/resources/system/` 的五类目录骨架与说明。Tauri manifest 显式包含该目录；现有插件发布已经递归复制完整插件目录，因此构建脚本增加流程/资源资产存在性检查，无需再复制一份。扩展发行布局静态测试。
- 修改知识层真实 Excel 集成测试：只有显式设置 `CALLOUT_XLSX_TEST_FILE` 时运行，避免自动读取用户 Documents 下内容可变的同名文件；原始 29 行/27 图断言保持不变，所有合成夹具保留。
- 删除：无。

API 全包中的既有失败（T20 证据已记录其 Git 初始基线复现）：

1. `TestHTTPDegradedEnvelope`：实际诊断码 `DISCOVERY_DESCRIPTOR_INVALID`，断言要求 `DISCOVERY_DESCRIPTOR_UNAVAILABLE`。
2. `TestRuntimeDescriptorReturnsStructuredEnvelopeWhenUnavailableOrCorrupted/missing_agent_port`：同上。
3. `TestCatalogContract`：工具目录实际 `degraded`，断言要求 `available`。
4. `TestEmptyCatalogSemantics/valid_empty_catalog`：实际 `degraded`，断言要求 `valid_empty`。

资源覆盖的边界包括：中文/英文和 BOM 表头、CSV 与 XLSX、缺列/空值/列数错误、必需与可选数据缺失、清单旁置回退、公共资源绑定回退和流程覆盖、项目内相对/项目外绝对绑定、工作目录变化、非法 XML/YAML、缺主地图项、丢失样式/符号、无效 PNG/非有限数字、重复导入、用户覆盖内置名称、内置删除拒绝、路径越界、符号链接、文件大小限额及失败导入不留下目标/临时文件。

## 跳过的测试及原因

- 实际外部 Excel 集成用例默认跳过：未提供固定原始工作簿。初次运行曾自动命中本机同名文件，其内容为 18 行/15 图，与测试要求的固定版本 29 行/27 图不同；不修改用户文件，也不降低原断言。
- 未构建桌面发行包和运行真实 QGIS；新增的发行布局静态测试通过，真实 bundle/安装包检查需后续发行产物。Windows 脚本在 macOS 上只做静态契约检查，未宣称真实运行成功。
- 不运行整个仓库的完整构建脚本，避免其清理/部署当前应用；本卡只验证相关源码和静态打包声明。

## 与方案不一致之处

- 原 T20 绑定入口仅接收绝对路径；按用户最新要求改为接收项目相对路径，优先相对持久化，解析以固定项目根为基准。
- 对照表除 CSV 外也接受 XLSX；数据清单和样式集的 XLSX 路径已由合成工作簿验证。
- 缺少数据文件的合法数据清单允许导入并返回诊断，用户可随后绑定目录；格式错误仍拒绝导入。否则无法通过界面完成“先导入清单，再选择数据目录”的操作。

## 遗留问题与后续任务需要知道的事

- 类型在 `internal/resource/types.go`。`Library.Resolve(Request)` 返回 `ResolvedResource`，资源问题在 `Problems`，不依赖方案或调用模型。公共库 `Get` 优先用户资源；同一来源的同类型同名资源冲突会明确报错。
- 接口：`GET /api/resources?scope=builtin|user|all` 返回 `LibraryItem[]`；`GET /api/resources/{type}/{name}` 返回解析结果；`POST /api/resources/import {source_path,type}` 返回解析结果；`DELETE` 同资源路径返回 `{deleted:true}`；`PUT /api/resources/bindings {binding_key,base_dir}` 返回 `{saved:true}`。全部沿用既有 envelope。
- 默认用户库通过 T47 的运行目录解析为 `<项目>/autocarto_data/resources`。绑定键为 `flow:<flow-id>/<resource-key>` 或 `library:<资源名>`，兼容旧绝对路径值。
- 资源文件存在性、表格结构、XML/YAML 基本结构在本卡检查；QML/QPT 的实际 QGIS 加载效果、内置版式布局效果及真实数据内容，由消费方任务和 QGIS 集成测试验证。PDF 只验证文件头，不渲染或提取内容。
- T22 只建立内置库骨架；实际样式、路线样式、版式和符号仍由 T41/T43/T44/T50 生产。没有用空假资源让示例体检通过。
- T23 可直接依赖 `Library.Resolve` 及共享诊断类型。运行计划的编译、失效和重新编译属于 T23，绑定 API 本身不伪造计划。


T23 联调补验：公共 symbols“图例”的旧 JPEG 引用不符合本卡 SVG/PNG 白名单；已保留旧 JPEG，将其解码像素无损另存 PNG，并更新公共对照表。已检查模式/尺寸/每个像素完全一致，未放宽解析器规则。
