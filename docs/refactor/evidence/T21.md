# T21 FLOW.md 确定性解析器

## 结论

完成。仅在 `enio2` 副本实施，原 `Eino` 项目未修改。

## 改动摘要

- 新增：`carto_agent/internal/flow/doc_types.go`，定义头部、输入属性、资源、步骤、产出、引用、条件、补充说明和诊断类型。
- 新增：`parse.go`，通过 goldmark AST 识别二级分节、三级步骤和顶层字段列表；支持规范同义词、重复分节合并、中文和英文头部键、全角和半角冒号、加粗字段、源行号及诊断。做法中的围栏代码、表格、子列表和续段保留为 Markdown。
- 新增：`parse_condition.go`，转换规范列出的确定性条件句式；未识别条件保留原文。解析不调用模型、不绑定方案、不访问资源文件。
- 新增：`parse_test.go`、三个完整示例夹具及空标题模糊测试回归夹具。
- 修改：`carto_agent/go.mod`、`go.sum`，添加纯 Go 依赖 `github.com/yuin/goldmark v1.7.13`；根据该版本官方模块 README 及 AST、parser、text 源码实现。
- 删除：无。

## 运行的命令与结果

以下命令均在 `enio2/carto_agent` 执行。

| 命令 | 结果 |
|---|---|
| `go get github.com/yuin/goldmark@v1.7.13` | 成功；只增加 goldmark 依赖及校验和 |
| `gofmt -w internal/flow/doc_types.go internal/flow/parse.go internal/flow/parse_condition.go internal/flow/parse_test.go` | 通过 |
| `go test ./internal/flow -run TestParse -count=1` | 最终通过；三示例及 9 组边界测试通过 |
| `go test ./internal/flow -run 'TestParse\|FuzzParseDoesNotPanic' -count=1` | 通过；包含模糊测试已保存的空标题回归输入 |
| `go test ./internal/flow -run '^$' -fuzz FuzzParseDoesNotPanic -fuzztime=5s -parallel=2` | 最终通过；执行 80,304 次；同时校验同一输入重复解析的 JSON 一致 |

首轮模糊测试发现连续空标题 `##\n##` 引起源区间越界。原因是 goldmark 的空 ATX 标题没有正文源片段；已用标准 ATX 解析器包装器记录标题源位置修复，保留最小输入回归夹具，并验证空标题仍正确划分分节。没有用异常恢复隐藏解析错误。

三个示例的结构断言：

| 示例 | 步骤 | 输入 | 资源 | 额外断言 |
|---|---:|---:|---:|---|
| 行军路线 | 11 | 6 | 6 | 负责角色、路线格式、初审/终审产出、布尔与 provided 条件、失败策略、输入与前序产出同名引用 |
| 统计专题 | 4 | 11 | 1 | 可选图层和可选报告产出、角色和文件/版面产出 |
| 交通线路 | 4 | 4 | 2 | 空间分析角色、图层引用、版面和 PDF 产出 |

三个示例解析均无诊断；每个示例重复解析 20 次，JSON 完全相同。边界测试覆盖同义词、加粗字段、混合冒号、无序号和三类序号标题、分节合并、未知分节、输入未知属性保留、全部资源/产出类型、缺字段、非法 YAML、缺结束标记、前向/未解析引用、重复产出、围栏伪标题和嵌套伪字段、表格、CRLF/BOM 源行号、空标题及 Setext 标题。

## 跳过的测试及原因

- 未运行全仓后端、前端、QGIS 和打包测试；本卡只新增确定性解析，不接入这些运行链路。T20 的存储、导入和接口由对应任务单独验证。

## 与方案不一致之处

- 任务卡示例文件名为 `doc.go`；按协作分工使用 `doc_types.go`，不改变包名及类型职责。
- 为“同类分节合并并给出提示”补充 `FLOW_SECTION_DUPLICATE`，级别为 `info`；规范要求该提示，但 §9 尚未命名对应诊断码。
- 增加可选诊断源行号 `line`，方便界面定位；不影响既有诊断字段。

## 遗留问题与后续任务需要知道的事

- 对外入口：`Parse(raw string) *FlowDoc`、`ParseMetadata(raw string) (FlowMetadata, []Diagnostic)`、`ParseCondition(raw string) *ConditionRule`。文档错误通过诊断返回，解析结果不返回 Go error。
- `FlowDoc.Meta.ID` 仅反映显式头部编号；编号目录回退和生成交给 T20，解析器不接收目录参数。
- `ConditionRule.Input` 和 `DocRefs.Inputs` 暂存输入显示名，T23 编译器再生成并映射输入 key。
- 未明确声明的产出不在解析阶段推断；角色/输入类型推断、资源存在性和绝对路径提示、模型辅助条件转换交给 T23/T22。
- 资源位置原文保留，不按工作目录解析，也不转换为绝对路径；兼容用户要求的项目内相对路径约定。
- 只读目录和用户目录的存储、导入、API 均由 T20 实现；本卡未改动相关文件。
