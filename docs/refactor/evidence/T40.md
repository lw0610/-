## 改动摘要

- 修改 `_shared/data_loading_impl.py`：
  - 矢量/栅格加载新增 `reuse_existing=true`，按规范化文件身份及 `layername` 复用有效同类图层；比较时忽略其他 provider 选项。Windows 大小写规则由纯逻辑测试覆盖。
  - 返回实际 `layer_id/layer_name/source/crs/geometry_type/reused`；关闭复用时可建立第二个独立图层，原 `output` 继续返回实际图层名。
  - 新增清单 handler：读取 CSV/XLSX、中英文列名、名称筛选、显式基准目录、必需/可选文件、图层分组、条目状态、坐标系汇总。不转换坐标系。
  - 严格模式先检查全部选中数据，必需文件缺失时不加载或复用任何条目、不创建分组。非严格模式可加载可用条目，但必需数据缺失仍返回失败；可选缺失仅报告。
  - 原两个导出函数正文经 AST 比较保持不变。
- 新增 `_shared/data_loading_support.py`：不依赖 QGIS 的源身份、布尔参数、CSV/XLSX 解析。XLSX 使用标准库读取首工作表，支持共享字符串、内联文本、稀疏单元格和缓存数值，不执行公式、不增加第三方依赖。
- 新增 `_shared/admin_boundary_impl.py` 与 `admin-boundaries` 工具入口：
  - 按级别、全名或六位代码精确选择；重名返回候选，不取第一项。
  - 优先读取内置资源目录，缺数据文件时回退原离线技能目录。已有资源校验失败不会静默换源。
  - 检查来源清单、原始字节数与 SHA256、身份字段、CRS84 和要素数；使用 QGIS/GEOS 检查选定真实面，不依赖 GeoPandas 或 Shapely。
  - 原样保留所选 GeoJSON 要素坐标与属性；生成边界与来源记录，原子独占发布文件；相同结果重复调用复用文件与图层，已有不同内容不覆盖。
  - 默认输出到项目运行目录 `data/boundaries`。相对输入、清单、基准目录和显式输出按 `core.paths.resolve_project_path` 解析；来源记录优先保存项目相对路径。
- 新增 `data_load_list.yaml`、`admin_boundary_extract.yaml`；为原两个加载 YAML 增加复用参数和映射。新工具中文显示名为“按清单加载数据”“提取行政区边界”，已与 T10 内容代理协调，关键词、参数说明和执行绑定齐全。
- 新增 `admin-boundaries/SKILL.md`，完整 v2 头部、分组“数据”；`data-loading` 工具列表加入清单工具并补通用说明。与 T11 代理共享头部规范，未改它维护的其他包。
- 新增三份回归文件：`test_data_loading.py`、`test_admin_boundary.py`、`test_data_loading_qgis.py`。
- 必要的既有调用适配：T01 统计回放与 `test_statistical_workflow_qgis.py` 的同源灰底第二层增加 `reuse_existing=false`，保留两个独立图层。未改布局、数据和黄金快照。

## 与方案不一致之处

- 任务卡说明行政区数据搬迁在 T52。本卡不复制约 18 MB 数据形成第二份，而实现新资源目录优先和现存数据回退；`LICENSE`、`UPSTREAM.md`、`upstream-manifest.json`、`upstream/`、原模板与测试保持原位且不修改。真实来源完整性已重新验证。
- 为满足普通 Python 不依赖 QGIS 的测试要求，清单与身份解析单独放入 `data_loading_support.py`；执行仍由卡内 `data_loading_impl.py` 承担。
- 04 文档建议复用 Go 的 XLSX 读取实现，但 QGIS 工具不能直接导入 Go 包。本卡使用 Python 标准库实现对应的首表/值读取，不引入进程/RPC 耦合或 openpyxl 依赖；清单格式保持一致。
- 两个明确需要独立统计图层的既有调用必须显式关闭新的默认复用。这是保留原场景行为所必需，未通过修改基线掩盖缺层。

## 遗留问题与后续任务需要知道的事

- T52 搬迁数据时，应把三份原始 GeoJSON 连同来源清单与许可/上游记录完整迁入资源目录，保持源字节与哈希；工具兼容资源根目录直接放文件或保留 `data/` 子目录两种形式。
- 同源复用返回现有图层的真实名称，不按本次 `layer_name` 重命名已有图层。需要不同样式的第二个独立图层应明确关闭复用。
- `strict` 的无加载保证针对必需文件缺失。文件存在但 provider 无法读取时，条目报告 `failed`，可能已有其他条目成功；工具不会声称整个清单全部成功。
- 仅在 macOS 真机执行 QGIS；Windows 路径大小写规则有纯逻辑验证，未声称 Windows 实机验证。
- 本卡边界默认输出已使用项目运行目录。现有其他导出工具的统一路径改造由 T47 承担，本卡未改其行为。
