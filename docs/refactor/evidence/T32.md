# T32 前端：对话中的流程

## 实施前核对与协议约定

- 已读任务卡、01 §3.5/3.6、03 的启动/失败策略/事件协议，全文核对 `flowrun/types.go` 与 Controller 发出的八类事件、现有 `session_attach`、前端序号/恢复和 HITL 路径。
- 事实：现有普通聊天发送 `chat`；指定流程按 03 改为 `task.data.flow={id,inputs}`，既有运行模式、意图、项目、实例字段保留。自动模式继续使用原普通聊天路径。
- 与 T31 主代理确定：`flow_event.data` 为 `{event,session_id,flow_run_id,payload}`；`session_state.data.flow_run` 和 REST `SessionRecord.flow_run` 为真实 `flowrun.RunState`，不是前端另外猜出的摘要。未带字段保留投影，显式 null 清空；`flow_run_event_seq`（或 run 的 `event_seq`）标记快照覆盖水位。
- 事实：attach 快照和回放可仅为 `run_event`，现有前端只追踪序号、不自动拆出旧消息。本卡只拆出流程摘要、流程事件及带流程标记的回放过程帧，保留普通消息原有行为。旧回放序号不高于流程快照水位时不覆盖权威状态；水位为 0 时用已有 run_id/attempt 规避重复启动和已完成步骤回退。
- 过程消息和历史消息由 T31 提供 `data.flow_run_id/step_id`。它们只用于显示分组，不用于推断完成状态。
- `flow_preview` 结果约定为 `{flow_id,name,plan,diagnostics,input_check:{missing:string[],valid:boolean}}`，兼容工具返回的 data/result 包裹。重启继续约定为 `task.data.flow={id,resume_run_id}`，省略 inputs；原始资料由服务端找回，不以“继续流程”指令替代。
- 发现并反馈实际 HITL 差异：现有单选卡发送 `option/text`，ConfirmAgent 最初只接受 choice/selected/value；主代理已负责后端兼容。本卡保留原回包，用既有 InterruptCard/KnowledgeReviewCard，不新造恢复通道。

## 实现结果

### 流程选择和输入

- `features/flow-run/useFlowComposer.ts`、`FlowComposer.tsx`：自动/已启用流程、`/chat?flow=...` 初始化、当前方案变更和过期详情重新解析。初始方案异步恢复不会清掉链接指定的流程，后续主动切换方案会重置选择。
- 表单支持 text/file/folder/choice/boolean/number/layer。对话原文不显示，严格发送 `{$ref:'current_user_message'}`；选项包含 default 与 options 的并集，避免规范示例 default 不在 options 时丢失默认项。false 和 0 作为合法输入保留；必填或数字错误保留已写消息。
- 文件与目录复用桌面选择器。图层使用会话绑定实例（未绑定时用当前实例）的 `GET /api/instances/{id}/layers` 契约；失败或空目录明确提示，允许手写名称/ID、使用编译选项，未假装已取得图层列表。接口由紧接的 T31-layers 子范围实现，T32 验证为约定响应夹具。
- `useChatMessaging` 增加可选流程参数，`WebSocketClient.sendTask` 发送真实 task 帧；自动模式、取消和普通 HITL 走原路径。ChatInput 支持异步发送结果，校验失败/发送失败不清空消息，发送期间防止重复提交。

### 进度、恢复、人工确认和预览

- 独立 `features/flow-run/{types,model,store}.ts` 按会话和 flow_run_id 保存投影，接受八类控制器事件、真实 RunState 快照和水位。处理等待、运行、重试、跳过、确认、完成、失败、取消及 interrupted；运行和步骤名称不依赖角色编号。
- `FlowProgressCard` 显示每步角色、状态、尝试次数、耗时、跳过原因、失败问题、回执、校验结果、产出和最终交付。步骤内部工具/思考消息折叠到对应步骤，能力中文名来自真实 catalog；历史标记过程可恢复。运行状态始终来自事件/快照。
- 失败三选项和人工确认复用 InterruptCard，知识核对复用既有 KnowledgeReviewCard/弹窗回调。流程确认只展示服务器提供的有效选项，移除对这类卡不适用的“自定义回答”和额外“拒绝”，补充说明继续保留；其他 HITL 不变。选择值原样发回，显示时转为中文并标记到所属步骤。
- interrupted 卡可“继续此流程”；成功发送后等待服务端确认，避免重复点击；不补造新 inputs。REST 加载和 attach 都恢复流程摘要；删除会话清除对应投影，其他会话事件不会改变当前对话。
- Plan 工具结果持久化为带 `flow_preview` 的消息，历史原始 tool_result 同样可渲染；`FlowPreviewCard` 复用流程中心 StepPreview，展示诊断、缺失输入和只预览提示。普通聊天及已有工作流/HITL/知识核对测试继续覆盖。

### 必要范围扩展：桌面成果打开

主代理明确授权 Rust 小范围扩展，因为现有前端、Tauri 都没有通用本地成果打开接口，直接猜测 file:// 可用不能满足“点击打开”。

- `src-tauri/src/local_output.rs` 和 `lib.rs` 新增 `open_local_path(path)`：复用 T47 `resolve_project_path`，相对路径固定按项目根解析，不依赖 cwd；canonicalize 后验证目标，拒绝 URL、不存在路径、特殊文件、脚本、可执行文件与应用包内部路径。普通目录及受限成果扩展名允许打开。
- 系统程序通过 `Command` 的单个路径参数调用，未拼接 shell。目录交给系统文件处理程序/文件管理器；操作只由用户点击触发。前端显示错误反馈；普通浏览器复制路径并说明桌面应用可打开，复制能力缺失时如实提示。
- Rust 单测仅验证解析与拒绝边界，没有实际启动系统查看器；浏览器回放中的 native invoke 为记录调用的夹具，没有打开真实文件。
