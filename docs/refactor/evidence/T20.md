# T20 流程包存储、导入导出与接口

## 结论

存储、导入导出、历史版本、资源文件操作及 HTTP 接口已实现；定向测试通过。发行产物验证留待最终构建。完整 API 套件的 4 组失败已在未重构 Git 基线的独立临时副本中复现，错误码与断言完全相同。

## 改动摘要

- 新增 `internal/flow` 的存储、目录/ZIP/Markdown 导入、ZIP 导出、包复制、资源导入删除、基准目录绑定；使用 T21 共享的元数据解析器。
- 覆盖保存先保留原资源与历史，暂存后切换目录；拒绝路径穿越、符号链接、特殊文件和超限包；ZIP 导出不覆盖已有文件。
- 新增 `/api/flows` 及导入、复制、导出、资源、绑定接口。编译接口由 T23 接入；目前计划为 null、诊断为空数组。
- 新增内置流程目录与 Go 路径解析；Tauri 资源映射包含 flows。
- 新增存储及 HTTP 行为测试。发行包测试区分源码资源声明检查和已有发行产物检查，未构建时明确跳过后者。

## 跳过的测试及原因

- 尚未生成桌面发行包，不能以资源映射检查替代发行包实际内容验收。
- 本机系统 Python 无 pytest，打包检查用其原有 unittest 入口执行，断言相同。

## 与方案不一致之处

- 实际 `build.sh` 的 ZIP 和 `build.bat` 的 robocopy 都复制整个插件目录，已自然包含 flows，不增加重复复制步骤；桌面 bundle 的显式白名单需修改，已经加入。
- macOS 系统 `/var`、`/tmp` 是正常系统别名；安全检查允许这两个系统别名，但仍拒绝用户提供的符号链接及包内链接。
- 相对运行目录的全局规则按用户补充在 T47 统一；现阶段保留可注入 Store 和现有路径入口。
