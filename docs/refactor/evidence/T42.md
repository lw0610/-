# T42 拆分 cartography_style_impl.py

## 结论

完成纯拆分。原文件从 3570 行缩为 84 行，只包含说明与导入导出，没有函数定义。原有 52 个函数均可从兼容路径导入，`handlers/style.py` 的 18 个公开导出仍指向同一处理函数对象。

两套实际 QGIS 黄金回放均与 T01 基线一致。受控完整 Python 回归中，旧实现与拆分实现的测试节点结果及出现次数完全一致，没有新增结果差异；全量测试当前自身存在失败，不能表述为全量通过。

## 改动摘要

- 新增十个职责模块：

  | 模块 | 函数数 | 内容 |
  |---|---:|---|
  | `style_common.py` | 8 | 主线程包装、图层查找、颜色/透明度/绘制模式转换、样式信息 |
  | `style_basic_impl.py` | 8 | 基础符号、透明度、混合模式、色带、大小、样式查询与读写 |
  | `style_thematic_impl.py` | 7 | 分级、规则、热力、点位移、2.5D 与分类信息 |
  | `labeling_impl.py` | 1 | 通用标注 |
  | `basemap_presets_impl.py` | 7 | 原底图预设、线符号构建与原有常量 |
  | `symbolize_mapping_impl.py` | 1 | 原点表与符号表映射 |
  | `route_drawing_impl.py` | 13 | 原路线绘制、批处理、控制点、路线标注和旧组合入口 |
  | `route_points_impl.py` | 2 | 汇合点标注及从旧组合入口抽出的建点区段 |
  | `callouts_impl.py` | 2 | 原图文注记实现及异常包装 |
  | `table_io.py` | 4 | CSV、列名查找、值读取和布尔转换 |

- 修改 `cartography_style_impl.py` 为兼容导出层。按规范将两个私有 helper 改名为 `_label_route_paths`、`_label_rendezvous_points`，旧 helper 名通过导入别名继续可用。保留全部原 handler 名、主线程包装范围、参数、默认值、异常处理、阶段回执、视觉设置与固定重试行为。
- 从组合入口原样抽出 `_prepare_route_points_layer`。仍更新原来的 `points_layer` 回执对象，未增加新工具、参数或执行阶段。
- `_style_info` 改为在函数内导入专题渲染信息 helper，避免通用模块与专题模块互相导入；其余函数正文不变。
- 在 `carto_agent/defaults/architecture/removal_ledger.yaml` 登记兼容导出层，删除阶段为 T52，列出调用方迁移、黄金回归和完整测试等删除条件。
- 必要的测试适配：`test_callout_text_layout.py` 原用 AST 固定读取旧文件中的注记函数，本次只将读取路径改为 `callouts_impl.py`，断言不变。此项超出任务卡列出的生产模块路径，是维持原测试含义所必需。
- 必要的守卫适配：`scene_word_debt.txt` 按实际源码位置搬移旧场景词债务，未放宽守卫、增加豁免或新增场景逻辑。原三条单体文件记录对应迁至路线、点标注、符号映射模块；后续 T43 仍需消减这些债务。
- 未修改 `handlers/*.py`、生产 YAML、黄金输入/基线、原 Eino、`autocarto_data/` 或外部渲染插件。未提前实施 T41 的样式资源化或 T43 的工具拆分。

## 与方案不一致之处

- 06 §3 没有指定旧组合 handler 所属模块。本卡将编排入口放入 `route_drawing_impl.py`，建点区段放入 `route_points_impl.py`；兼容模块纯导出，避免新建额外的单体编排模块或形成循环依赖。
- 任务要求“拆分前后 pytest 结果一致”，当前项目全量测试并非全绿。本卡以相同测试集合的结果无新增变化验收，同时明确保留失败事实，没有为取得全绿而扩大修改范围。
- 场景词仍保留在迁出的旧实现中；这是 T42 “只移动、不改行为”的要求，清除视觉预设与场景命名属于 T43。守卫债务按新位置登记，没有把移动解释成债务已解决。
