# T24 流程中心与资源库界面

## 状态

已完成。界面与接口封装、正式后端联调和试运行闭环均已通过；真实浏览器验收见 [T53-ui](T53-ui.md)。下文保留本卡早期契约回放和依赖尚未交付时的记录。

## 改动与必要范围扩展

- 新增 `/flows`、`features/flows`：流程列表、方案选择、带未保存保护的编辑器、模板段落、步骤/输入预览、错误分组和修复动作、能力搜索、资源面板、公共资源库、导入/覆盖/另存/复制/导出对话框。内置流程只读，删除和写入受保护。方案角色修复保留其余配置，资源基准目录使用系统文件夹选择器或手工路径。
- 复用既有 API client，在功能目录独立封装接口和类型，避免继续扩大 `lib/api.ts`。修复流程只改对应步骤的负责字段，跳过代码块；资源选择插入资源声明，执行计划始终只读。
- 增加顶栏入口并将流程页纳入工作区路由，不依赖设置页加载成功才可访问。
- 公共资源支持用户同名优先、内置只读、CSV 条目/实际路径/存在状态、符号缩略图及参考文档预览。
- 规范要求符号与文档预览，但 T22 的接口只有元数据。因此必要扩展 Go API：`GET /resources/{type}/{name}/preview`，仅接受已解析文档或符号条目序号，拒绝任意路径、符号链接、越界、非白名单类型和超过 10 MB 文件；返回 nosniff/sandbox 头。新增真实文件 API 测试覆盖权限边界。
- 独立 `playwright.flows.config.ts` 仅启动本项目的前端测试服务，使用隔离 Chrome profile 与内存 API 契约回放。现有通用 Playwright 配置会终止固定端口进程并写入用户默认运行目录，本卡不调用该配置；T53 必须改为隔离验证环境。
- 测试环境发现 Node 26 的全局 Web Storage 与 jsdom 冲突，导致原有四项 localStorage 测试失败，并出现 worker 退出错误。显式关闭该 Node 功能后，完整 300 项测试通过。为使普通 `npm test` 也可靠运行，已仅在测试子进程支持该开关时传入 `--no-experimental-webstorage`，不改应用的浏览器存储实现。
