# T14 前端：方案配置与工具中心改版

## 实施前事实与范围

- 方案 HTTP 使用 AgentProfileView，runtime_agents/plan.agents 是有序条目数组；界面内部仍用记录表。v2 增加 version、flows、迁移警告、角色类型/执行器和 tool_packages。兼容读 v1 skill_packages，但不在前端复制角色编号迁移规则。
- 原前端 normalizers 会丢掉未编辑字段，并强制把 Plan.mode 改 all。需同时修正 HTTP 归一化、界面编辑归一化和序列化，保留职责模板、模型配置、执行器、流程和未识别编号。
- 真实包详情不序列化 Tools（Go json:"-"），只返回 tool_refs。UI 用引用与公开 catalog 的中文元数据拼接清单；不假定 YAML 目录就是所属包。
- 原普通导入服务仍支持 workflow/knowledge、含工具定义需扩展清单；前端只拿路径，不能假装已读取本机 SKILL.md。主代理确认 T14 完成开发者提示和结果提示，严格无 tools 导入限制留 T52 服务端切换。
- 根环境还继承原 Eino 的 AUTOCARTO_PROJECT_ROOT，验证显式使用新项目根及独立运行目录。

## 结果与验证

### 已完成的界面与契约

1. `src/lib/api.ts` 增加 v2 方案、角色类型、执行器、流程开关、迁移警告及工具包字段。HTTP 有序条目数组与编辑器记录表之间转换，保留未编辑的顶层、方案、模型、提示词和角色字段。v2 保存只写 `tool_packages`；v1 返回仍可编辑，按 v1 输入交由服务端迁移，不在 UI 根据角色编号猜测类型。显式空工具包数组不会被旧字段重新填充。
2. 角色编辑器使用通用“类型”字段；任意编号均可为专用执行器，原 `knowledge_engineer` 编号也可为普通角色。通用角色使用中文分组选择器，显示名称、说明、工具数并展开真实工具清单；系统基础包锁定，隐藏包和废弃方法包不进入选择器。仅在用户主动切换为执行器时清空手工工具包授权；只修改显示名时保留执行器、流程限定、职责模板和未知字段。
3. 共享区域改为“所有执行角色共享的工具包 / 所有规划角色共享的工具包”。角色卡显示类型、职责摘要、工具包及通过 `tool_refs` 合并去重的工具总数；计数纳入共享包和元数据规定的自动挂载包。未知旧编号和迁移警告明确展示、保存时保留。
4. 方案编辑器接入 `GET /api/flows?scheme=...`，显示名称、版本、来源和体检状态；缺省为全部启用，显式选择保留未找到的既有流程编号。流程名称跳转到所选方案下的指定详情。全屏方案编辑层内补充“保存当前方案”，使编辑后的配置可直接保存。
5. 工具中心只显示非废弃工具包，系统基础包和隐藏包放在折叠“系统”区，系统基础包停用开关锁定。详情以 `tool_refs` 和公开 catalog 拼接中文/英文清单，展示使用说明、参考资料和引用情况。能力手册按真实 `package_id` 分组，中文名、说明和关键词可搜索，提供写流程的描述示例。
6. 修正公开 catalog 的读取形状：真实接口返回顶层 `items`，原前端只读取旧的嵌套 `catalog`。现在保留真实 `display_name/description/keywords/package_id`，并兼容旧形状；不使用 YAML 目录推断归属。
7. 导入界面标明仅面向开发者，并提示无 `tools` 的 SKILL.md 应改写成流程包或作为资源。**T14 未声称已实现服务端拒绝无 tools 包**：此限制按主代理安排由 T52 统一切换；现有导入的覆盖、跳过、重试和运行态反馈机制保留。

### 必要的范围联动

- `carto_agent/internal/control/settings_workspace.go` 和前端注册表仅同步导航文案“工具包与能力 / 工具包目录”。真实导航元数据由后端提供，只改前端备用值无法完成文案统一；未变更设置保存或目录解析逻辑。
- `src/features/flows/FlowWorkspace.tsx` 支持 `flow/scheme` 查询参数。先初始化所选方案，再加载其流程列表并打开详情；明确的方案链接不被运行中方案覆盖。请求序号和当前方案检查阻止旧详情响应覆盖后续选择，手工切换方案取消未完成的链接选择。该文件由主代理授权小范围联动，其余流程中心实现归 T24。
