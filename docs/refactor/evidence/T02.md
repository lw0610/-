## 跳过的测试及原因

- 未直接运行 `./build.sh check`：已完整检查其调用链。它会清理本地构建产物、执行构建和可选运行检查；其中非 live Playwright 启动命令硬编码 `AUTOCARTO_HOME="${HOME}/.autocarto"`，并会终止固定端口的进程。为遵守不得影响已有运行环境和数据的约束，本卡使用隔离目录运行有关测试，由后续总验收统一处理完整构建与端到端检查。
- 本机普通 Python 没有 pytest；本卡三个目标模块均为 unittest，因此直接用标准库运行器执行全部 31 项。QGIS Python 裸启动找不到 `encodings`；显式设置其 `Resources/python3.12`、`lib-dynload`、`site-packages` 后可启动，但也没有 pytest。本卡没有安装或改动 QGIS 环境。
- Go 全量、前端构建、Rust、Playwright 和已打包/live smoke 留给最终集成验收。本卡没有启动服务、同步或部署插件。

## 与方案不一致之处

- 任务卡将旧内嵌技能树的测试边界描述为 workflow/knowledge；事实是原副本已含 `category` 包和省略 `kind` 的历史包，且系统真源还包括正常分类包。原测试在改动前已失败。本卡使测试按系统真源检查合法包种类及工具定义分离，省略种类仍由现有加载器推断，没有修改包正文或生产加载规则。
- `server_deep_skill_test.go` 改动前已经将工作目录及导入源/目标放在 `t.TempDir()`；四个目录是遗留文件，不能据此推断当前测试仍会向源码树导入。本卡额外隔离配置环境，导入相关测试通过。
- 全局路径检索中的 `~/.autocarto/config/agent_configs` 原本只是路径展开测试样例，不是对删除副本的读取。本卡改为 `~/.autocarto/config/example`，避免与退役源码路径混淆；运行时仍可使用其正式 agent 配置目录。
- `autocarto/config/agent_configs/` 是退役的源码副本，不能称为当前活动方案。正式内嵌默认来自 `carto_agent/defaults/agent_configs/`，运行配置位于 `AUTOCARTO_HOME/config`，由已有配置管理器初始化和刷新。
