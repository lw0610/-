# T10 工具中文化与关键词

## 结论

实现完成。原有 311 个工具均有 4–12 字的中文动宾显示名、中文说明和中文关键词数组，全部参数有中文说明；增加了单位、范围及兼容参数限制的说明。公开 `GET /api/tools/catalog` 的 `catalog.items[]` 返回 `display_name`、`description`、`keywords` 和已有归属解析产生的 `package_id`。新元数据不改变工具授权、可用性判断或执行绑定。

定义结构验证与全部目录 HTTP 用例通过；任务卡的 Go 三包总检查仍有 4 个已存在的发现/空目录语义失败，不能声称全量测试通过。

## 改动摘要

- 新增：`scripts/refactor/export_tool_names.py`，读取唯一工具定义源，导出名称、中文名、说明、所属目录、domain、关键词和文件路径。CSV 使用 UTF-8 BOM，可供表格软件查看；默认写标准输出，`--output` 指定输出文件。
- 修改：原有 311 个工具 YAML。295 个显示名调整，311 个补充关键词，4 个工具说明中性化，174 个参数说明补齐单位、取值或约束。既有中文说明和有用的调用约束保留。
- 修改：`ToolMetadata.Keywords` 的 YAML/JSON 加载、规范化和克隆；skill 转换、运行时传输类型、compute/interactive 目录、capability 快照与投影、公开目录契约的显示名和关键词透传；能力查询支持按中文名和关键词搜索。显示名和关键词变化进入 schema revision，关键词排序、重复或首尾空白不产生无意义修订。
- 修改：Python 定义验证及 Go 加载、快照、修订、关键词匹配、HTTP 契约测试。新测试检查字段结构和传递行为，不绑定某份提示词的固定措辞。
- 修改：消减 `scene_word_debt.txt` 中两个 print-layout YAML 的 3 个场景词组合；保留并行 T42 的 Python 债务迁移结果。
- 删除：无；没有新增兼容接口。

## 跳过的测试及原因

- 没有重复执行全量构建、Rust、前端或端到端测试：本卡没有修改前端及工具实现；已执行卡内 Python/Go 检查，并补查真实公开契约和 capability/control 中间链路。完整跨卡构建与运行验收由主任务统一执行，避免本卡启动固定端口服务、清理其他卡构建产物或写入现有运行环境。
- 没有调用实际制图工具验证元数据编辑：解析对照确认全部执行绑定和参数结构未改；执行层行为由工具层对应任务和黄金样例验证。

## 与方案不一致之处

- `handlers_tool.go` 实际只序列化 control 的公开投影，且 `ToolInfos` 不直接公开。仅改任务卡列出的三个 Go 文件会丢失字段。本卡必要扩展至 `skill` 转换、`middlewareclient`、`compute`、`toolrouter`、`capability`、control 公开目录构建和 websocket runtime 同步；已在动手扩展前记录原因。最终公开字段增加在 `toolcatalog.Capability`，无需为凑文件列表修改 handler 分支逻辑。
- 旧 HTTP 测试要求 `package_id` 一律缺失，与本卡“返回所属工具包”冲突，已去除该过时断言；其余旧 `kind/domain/enabled` 顶层包策略字段继续不公开，授权和启用信息仍遵守既有契约。
- 原 311 份说明已全部含中文，并非所有说明都需要重写。浏览器、遥感及质量工具的较长调用/真实性约束没有为压成一两句而删除；后续方法说明整理可继续在 T12 中处理。
- 部分版面兼容参数目前并未被处理器使用（例如比例尺段数固定为 4/0、若干长度沿用原值）；本卡如实标注兼容限制，没有把新增单位说明伪装成已实现功能。`assign_skill_packages.mode` 实际接受 `runtime/plan`，文案使用真实区段名并解释 Build 对应 runtime。
- 本卡元数据完成并做结构不变性审计后，已交由 T40 继续改两个加载工具并新增能力；本记录的 311 和“不改执行绑定”只针对 T10 完成时的原工具集合，不覆盖并行 T40 的执行层改动。
