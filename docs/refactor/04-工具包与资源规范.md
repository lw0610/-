# 04 工具包与资源规范

实现任务：T10、T11、T12（工具包）、T22（资源库）、T41、T43、T44、T45（资源的生产与消费）、T50（内置资源）。

## 1. 工具包

### 1.1 存放与格式

工具包继续使用 `autocarto/skills/system/<package-id>/SKILL.md`，`kind: category`。保留这个目录有两个原因：`internal/config/paths.go` 用 `skills/system` 作为资产根目录的识别标记（`pluginRootRequiredMarker`）；Eino skill 中间件按 SKILL.md 读取正文，正好用于按需提供使用说明。

```text
autocarto/skills/system/<package-id>/
├── SKILL.md          # 头部信息 + 使用说明
└── references/       # 可选：较长的参考资料（方法说明、脚本模板等）
    └── *.md
```

### 1.2 头部信息（v2）

```yaml
---
name: print-layout              # 编号，保持现有编号不变，供旧配置迁移
display_name: 版面编排           # 新增：中文显示名
description: 创建和编辑打印版面、按版式一次排版、添加图例比例尺指北针、导出 PDF/PNG/SVG
kind: category
domain: 版面与输出               # 新增：界面分组，取值见 §1.4
runtime: qgis
enabled: true
system: false                   # 新增：true 表示系统基础包，自动挂给所有角色，不出现在勾选列表
hidden: false                   # 新增：true 表示隐藏包，用户不能勾选，由 auto_mount 决定挂给谁
auto_mount: ""                  # 新增：隐藏包的自动挂载对象，见下表
tools:
  - layout_compose
  - layout_create
  - …
---
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 包编号，`^[a-z0-9][a-z0-9-]*$` |
| `display_name` | 是（v2） | 中文名，用于界面和体检提示 |
| `description` | 是 | 一句话说明，写清楚能做什么，不写场景 |
| `kind` | 是 | 固定为 `category` |
| `domain` | 是（v2） | 界面分组 |
| `runtime` | 否 | 沿用现有取值：`qgis`、`cli`、`internal` |
| `enabled` | 否 | 默认 `true` |
| `system` | 否 | 默认 `false` |
| `hidden` | 否 | 默认 `false` |
| `auto_mount` | 否 | 只对隐藏包有效：`main`（Build 主智能体）、`plan_main`（Plan 主智能体）、`executor:<类型>`（如 `executor:route_knowledge`）。为空时该隐藏包不会自动挂载，只能在方案文件中显式引用（例如创建者方案引用 `creator-tools`），界面不提供勾选 |
| `tools` | 是 | 工具名列表；一个工具可以出现在多个包里，但应尽量只属于一个包 |

`kind: workflow`、`kind: knowledge` 在 T52 之后不再被加载；过渡期内仍可加载，但不出现在方案界面中（见 05 文档）。

### 1.3 正文与参考资料

- 正文是"使用说明"，智能体需要时通过 skill 中间件读取。只写通用方法：这类工具适合做什么、参数怎么选、常见错误、结果怎么检查。**不写具体专题、不写具体图层名、不写本机路径。**
- 正文不超过约 8 KB。更长的方法说明放进 `references/`，正文里列出参考资料清单，例如"缓冲与邻近分析：references/缓冲与邻近分析.md"。
- 智能体通过内部工具 `reference_read` 读取参考资料（§1.6）。

### 1.4 分组（`domain` 取值）

| 分组 | 工具包 |
|---|---|
| 数据 | 数据加载与导出、格式转换、文件操作、坐标系、地理编码、GPS 数据、统计数据准备、中国行政区边界 |
| 在线数据 | 网页与浏览器取数、遥感影像（GEE） |
| 矢量 | 要素筛选、属性字段、几何处理与叠加、矢量生成 |
| 栅格与分析 | 栅格分析、GDAL 处理、GRASS 分析、空间统计与聚类、网络分析、可视域分析、点云、网格与剖面 |
| 制图 | 符号与标注、路线专题绘制、统计图表、画布导航 |
| 版面与输出 | 版面编排 |
| 脚本 | PyQGIS 脚本 |
| 质检 | 质量审查 |
| 系统 | 工程与图层状态（系统基础包）、运行控制（系统基础包）、流程控制（隐藏，只挂给 Build 主智能体）、能力查询（隐藏，Plan 自动挂载）、创建者工具（隐藏）、路线知识（隐藏，专用执行器） |

工具包最终清单和来源见 `05-迁移对照表.md` §2。

### 1.5 中间件加载规则（T12 修改）

现在 `RuntimeSkillConfig.GetAgentMiddlewareSkills` 会跳过所有 category 包，所以工具包正文从来没有提供给智能体。改为：
- 角色拥有的工具包（含系统基础包），只要正文去掉标题后不少于 200 个字符，就加入该角色的 skill 中间件列表，智能体可以按需读取。
- 隐藏包按其绑定关系提供（专用执行器、创建者方案）。

### 1.6 参考资料读取工具 `reference_read`

- 运行时：`internal`，属于系统基础包"运行控制"。
- 参数：`path`（字符串）。可以是工具包参考资料的相对路径 `<package-id>/references/<文件>`，也可以是流程资源中文档的绝对路径。
- 只允许读取以下目录内的 `.md`、`.txt`、`.csv`、`.json`、`.yaml`：工具包目录、内置与用户流程包的 `resources/docs` 和 `resources/` 下的对照表、内置与用户资源库。拒绝其他路径和符号链接。
- 返回文本，超过 200 KB 时截断并提示。

## 2. 工具定义中文化（T10）

每个工具 YAML（`autocarto/tools/system/<domain>/<tool>.yaml`）：

| 字段 | 要求 |
|---|---|
| `metadata.display_name` | 中文，4–12 个字，动宾结构，如"加载矢量图层""按版式一次排版"。现有 92 个 `display_name` 等于英文名的工具全部补齐 |
| `spec.description` | 中文，一到两句：做什么、输入什么、产出什么；不写具体专题 |
| `metadata.keywords`（新增，可选） | 中文同义词数组，供能力匹配和能力手册搜索，如 `["叠加", "相交", "求交"]` |
| `spec.parameters[].description` | 中文，写清单位和取值范围 |

Go 侧 `internal/tool/types.go` 的 `ToolMetadata` 增加 `Keywords []string`，工具目录接口（`/api/tools/catalog`）返回 `display_name`、`description`、`keywords`、所属工具包。

另外修复 3 个使用 CRLF 换行的工具 YAML（T02 中用脚本找出并统一为 LF）。

## 3. 资源

### 3.1 资源类型与存放

| 类型 | 文件 | 典型用途 |
|---|---|---|
| 数据清单 `data_list` | `.csv` / `.xlsx` | 一组需要加载的数据文件 |
| 数据文件夹 `data_folder` | 文件夹 | 文件夹内的全部矢量/栅格文件 |
| 样式 `style` | `.qml` | 单个图层的符号与标注 |
| 样式集 `style_set` | 文件夹（若干 `.qml` + `对照表.csv`） | 一套底图样式 |
| 路线样式 `route_style` | `.csv` | 路线的阵营/拓扑到绘制样式的映射 |
| 版式 `layout` | `.qpt` 或内置版式名 | 版面 |
| 符号 `symbols` | 文件夹（`.svg`/`.png` + `对照表.csv`） | 专题点符号 |
| 文档 `doc` | `.md` / `.txt` / `.pdf` | 参考资料、制图规范 |

位置：
- 流程包自带：`<flow-dir>/resources/...`
- 内置资源库：`autocarto/resources/system/<类型目录>/...`（`data/`、`styles/`、`layouts/`、`symbols/`、`docs/`）
- 用户资源库：`$AUTOCARTO_HOME/resources/<类型目录>/...`
- 资源库中的资源名 = 文件名（去扩展名）或文件夹名。

所有对照表的表头都同时接受中文和英文列名（下文"中文/英文"），编码为 UTF-8（允许 BOM）。`.xlsx` 读取复用 `carto_agent/internal/knowledge/callout_xlsx.go` 中已有的实现，提取到共享包后使用。

### 3.2 数据清单 `data_list`

| 列（中文/英文） | 必填 | 说明 |
|---|---|---|
| 名称 / name | 是 | 加载后的图层名，也是步骤里引用的名字 |
| 路径 / path | 是 | 绝对路径，或相对路径 |
| 类型 / type | 否 | `矢量`/`vector` 或 `栅格`/`raster`；不写时按扩展名判断 |
| 必需 / required | 否 | 默认"是"；"否"表示缺失时只警告 |
| 说明 / description | 否 | |

相对路径的基准目录：
1. 有绑定时用绑定的目录（`$AUTOCARTO_HOME/config/resource_bindings.yaml`，键为 `flow:<flow-id>/<resource-key>` 或 `library:<资源名>`）；
2. 没有绑定时用清单文件所在目录；
3. 两者下都找不到文件时，体检报 `FLOW_DATA_FILE_MISSING`，界面提示"选择文件夹"。

消费方：`data_load_list` 工具（06 文档 §1.2）。

### 3.3 样式 `style` 与样式集 `style_set`

- 单个样式：QGIS 图层样式文件 `.qml`，可包含符号、标注、透明度等。
- 样式集：一个文件夹，内含若干 `.qml` 和一个 `对照表.csv`：

| 列（中文/英文） | 必填 | 说明 |
|---|---|---|
| 图层 / layer | 是 | 目标图层名 |
| 别名 / aliases | 否 | 其他可匹配的图层名，用顿号或分号分隔，如"河南铁路、铁路线" |
| 样式文件 / style_file | 是 | 相对于样式集文件夹的 `.qml` 文件名 |
| 标注字段 / label_field | 否 | 覆盖 `.qml` 中的标注字段；写"无"表示关闭标注 |
| 说明 / description | 否 | |

匹配规则：图层名先与"图层"列精确匹配，再与别名精确匹配；都不匹配的图层不处理，并在结果中列出。

消费方：`style_set_apply`、`layer_load_style`（06 文档 §2）。

### 3.4 路线样式 `route_style`

把现在写在 `autocarto/knowledge/vocabulary.py` 的 `ROUTE_STYLE_PRESETS` / `DEFAULT_ROUTE_STYLE` 变成资源：

| 列（中文/英文） | 必填 | 说明 |
|---|---|---|
| 拓扑 / topology | 是 | `standard`、`branch`、`multi_start`（标准、分支、多起点汇入） |
| 阵营 / side | 是 | `friendly`、`enemy`、`neutral`（我方、对方、中立） |
| 路线类型 / route_type | 是 | 写入 routes.csv 的 `route_type` |
| 绘制方式 / draw_type | 是 | `bezier_arrow`、`branch_bezier`、`multi_start_bezier` |
| 样式编号 / style_id | 是 | 路线渲染器的样式编号，如 `bezier_red_gradient` |
| 线宽系数 / width_scale | 否 | |
| 图例名称 / legend_label | 否 | 图例中显示的名称 |

内置资源：`autocarto/resources/system/styles/路线样式-红蓝对比.csv`（与当前预设等价）、`路线样式-单色.csv`（考察、交通等非对抗路线使用）。

消费方：知识编译器（生成 routes.csv 时）、`route_draw`（数据集中没有 `style_id` 时）。

### 3.5 版式 `layout`

**QGIS 模板 `.qpt`**（用户在 QGIS 版面设计器里做好后"另存为模板"）：
- 主地图项的 ID 设为 `main_map`；图例 ID 设为 `legend`（可选）。
- 需要替换的文字，在文本项里写占位符：`{{标题}}`、`{{综述}}`、`{{制图日期}}`、`{{数据来源}}`、`{{制图单位}}`，或任意 `{{名称}}`。
- 消费方：`layout_apply_template`（06 文档 §5.2）。

**内置版式**（开发者维护，用户按名称选用）：`autocarto/resources/system/layouts/<名称>.layout.yaml`，由 `layout_compose` 使用。格式：

```yaml
name: 四角对齐版式
description: 标题在装饰框上方居中，综述在主图右上，图例在主图左下，比例尺在主图右下，指北针在主图左上
page:
  default_paper: A1
  default_orientation: landscape
  margins_mm: {top: 25, right: 15, bottom: 15, left: 15}   # 示意值；T44 从黄金样例基线量取实际值
fonts_mm:                    # 按纸张的字号表（毫米），写入后锁定
  A0: {title: 15,   legend_title: 4,   legend_body: 3,   scalebar: 2.5, overview_title: 4,   overview_body: 3}
  A1: {title: 11.5, legend_title: 3.5, legend_body: 2.5, scalebar: 2,   overview_title: 3.5, overview_body: 2.5}
  A2: {title: 9,    legend_title: 3,   legend_body: 2.5, scalebar: 2,   overview_title: 3,   overview_body: 2.5}
  A3: {title: 8,    legend_title: 2.5, legend_body: 2,   scalebar: 2,   overview_title: 2.5, overview_body: 2}
  A4: {title: 5.5,  legend_title: 2.5, legend_body: 2,   scalebar: 2,   overview_title: 2.5, overview_body: 2}
elements:
  main_map:    {fill: content_area}
  border:      {type: decorative_border, around: main_map, offset_mm: 5}
  grid:        {enabled: true, density: sparse}
  title:       {anchor: {to: border, at: top_center, placement: outside}, bold: true, frame: false, background: false}
  overview:    {optional: true, anchor: {to: main_map, at: top_right, placement: inside},
                frame: true, background: "#ffffff", max_width_ratio: 0.125}
  legend:      {anchor: {to: main_map, at: bottom_left, placement: inside}}
  scalebar:    {anchor: {to: main_map, at: bottom_right, placement: inside}, max_width_mm: 80}
  north_arrow: {anchor: {to: main_map, at: top_left, placement: inside}}
```

`anchor.at` 取值：`top_left`、`top_center`、`top_right`、`middle_left`、`center`、`middle_right`、`bottom_left`、`bottom_center`、`bottom_right`；`placement` 为 `inside`（在参照框内对齐）或 `outside`（在参照框外紧贴）。初始内置两个版式：`四角对齐版式`（来源：`print-layout-marching-route`、`print-layout-thematic`、`print-layout-standard` 中的规则）和 `统计专题版式`（来源：`print-layout-statistical`：标题在上、图例在主图侧边、说明信息栏在下、无装饰框和军标）。

### 3.6 符号 `symbols`

文件夹内放 `.svg` / `.png` 和 `对照表.csv`，列与现有 `symbol_mapping.csv` 一致：

| 列（中文/英文） | 必填 | 说明 |
|---|---|---|
| 符号类型 / symbol_type | 是 | 如 `start_flag`、`battle`、`meeting`、`rendezvous`、`waypoint` |
| 文件 / svg_path | 是 | 相对于符号文件夹的文件名 |
| 大小 / size | 否 | 毫米 |
| 优先级 / priority | 否 | 数字越大越优先显示 |
| 锚点X / anchor_x、锚点Y / anchor_y | 否 | |
| 说明 / description | 否 | 图例中的名称 |

内置资源：`autocarto/resources/system/symbols/军标/`（来自 `autocarto/knowledge/assets/symbols/` 的 8 个 SVG 和 `vocabulary.py` 的 `SYMBOL_PRESETS`）、`autocarto/resources/system/symbols/图例/`（来自 `autocarto/resources/legend_arrow.jpg`）。

### 3.7 文档 `doc`

任意参考资料。步骤需要时，执行器在步骤消息中列出路径，智能体用 `reference_read` 读取（PDF 只列路径，不提供读取）。

### 3.8 资源解析结果

资源库（`internal/resource`，T22）对外提供：

```go
type ResolvedResource struct {
    Key          string            // 流程内的资源键，例如 basemap
    Label        string            // 中文名，例如 中国底图
    Type         string            // data_list / style / style_set / route_style / layout / symbols / doc / data_folder
    Origin       string            // flow / library_user / library_builtin
    Location     string            // FLOW.md 中写的位置
    ResolvedPath string            // 绝对路径；内置版式为 .layout.yaml 的路径
    BaseDir      string            // 数据清单的实际基准目录
    BindingKey   string            // 例如 flow:marching-route/basemap
    Entries      []ResourceEntry   // 数据清单条目、样式集条目、符号条目
    Problems     []Diagnostic      // 资源级诊断
}
type ResourceEntry struct {
    Name, Path, Kind string
    Exists           bool
    Extra            map[string]string // 别名、标注字段、大小等
}
```

接口（T22）：`GET /api/resources?scope=builtin|user|all`、`GET /api/resources/{type}/{name}`、`POST /api/resources/import {source_path, type}`、`DELETE /api/resources/{type}/{name}`（仅用户资源）、`PUT /api/resources/bindings {binding_key, base_dir}`。

## 5. 给用户：在 QGIS 中制作资源

**样式（.qml）**：在 QGIS 中把图层的符号和标注调好 → 图层属性 → 样式 → 另存为 QGIS 图层样式文件（.qml）→ 放入流程包 `resources/styles/`。一套底图样式：每个图层导出一个 .qml，放在同一个文件夹，再写一张 `对照表.csv`。

**版式（.qpt）**：在 QGIS 版面设计器中排好版 → 把主地图项 ID 设为 `main_map` → 需要替换的文字写成 `{{标题}}` 等占位符 → 版面 → 另存为模板（.qpt）→ 放入 `resources/layouts/`。

**数据清单**：用 Excel 写两列"名称、路径"，路径可以写相对路径，导入后在流程中心选择基准文件夹。
