# 新增工具与工具包

本文面向开发者，字段以当前 Go 定义、正式工具和包元数据为准。资源参数与句柄合同见 [v2 解析与交付规范](refactor-v2/02-解析与交付规范.md)，实际治理与验证见 [逐卡证据](refactor-v2/evidence/)。

先判断需求能否用现有能力完成。专题步骤和业务规则写入流程，颜色、版式、数据来源写入资源；只有缺少通用操作机制时才新增工具。

## 新增工具

QGIS 工具定义位于 `autocarto/tools/system/<domain>/`，实现优先放在该域的 handlers 或 `_shared/` 中。运行时由后端发布 execution manifest，插件按这份权威目录执行。

工具定义使用 `tool/v1`，包含中文名称、说明、关键词、参数和 handler 映射。复制一个同运行时的现有工具作为起点，例如 `data_load_list` 或 `layout_compose`，完整保留必要结构。

```yaml
apiVersion: tool/v1
kind: Tool
metadata:
  name: inspect_dataset
  display_name: 检查数据结构
  keywords: [字段检查, 数据检查]
  domain: data-loading
  runtime: qgis
spec:
  description: 检查指定数据的字段与几何结构，返回实际检查结果。
  parameters:
    - name: input_path
      type: string
      required: true
      description: 数据文件路径，相对路径按项目根解析
execution:
  handler: handlers.loader.inspect_dataset_handler
  param_mapping:
    input_path: '{{ input_path }}'
```

这是结构示意，定义发布前必须实现并导出对应 handler。`metadata.name` 是稳定代码标识符，`metadata.display_name` 建议使用 4–12 字中文动宾短语；参数说明写清单位、默认值和边界。不要把某个专题名称、个人绝对路径或外部插件安装路径写进通用实现。

操作结果返回真实图层 ID、版面 ID、文件路径和检查结论。对可重复调用的操作，优先复用已有数据或替换明确指定的同名对象；失败时保留旧结果，不能返回虚假的成功。

修改了 `handlers/__init__.py`、延迟导出模块或 YAML 路径时，检查实际 manifest 调用，不只检查 Python 文件里存在同名函数。

## 声明资源参数

工具与技能定义均支持 `type: resource`。`resource_type` 是期望资源类型，必填；`default_resource` 可选，填稳定公共编号。默认资源只在调用方省略参数时解析，不可用时明确报错，不寻找同名路径降级。例如公开路线工具的资源参数：

```yaml
- name: route_style
  type: resource
  resource_type: route_style
  default_resource: route_style.mono
  description: 使用的路线样式资源
```

模型提供资源标签、编号或路径字符串。流程内先用本步作用域解析，流程外使用公共库/明确路径；显式覆盖和锁定统一生效。后端唯一 Go Resolver 负责格式、名称、类型、清单、绑定、摘要和条目校验，再交付 `resource-handle/v1` 结构化句柄。普通模型输入不能伪造句柄对象；可信内部执行器也需在运行作用域核对编号。Python 不再读取公共资源 CSV/XLSX 或自行搜索用户/内置目录。

处理器调用 `resource_handle.require_handle` 检查类型，直接消费句柄的 `entries`、`root`、`entry`、`format` 等规范化字段；错误时返回明确原因。版式 YAML 与 QPT 同属 `layout`，用 `format` 区分工具能接受的格式。测试复用 Go 生成的静态句柄或动态测试辅助器，禁止手写一套 Python 解析逻辑假装生产链路。

资源格式只有一个来源：`carto_agent/internal/resource/formats/resource_formats.yaml`；前端通过 `/api/resources/types` 获取类型及 FLOW 类型词。新增格式须更新此规范及 Go 校验/跨语言消费测试，避免在不同语言硬编码两份列名规则。

## 工具资产与场景资源

私有渲染默认值、查询所需固定底表放在工具域的 `assets/`，通过受限工具资产路径接口读取，不加入公共库。例如行政区数据在 `tools/system/admin-boundaries/assets/中国行政区边界/`，路线渲染默认值在 `route-cartography/assets/renderer-defaults.json`。

用户需要可替换的样式、符号与版式应成为正规资源。特定流程的配色、场景符号放该流程 `resources/`；多个流程共享且通用的内容才进入公共资源库。旧预设工具使用隐藏兼容资产，登记了下线条件，正式工具不从该入口绕过公共资源覆盖。

执行器也要声明资源契约，由链接阶段检查；不能在执行器代码里用固定名称或路径补默认依赖。当前路线知识执行器要求明确路线样式与含 `start_flag`、`waypoint` 的符号集。其知识层的场景扩展隔离属于后续 G1，本轮没有宣称完成。

## 加入工具包

工具包位于 `autocarto/skills/system/<package-id>/SKILL.md`。其中的 `tools` 决定该包授予哪些工具；仅在说明正文提到工具不会授予权限。

```markdown
---
name: dataset-inspection
display_name: 数据检查
description: 检查空间数据的字段、几何和来源。
kind: category
enabled: true
domain: 数据
system: false
hidden: false
auto_mount: ''
tools:
  - inspect_dataset
---

# 数据检查

在这里写通用使用说明、选择方法、参数约束和结果核验方式。
```

`auto_mount` 在当前真实 schema 中是字符串：普通包留空（`''`）或省略，不能写数组 `[]`。隐藏包可使用 `main`、`plan_main`、`executor:<执行器名>`；分别面向 Build 主角色、Plan 主角色、指定执行器。`hidden: true` 本身不自动授权；`system: true` 的启用包会作为基础包自动授予运行角色，范围明显更广。

`domain` 控制界面分组。一般工具包使用 `system: false`、`hidden: false`；系统基础包与隐藏自动挂载包属于运行机制，新增时需要同时验证授予范围，不应为了方便把专业工具授予所有角色。

每个公开工具恰好属于一个可见工具包，或明确登记在隐藏包；同一公开工具不能重复放入多个可见包。`TestToolsBelongToToolkits` 验证归属；隐藏包不是免检入口，需说明用途与授予范围。

## 使用说明和参考资料

正文说明“什么时候用、如何判断、怎么检查结果”。避免复制完整专题流程或写具体地区、数据集和色彩预设。

正文去掉头部、Markdown 标题及空白后达到 200 个字符的正式工具包，会向实际持有该包的角色提供按需阅读入口；较短的纯工具集合仍可授予所列工具，但不因此提供方法阅读入口。较长方法放在 `references/`，正文说明什么时候阅读它；参考读取工具支持受限目录和文本扩展名，不承担 Python 执行功能。

角色只选择工具包，方案启用流程。不要通过新增混合包类型解决工具授权问题。

## 验证

按改动范围运行定义校验、handler 映射、实际 QGIS 行为和相关 Go 目录测试。涉及权限时验证角色实际可用工具集合；涉及持久化时验证重启和失败回滚；涉及制图时与固定输入的黄金快照比较。

工具参数定义字段是 `spec.parameters`，不是 `spec.inputs`；`execution.param_mapping` 引用这些参数名。结构校验只能验证定义，不能证明 handler 已实现或真正可调用，发布前还要通过后端生成的 manifest 调用它。

项目的跨系统门禁为 `./build.sh check`。当前重构的逐卡验证及未通过项记录在 `docs/refactor-v2/evidence/`，不把跳过当作通过。
