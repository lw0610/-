# 项目介绍

当前实现位于 `enio2`，原 `Eino` 保留。[v4 方案](refactor-v4/README.md) 继续增加按角色位协作、自动获取与数据仓、OSM 工具和会话文件区；对应 [验证记录](refactor-v4/evidence/) 区分离线通过与未执行的真实在线验证。[v3 方案](refactor-v3/README.md) 解决界面等待编译、公共资源过宽和数据选择隐藏在配置里的问题；具体通过和未覆盖范围以 [验证记录](refactor-v3/evidence/) 为准。

AutoCarto 将自然语言需求、专业角色和 QGIS 操作连接起来。角色的工具包负责能力，流程包负责制图步骤，用户输入提供本次数据，模板与样式库提供可复用的视觉配置。路线知识子系统仍含场景专用内容；本次没有顺带完成 v2 的 G1 隔离和 G3 WebSocket 分层。

## 内容怎样配合

| 内容 | 负责什么 | 管理入口 |
|---|---|---|
| 智能体方案 | 角色职责、提示词、模型、工具包和启用的流程 | 模型与智能体设置 |
| 工具包 | 一类实际操作、工具用法和参考资料 | 工具中心、角色配置 |
| 流程包 | 适用范围、输入、资源、步骤、完成标准和交付 | 流程中心 |
| 运行输入 | 本次文件、文件夹、工程图层、标题和选项 | 对话页流程表单 |
| 数据需求与来源 | 声明类别、字段、范围，规划来源并核验结果 | 流程数据需求、运行获取计划、数据获取设置 |
| 数据仓 | 保存已核验结果、来源、摘要，按条件复用 | 设置中的数据获取 |
| 会话文件区 | 查看真实产出、来源及只读预览 | 右侧文件页签 |
| 模板与样式库 | 可重复使用的版式、QML、样式集 | 流程中心“模板与样式” |
| 流程自带资源 | 固定文件说明、专用符号、路线样式和资料 | 流程自己的资源页 |

没有合适流程时，仍支持角色按职责自由委派。Plan 用于只读规划与预览，Build 用于执行工具，两种模式不会自动串接。

## 从选择到运行

选择流程后立即得到执行计划和输入表单。保存、新建、复制和导入不会启动后台模型分析；点击“保存”直接显示最新步骤预览，同一行的“试运行”进入运行输入页面。必要的结构与资源检查随计划生成和运行自动进行。

流程中心不再提供重新编译、分析进度或完善状态。预览展示已保存流程的步骤和声明；实际执行仍需要角色对应的模型、工具与 QGIS 连接，运行快照保存当时的执行计划。

用户选择文件或文件夹后立即检查存在性、类型和必需文件。系统记住成功启动运行时的文件/文件夹选择，下次预填；手工清除或输入声明“不记住”可以关闭。记忆只存在本机运行目录，不进入流程包或导出包。

固定多文件流程的 CSV 是文件说明。作者把清单关联到文件夹输入，用户只选目录；目录名不限。清单没有关联时，文件从清单旁读取，适合小型数据随包携带。变更文件集合仍需作者维护清单，当前尚无图形化逐行编辑器。

参与角色将流程分工与用户方案解耦。系统优先使用合适的方案角色，按策略只为本次运行补充普通工具包，缺角色时可用流程自带角色或专用执行器；严格策略会要求用户完成对应。质量审查需实际支持读图的模型。用户已有方案文件不会因此被改写。

声明了数据需求的输入可选择自动获取或补齐缺项。系统按类别、字段、范围与比例尺列出候选来源；结果经过规范化及核验才绑定到流程，原文件只读。范围依赖路线抽取时，获取步骤等待真实路线数据集。来源和近似说明随结果保留；服务未启用、来源未就绪或数据不合格会明确失败，不编造文件替代。统计表门户自动获取未启用时仍需用户提供。

每步仅收到当前做法、前序真实产出和明确引用的资源。Go Resolver 统一按编号、类型、覆盖和锁定解析资源；Python 只消费句柄。文件变化和数据选择重新链接；运行开始再次校验，避免仅凭之前表单通过就使用已被移动的数据。

## 会话文件与数据服务

右侧工作区分为文件、任务、过程，文件区显示工具登记的真实结果与来源，可只读预览表格、图片、文档以及地理文件的信息和缩略图。预览不增加工程图层；源路径与当前产物可以区分。OSM 默认关闭，需在扩展服务开启；天地图和 GEE 需要对应的认证配置，真实联网获取效果不能由离线测试替代。

## 模板与样式怎样复用

可以直接导入 `.qpt`、`.layout.yaml`、`.qml` 或 QML 文件夹，自动识别类型；也可以从已连接的 QGIS 工程保存版式、单图层样式或样式集。版式导出只改保存副本的主图标识，工程保持原样；样式集自动导出 QML 和对照表。

公共库有稳定编号和 `resource/v1` 清单。同名用户项不会自动替代内置项；无锁定的同名歧义需要选择，只有显式 `overrides` 才覆盖。`flow.lock` 保存依赖身份，导出默认携带公共模板与样式，导入保留差异副本，不静默覆盖用户库。

内置公开三项为国标底图样式、四角对齐版式、统计专题版式。默认单色路线是工具资产，专题红蓝路线和符号属于行军流程。旧用户库里的其他类型保留迁移入口，可以复制进引用它们的用户流程。

## 目录与入口

```text
enio2/
├── autocarto/
│   ├── core/                  QGIS 插件启动、连接与执行
│   ├── tools/system/          工具定义、实现和私有 assets
│   ├── skills/system/         工具包及说明
│   ├── flows/system/          内置流程及各自资源
│   ├── resources/system/      内置模板与样式
│   └── tests/                 Python、真实 QGIS 与黄金回归
├── carto_agent/               Go 解析、执行计划、资源与运行控制器
├── autocarto-web/             前端与 Tauri 桌面端
├── autocarto_data/             本机配置、输入记忆、日志、会话、用户流程和资源
└── docs/                      指南、重构方案及验证记录
```

内置流程为行军路线图、统计专题图、交通线路图、通用数据成图；另有 [人口密度与考察路线验收包](refactor/acceptance-flows/)。流程需在所选方案中启用，不会只因目录存在就获得运行权限。公开工具归属明确工具包，隐藏兼容或专用执行器工具单独登记。

默认运行目录在固定项目根下，配置相对路径不随启动工作目录变化。可通过 `AUTOCARTO_HOME` 覆盖，必要时用绝对 `AUTOCARTO_PROJECT_ROOT` 指定项目。旧目录配置会在启动时先备份，将可以匹配的关联项迁为输入记忆；无法匹配或冲突的项保留，避免猜测用户数据。

开发仍可在 `autocarto-web/` 中执行 `npx tauri dev`，自动构建当前 Go 后端。`./build.sh dev` 另外会部署 QGIS 插件，启动前保存工程并确认 profile；`npm run dev` 只启动网页。完整命令、相对路径和备份方法见 [README](../README.md)。

日常验证用 `./build.sh check`，采用隔离运行目录，不部署插件。离线验收执行真实控制器、回执校验和 QGIS，固定角色动作及审查结构不等于在线模型准确性验证。恢复快照保留解析记录，不能恢复外部文件过去的字节。

使用说明见 [流程指南](流程包编写指南.md)、[模板与样式指南](资源制作指南.md)，新增能力见 [新增工具与工具包](新增工具与工具包.md)。
