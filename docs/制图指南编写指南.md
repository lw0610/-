# 流程编写指南

流程是一份给智能体阅读的 Markdown 文档，保存为 `FLOW.md`。在流程页新建或复制内置流程，直接编辑正文，下方实时预览；保存不调用模型。运行时，模型结合流程、用户消息和实际数据提出本次制图计划。

## 文档写法

```markdown
---
名称: 河流专题图
说明: 为用户指定区域制作河流分布图，标出河名，适用于水系分布与流域底图任务。
版本: 6.0.0
---

# 河流专题图

需要线状河流数据，优先用内置图层「河流线」，本机没有、范围或比例尺不适合时自动检索。
用户提供文件或工程已有合适图层时直接复用。

以下尺寸按 A1；其他纸张按短边比例缩放（A0 ×1.41、A2 ×0.71、A3 ×0.5、A4 ×0.35），
字号不小于 1.8 毫米，线宽不小于 0.1 毫米，字体使用系统可用的中文黑体。

| 图层 | 内置图层 | 怎么画 | 标注 | 上下顺序 |
|---|---|---|---|---|
| 河流 | 图层「河流线」 | 浅蓝（#A6CEE3）实线，0.46 毫米 | 河名，10 磅，浅蓝（#A6CEE3），沿河线放置；同名且首尾相接河段合并标注，不重复 | 背景之上 |

核验范围、几何和名称字段，加载真实数据，按表中画法设置，读回颜色、线宽、标注开关和放置方式核对。
使用版面「四角对齐版式」，纸张默认 A4 横向。
主图覆盖所选区域，图例展示实际图层，说明实际数据来源。

导出 PDF，交付成果路径和数据来源，不改写原文件。
```

头部的名称和说明供列表、搜索和流程匹配；编号取目录名。说明应写清适用请求。版本供内部依赖核验，界面不展示为用户操作项。

正文可以用段落、列表、表格组织。程序解析头部以及明确的样式、版面、图层引用，其余交给模型理解。表格本身不会被编译成固定步骤。写清每项数据的含义、几何、范围、标注、来源偏好和处理方法，以及默认纸张、输出格式、可选环节和成果核对要求即可。

不要在流程中写本机数据路径、固定角色分工或工具调用 JSON；颜色、线宽、字号等制图参数应直接写清。任务数据通过消息、附件、文件夹或 `@图层` 提供，不打包进流程。

## 图层、样式与版面引用

- `内置图层「省域面」` 或 `图层「省域面」`：引用内置图层库登记的数据。数据名称与样式名称可以相同，通过前缀区分。
- `样式「河流线」`：引用 QML 样式。
- `版面「四角对齐版式」`：引用版面模板，资源原名称不变。

图层只按明确前缀识别；不带前缀的 `「名称」` 不作为图层绑定。内置图层原文件只读，确需筛选或裁剪时生成派生结果。名称没有登记时，保存提示缺少引用但仍允许保存；运行时结合实际文件、别名、类别和检索方式确定替代来源，并在计划卡说明。

样式与版面从对应页签插入引用。它们进入 `flow.lock` 的资源记录并可随流程导出；图层引用在独立的 `layers` 段记录编号、名称和内容摘要，用于提示本机图层变化，不锁定本机路径。流程导出只带图层引用，不把底图数据打进流程包。路线样式“红蓝对比”、军标和图例属于路线工具预设，直接在正文说明用途即可。

## 底图怎样画

建议表格使用“图层 | 内置图层 | 怎么画 | 标注 | 上下顺序”五列，也可以用内容等价的段落。表格供人和模型阅读，程序不会解析列名或把正文转换成固定结构。

- **怎么画**：写颜色及十六进制值、毫米线宽或点大小、线型。多层符号按自下而上写，例如公路先画黑色 0.4 毫米线，再叠浅灰色 0.3 毫米线；不因使用这种外观改变道路的实际类别。
- **标注**：写“省名”“河名”“站名”等含义，注明字号、单位、颜色、描边及放置方式。不把 `NAME` 或 `name` 写死为要求；由图层登记的标注字段或实际字段确定。河名可写“沿线，同名相连线段合并标注，不重复”；无需标注的明确写“不标注”。
- **上下顺序**：说明哪个背景在下、专题层和点在上。分级、分类或连续渲染是专题表达，不能被底图的统一填充覆盖。
- **复杂标准符号**：可以引用 `样式「名称」` 并说明用途。行军底图只保留 `样式「铁路」`，其余七层写明参数；轨道交通覆盖流程保留河流和水域样式。现有样式仍可预览、引用和复用。
- **基准尺寸**：写明按 A1 或其他纸张设计。A1 基准换为 A0 ×1.41、A2 ×0.71、A3 ×0.5、A4 ×0.35；线宽、点大小、字号和偏移统一缩放一次，字号不小于 1.8 毫米、线宽不小于 0.1 毫米。毫米和磅不要混用。
- **中文字体**：写“系统可用的中文黑体”，按微软雅黑、苹方、思源黑体、Noto Sans CJK 的可用性选择，不绑定某个系统专有字体。

没写画法的图层先用内置登记的默认样式；也没有默认样式时，执行智能体按类别选择简洁表达，并在交付里说明。执行后读回实际颜色、线宽、标注字段与开关、放置方式和字体；颜色一致、线宽误差不超过 0.01 毫米。差异依据真实返回在原步骤修正，不重新获取数据。

运行时，规划智能体把相关图层表原文、尺寸基准和缩放规则带入该符号化步骤的 `instructions`，由执行智能体翻译为工具参数。计划格式没有新增表格字段，程序也不新增正文结构解析。

## 数据怎样确定

顺序为：用户本次提供 → 工程已有 → 流程点名的内置图层 → 类别、范围和比例尺匹配的内置图层 → 数据仓或统计库 → 自动检索。用户给文件夹时先按文件名、图层名和实际几何对应，匹配不确定的项显示“请确认”。程序不会把每个任务都限制到某个固定目录。

计划卡逐项显示来源、依据、范围、预检状态和样式。可直接改为用户文件、工程图层、其他内置图层或检索方式；保存后重新预检，不调用模型重新编译流程。无法使用的数据必须先处理才能开始。

前一步生成的数据直接作为后一步的输入；已有产出只引用，不在计划的数据项和产出中重复声明同一编号。范围可以写“路线外扩 20%”或“市域外扩 5%”，等真实路线或市域就绪后再计算；不用在流程里提前写外包框。数据在首次使用之前准备，已取得和已核验的结果复用。

统计主题写明地区层级、指标、口径和单位。用户未指定年份时，先用统计库最新年份，没有则查最新已发布年份，并在计划卡写明。图片或扫描 PDF 表格由读表能力提取，随后核对地区、年份、单位、缺项和合计。

路线流程还应写清是否需要抽取：用户已有路线数据集，或本次已经确认并生成数据集时，直接绑定并用于绘制；没有要求重抽就跳过抽取。确需抽取时，正文写清路线样式与符号，例如“红蓝对比”和“军标”。规划时必须将它们写进抽取步骤的 `parameters.route_style`、`parameters.symbols`，随真实原文引用交接，不能只在步骤说明里提到。修改绘图参数时复用已确认知识，不重新抽取相同史料。

## 保存、执行与迁移

保存只做本地文档和引用检查，不调用模型、不生成固定执行步骤。实际计划由模型在任务开始时提出；“成图后请核对”列出需检查的图面要求，数据预检与执行准备另行展示。

旧 `GUIDE.md` 和结构化 `FLOW.md` 会备份转换为普通正文。旧资源保留迁移报告，转换后检查内容。历史 v1 计划只读，可点“按新格式重新生成”；仍在运行中的旧任务保留原来的继续或停止入口。

内置流程只读，可复制为自己的流程。停用后不进入模型流程索引；选择流程不会改变启用状态。
