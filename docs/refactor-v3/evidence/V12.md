# V12 后台编译任务

## 结论
完成后台管理器与生产装配。生产 HTTP/运行入口的切换由紧随其后的 V13 完成。

## 改动摘要
- 新增 `EnrichmentManager`：生命周期上下文、同流程/方案去重、源变更时替换任务、进度查询/取消、逐项落盘；先完成流程级，再并发增强步骤。
- 全进程模型调用信号量（默认 3）、单次调用 90 秒/任务 900 秒超时；单步失败保留失败记录，其余步骤继续；已完成记录可在进程重建后继续复用。
- 新增 `flow_compile` 配置及默认值，可指定编译 provider；主程序创建并启动管理器，注入 API 和 WebSocket 广播。默认不预热。
- 事件投递独立排队，慢 WebSocket 客户端不持有任务状态锁；日志包含 flow、step、job、reason、耗时和尝试次数，不记录模型正文或凭据。
- 后台清理前枚举当前方案的键，保留跨方案当前结果与最近 200 个其他记录。

## 运行的命令与结果
所有命令显式使用 enio2 项目/资产路径与临时运行目录。

| 命令 | 结果 |
|---|---|
| `go build ./...` | 通过（`/tmp/enio2-v12-build.log`） |
| `go test ./internal/flow -run TestEnrichment -count=1` | 通过 |
| `go test -race ./internal/flow -run TestEnrichmentManager -count=1` | 通过（`/tmp/enio2-v12-race.log`） |
| `go test -p 1 ./internal/flow/... ./internal/api/... ./internal/websocket/... ./internal/config/... -count=1` | API / WebSocket / config 通过；flow 被 V30 公共资源范围变化后的旧 lock/bindings 夹具阻断，由对应迁移修复（`/tmp/enio2-v12-tests.log`） |

## 计数与耗时
| 场景 | 结果 |
|---|---|
| 5 次并发入队同一流程 | 同一个 job_id，首次 1+3 次模型调用 |
| 模型被 gate 阻塞时读取执行计划 | 立即返回 enriching；无额外模型调用 |
| 改第 3 步后重新入队 | 只增加 1 次调用 |
| 流程级成功后取消生命周期，重新创建编译器/管理器 | 流程级不重做，只完成剩余 3 步 |
| 两流程同时增强，配置并发为 2 | 实际最大并发为 2 |
| 每个流程第 2 步超时 | 仅该步 failed，其余两步 ready，仍可使用部分计划 |

## 跳过的测试及原因
不涉及前端/QGIS，完整门禁留给 V50/V51。

## 与方案不一致之处
- 活跃任务按完整当前内容键集合去重；不使用会随完成进度缩小的“缺失集合”判定替换，否则轮询/重复打开会不断取消正常任务。
- 生命周期/用户取消不把未完成项写成需等待 600 秒的失败记录，重启立即补做；单次调用超时正常保存 timeout 失败记录。
- Compile 同步辅助入口暂保留供既有测试/离线验收；V13 清除所有生产请求和运行路径调用，避免维护两套测试运行时。
- 编译并发与超时配置在进程启动时装配；provider 随环境修订重新选取，不改变无关增强键。

## 修改了涉及范围以外的文件
- `internal/api/api.go`、`internal/flow/base_plan.go`：共享管理器注入，以及 Plan 附后台状态。
