# V32 从当前工程保存接口

## 结论
完成。三种保存类型通过实例桥接导出到隔离暂存区，再交给唯一 Go 资源导入器校验入库。

## 改动摘要
- GET /api/instances/{id}/layouts 调用 layout_list，返回包含地图项 ID/UUID 的 layouts 数组。
- POST /api/resources/capture 支持 layout / style / style_set；检查实例连接与工具授权，调用 V31 新工具或 layer_save_style。
- 暂存目录在用户运行库 .staging 中，成功、冲突、导出失败和资源验证失败均清理。仅导入服务创建的路径，不信任工具返回的任意路径。
- capture 可提供 replace_id：同类型用户资源走保留 ID、增加补丁版本、备份后原子替换的既有事务。
- PUT /resources/{id}/content 支持 entry_aliases（图层名到别名字符串），与 source_path 二选一；复制后生成规范对照表并使用同一替换事务，不接受任意输出路径。
- 实例图层查询投影增加可选 type / visible，与 V31 的真实图层树可见性对应，供默认选择使用。

## 计数与耗时
请求调用 QGIS 工具，不调用模型。接口整体耗时由实际工程导出决定；测试耗时见上表。

## 跳过的测试及原因
真实 QGIS 工具行为由 V31 的真实解释器测试验证；跨界面、保存后引用运行由 V51 汇总。

## 与方案不一致之处
- 单独新增 handlers_resource_capture.go，避免把桥接逻辑堆入已有资源管理文件。
- 增加 replace_id 和 entry_aliases，是规范要求“同名替换/另存为”及“调整别名”的必要后端支持；原 source_path 替换接口保持兼容。

## 修改了涉及范围以外的文件
- handlers_instance_layers.go：公开已有工具的图层类型与可见性字段。

## 遗留问题与后续任务需要知道的事
GET layouts 的 data 为 {layouts:[...]}；地图选择建议传 UUID。单图层保存需要 layers 中恰好一个图层 ID；样式集空 layers 采用工具默认的全部可见矢量图层。
