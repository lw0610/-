# V40 数据输入、清单关联、输入记忆与旧运行兼容

## 结论
完成。资源文件夹现在来自流程输入；表单校验与启动使用同一实现，运行保存自己已校验的资源快照。输入记忆及绑定迁移的细节见 [V40-input-memory.md](V40-input-memory.md)。

## 改动摘要
- 新增：`ResourceDoc.FolderInput`，数据清单末尾的文件夹输入属性、输入存在/类型诊断；输入资源重链接；只读输入校验及记忆 API；用户流程 `convert_to_input` 修复动作。
- 修改：资源解析请求和计划携带 `base_dir_from_input`。未选择位置时相对条目 `exists: null`，只检查清单结构；选择后检查必需文件和 Shapefile 附属文件，句柄保留声明位置、实际基准目录和绝对文件路径。关联资源不再携带旧绑定键，也不回退到清单目录。
- 修改：`ValidateInputs` 与启动共用内部 `validateInputPlan`。该函数同时返回诊断和实际已校验的资源快照，启动不再解析第二次；静态体检与输入关联都计入输入使用情况。表单的对话原文占位只用于编辑校验，实际启动必须提供真实原文。
- 修改：只读检查读取既有增强缓存，以保持模型细化类型及输入约束与实际运行一致；不调用模型，不生成 `flow.lock`，不写编译缓存或记忆。
- 修改：仅成功保存新运行后记住文件/文件夹选择；复制不复制记忆，删除用户流程先清除记忆，清除失败不会静默删除流程。未关联旧绑定只读兼容；旧绑定写接口对已关联资源转写记忆，其余返回 410。
- 修改：手工记忆使用与基础计划相同的确定性输入定义；显式文本、单选、对话原文不会被说明中的“文件”误判，`不记住` 输入拒绝手工保存非空值。
- 修改：修复动作先持久化流程关联作为可恢复的迁移意图，再通过原绑定锁内的 `Consume` 备份并转移记忆。失败保留原值；重试可完成，不覆盖较新的用户选择。
- 新增：旧 v1/v2 编译器运行快照的保守恢复比较。稳定输入键升级按名称比较当前声明，但继续执行时仍使用原快照和原键；条件、引用、约束、步骤语义、输出和角色工具权限必须等价。实际文件变化仍按原指纹机制要求确认。
- 新登记的兼容层：`flow_bindings_input_memory_adapter_v2`、`resource_bindings_to_input_memory_v2`、`flow_run_v2_plan_key_upgrade`。

## 跳过的测试及原因
- 本卡不重复真实 QGIS 操作：文件/清单解析与输入记忆均为 Go 本地逻辑，工具消费的句柄接口未改变。QGIS 端 V31/V32 的实际验证记录分别见对应证据。
- 集成后的完整 `./build.sh check`、前端与验收门禁由 V50/V51 执行。

## 与方案不一致之处
- 为避免验证完毕后再次读取到不同资源修订，公开 `ValidateInputs` 委托内部 `validateInputPlan`，启动直接复用同一内部函数返回的已检查快照，保持共同验证逻辑并减少重复解析。
- 重新开始在结束旧运行之前完成全部输入校验及最终指纹比较；随后只使用已确认快照。外部文件仍可能自行改变，沿用资源确认原语义，不承诺恢复文件内容。
- 跨版本旧运行只在可证明执行结构等价时放行。新增必填输入、步骤动作、执行角色或工具权限改变时仍要求新建运行；不会仅因编译器版本升级就一概拒绝，也不会修改旧运行的键。
- 输入记忆迁移冲突时保留原绑定；已有新记忆优先。手工选择和故障恢复不依赖 map 遍历顺序。

## 修改了涉及范围以外的文件
- `flowrun/resume_legacy.go` 及测试、`flow/link.go` 快照指纹辅助函数：补齐规范要求的旧运行恢复边界，避免稳定键与编译器版本升级导致所有旧记录失效。
- `api/resource_v2_acceptance_test.go`、旧绑定相关 API 用例：旧固定绑定断言更新为关联输入与本机记忆；仍检查跨复制、改名和导出的资源身份及实际路径。

## 遗留问题与后续任务需要知道的事
- 记忆文件仅存绝对路径，不进入流程包和导出包。旧公共库绑定与尚未改写的用户流程绑定在兼容期继续只读，未擅自改变真实用户数据。
- 旧运行的资源确认保留既有含义：继续使用原引用不能恢复已被外部修改的文件内容。
