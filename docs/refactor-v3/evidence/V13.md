# V13 接口与运行入口非阻塞

## 结论
完成。HTTP、运行开始/恢复、可用流程摘要均只读取当前执行计划；模型增强只能由后台管理器或离线测试辅助入口触发。

## 改动摘要
- `POST /compile` 返回 202 与 `{job,plan,diagnostics}`；新增状态查询、取消、保存/草稿体检接口。
- 新建/保存/导入/复制先生成当前计划，再向共享管理器入队；详情、列表、体检只读本地解析与缓存。列表附 `plan_status`。
- EnsureRunnable 和 AvailablePlans 不再调用模型，保留资源/结构二次检查与错误级诊断阻止运行的规则。
- V21 前端同时移除 stale 消费，因此本轮直接删除详情 `stale` 字段与 Inspect，不再输出旧“计划过期”提示。
- 运行快照本来就序列化完整 FlowPlan，新增测试确认 enriching/pending 状态持久化；未完善步骤不把建议能力写进步骤消息，旧运行快照仍兼容。
- 成功持久化后的环境解析失败仍返回“已保存”与安全诊断，避免旧 Fetch aborted 后重试产生重复创建。

## 计数与耗时
- 新建、详情、列表、保存、复制、导入、体检、草稿体检、AvailablePlans、EnsureRunnable 的计数模型调用均为 0。
- 慢模型阻塞时 POST /compile 在 1 秒预算内返回 202，随后断开请求任务仍为 running；状态查询与 DELETE 取消正常。
- 三个真实目录示例以后台任务完成模型增强，然后 GET 当前计划；无关正文修改和启停其他流程不增加调用次数。
- enriching 计划可以正常运行，run.json 保存计划与步骤增强状态。

## 跳过的测试及原因
完整门禁等待 V40/V42 夹具迁移和 V50；本卡不修改渲染工具。

## 与方案不一致之处
同步 Compile 保留为现有测试和离线验收辅助，生产请求与运行入口不存在调用；旧 EnsureCompiled 仍是 EnsureRunnable 的无模型别名。V50 增加路由清单/结构守卫，避免重新引入同步调用。

- `internal/api/resource_v2_acceptance_test.go`：compile HTTP 状态码期望更新为 202；资源输入行为由 V40/V42 迁移。
