# V11 分级增强缓存

## 结论
完成。审查并接续 Claude 遗留的未提交实现；请求入口改造留给 V13。

## 改动摘要
- 流程级和步骤级增强按实际模型请求内容、编译器版本 3 和模型名分别缓存；输入键保持名称，资源摘要不含数据条目数。
- 执行计划合并已有增强结果，显示 basic/partial/ready 与逐步状态；失败结果、原因和重试间隔落盘，强制任务忽略已有记录。
- 旧整份计划缓存不再读取，首次增强清理；原子文件写入，当前已使用方案的引用键受到保护，其余保留最近 200 个。
- 修复候选能力 BM25 累加顺序导致的键不稳定；执行计划结构标识不再包含全局配置修订、启用流程清单或模型名称。

## 与方案不一致之处
- 内容键直接哈希完整的模型请求结构，确保实际上下文变化与缓存失效一致，避免手写字段列表与提示词分叉。
- 编译器暂保留同步 Compile 供现有测试使用，V13 会从生产请求和运行入口中完全移除调用。
- 缓存保护记录已读取方案的当前键；后续后台管理器在清理前补充枚举当前方案，跨方案任务不会误清理已知的活动记录。
