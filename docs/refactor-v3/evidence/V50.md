## 结论
后端非阻塞、任务竞态、路由清单、公共库守卫与前端集成测试已完成。完整门禁最终结果见 V51。

## 改动摘要
- `internal/api/nonblocking_acceptance_test.go` 对全部 22 条流程 HTTP 方法/路由执行成功场景（旧绑定接口为预期 410），包含新建、读取、保存、导入、复制、导出、草稿体检、编译入队/取消/状态、资源导入/删除/升级/迁入、输入校验/记忆；遍历真实 mux 路由表，新增接口缺少样例会失败。
- 模型使用慢响应与请求上下文标记，断言 0 次模型调用携带请求上下文；后台任务确实创建并调用模型，避免关闭模型掩盖同步路径。
- `internal/websocket/flow_nonblocking_acceptance_test.go` 使用真实 Compiler、真实 Controller、真实 run.json 存储测试 preview、可用流程注入、排队启动与直接启动，角色执行用离线回执适配器。
- `internal/flow/enrichment_acceptance_test.go` 覆盖运行中增量任务被手动强制任务取代、重复强制去重、任务整体超时、缓存写失败、失败原因进入当前计划、旧任务失败不污染编辑后的新计划。
- 修复上述测试发现的两个状态缺口：Force 请求可以替换非 Force 活跃任务；cache_io/整体 timeout 显示在 plan.enrichment.failed 与警告诊断。
- 真实 TS→Go HTTP fixture 的公共资料替换为 QML 样式，流程自带 doc 保留；数据清单使用 folder 输入，CSV 公库导入作为拒绝用例。

- 新增公共库守卫：读取权威 public 定义，仅允许 layout/style/style_set；检测私有类型清单、孤立文件和越界入口；删除已退出公库的空目录占位。
- 完整门禁纳入流程中心与对话流程浏览器测试；静态测试服务器支持 Next 的 /flows 等扩展名省略路由。
- 后台刷新增加选择代次和卸载防护；最后一次输入检查期间改变流程、输入、会话、工程实例、运行模式或输入约束时，不发送过时流程；只有后台进度变化不会误取消正常发送。增加轮询、终态停止、乱序响应、A→B→A 选择、卸载及失败重试测试。
- 纳入 Go embed 必需的 defaults/config.yaml；检查全部凭据字段为空，不读取真实运行配置。这修复 V00 已发现的新检出无法编译问题。

## 完整门禁发现的守卫适配
- 第一轮普通 Python 有三项失败，生产 Go/前端和全部 QGIS 专项通过。字节治理测试误把 v3 强制的输入/资源声明算入业务正文；改为对 R30 基线和当前文件使用同一投影，70% 阈值及全正文约束词限制不变。两份业务正文与 v2 最终提交逐字节一致，详见 V42。
- 退役工具守卫以前把 tools/system 下每个 YAML 当作 Tool；路线资产加入 resource/v1 清单后触发 metadata KeyError。现按声明 kind 识别 Tool/ToolPackage，同时强制名称/元数据完整和扫描非空，原归属/模块/导出检查不变。定向 1 passed，`/tmp/enio2-v3-retired-tools.log`。
- 这些修复没有修改生产行为或放宽退役工具约束；完整重跑结果见 V51。
