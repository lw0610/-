# 03 模板与样式库规范

实现任务：V30（后端收窄）、V31（从 QGIS 保存的工具）、V32（保存接口）、V33（前端）。

## 1. 范围与去向

公共资源库改名为**模板与样式库**，只收"在 QGIS 里制作、跨流程反复使用"的东西。

| 类型 | v3 归属 | 说明 |
|---|---|---|
| 版式 `layout`（`.qpt`、`.layout.yaml`） | **模板与样式库** | 可导入、可从工程保存、可覆盖内置、随流程导出 |
| 样式 `style`（`.qml`） | **模板与样式库** | 单个图层样式 |
| 样式集 `style_set`（多个 `.qml` + 对照表） | **模板与样式库** | 一套底图样式；对照表可自动生成 |
| 符号集 `symbols` | 流程自带 | 已确认事项 2；目前只服务路线专题点 |
| 路线样式 `route_style` | 流程自带；工具默认值为工具资产 | "路线样式-单色"（`route_style.mono`）迁为路线工具的资产 |
| 数据清单 `data_list` | 流程自带（文件说明） | 位置来自文件夹输入或清单所在目录（见 `04`） |
| 数据文件夹 `data_folder` | 流程自带 | 随流程包附带的数据 |
| 参考文档 `doc` | 流程自带 | 方法说明在工具包 `references/` 中 |

v2 落地的资源清单、编号、显式覆盖、摘要、`flow.lock`、随包导出、唯一解析器与资源句柄**全部保留**，只是公共库可接受的类型变少。

## 2. 类型可见性与工具资产资源

### 2.1 格式规范

`carto_agent/internal/resource/formats/resource_formats.yaml` 的每个类型增加 `public: true|false`：`layout`、`style`、`style_set` 为 `true`，其余为 `false`。`formats.go` 增加 `IsPublicType(type) bool`。`GET /api/resources/types` 返回每个类型的 `public` 字段，前端据此决定资源库与流程编辑器中可选的类型。

### 2.2 工具资产资源

- 位置：`autocarto/tools/system/<工具域>/assets/resources/<分组>/…`，带资源清单（与公共资源相同的 `resource.yaml` / `<名>.resource.yaml`），`owner: tool`。
- 解析器新增这一类根目录：启动时扫描 `autocarto/tools/system/*/assets/resources/`。
- 只能通过编号被使用：工具 YAML 的 `default_resource`、专用执行器契约。**不出现在资源库列表、不能被用户资源覆盖**（用户资源的 `overrides` 指向工具资产编号时报 `RESOURCE_OVERRIDE_CONFLICT`）、不随流程导出。
- V30 把 `autocarto/resources/system/styles/路线样式-单色.csv` 及其清单迁到 `autocarto/tools/system/route-cartography/assets/resources/styles/`，编号 `route_style.mono` 不变，`route_draw.yaml` 的 `default_resource` 无需修改。

迁移后内置公共资源只剩：`layout.four-corner`（四角对齐版式）、`layout.statistical`（统计专题版式）、`style_set.gb-basemap`（国标底图样式）。

## 3. 导入：自动识别类型

`POST /api/resources/import {source_path, name?}` 不再要求 `type`（过渡期接受 `type`，但必须与识别结果一致，否则返回 400；登记兼容层）。

| 来源 | 识别为 | 备注 |
|---|---|---|
| 以 `.layout.yaml` 结尾的文件 | 版式（`layout_yaml`） | 按 v2 规则校验结构 |
| `.qpt` 文件 | 版式（`qpt`） | 必须有 `id="main_map"` 的地图项；没有时返回明确错误，提示"在 QGIS 中把主地图项 ID 设为 main_map，或使用'从当前工程保存'" |
| `.qml` 文件 | 样式 | 读取几何类型 |
| 含 `.qml` 的文件夹 | 样式集 | 有对照表时按对照表；**没有对照表时自动生成**：每个 `.qml` 一行，图层名 = 文件名去扩展名，别名、标注字段为空；生成的 `对照表.csv` 写入导入后的副本，并在结果中提示"已按文件名生成对照表，可在详情中调整别名" |
| 其他 | 拒绝 | 返回"模板与样式库只接受版式（.qpt / .layout.yaml）、样式（.qml）和样式集（包含 .qml 的文件夹）；其他资源请放进流程包的 resources/" |

导入时同名冲突、生成编号、写入清单的规则沿用 v2 R51。

## 4. 从当前 QGIS 工程保存

### 4.1 新工具（V31，Python）

| 工具 | 位置 | 参数 | 行为 |
|---|---|---|---|
| `layout_save_template` | `autocarto/tools/system/print-layout/layout_save_template.yaml`，实现放在新文件 `_shared/layout_template_save_impl.py` | `layout`（版面名称）、`path`（输出 `.qpt`）、`main_map_item`（可选） | 把工程中的版面另存为模板。版面只有一个地图项时，保存的副本中把它的 ID 设为 `main_map`（不改工程中的版面）；有多个地图项且未指定 `main_map_item` 时报错并列出可选地图项。返回 `{path, map_items, placeholders}`，`placeholders` 为文本项中识别到的 `{{名称}}` |
| `style_set_export` | `autocarto/tools/system/cartography/style_set_export.yaml`，实现放在新文件 `_shared/style_set_export_impl.py` | `layers`（可选，名称或 ID；默认全部可见矢量图层）、`directory`（输出文件夹） | 每个图层用 `saveNamedStyle` 导出 `.qml`（文件名为图层名，非法字符替换）；写 `对照表.csv`（图层、别名、样式文件、标注字段、说明），标注字段取简单标注的字段名，其余留空。返回条目列表 |
| `layer_save_style`（现有） | — | — | 单图层样式沿用现有工具 |

- 两个新工具的 `policy` 与现有 `open_project` 一样为公开并具备 `tool.invoke` 权限（`carto_agent/internal/api/handlers_instance.go:523` 的授权检查要求如此）。
- 加入对应工具包：`autocarto/skills/system/print-layout/SKILL.md`（`layout_save_template`）、`cartography-styling/SKILL.md`（`style_set_export`），智能体在对话中也能使用。
- 这两个工具写文件，不读取资源表，不违反"Python 不解析资源表"的约束。

### 4.2 保存接口（V32，Go）

- `GET /api/instances/{id}/layouts`：调用现有工具 `layout_list`，返回工程中的版面名称与地图项。
- `POST /api/resources/capture {instance_id, kind, name, layout?, main_map_item?, layers?}`，`kind` 为 `layout` / `style` / `style_set`：
  1. 检查实例已连接（`a.localBridgeProvider.HasInstanceConnected`），按 `authorizeInstanceToolInvoke` 授权；
  2. 在 `$AUTOCARTO_HOME/resources/.staging/<随机编号>/` 下准备输出位置；
  3. 通过 `bridgeprovider.NewComputeToolInvoker(a.localBridgeProvider).InvokeTool` 调用 `layout_save_template` / `layer_save_style` / `style_set_export`（与 `handleInstanceProjectAction` 相同的调用方式）；
  4. 用 v2 的 `ImportNamed` 导入为用户资源（生成清单与编号），删除临时目录；
  5. 返回导入后的资源（同名冲突时返回 409，前端提供"替换 / 另存为"，与导入一致）。

## 5. 列表与解析行为

- `GET /api/resources?scope=all|user|builtin`：只返回公共类型。
- `GET /api/resources?scope=retired`：返回用户库中**非公共类型**的旧资源（v2 期间可能导入过），附引用它们的流程。
- FLOW.md 中 `类型「名称」：公共资源库` 指向非公共类型时：
  - 用户库中有同名旧资源 → 仍然解析（一个版本的兼容期），报 `FLOW_RESOURCE_LIBRARY_TYPE_RETIRED`（警告），修复动作 `adopt_into_flow`；
  - 没有 → `FLOW_RESOURCE_NOT_FOUND`，提示"这类资源不再放在公共库，请放进流程包的 resources/"。
- 导出流程包时，`include_library_deps` 只附带公共类型；流程自带资源照旧随包。

## 6. 移入流程（`adopt_into_flow`）

`POST /api/flows/{id}/resources/adopt {resource_id, label}`（仅用户流程；内置流程提示先复制）：

1. 把资源（含清单）复制到 `<流程目录>/resources/<分组>/`；
2. 把 FLOW.md 中该资源声明的位置改写为流程内相对路径；
3. 删除对应的锁定条目；
4. 返回保存后的流程详情（执行计划立即可用，后台入队增强）。

前端在"旧资源"列表和诊断修复中提供"移入流程"按钮。

## 7. 前端（V33，`features/flows/ResourceLibrary.tsx` 等）

- 页签改名"模板与样式"，分"版式 / 样式 / 样式集"三栏或筛选；**去掉"资源类型"选择器**。
- "导入"：选择文件或文件夹，后端自动识别；样式集没有对照表时展示生成结果并允许修改别名后保存（调用现有替换接口）。
- "从当前工程保存"：需要已连接 QGIS 工程；对话框中选择种类：
  - 版面 → 版式：列出 `GET /api/instances/{id}/layouts` 的版面，多地图项时选择主地图；
  - 图层样式 → 样式集：列出当前工程图层（现有 `GET /api/instances/{id}/layers`），默认勾选可见矢量图层；
  - 单个图层 → 样式；
  - 填写名称后保存。
- v2 的覆盖、复制、替换、引用查询、删除保护界面保留。
- 有旧资源时显示折叠区"旧资源（待迁移）"：列出引用它们的流程与"移入流程"按钮。
- 流程编辑器"从模板与样式库选择"只列公共类型；插入的类型词与 v2 一致。
