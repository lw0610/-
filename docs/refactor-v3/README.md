## 1. 目标

**一句话**：任何界面操作都不再等模型；公共资源只管"在 QGIS 里做好、反复使用的模板与样式"；数据位置作为流程运行时的输入来选择，并被记住。

具体四件事：

1. **编译不阻塞**：选流程、打开详情、保存、新建、导入、复制、体检、开始运行，都不同步调用模型。模型补全（"增强"）放到后台任务里做：不随请求取消、按步骤增量、逐步落盘、进度可见。
2. **"解析预览"拆分**：拆成"体检"（秒级、不调模型、可检查未保存的草稿）和"重新编译"（后台、可继续编辑）。
3. **公共资源收窄为模板与样式库**：公共库只有版式、样式、样式集；导入自动识别类型；可以把当前 QGIS 工程的版面、图层样式一键保存进库。其他类型改为流程自带或工具资产。
4. **数据即输入**：流程用"文件 / 文件夹 / 图层"输入声明数据；数据清单可以关联一个文件夹输入；系统记住上次选择并即时校验缺失文件。"绑定基准目录"这个概念退出。

## 2. 现状问题（证据均来自当前代码）

**Q1 界面操作同步调用模型编译**
- 对话页选流程：`autocarto-web/src/features/flow-run/useFlowComposer.ts:54` 读取详情后，若没有计划或计划过期，立刻调用 `flowApi.compile`（`autocarto-web/src/features/flows/api.ts:43`，`force: true`，300 秒超时）。
- 编译在请求上下文中同步执行（`carto_agent/internal/api/handlers_flow_compile.go:30`）：1 次流程级模型调用 + 每个步骤 1 次，**串行**，每次最多 2 次尝试（`carto_agent/internal/flow/compile_llm.go:67`）。行军流程 11 步，即 12–24 次远程模型调用。
- 前端 300 秒超时后放弃请求，后端随请求上下文一起取消，已完成的部分全部作废、不落盘。开发运行目录中没有 `autocarto_data/data/flow_cache`，说明编译从未成功保存过。
- 保存、新建、导入、复制同样同步编译（`carto_agent/internal/api/handlers_flow.go:118`、`:159`、`:193`、`:257` → `decorateFlow(…, true)`），前端为此给这些请求 300 秒超时。
- 对话"自动"模式下每条消息前，`AvailablePlans` 对每个启用流程调用 `compileSource`（`carto_agent/internal/flow/compile.go:173`），缓存失效时在消息执行**之前**同步编译（4 个内置流程共 25 步）。
- 运行开始（`carto_agent/internal/flowrun/controller.go:55`）、恢复（`resume_resources.go:74`、`:163`）、`flow_preview`（`carto_agent/internal/websocket/flow_runtime.go:205`）都经由 `EnsureRunnable`，缓存失效时同样同步编译。

**Q2 编译缓存过于敏感、没有增量**
- 编译键（`carto_agent/internal/flow/cache.go:19`）包含：方案修订号（其中混入了**整个 `config.yaml` 的哈希**，`carto_agent/internal/api/flow_environment.go:190`）、全部角色、全部工具包与能力、所有启用流程的列表、模型名。改任何设置、启停任意流程、改任意角色，所有流程的计划同时失效；缓存还按方案分目录。
- 任何变化都整份重编，没有按步骤增量：改一个步骤，11 个步骤全部重新调模型。

**Q3 输入键不稳定**
模型生成英文输入键（`compile_llm.go:100` 起）；模型失败时回退为 `input_1`、`input_2`（`compile_llm.go:162` 起）。基础结果和模型结果的键不同，无法"先显示表单、后补全"，也无法按键记住用户的输入。

**Q4 "解析预览"含义不清、重复编译**
按钮实际做的是"保存 + 强制重新编译 + 体检"（`autocarto-web/src/features/flows/FlowWorkspace.tsx:174`）。有未保存修改时，先保存（保存本身已同步编译一次），再强制编译一次；没有修改时也强制重编。

**Q5 公共资源类型过宽**
- 资源库导入前要先从 8 种类型里选一种；而内置公共库只剩 4 项：两个版式、"国标底图样式"、"路线样式-单色"。
- 数据清单 / 数据文件夹（随任务和电脑变化，不是模板）、路线样式（某个渲染插件的参数表）、符号集（目前只服务路线专题点）、参考文档（方法说明已在工具包里），都不适合公共化。
- 样式集要求用户手写"图层 → 样式文件"对照表 CSV，门槛高；没有"从当前工程保存"的入口。

**Q6 数据靠"绑定基准目录"**
- 行军流程的外部底图靠 `config/resource_bindings.yaml` 绑定；开发运行目录中的绑定仍是 v1 哈希键：`flow:marching-route/resource_6d294f11b03f: ../数据/底图数据/China_map`。
- 前端的绑定对话框、`bind_base_dir` 修复动作、"旧绑定未能对应"提示都源于这个概念。数据位置本质上是"每次运行的输入"，其他三个内置流程已经用输入来接收数据。

**Q7 编译过程不可观测（附带问题）**
后端日志没有编译开始、结束、耗时、失败的记录。另外开发运行配置 `autocarto_data/config/config.yaml` 的 `data_dir` 仍指向 `Eino/autocarto_data/data`，当天的后端日志写进了原 Eino 项目的 `agent.log`，排查困难。

## 3. 目标设计

### 3.1 三级执行计划

| 级别 | 内容 | 来源 | 何时可用 | 调模型 |
|---|---|---|---|---|
| 基础计划 | 解析结构、确定性输入（稳定键）、确定性条件规则、角色绑定、静态体检、资源链接 | FLOW.md、方案、资源 | 随时，毫秒级 | 否 |
| 增强结果 | 流程级：触发词、输入类型补全、输入约束；步骤级：建议能力、缺失能力、推断产出、条件规则补全、备注 | 后台编译任务 | 任务进行中按步骤逐个可用 | 是 |
| 执行计划 | 基础计划 + 已有的增强结果（按步骤合并） | 合并 | 随时 | 否 |

所有请求处理路径和运行入口只使用"执行计划"。模型失败或未配置时，执行计划等于基础计划（与现有"确定性回退"一致），流程照样可以运行。详见 `01`。

### 3.2 运行链路

```text
保存 / 新建 / 导入 / 复制 / 选中流程
        │ 立即返回（不调模型）
        ▼
基础计划（解析 + 确定性输入 + 角色 + 体检 + 资源链接）──► 合并已有增强结果 ──► 执行计划 ──► 界面 / 运行
        │
        └─► 后台编译任务（去重；不随请求取消；限并发；逐步落盘）
                 │ 每完成一个步骤
                 └─► 写入增强缓存（按流程级 / 步骤级内容键）──► 推送 flow_compile 事件 ──► 界面自动刷新
```

### 3.3 资源与数据的去向

| 现在 | 之后 |
|---|---|
| 公共资源库 8 种类型 | "模板与样式库"：版式、样式、样式集 |
| 数据清单 / 数据文件夹（公共） | 不再公共；数据清单只作为流程自带的"文件说明"，位置来自文件夹输入 |
| 路线样式（公共"路线样式-单色"） | 工具资产（`route_style.mono` 编号不变，供 `route_draw` 默认使用）；流程专用的放流程自带 |
| 符号集、参考文档 | 流程自带 |
| 绑定基准目录 | 文件夹输入 + 记住上次选择 |

## 5. 整体验收标准

1. **W1 秒开**：选流程、打开流程详情、保存、新建、导入、复制、体检，都不调用模型（计数测试为 0）；本地接口在无大数据时 1 秒内返回；选中流程后输入表单立即显示。
2. **W2 后台编译可靠**：请求断开、页面刷新不影响编译任务；进度可见、完成后界面自动刷新；单个步骤失败不影响其他步骤；已完成的步骤结果落盘，重启后不重做。
3. **W3 增量与稳定**：只改一个步骤时只重新增强该步骤（计数）；修改与编译无关的设置、启停其他流程、调整界面布局，不使任何增强结果失效。
4. **W4 运行不被阻塞**：计划完善中也能直接运行（使用执行计划），`run.json` 记录计划完善状态。
5. **W5 模板与样式库**：资源库只显示版式、样式、样式集；导入无需选择类型；可从当前 QGIS 工程保存版面为版式、保存图层样式为样式集；其他类型的旧用户资源有迁移入口。
6. **W6 数据即输入**：行军流程首次运行在输入表单中选择底图文件夹，之后自动预填；选择后立即提示缺失文件；界面不再出现"绑定基准目录"；开发运行目录中的旧绑定自动迁移为记住的输入值。
7. **W7 不退化**：v2 R73 的五项真实 QGIS 离线验收与黄金样例回归通过。
8. **W8 门禁**：`./build.sh check` 通过。

## 6. 全局执行约束（所有执行智能体必须遵守）

在 v2 `README.md` §6 的全部约束基础上（一次一张卡、不破坏用户数据、资源只由 Go 解析、兼容层登记、测试测行为不测措辞、中文文案、写验证记录、以代码为准、质量门禁、提交不推送），增加：

1. **请求处理路径中不得同步调用模型**：HTTP 处理函数、WebSocket 消息处理、`AvailablePlans`、运行开始与恢复，只能读取执行计划或把编译放入后台任务。新增代码违反此条视为缺陷（V50 有计数测试守护）。
2. **后台任务不得使用请求上下文**：编译任务的上下文来自进程生命周期（`cmd/agent/main_deep.go` 的 `lifecycleCtx`），并带自己的超时与取消。
3. **公共资源库只接受版式、样式、样式集**；其他类型只能作为流程自带或工具资产存在。
4. **记住的输入值只存在本机运行目录**，不得写入流程包、导出包、日志正文或遥测。
5. **本方案的验证记录写在 `docs/refactor-v3/evidence/`**，提交信息以任务号开头（例如 `V12: 后台编译任务`），在 `refactor/v3` 分支上提交，不推送、不合并。
6. **不得读写真实的 `autocarto_data/`**：测试一律使用临时运行目录；只有 V40 的启动迁移会在用户运行时改写绑定与输入记忆文件，且必须先备份、可重复执行。

## 9. 术语

| 术语 | 含义 |
|---|---|
| 基础计划 | 只用确定性规则从 FLOW.md、方案、资源得到的执行计划；不调模型，随时可用 |
| 增强结果 | 模型对流程和每个步骤补全的内容（触发词、建议能力、推断产出、条件规则等），按内容键缓存 |
| 执行计划 | 基础计划合并已有增强结果后的计划；界面展示与运行都用它 |
| 计划状态 | `ready`（全部增强已完成）、`enriching`（后台任务进行中）、`partial`（部分步骤未完善且没有进行中的任务）、`basic`（未配置编译模型） |
| 后台编译任务 | 在进程内后台执行的增强任务，按 (流程, 方案) 去重，进度通过 `flow_compile` 事件推送 |
| 体检 | 只做确定性检查（结构、角色、能力、资源、输入），秒级返回；可以检查未保存的草稿 |
| 模板与样式库 | v3 的公共资源库，只含版式、样式、样式集 |
| 工具资产资源 | 随工具发布、带资源清单、只能通过编号被工具默认值或执行器引用的资源；不在资源库中显示 |
| 输入记忆 | 本机记住的每个流程文件 / 文件夹输入的上次取值，用于预填输入表单 |
