# 04 数据输入规范

实现任务：V10（输入类型属性与稳定键）、V40（数据清单关联输入、输入记忆、即时校验、绑定退出与迁移）、V41（前端）、V42（内置流程与文档）。

## 1. 原则

- **数据位置是每次运行的输入**，不是资源，也不是"绑定"。流程在"需要准备"里声明需要的文件、文件夹或图层；用户在运行前的输入表单中选择。
- **系统记住上次的选择**，下次自动预填；用户可以随时改。
- **选择后立即校验**：缺哪些文件、附属文件是否齐全，当场提示。
- 数据清单仍然有用：它说明"这个文件夹里应该有哪些文件、加载成什么图层名、哪些是必需的"。它是流程自带的**文件说明**，位置来自一个文件夹输入，或者就是清单所在目录（数据随流程包附带时）。

## 2. 输入声明

### 2.1 语法（在现有"名称（属性）：说明"基础上扩充）

| 属性 | 含义 | 现状 |
|---|---|---|
| `必填` / `可选` | 是否必填 | 已有 |
| `文件`、`文件夹`、`图层`、`对话原文`、`文本`、`数字` | **显式类型** | 新增（现在类型靠说明中的关键词推断或由模型决定） |
| `是/否` | 布尔 | 已有 |
| `可选值：A、B、C` | 单选 | 已有 |
| `默认…` | 默认值 | 已有 |
| `与「X」二选一` | 至少提供其一 | 已有 |
| `不记住` | 文件 / 文件夹输入不记住上次选择 | 新增 |

示例：

```markdown
## 需要准备
- 史料原文（与「路线数据集」二选一，对话原文）
- 路线数据集（与「史料原文」二选一，文件夹）：已经整理好的路线数据集
- 底图数据（必填，文件夹）：存放中国底图 8 个图层的文件夹，首次运行时选择，之后自动记住
- 纸张（默认 A1 横向；可选值：A0 横向、A1 横向、A2 横向、A3 横向、A4 横向）
- 质量审查（是/否，默认否）
```

### 2.2 类型的确定顺序（全部确定性）

1. 显式类型属性；
2. `是/否` → 布尔；有 `可选值` → 单选；
3. 说明中的关键词（沿用现有回退规则：含"对话"且含"原文" → 对话原文；含"文件夹" → 文件夹；含"文件" → 文件）；
4. 以上都没有 → 文本；体检提示 `FLOW_INPUT_TYPE_IMPLICIT`（提示）："建议在括号里写明类型，例如（可选，文件）"。

模型增强只能把第 4 种情况的"文本"细化为其他类型（例如图层）；显式属性和关键词得出的类型不允许被模型改动。

### 2.3 稳定的输入键

- **输入键 = 输入名称**（括号前的文字，去掉首尾空白）。模型不再生成键；删除 `compile_llm.go` 中 `inferFlow` 对键的要求与 `inputKeyPattern` 校验；`fallbackInputs` 的 `input_N` 键退出。
- 同一流程中输入名称必须唯一，重复时报 `FLOW_INPUT_DUPLICATE`（错误）。
- 条件规则、输入约束、`run.json` 的输入值、执行器的输入检查都改用这个键。
- 旧的 `run.json` 带有自己的计划快照，恢复旧运行时按快照中的键处理，不做重新映射。

## 3. 数据清单关联文件夹输入

### 3.1 写法

在"使用的资源"中，数据清单声明的末尾用括号写明文件所在的输入：

```markdown
## 使用的资源
- 数据清单「中国底图」：resources/data/中国底图.csv（文件所在文件夹：「底图数据」）
```

- 被引用的输入必须存在且类型为 `文件夹`，否则报 `FLOW_DATA_INPUT_INVALID`（错误）。
- 没有括号属性的数据清单：文件相对于清单所在目录（数据随流程包附带的情况，如 `docs/refactor/acceptance-flows/` 中的两个验收流程），行为与现在相同。
- 清单中的绝对路径行照旧可用（体检警告 `FLOW_RESOURCE_PATH_EXTERNAL`）。

### 3.2 解析与链接

- `carto_agent/internal/flow/parse.go` 的资源声明解析：位置末尾的 `（文件所在文件夹：「X」）` 解析为 `ResourceDoc.FolderInput = "X"`，位置本身去掉括号部分。
- `carto_agent/internal/resource` 的解析请求增加 `BaseDirFromInput string`（输入名称）与 `BaseDirOverride string`（输入取值）：
  - 只知道关联、不知道取值时（展示执行计划）：只校验清单格式，报 `FLOW_DATA_FROM_INPUT`（提示）："文件位置在运行时由「底图数据」决定"；条目的 `exists` 为未知，不报缺失。
  - 知道取值时（输入校验、运行开始）：以取值为基准目录检查每个条目及其附属文件，沿用 `FLOW_DATA_FILE_MISSING`、`FLOW_DATA_SIDECAR_MISSING`。
- 运行开始时（`flowrun.Controller.Start` → `startPlan`）：`ResolveInputs` 之后，用输入取值重新链接关联的数据清单；必需文件缺失则拒绝运行并返回逐项原因；成功后句柄的 `base_dir` 为输入取值，条目路径为绝对路径（工具侧无需改动）。
- 步骤消息中写成："「中国底图」（数据清单，8 项，位于「底图数据」）"。

## 4. 记住上次选择（输入记忆）

### 4.1 存储

`$AUTOCARTO_HOME/config/flow_input_memory.yaml`：

```yaml
apiVersion: flow-input-memory/v1
flows:
  marching-route:
    底图数据: /Users/<用户>/研究生/QGIS-agent/数据/底图数据/China_map
```

- 键为 (流程编号, 输入名称)；值为绝对路径。
- **何时写入**：运行成功开始（输入校验通过）后，对类型为文件 / 文件夹且没有 `不记住` 属性的输入写入；用户在流程中心"输入"页手动修改时写入。
- **不写入**：流程包、导出包、日志正文。复制流程不复制记忆；删除用户流程时删除其记忆。
- 写入方式：临时文件 + 原子重命名，进程内加锁（与 v2 绑定存储相同的做法）。

### 4.2 接口

| 接口 | 行为 |
|---|---|
| `GET /api/flows/{id}/inputs/memory` | 返回该流程记住的值 |
| `PUT /api/flows/{id}/inputs/memory/{label} {value}` | 手动设置（校验类型与存在性） |
| `DELETE /api/flows/{id}/inputs/memory/{label}` | 清除 |

### 4.3 表单预填顺序

记住的值 > 声明的默认值 > 空。预填的值同样经过 §5 的即时校验（例如上次的文件夹已被移动，会立即提示）。

## 5. 即时校验

- 接口：`POST /api/flows/{id}/inputs/check {scheme, values}`，返回 `[{label, level, code, message}]`；不调模型，不写文件。
- 检查内容：必填是否填写；文件 / 文件夹是否存在、类型是否正确；关联数据清单中的必需文件与附属文件是否齐全（逐项列出缺失文件名）；"二选一"约束。
- 与运行开始共用同一个函数：新增 `flowrun.ValidateInputs(plan, values, projectRoot) []InputProblem`，`Start` 与校验接口都调用它，保证"表单上通过 = 运行时通过"。
- 图层输入：由前端用已加载的工程图层列表检查（现有 `GET /api/instances/{id}/layers`），后端不额外调用 QGIS。
- 前端在值变化后 500 毫秒内调用（防抖），结果显示在对应输入下方。

## 6. 绑定退出与迁移

### 6.1 启动迁移（V40）

进程启动时执行，**先备份**、**可重复执行**：

1. 读取 `config/resource_bindings.yaml`（v1 无版本号格式，或 v2 `resource-bindings/v2` 格式）。
2. 对每条 `flow:<流程>/<键>` 绑定，读取该流程（内置或用户）当前的 FLOW.md，找到关联了文件夹输入的数据清单声明，按以下两种旧键算法比对：
   - v1：`resource_` + `sha256(类型 + "\x00" + 标签)` 的前 12 位十六进制（已验证：开发运行目录中的 `resource_6d294f11b03f` = `sha256("data_list\x00中国底图")` 前 12 位）；
   - v2：`path:<相对 resources/ 的路径>` 或清单编号。
3. 匹配成功 → 写入输入记忆 `flows[<流程>][<关联的输入名称>]`，值规范化为绝对路径（越出项目根的 `../…` 相对值按项目根解析）。
4. 匹配到的数据清单**没有**关联文件夹输入（用户流程尚未改写）→ 绑定在兼容期内继续只读生效，体检报 `FLOW_DATA_BINDING_LEGACY`（警告），修复动作 `convert_to_input`。
5. `library:<编号>` 绑定（公共数据清单已退出）→ 兼容期内只读生效，同时提示迁移。
6. 迁移完成的绑定从 `resource_bindings.yaml` 中移除；文件为空后保留空文件（便于回退）。

开发运行目录迁移后应得到（V42 已给行军流程加上"底图数据"输入之后）：

```yaml
apiVersion: flow-input-memory/v1
flows:
  marching-route:
    底图数据: /Users/<用户>/研究生/QGIS-agent/数据/底图数据/China_map
```

### 6.2 修复动作 `convert_to_input`（仅用户流程）

在 FLOW.md 的"需要准备"中追加 `- <清单名>所在文件夹（必填，文件夹）：<清单名>的文件所在文件夹`，并在该数据清单声明末尾加上 `（文件所在文件夹：「<清单名>所在文件夹」）`；原绑定值写入输入记忆。保存后执行计划立即刷新。

### 6.3 接口与界面

- `PUT /api/flows/{id}/bindings`：关联了输入的清单 → 写入输入记忆（兼容一个版本）；未关联的清单 → 410，提示使用 `convert_to_input`。
- 前端删除：流程中心的"绑定数据基准目录"对话框、诊断修复 `bind_base_dir`、"有 N 条旧绑定未能对应"横幅（改为"旧绑定已迁移为输入记忆"或"有 N 条旧绑定待转换"）。
- `resource_bindings.yaml` 的读取保留一个版本（兼容层，登记到 `removal_ledger.yaml`）。
