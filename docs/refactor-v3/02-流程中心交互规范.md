# 02 流程中心交互规范

实现任务：V20（对话页选流程秒开与完善进度）、V21（流程中心操作拆分）；V33、V41 涉及的模板库与输入表单交互分别见 `03`、`04`。

## 1. 计划状态的统一展示

新建共享组件 `autocarto-web/src/features/flows/PlanStatusBadge.tsx`，对话页与流程中心共用：

| `plan_status` | 显示 | 说明文字（悬停或展开） |
|---|---|---|
| `ready` | 已就绪 | 全部步骤已完善 |
| `enriching` | 完善中 3/11 | 后台正在用模型补全建议能力等内容，不影响填写和运行 |
| `partial` | 部分未完善 | 列出失败步骤与原因（超时、模型返回格式不对等），提供"重新编译" |
| `basic` | 基础计划 | 未配置编译模型；流程按确定性结果运行 |

数据来源：执行计划中的 `plan_status` 与 `enrichment`；收到 `autocarto:flow_compile` 事件时更新；没有 WebSocket 时每 5 秒轮询 `GET /api/flows/{id}/compile-status`，状态为终态后停止。

## 2. 对话页选择流程（`features/flow-run/useFlowComposer.ts`、`FlowComposer.tsx`）

**现在**：选中后显示"正在读取流程输入…"，内部先读详情，再同步等待强制编译（最长 300 秒），超时报错。

**之后**：

1. 选中流程 → `GET /api/flows/{id}?scheme=`（普通 15 秒超时，正常 1 秒内）。"正在读取流程输入…"只在这次请求期间显示。
2. 立即用执行计划中的 `inputs` 渲染输入表单（输入键稳定，后续增强不会改变表单）。
3. 输入表单预填：记住的值 > 声明的默认值 > 空（见 `04` §4）；选择文件或文件夹后即时校验（见 `04` §5）。这一条依赖 V40 的接口，由 V41 实现；V20 只用声明的默认值预填。
4. 表单上方显示 `PlanStatusBadge`。状态为 `partial` 时自动调用 `POST /api/flows/{id}/compile`（`force: false`）入队，不等待结果。
5. **永远不在选流程时同步等待编译**；删除 `useFlowComposer.ts` 中"计划缺失或过期就 `await flowApi.compile`"的分支。
6. 发送：只要执行计划没有错误级诊断、必填输入已填，就允许发送。计划状态不是 `ready` 时，在发送按钮旁提示"有 N 个步骤尚未完善，将按基础计划运行"（已确认事项 1）。
7. 读取失败时显示错误与"重试"按钮，不阻止切回"自动"。

## 3. 流程中心（`features/flows/FlowWorkspace.tsx`）

### 3.1 按钮

| 按钮 | 行为 | 是否调模型 | 耗时 |
|---|---|---|---|
| 保存 | 保存 FLOW.md（旧版本自动备份，与现在一致）；返回执行计划；后端自动在后台完善 | 后台 | 秒级返回 |
| 体检 | 对**编辑器中的当前内容**做确定性检查（有未保存修改时检查草稿，不保存）；刷新右侧"步骤预览 / 体检 / 资源 / 输入" | 否 | 秒级 |
| 重新编译 | 强制后台重新完善全部步骤；按钮旁显示进度；可以继续编辑 | 后台 | 立即返回 |
| 试运行 | 跳到对话页并选中此流程（现有行为）；执行计划无错误即可点击 | 否 | — |

- 删除"解析预览"按钮及其"先保存再强制编译"的逻辑（`FlowWorkspace.tsx:174` 的 `compile` 与按钮处理函数）。
- 页面标题旁显示 `PlanStatusBadge`。
- "执行计划已过期，请重新解析"的提示删除（执行计划永远对应当前保存的版本）。
- 后台任务完成时：若编辑器没有未保存修改，自动刷新右侧面板；有未保存修改时只更新状态徽标，并提示"已保存版本的执行计划已更新"。

### 3.2 右侧面板

- **步骤预览**：每张步骤卡显示该步的增强状态——"建议能力：完善中…"、"未完善：模型超时"（附"重新编译"入口）、或建议能力清单。
- **体检**：诊断按来源分两组：结构与资源（确定性）、模型辅助（增强失败或推断提示）。修复按钮沿用 v2 的动作，但删除 `bind_base_dir`（见 `04` §6）。
- **资源**：只显示流程自带资源和引用的模板与样式（v2 R61 的界面保留），数据清单显示"位于输入「X」"而不是绑定状态（见 `04`）。
- **输入**：显示输入表单预览（类型、必填、默认值）以及本机记住的值（可清除、可修改，见 `04` §4）。

### 3.3 新建、导入、复制

请求改为普通超时；返回后直接打开详情，计划状态通常为 `enriching`。删除"流程已创建，解析尚未完成，可继续编辑后点击'解析预览'"等提示。

## 4. 前端接口变化（`features/flows/api.ts`、`types.ts`）

- 删除 `compilationRequest`（300 秒）；`create`、`save`、`import`、`copy` 使用默认超时。
- `compile(id, scheme, force)` 返回 `{job, plan, diagnostics}`（`202`）；新前端只用 `job`，并且**不等待**任务完成。
- 新增 `check(id, scheme, flowMD?)` → `POST /api/flows/{id}/check`。
- 新增 `compileStatus(id, scheme)` → `GET /api/flows/{id}/compile-status`。
- 新增 `cancelCompile(id, scheme)` → `DELETE /api/flows/{id}/compile`。
- `types.ts`：`FlowPlan` 增加 `plan_status`、`enrichment`；`FlowStep` 增加 `enrichment`；`FlowDetail.stale` 删除（过渡期可保留只读字段并在 V21 完成后删除）。
- `components/providers/WebSocketProvider.tsx`：收到 `flow_compile` 消息时派发 `autocarto:flow_compile` 浏览器事件（`detail` 为任务状态）。
