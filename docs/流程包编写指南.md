# 流程包编写指南

本文对应 [v4 方案](refactor-v4/README.md)。流程包说明“准备什么、交给谁、怎么做、交付什么”，工具包提供操作能力，模板与样式库保存可以反复使用的版式和图层样式。角色补位、数据获取和文件区的实现与验证范围见 [v4 验证记录](refactor-v4/evidence/)，[v3 记录](refactor-v3/evidence/) 保留历史结果。

## 从一个能运行的例子开始

在流程中心新建流程，或复制 [空白模板](refactor/templates/FLOW.md)。内置流程只读，修改前复制为自己的流程。导入接受文件夹、ZIP 或单个 `FLOW.md`；ZIP 可以直接包含文件，也可以只有一个顶层文件夹。同编号的用户流程可选择替换并保留旧版本，另存为时使用新编号。

```text
my-flow/
├── FLOW.md
├── flow.lock                  模板与样式依赖的编号、版本和摘要
└── resources/                 流程自己的资源
    ├── data/文件说明.csv
    ├── layouts/专用模板.qpt
    ├── symbols/专用符号/
    └── docs/来源.md
```

一个直接接收文件的最小流程：

```markdown
---
编号: my-map
名称: 数据检查与成图
说明: 核验输入数据并制作地图
版本: 1.0.0
---

## 适用场景
用户已经提供空间数据，希望检查后生成地图。

## 需要准备
- 数据文件（必填，文件）：用户提供的空间数据
- 地图标题（必填，文本）：成果地图的标题
- 纸张（默认 A4 横向；可选值：A4 横向、A3 横向）

## 使用的资源
- 版式「统计专题版式」：公共资源库/layout.statistical

## 步骤
### 第1步 检查并加载数据
- 负责：数据工程专家
- 做法：读取「数据文件」，核对几何、字段和坐标系，报告缺口，不猜测缺失字段。
- 完成标准：「可用图层」（图层）
- 失败时：询问用户

### 第2步 排版并导出
- 负责：制图布局专家
- 做法：按「统计专题版式」与「纸张」排版「可用图层」，标题使用「地图标题」，导出 PNG。
- 完成标准：「成果图片」（文件，png）

## 必须遵守
- 不编造来源或统计值，不覆盖原始数据。

## 交付
成果路径、来源与未解决的问题。
```

未声明参与角色时，负责角色仍按当前方案显示名或编号匹配。声明参与角色后按角色位匹配、补充本次工具或使用流程自带角色；严格策略下不能补位。在方案页启用流程后，到对话页选择流程即可填写输入。计划生成和运行时自动检查可确定的结构和文件条件，文件存在不代表 QGIS 必然能正确读取其几何或字段。

## 参与角色

参与角色是流程需要的分工，不是强迫用户在方案里建立同名智能体。三级标题是角色位，步骤中的“负责”引用它：

```markdown
## 参与角色
### 数据工程专家
- 职责：检查并加载空间数据
- 工具包：数据加载与导出

### 质量反馈智能体
- 职责：读取成果图片检查版面
- 工具包：质量审查
- 模型：读图

### 制图知识抽取专家
- 执行器：路线知识抽取
```

工具包可用目录编号或显示名。普通角色写工具包，专用执行器写执行器，两者不混写。系统先尊重“角色对应”，再找同名或能力足够的方案角色；方案允许补齐时，只为本次运行授予缺少的普通工具包，或建立流程自带角色，不修改用户方案文件。隐藏工具包和脚本、工具创建包不会自动授予。专用路线执行器缺失时按策略使用系统执行器。

方案策略可选自动补齐、优先流程自带角色、严格使用方案角色。被禁用的角色不参与匹配。“只用方案角色：是”可对单个角色收紧。读图必须有已标记支持读图的模型；仅写“读图”不会让普通文本模型拥有图像能力。预览会说明角色来自哪里，可以在“角色对应”中调整。

## 能力

步骤还可以声明只在本步需要的包：`- 能力：几何处理与叠加；可选：栅格分析`。分号前是必需，后面的可选包只有可用时才使用，不会因缺少而阻断。这里填工具包，不填英文工具函数或泛泛的自然语言愿望。专用执行器按自身固定能力执行。

## 数据需求

数据需求声明“要什么、按什么范围”，来源目录与规划器决定从哪里取。没有声明的数据仍由用户提供；保存和预览只解析，不联网、不调用模型：

```markdown
## 数据需求
### 行政区数据
- 类别：行政区划面
- 层级：「行政区级别」
- 范围：「区域」
- 参数：within=「区域」
- 推荐来源：中国行政区边界（内置）

### 中国底图
- 清单：「中国底图」
- 范围：「路线数据集」外扩 20%
- 比例尺：自动
```

单项标题必须对应同名文件或图层输入；一组数据用清单，并把清单关联到文件夹输入。运行表单可选我来提供、自动获取，清单还可提供文件夹并补齐缺项。引用的区域、年份等在自动获取时才要求填写；范围依赖前序路线数据集时，预览明确显示等待该步骤。

获取计划逐条列出来源、备选、不可用原因与估计值，来源可更换，也可单项自己提供。推荐来源只改变排序，不绕过服务可用性或疆域来源规则。自动获取结果经过确定性格式、字段、几何与范围核验后才交给业务步骤；失败时可以换来源、提供文件、跳过可选项或停止。数据来源说明会保留真实来源、许可、时间与近似信息，版面可引用「数据来源说明」。未配置服务、未开放门户自动获取、无可用来源都不能当成成功。

## 数据清单的类别与字段

清单仍是文件说明，用户不需要把几何塞进 CSV。作者为可自动获取的行增加类别与输出字段：

```csv
名称,路径,类型,必需,类别,字段,说明
省域,省域.shp,矢量,是,省域,NAME,省级行政区面
河流线,河流线.shp,矢量,是,河流线,NAME=name,河流名称用于标注
```

“类别”必须来自目录，空白表示该行只能自己提供。“字段”是目标字段与标准字段映射；`NAME` 等同 `NAME=name`，`CODE=code` 指定目标名称，多个用分号隔开。字段为空时保留来源字段。`自动获取=否` 可禁用某行获取，`推荐来源` 可指定来源编号或名称。原数据不会被覆盖；获取与规范化的成果进入数据仓，逐行绑定给清单，业务步骤仍按原图层名加载。

## 输入名称、类型和记忆

每项格式是 `名称（属性）：说明`。名称在流程内必须唯一，也是稳定的输入键，不会被转换成另一个英文键。改输入名称会得到一个新的记忆位置；旧运行按照自己的计划快照恢复。

| 属性 | 用途 |
|---|---|
| 必填 / 可选 | 是否必须填写 |
| 文件 / 文件夹 / 图层 | 文件选择、目录选择、工程图层选择 |
| 对话原文 | 读取当前用户消息 |
| 文本 / 数字 | 普通文字或有效数字 |
| 是/否 | 布尔选项 |
| 可选值：A、B、C | 单选，顿号分隔；默认值应在选项中 |
| 默认 ×× | 没有记忆值和本次取值时使用的默认值 |
| 与「另一项」二选一 | 至少提供其中一项；同时提供时在步骤中说明优先级 |
| 不记住 | 文件、文件夹不保存上次选择 |

显式类型优先，其次是布尔和选项、说明中的文件/文件夹等关键词，最后才是文本。缺少明确类型会有提示，建议在属性中明确填写。不要在属性括号内再嵌套括号，复杂说明放在冒号后。

文件和文件夹默认记住上次成功启动运行时的值，也可以在流程中心“输入”页手动修改或清除。预填顺序是记住的值、声明默认值、空值。记忆只写入本机运行目录 `config/flow_input_memory.yaml`，保存绝对路径，复制和导出流程均不携带它；删除用户流程也删除其记忆。

选择文件或文件夹后，表单即时检查存在性、类型、必填和二选一约束；有关联数据清单时逐项检查必需文件及 Shapefile 附属文件。移动数据后旧记忆可能失效，重新选择即可。图层输入由当前工程图层列表检查。检查通过后若文件被外部改动，运行开始仍会重新检查。

## 一份文件与固定多文件的区别

只需要一个空间文件时，使用上例的文件输入。需要用户任意选择一批数据时，使用文件夹输入，由步骤说明检查、加载哪些数据。

如果流程要求一套固定文件，由流程作者准备一份包内数据清单，用户运行时只选文件夹：

```markdown
## 需要准备
- 底图数据（必填，文件夹）：存放本流程所需底图的文件夹

## 使用的资源
- 数据清单「底图」：resources/data/底图.csv（文件所在文件夹：「底图数据」）
```

关联名称必须指向已有的文件夹输入。打开详情时只检查清单格式，并提示文件位置由该输入决定；选择目录后才检查真实文件。相对文件路径以本次选择的文件夹为准，不固定到某个目录名。没有关联属性时，文件相对于清单所在目录，适合把小型数据直接随流程携带。

“CSV 数据清单”是文件说明，不是地图几何。换同一套数据的存放位置不需要修改 CSV；增删固定图层或改变文件名时，流程作者需要更新清单。当前没有图形化逐行清单编辑器；普通使用者可选一个直接接收文件/文件夹的流程，避免接触清单。

## 资源与依赖

```markdown
- 样式集「基础样式」：公共资源库/style_set.gb-basemap
- 版式「统计专题版式」：公共资源库/layout.statistical
- 路线样式「专用路线」：resources/styles/专用路线.csv
- 符号「站点」：resources/symbols/站点
- 参考「来源」：resources/docs/来源.md
```

公共库在界面叫“模板与样式”，只包含版式、样式、样式集。FLOW 仍使用 `公共资源库` 这个位置词。数据清单、数据文件夹、符号、路线样式、参考资料放在流程自己的 `resources/`；工具默认资产由工具按编号使用。

资源类型词使用系统支持的类型；`「名称」` 是本流程引用标签，冒号后才是位置。步骤中引用标签后，系统才把该资源交给这一步。样式集和符号集引用资源目录，不引用单张对照表。包内路径相对流程目录；绝对路径可以使用，但会影响分享并给出提示。

`flow.lock` 锁定公共依赖身份。没有锁定且同类型同名有多个候选时，需要明确选择；用户同名资源不会自动优先。只有 `overrides` 明确声明的覆盖才替代内置项。替换、重命名保留编号，复制生成新编号，内容替换递增版本。工具资产不能被用户资源覆盖。

知识抽取专用执行器的步骤应明确引用路线样式和符号集；符号集至少含 `start_flag`、`waypoint`。不要把这些依赖藏进提示词或工具源码。更多格式见 [模板与样式指南](资源制作指南.md)。

## 步骤、条件与产出

做法写目标、方法、数据和约束，使用能力手册里的中文能力描述。参数枚举、工具细节、固定颜色和字号不必在每个流程重复。资源承载可替换内容，工具包说明具体工具怎么用。

用 `「名称」` 引用输入、资源或前序产出。产出名称应唯一，不能引用还未执行的步骤产出。

| 完成标准 | 运行时校验 |
|---|---|
| `「可用图层」（图层）` | 工程里实际存在的图层 |
| `「成果图片」（文件，png）` | 实际文件存在、非空且格式合适 |
| `「版面」（版面）` | 工程里实际存在的版面 |
| `「说明」（文本）` | 非空交接内容 |
| `「路线数据集」（数据集，路线格式）` | 实际目录及规定六表 |

条件尽量写明确的输入存在性或布尔选择，例如“提供了「统计表」时执行”“未提供「路线数据集」时执行”“「质量审查」为是时执行”。可确定的条件直接解析，其他条件在实际运行时结合输入和前序结果判断；无法判断时会提示，不能把未知条件默认为真。对话原文会读取当前消息，因此已有数据集优先的流程，应明确“已提供数据集且没有重新抽取要求时跳过抽取”。

失败处理可写：停止流程、跳过本步、询问用户、重试一次后询问用户；缺省为最后一种。负责角色写“用户”表示人工确认。

## 保存、步骤预览与试运行

- **保存**：保存文件并直接切换到最新步骤预览，不启动后台模型分析。
- **步骤预览**：显示已保存流程的步骤、角色、说明、资源和产出要求。标题和步骤顺序按文档结构解析；修改编辑器内容后需要保存才更新预览。
- **试运行**：与“保存”放在同一行，进入对话页填写本次运行输入。未保存的内容或阻止运行的问题需要先处理；流程还需在当前方案中启用。

重新编译按钮、分析进度和后台自动完善已移除。打开、保存、新建、复制或导入流程不会触发模型分析请求，不需要等待模型返回后才能查看步骤。

独立的体检按钮、页签和草稿检查接口已移除。流程必要的格式、角色、资源及输入校验仍自动执行；阻止运行的问题会在页面或运行入口提示。

执行计划包含输入、步骤、角色、条件和资源。预览不执行制图工具，也不代表实际运行已经成功；实际角色执行所需的模型、工具和 QGIS 连接仍须配置。

常见处理：

| 提示 | 操作 |
|---|---|
| 角色或能力不满足 | 查看角色对应、方案补齐策略与角色必需工具包；严格策略下需调整方案 |
| 暂不能自动获取 | 根据条目的不可用原因启用所需服务，换来源，或自己提供文件 |
| 类别/字段/范围无效 | 对照类别目录修改需求或清单；范围引用必须存在 |
| 等待第 N 步确定范围 | 前序产出就绪后再获取，无须猜测范围 |
| 缺少读图模型 | 在模型设置标记实际支持图片的模型，并选择可用模型 |
| 文件位置来自输入 | 在输入表单选择文件夹 |
| 缺少必需文件或附属文件 | 检查提示的实际文件名并重新选择输入 |
| 资源不存在、同名歧义或锁定编号丢失 | 上传包内资源，或选择明确的模板与样式 |
| 版本/摘要变化 | 核对内容后更新锁定 |
| 旧资源类型退出公共库 | 从“旧资源”区移入用户流程，内置流程先复制 |
| 旧数据目录待转换 | 使用“转为文件夹输入”，之后从输入表单选择 |

旧目录配置只在兼容期内只读使用；启动时把已经关联输入的项目迁到本机输入记忆并备份。未关联的用户流程可使用转换操作，历史数据不会因为迁移失败被静默删除。

## 分享与运行记录

导出默认附带已锁定的版式/样式/样式集到 `resources/_deps/`；流程自带资源随包保存，工具资产随工具发布。导入时同编号同摘要复用本机库，否则保留随包副本；需要时明确安装为新用户资源或改用本机库，不静默覆盖。

清单中的外部数据不会因为清单随包就自动全部复制。接收方提供实际文件并在输入表单选择位置，本机记忆不随包传播。导入后查看步骤和资源，再填写运行输入，系统自动校验。单文件上限 200 MiB、单包上限 2 GiB。

开发接口：`GET /api/flows/{id}` 读取流程与预览，`PUT /api/flows/{id}` 保存后返回最新计划；运行输入通过 `POST /api/flows/{id}/inputs/check` 校验。客户端使用 `X-AutoCarto-Contract-Version: v1`。保存和预览不需要再请求编译或轮询编译状态。

每次运行在会话 `flows/<运行编号>/run.json` 保存输入、执行计划、步骤和真实产出。恢复时检查流程与资源变化；需要重新开始时不会把新内容悄悄混进原运行。快照保留引用和解析结果，并不备份外部文件字节。成果以工具实际返回路径为准，通常归档到会话 `exports/`。

完整包示例：[人口密度](refactor/acceptance-flows/province-density/FLOW.md)、[考察路线](refactor/acceptance-flows/survey-route/FLOW.md)。其中人口和考察安排是明确标注的合成验收输入；`resources/acceptance.json` 是离线固定动作夹具，普通流程不需要它。
