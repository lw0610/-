# 03 统一数据服务规范

## 1. 目标

1. **只有一条路**：无论在对话中还是在计划中，取得数据都经过同一个数据服务：先 `data_find` 查候选，再 `data_get` 获取；网页、浏览器、自定义 OSM 查询只作为兜底，取得的文件再经 `data_register` 进入同一套记录。
2. **选择有固定顺序、有理由**：候选的筛选与排序是确定性的（复用 v4 规划器），每个候选都附“为什么选它 / 为什么不可用”。智能体只能在候选中选，不能编造来源。
3. **只有一个执行者**：对话中的取数由系统内置的“数据获取智能体”负责；计划中的取数由计划执行器调用同一引擎。其他角色不直接取数。
4. **都有来源记录**：所有取得的数据进入数据仓或会话目录，带来源、时间、摘要、许可，并登记到会话文件区。

## 2. 统一后的取数方式

| 层级（排序） | 候选类型 | 来自 | 实现（复用） |
|---|---|---|---|
| 1 | 用户本次提供 | 消息附件、拖入的文件或文件夹、消息中的路径 | 计划 `data.from=user`；清单逐行解析（v4 `EntryOverrides`） |
| 2 | 本会话已有 | 会话文件区中类别相符的文件 | `internal/sessionfiles` |
| 3 | 工程已有图层 | 当前 QGIS 工程中类别或名称相符的图层 | `get_layers_info`（本机调用，不联网） |
| 4 | 数据记忆 | 上次在同一指南、同一数据上使用的路径 | 现有输入记忆存储改造（§7） |
| 5 | 数据仓 | 已获取、未过期的同参数结果 | v4 `internal/acquire/store.go` |
| 6 | 本机数据源 | 用户登记的文件夹 | v4 `local_folder` 适配器 |
| 7 | 内置离线 | 中国行政区边界等 | v4 `offline_asset` 适配器、`admin_boundary_extract` |
| 8 | 官方接口 | 天地图 | v4 `tianditu` 适配器 |
| 9 | 开放数据下载 | Natural Earth、OSM 中国区域提取包 | v4 `http_file` 适配器 |
| 10 | 在线查询 | OSM（多节点）、GEE 数据集模板 | v4 `overpass` 适配器（`internal/osmdata`）、`gee` 适配器 |
| 11 | 门户网站 | 国家统计局、1:100 万公众版等 | 数据获取智能体用浏览器操作 + `data_register` |
| 12 | 联网搜索 | 其他公开来源 | 数据获取智能体用 `web_search` / `web_read_page` / `web_download_file` + `data_register` |

层级 1–10 由引擎确定性执行；11、12 需要模型操作网页，只在 1–10 都没有可用候选、且设置允许时出现。合规规则（v4 `02` §5，疆域类数据不用境外开放数据）在所有层级生效。

## 3. `data_find`

### 3.1 输入

```json
{
  "need": {
    "name": "中国底图",
    "what": {"list": "中国底图"},
    "extent": "「路线数据集」外扩 20%",
    "scale": "auto",
    "fields": {},
    "params": {}
  },
  "guide": "marching-route",
  "include_fallback": false
}
```

| 字段 | 说明 |
|---|---|
| `what` | 三选一：`{"category": "铁路"}`（类别编号或别名）、`{"list": "<数据清单资源>"}`（需 `guide`）、`{"description": "河南省各县 2023 年人口"}`（按类别别名与参数规则识别；识别不了时返回“未识别”及相近类别） |
| `extent` | `全国`、行政区名称、文件路径、`@图层名`、`bbox:南,西,北,东`、`「数据名」外扩 N%`（引用计划中的数据，可为“待定”） |
| `params` | 类别参数，如 `{"level": "县", "year": "2023", "indicator": "常住人口"}` |
| `include_fallback` | 为真时，在没有可用候选时附上门户网站与联网搜索的建议（不执行） |

### 3.2 输出

```json
{
  "find_id": "df-7c21",
  "resolved": {"category": null, "list": "中国底图", "extent": {"bbox": [102.1, 24.3, 111.8, 36.0], "pending": false}, "scale_denominator": 3000000},
  "rows": [
    {
      "row": "铁路",
      "category": "transport.railway",
      "recommended": "c3",
      "candidates": [
        {"id": "c1", "kind": "user_memory", "name": "上次使用：/Users/me/底图/铁路.shp", "available": true, "reasons": ["同一指南上次使用"], "notes": []},
        {"id": "c3", "kind": "online_query", "source_id": "source.osm.overpass", "name": "OpenStreetMap 在线查询", "available": true,
         "reasons": ["覆盖所需范围", "适合 1:300 万"], "notes": ["ODbL，须署名", "预计约 30 MB（估计）"], "handbook": "全球道路铁路水系等；国内完整度因地区而异"}
      ],
      "excluded": [{"source_id": "source.naturalearth.10m", "reason": "该来源过于概略，不适合 1:300 万"}]
    }
  ],
  "fallback": []
}
```

- `rows`：单个类别时只有一行；清单时每行一项。
- `recommended`：按 §2 层级与 v4 排序规则（`datasource.PlanningEnvironment.Rank`）得到的第一个可用候选。
- 结果在会话内保留 30 分钟，供计划校验与 `data_get` 引用（`02` §4.2 `PLAN_SOURCE_NOT_FROM_FIND`）。
- 不联网、不调模型；“工程已有图层”需要已连接 QGIS，未连接时该层跳过并注明。

### 3.3 实现

新建 `internal/dataservice/`：类别解析复用 `datasource.Catalog.ResolveAcquisitionCategory`，范围解析复用 `internal/acquire/planner.go` 的范围函数（改为可导出、可不依赖 `FlowPlan` 调用），排序复用 `PlanningEnvironment.Rank`，再加入层级 1–4 的候选。

## 4. `data_get` 与 `data_register`

### 4.1 `data_get`

```json
{"find_id": "df-7c21", "choice": {"铁路": "c3", "*": "recommended"}, "target": {"folder_name": "中国底图"}}
```

- 层级 1–4：只绑定、不复制；按类别与字段要求核验（字段不符时提示，用户确认后继续）。
- 层级 5–10：调用 v4 获取引擎（`internal/acquire/executor.go` `Engine.RunItem`），含规范化、核验、入数据仓。
- 清单：按清单文件名输出到一个“获取目录”，与用户提供的文件按行合并（复用 v4 逐行解析），后续可以像用户提供的文件夹一样使用。
- 返回：每行的路径、来源、获取时间、摘要、许可与署名、注意事项、警告；登记到会话文件区；追加到本会话的「数据来源说明」。

### 4.2 `data_register`

用于兜底（层级 11、12）：数据获取智能体用浏览器或网页下载取得文件后，调用 `data_register` 把文件按需求核验、规范化并写入数据仓，来源写明“门户网站”或“联网搜索”、网址与时间。没有经过 `data_register` 的文件不能作为计划的数据使用。

## 5. 数据获取智能体（系统专家）

| 项目 | 内容 |
|---|---|
| 存在方式 | 系统内置，不出现在方案中，所有方案都可用（与 GeoCode 的 OSM 下载子智能体、LLM-Find 的思路一致） |
| 模型 | 方案主角色的模型；设置中可另选（README §9 第 4 项） |
| 工具 | `data_find`、`data_get`、`data_register`、`geodata_inspect`；兜底：`osm_*`（自定义标签查询）、`web_search`、`web_read_page`、`web_download_file`、`browser_*` |
| 谁调用 | 对话中由编排智能体委派（“获取以下数据：……”）；计划中由执行器在 `acquire` 步骤需要兜底时调用 |
| 固定做法（写入其提示词） | ① 对每项需要先 `data_find`；② 用户说明了偏好且候选中有就按用户的；③ 否则用推荐候选 `data_get`；④ 没有可用候选时说明原因，按设置决定是否兜底：OSM 可表达的类别先用自定义 OSM 查询，统计类先用门户网站（国家统计局方法见 `browser-data-acquisition/references/china-statistics-data.md`），其他才联网搜索；兜底前需要用户同意时先问；⑤ 兜底取得的文件必须 `data_register`；⑥ 逐项报告：用了哪个来源、为什么、注意事项；⑦ 不编造数据、不用模型生成数值或几何 |

## 6. 工具包重新分配

| 工具包 | 现在 | 之后 |
|---|---|---|
| 新建“数据服务”（`data-service`：`data_find`、`data_get`、`data_register`） | — | 编排智能体：只有 `data_find`；数据获取智能体：全部 |
| `osm-data`、`browser-data-acquisition` | 数据工程专家、脚本专家 | 只给数据获取智能体 |
| `admin-boundaries` | 数据工程、空间分析、脚本专家 | 只给数据获取智能体（行政区边界经 `data_get` 获取） |
| `gee-remote-sensing` | 数据工程、空间分析、脚本专家 | 影像、DEM 等**数据下载**经数据服务（`gee` 适配器模板）；分类、变化检测等**分析**仍给空间分析专家（README §9 第 6 项） |
| `geocoding` | 数据工程专家 | 不变（这是对用户数据的处理，不是取数） |
| `file-operations` 中的 `file_downloader` | 数据工程专家 | 标为隐藏兼容工具，不再分配；下载统一走数据服务 |
| `data-acquisition`（`archive_extract`、`data_normalize`、`data_derive`、`data_load_tiles`） | 系统获取执行器 | 不变 |

- **默认方案**按上表修改 `defaults/agent_configs/default/agent.yaml`。
- **用户已有方案**的文件不改；运行时设置“只允许数据获取智能体取数”（默认开启，README §9 第 5 项）：开启时，构建方案角色时过滤掉取数类工具（`osm_*`、`browser_*`、`web_*`、`admin_boundary_extract`、`gee_run_script` 中的下载模板、`file_downloader`），保证 Y5。
- 编排提示（`02` §11）规定：需要数据时，在计划中写 `acquire` 数据项，或在对话中委派数据获取智能体。

## 7. 数据记忆

- 复用现有输入记忆存储（`<AUTOCARTO_HOME>/config/flow_input_memory.yaml`，`internal/flow/input_memory.go`），键改为“指南编号 / 数据名”，另加“类别 / 范围标签”键供无指南时使用。
- 记住：用户提供的路径、用户明确选择的来源。不记住获取到的值（复用通过数据仓完成）。
- 在 `data_find` 中作为层级 4 候选，并在计划卡中显示“上次使用”。

## 8. 数据源手册

借鉴 LLM-Find 的“每个来源一份手册”，在 v4 数据源清单（`autocarto/tools/system/data-acquisition/assets/sources/*.yaml`）中增加 `handbook`：

```yaml
handbook:
  good_for: 区域范围的道路、铁路、水系、站点、地名点、建筑
  not_for: 中国国界、省界等疆域表达；全国范围的大体量下载（改用区域提取包）
  coverage: 全球；国内完整度因地区而异
  scale: 1:5 万至 1:400 万；更小比例尺需取舍
  fields: 名称取 name:zh，没有时取 name；道路等级取 highway；编号取 ref
  cautions: 须在版面署名“© OpenStreetMap contributors”；公共节点有限流
  examples: [河南省主要公路, 武汉市地铁线路与站点, 秦岭地区主要河流]
```

- `data_find` 在候选中附一句手册摘要；数据获取智能体的提示词附上全部来源的一行索引（名称、适合什么）。
- 用户登记的本机数据源也可以写手册（设置页编辑）。
- 新增来源 = 新增清单与手册，不改代码（适配器种类已存在时）。

## 9. 来源记录与「数据来源说明」

- 每次 `data_get` / `data_register` 写来源记录（复用 v4 记录格式与密钥脱敏），并登记到会话文件区（v4 `internal/sessionfiles`）。
- 会话级「数据来源说明」：本会话计划中实际使用的数据及其来源、许可、署名、获取时间、近似与取舍说明；版面步骤可引用。

## 10. 设置

| 设置 | 选项 | 默认 |
|---|---|---|
| 联网获取数据 | 计划中确认后获取 / 直接获取 / 不联网获取 | 计划中确认后获取（与 `02` §6 联动） |
| 门户网站与联网搜索兜底 | 关闭 / 需要时先问我 / 允许 | 需要时先问我 |
| 只允许数据获取智能体取数 | 开 / 关 | 开 |
| 数据获取智能体模型 | 主角色模型 / 指定模型 | 主角色模型 |
| 数据源、数据仓、扩展服务 | 沿用 v4 F33、F60 的设置页 | — |

v4 的方案级 `flow_policy.auto_acquire` 删除，由“联网获取数据”替代（`05`）。

## 11. 错误与诊断

| 代码 | 含义 |
|---|---|
| `DATA_NEED_UNRECOGNIZED` | 无法识别需要的数据类别 |
| `DATA_EXTENT_UNRESOLVED` | 范围无法解析（区域重名时附候选） |
| `DATA_NO_CANDIDATE` | 没有可用候选，附排除原因与兜底建议 |
| `DATA_FIND_EXPIRED` | `find_id` 过期，需重新查询 |
| `DATA_CHOICE_INVALID` | 选择不是该次查询的候选 |
| `DATA_REGISTER_MISMATCH` | 登记的文件与需求的类别、几何或字段不符 |
| `DATA_NETWORK_NOT_ALLOWED` | 设置不允许联网获取 |
