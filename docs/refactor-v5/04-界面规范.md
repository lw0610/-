# 04 界面规范

目标：用户用一句话开始；补充信息靠附件、`@图层`、`/指南` 和回答问题卡；需要决定的事集中在一张计划卡里。不再有流程表单、角色对应和流程策略。

## 1. 对话输入

涉及 `autocarto-web/src/components/chat/ChatInput.tsx`、`ChatPanel.tsx`；删除 `features/flow-run/FlowComposer.tsx`、`useFlowComposer.ts` 及其测试（`05`）。

| 功能 | 交互 | 发送内容 |
|---|---|---|
| 附件 | 输入框左侧“添加”按钮选择文件或文件夹（桌面端用现有 `pickFilePath` / `pickDirectoryPath`）；支持拖入 | 消息元数据 `attachments: [{path, kind: file|folder}]`，输入框内显示为标签；后端校验存在性 |
| `@图层` | 输入 `@` 弹出当前工程图层列表（复用 `/api/instances/{id}/layers`） | `layers: [{id, name}]` |
| `/指南` | 输入 `/` 或点击“指南”按钮，列出已启用指南（名称与说明） | `guide_id`；输入框内显示指南标签，可移除 |
| 模式 | Plan / Build 切换保持现状（`ContextToolbar`） | 现有字段 |

- 发送不受“流程输入是否齐全”限制；缺什么由编排智能体在对话里问。
- 附件路径在后端记录为本会话“用户提供”的数据（`03` §2 层级 1），并进入数据记忆（`03` §7）。

## 2. 问题卡

- 编排智能体用 `hitl_request` 提问。带选项时显示为按钮组；多个问题在同一张卡里，各自选择后统一提交；“其他”可以输入文字。
- 用户也可以忽略卡片直接在输入框回答，回答作为普通消息发送。
- 复用 `components/chat/InterruptCard.tsx`，补充“多问题”“选项按钮”的显示（若现有结构已支持则只调整样式）。

## 3. 计划卡

新建 `features/plan/PlanCard.tsx`，显示在对话中（编排智能体调用 `plan_propose` 后）。

```text
┌ 制图计划 · 行军路线图（指南 4.0.0） ────────────────────────── v1 ┐
│ 目标：根据史料制作 A1 横向行军路线图                               │
│ 已知：纸张 A1 横向（您的消息）· 标题 中央红军长征路线图（推断）[改]  │
│ 假设：不做质量审查（默认）[改]                                     │
│                                                                    │
│ 数据                                                               │
│  史料原文      本条消息                                            │
│  路线数据集    由第 1 步产生                                        │
│  中国底图      8 项 ▸  省域 内置行政区 · 铁路 OSM 在线查询 · …  [改]│
│                                                                    │
│ 步骤  1 抽取路线知识 · 2 获取底图 · 3 底图符号化 · 4 路线与专题点 ·  │
│       5 版面 · 6 图文标注 · 7 导出                     [展开详情]   │
│ 产出  成果 PDF                                                     │
│                                                                    │
│ 需要联网获取约 120 MB 数据（估计）              [开始]  [取消]     │
└────────────────────────────────────────────────────────────────────┘
```

| 元素 | 行为 |
|---|---|
| 已知与假设的 [改] | 在输入框预填“把标题改为……”供用户编辑后发送，由编排智能体 `plan_revise` |
| 数据行的 [改] | 菜单：换来源（列出该次 `data_find` 的候选及理由、排除原因）、我来提供（选文件或文件夹）、用工程图层（选图层）。这三种是确定性修改，由后端直接修订计划（版本加一、重新校验），不经过模型 |
| 步骤 [展开详情] | 显示每步需要的能力、处理的图层、产出 |
| [开始] | 只在需要确认时出现（`02` §6）；点击后卡片转为进度卡 |
| [取消] | 放弃该计划 |

后端接口：`POST /api/sessions/{id}/plans/{plan_id}/edits`（换来源、我来提供、用工程图层），`POST /api/sessions/{id}/plans/{plan_id}/start`、`/cancel`。

## 4. 进度卡与失败卡

- 计划开始后，计划卡原位转为进度卡：每步状态（等待、进行中、完成、失败、跳过）、当前步骤说明、获取步骤的逐行进度（复用 v4 `features/flow-run/FlowProgressCard.tsx`、`AcquisitionProgress.tsx` 的显示逻辑，改为读取计划运行事件）。
- 失败时显示失败卡：失败原因；“正在调整计划”状态（编排智能体在修订）；需要用户决定时的选项（让智能体调整、我来提供数据、跳过——仅可选步骤、停止）。
- 完成时显示交付摘要：成果、数据来源说明、检查结果、遗留问题；成果链接到会话工作区“文件”页签（v4 F72）。

## 5. 会话工作区

沿用 v4 F72 的“文件 / 任务 / 过程”工作区（`components/workspace/**`）。“任务”页签顶部显示当前计划（目标、进度、数据来源），其下仍是待办与待确认项。

## 6. 指南库

原“流程中心”（`app/flows/`、`features/flows/FlowWorkspace.tsx`）改为“指南库”。

| 区域 | 内容 |
|---|---|
| 列表 | 名称、说明、版本、内置/用户、启用状态、诊断数；搜索 |
| 详情 | 按章节渲染：适用任务、需要明确的信息、数据表（附“当前可用来源”预览，来自 `data_find`，不联网）、图层处理表、制作要点、版面要求、产出与检查、资源 |
| 编辑 | Markdown 编辑与保存，保存后显示解析诊断；内置指南只读，可复制为用户指南 |
| 操作 | 导入（文件夹、ZIP、单个 `GUIDE.md`；只含 `FLOW.md` 时自动转换并显示报告）、导出、复制、停用、在对话中使用（跳到对话页并带上 `/指南` 标签） |
| 模板与样式 | v3 的“模板与样式库”保留，作为指南库中的一个页签 |

删除：角色对应页签、数据需求页签（内容并入详情的数据表）、试运行表单、输入记忆页签（并入设置中的数据记忆管理）。

## 7. 设置

| 保留 | 新增 | 删除 |
|---|---|---|
| 模型（含“支持读图”）、扩展服务（浏览器、网页、GEE、OSM、天地图）、数据获取（数据源、数据仓、本机数据源） | 计划确认（`02` §6）；联网获取数据、兜底、只允许数据获取智能体取数、数据获取智能体模型（`03` §10）；数据记忆管理（查看、清除） | 方案中的“启用的流程”（`components/settings/AgentFlowSelection.tsx`）；流程策略（`FlowPolicySettings.tsx`）；角色对应（`features/flows/RoleMappingPanel.tsx`） |

## 8. 文案要点

| 位置 | 文案 |
|---|---|
| 输入框占位 | 描述你要做的地图，可以添加文件、用 @ 引用图层、用 / 选择指南 |
| 计划卡标题 | 制图计划 · {指南名} |
| 需要确认 | 需要联网获取约 {体量} 数据（估计） / 本计划采用了需要你确认的假设 |
| 调整中 | 第 {n} 步未完成，正在调整计划 |
| 失败选项 | 让智能体调整 / 我来提供数据 / 跳过 / 停止 |

测试断言结构、状态与请求内容，不断言文案措辞。
