# 06 任务卡

每张卡可以单独交给一个执行智能体。交付时附上本卡、`README.md`，以及卡中“必读”列出的文档。

通用要求（每张卡都适用）：
- 遵守 `README.md` §7 及 v2、v3、v4 `README.md` §6 中仍适用的约束；开工前对照 §3 文件归属表，确认要改的文件没有被进行中的任务占用。
- 涉及删除或复用的，先读 `05-迁移与清理清单.md` 对应行；删除前确认没有引用。
- 完成后写 `docs/refactor-v5/evidence/<任务号>.md`（格式见 `docs/refactor-v3/evidence/README.md`），在 `refactor/v5` 分支提交（提交信息以任务号开头，不推送）。
- 命令约定：Go 命令在 `carto_agent/` 下执行；前端命令在 `autocarto-web/` 下执行；Python 命令在仓库根执行，`$PYTHON_BIN` 指能导入 QGIS 的解释器，`test_*_qgis.py` 每个模块单独进程运行。
- 测试使用临时运行目录，不读写真实 `autocarto_data/`，不访问真实网络（复用 v4 的假服务器与样例数据，`internal/testutil/`）；联网测试只在 `AUTOCARTO_LIVE_ACQUIRE=1` 时运行，跳过不算通过。
- “三种方案”指：默认方案、v4 的 Zttzt 结构夹具、只含主角色的最小方案（均在 `internal/testutil/`）。
- 模型行为用脚本化的测试模型模拟（复用现有测试替身），断言工具调用顺序与参数，不断言措辞。

## K00 基线

- **目标**：在可回滚的基础上开始 v5。
- **必读**：`README.md`
- **步骤**：
  1. 请用户确认把 v4 的实施结果提交到 `refactor/v4`（或得到用户明确授权后由本卡提交）；未确认时停止并报告。

  3. 记录现状：README §2.1 取数方式清单逐项核对（有出入写入记录）；对话页从选流程到发送的操作次数；四份内置流程在三种方案下能否启动。

- **验收**：分支存在；基线记录完整。
- **测试**：`./build.sh check`
