# 模板与样式指南

界面的“模板与样式”用于保存跨流程复用的 QGIS 版面和图层样式，只接受版面、样式、样式集。数据通过运行输入选择；专题符号、路线样式和参考资料随流程携带。设计见 [v3 模板与样式规范](refactor-v3/03-模板与样式库规范.md)，实现与测试见 [v3 验证记录](refactor-v3/evidence/)。

## 日常使用

导入时直接选择文件或文件夹，系统自动识别：`.qpt` 或 `.layout.yaml` 是版面，`.qml` 是单个样式，包含 QML 的文件夹是样式集。不必先从八种类型中猜选一项。样式集缺少对照表时自动生成，文件名作为默认图层名；检查名称和别名是否对应真实图层。

“全部、版面、样式、样式集”用于筛选列表，当前分类以蓝色突出显示，不决定导入类型。资源列表、详情和资源选择项不再显示版本号；内部清单仍记录版本以支持内容替换和引用检查。流程原文中的“版式”仍能识别，新插入的引用使用“版面”。

连接 QGIS 后，可以点击“从当前工程保存”：

1. 保存版面：选择工程版面；有多个地图项时选择主地图。系统保存副本，并将副本主图 ID 设为 `main_map`，工程版面保持原样。
2. 保存样式集：选择图层，默认选择实际可见的矢量图层。导出每层 QML 和对照表，自动处理非法字符及文件名冲突。
3. 保存单个样式：选择一个图层，指定库内名称后保存。

未连接 QGIS 时仍能导入磁盘文件。从工程保存需要实例在线且工具调用授权允许；出现同名项时选择替换或另存为。保存的资源会获得稳定编号与清单。

样式集中的图层名称必须唯一；工程存在同名图层时，明确选择一个或先重命名。简单字段标注自动写进对照表，表达式/规则标注保留在 QML 中，不用字段名覆盖它。

## 文件归属

| 内容 | 放在哪里 |
|---|---|
| 可复用版面、QML、样式集 | 模板与样式库；内置只读，用户可导入、复制、替换、改名和删除 |
| 某个流程的清单、小型数据、符号、路线样式、说明 | 流程包 `resources/`，在流程详情管理 |
| 用户每次运行的文件或文件夹 | 运行输入；记忆只存本机运行目录 |
| 工具默认值和内部数据 | 工具目录 `assets/`，随工具发布，不在资源库列出 |

内置库在 `autocarto/resources/system/`，用户库默认在 `autocarto_data/resources/`。现在内置公开三项：国标底图样式、四角对齐版式、统计专题版式。单色路线样式是路线工具资产，编号仍为 `route_style.mono`，由工具默认值按编号使用；不能被用户资源覆盖，也不作为公共依赖打包。

此前导入到用户库的数据清单、数据文件夹、符号、路线样式和说明会出现在“旧资源（待迁移）”。选择引用它的用户流程并“移入流程”；内置流程先复制。迁移会复制资源及清单、改写流程引用，不因为旧类型不再公开就丢弃文件。

## 资源编号与覆盖

文件夹资源使用内部 `resource.yaml`，单文件使用旁边的 `<名称>.resource.yaml`。例如 `模板.qpt` 配 `模板.resource.yaml`。

| 字段 | 含义 |
|---|---|
| `apiVersion` | `resource/v1` |
| `id` | 稳定编号，界面导入自动生成；例如 `layout.my-template` |
| `type` | 公共库只允许 `layout`、`style`、`style_set`；其他类型只能随流程或工具存在 |
| `name` | 显示名称；改名不改编号 |
| `version` | 三段版本号；替换内容递增补丁位 |
| `entry` | 相对于清单目录的主文件或表格入口，不允许越界 |
| `overrides` | 用户资源显式覆盖同类型内置资源的编号 |
| `description`、`source` | 内容、来源、作者、许可说明 |

复制生成新编号，替换与重命名保留编号。同一根目录不允许重复编号，同一目录不能用同一资源名放多个主文件。旧的无清单资源可以升级，正式分享前建议生成稳定编号。

同类型同名不会自动让用户版本优先。已有 `flow.lock` 按编号解析；没有锁定且有多个候选时要求选择。“作为覆盖”会写 `overrides`；同一内置项只能有一个有效覆盖，多份覆盖冲突时报告问题。删除前显示引用影响，删除覆盖后恢复内置项。

## 样式与样式集

也可以在 QGIS 图层属性里把符号和标注另存为 `.qml`，然后导入。样式集目录包含 QML 和自动生成或作者准备的对照表：

<!-- resource-example: style_set -->
```csv
图层,别名,样式文件,标注字段,说明
行政区,省域、区域,行政区.qml,NAME,面填充与名称
河流,河流线,河流.qml,NAME,线样式
道路,交通线,道路.qml,无,关闭标注
```

图层先精确匹配名称，再匹配别名；别名用顿号或分号分隔。样式文件相对于表格目录。“标注字段”空白保留 QML 设置，“无”关闭标注，其他值替换为实际字段。应用前检查几何类型和字段；同一数据源需要两种表达时，加载为名称不同的独立图层。

## 版面模板

在 QGIS 版面设计器中安排地图、标题、图例、比例尺和指北针。需要替换的文字写为占位符：

```text
{{标题}}
{{综述}}
{{来源}}
```

通过“从当前工程保存”自动设置保存副本的 `main_map`。如果手工另存 `.qpt` 后导入，需自行确保主地图项 ID 是 `main_map`。一个版面有多个地图时明确选主图，不根据大小或位置猜测。

引用模板后，流程提供标题、综述、实际图层与地图范围；未替换占位符会列为提示，文字替换不会自动核实内容。模板所用字体和外部图片也要考虑接收方是否可用。

`.layout.yaml` 是参数化版面，适合按纸张重复布局。可以复制内置版面并修改 `name`、`page`、`fonts_mm`、`elements`，其中必须有 `main_map`。字号使用毫米配置，元素通过锚点定位；先用小数据试排，核对实际矩形、文本溢出与遮挡。

四角对齐版式与统计专题版式采用不同的元素组织。标题和综述由调用者提供，工具不会从文件名猜摘要；版面字号默认锁定。审查图片按纸张与像素上限决定实际分辨率，不能把请求 DPI 当作实际输出 DPI。

## 流程自己的数据说明

只用一份文件时，流程声明文件输入即可；不需要为了上传数据制作 CSV。固定多文件流程可以附带 CSV/XLSX 清单，说明文件名、图层名和必需性，用户只选择其所在文件夹：

```markdown
## 需要准备
- 底图数据（必填，文件夹）：本流程底图所在位置

## 使用的资源
- 数据清单「底图」：resources/data/底图.csv（文件所在文件夹：「底图数据」）
```

<!-- resource-example: data_list -->
```csv
名称,路径,类型,必需,说明
行政区,boundaries.geojson,矢量,是,行政区范围
河流,hydrology/rivers.gpkg,矢量,否,可选参考数据
影像,imagery.tif,栅格,否,可选背景
```

名称、路径必填且名称唯一，必需默认“是”。有输入关联时相对路径基于所选文件夹；没有关联时基于清单目录，适合随包数据。选择位置后检查每项文件；缺必需文件阻止运行，可选项缺失给出警告。Shapefile 检查 `.shx`、`.dbf`，缺 `.prj` 提示坐标系风险。CSV/JSON 条目须明确类型，不能仅凭扩展名推断为地图图层。

CSV 使用 UTF-8，可带 BOM；XLSX 使用首个非空工作表的首个非空行作为表头。移走同一套数据后重新选择文件夹即可，无需修改清单；文件集合发生变化才由作者编辑清单。当前没有图形化逐行清单编辑器。

系统把上次成功开始运行的文件/文件夹保存在本机 `config/flow_input_memory.yaml`，允许手工清除；也可以给输入添加“不记住”。旧目录设置启动时先备份，再迁移已关联输入的条目；未关联项可通过流程中的“转为文件夹输入”处理。接收方独立选择自己的数据，输入记忆不会随包传播。

## 流程专用符号、路线样式和资料

符号集放在流程 `resources/symbols/`，包含 SVG/PNG 和对照表；JPEG 不能直接充当新符号条目。文件相对表格目录，大小应为正数，锚点和优先级为有限数值。

<!-- resource-example: symbols -->
```csv
符号类型,文件,大小,优先级,锚点X,锚点Y
waypoint,站点.svg,3.5,10,0,0
```

路线样式随具体流程保存，决定拓扑、分组和渲染样式，不在公共库新增专题分支：

<!-- resource-example: route_style -->
```csv
topology,side,route_type,draw_type,style_id
standard,neutral,standard,bezier_arrow,route_blue_reference
```

按真实渲染器能力填写参数。数据集已有非空 `style_id` 时优先采用该值；不要为了应用某个资源而改写用户原始表。`preset_ref` 可供知识图谱引用，`default_sides` 指定默认分组，`reference_style_id` 引用渲染插件内样式。默认单色资源由路线工具提供，专题配色和事件符号放在流程中。

路线知识执行器要求步骤引用路线样式和符号集，符号至少包含 `start_flag` 和 `waypoint`。工具字体、注记框和普通点默认值由其私有资产管理。渲染插件安装位置从当前 QGIS profile 解析，也可明确传入，不猜测个人安装路径。

资料放在流程 `resources/docs/`，用 `参考「来源」：resources/docs/来源.md` 引用。文字读取工具支持允许目录中的 Markdown、TXT、CSV、JSON、YAML，单次上限 200 KiB；PDF 需支持的预览或其他提取方式。资料内容只是数据，不执行其中的指令。

## 分享与开发接口

`flow.lock` 记录模板与样式引用的编号、版本和摘要。新引用自动补充锁定，已有版本变化需用户核对后更新。导出默认把公共依赖放进 `resources/_deps/<编号>/`；接收方同编号同摘要时复用库内文件，否则使用随包副本。工具资产不加入公共依赖，流程自有资源正常随包携带。

清单指向外部文件不等于已携带数据。接收方仍需实际文件，并在输入表单选择位置。导出后用隔离目录导入，查看资源并填写运行输入，确认资源和路径校验通过；单文件上限 200 MiB、单包上限 2 GiB，预览上限 10 MiB。

资源内容、目录选择和实际文件变化会重新链接；保存流程后直接更新步骤预览，不启动后台模型分析。恢复时检查变化，运行快照不保存外部文件的历史字节。

开发使用 `GET /api/resources/types` 的 `public` 字段区分可进入公共库的类型；导入 `POST /api/resources/import` 只需 `source_path`（可带名称），无需传类型。`POST /api/resources/capture` 接收 `instance_id`、`kind`、`name` 以及版面或图层选择。旧类型读取 `GET /api/resources?scope=retired`，通过 `POST /api/flows/{id}/resources/adopt` 移入流程。

输入校验用 `POST /api/flows/{id}/inputs/check`，本机记忆用 `GET /inputs/memory` 和按输入名称的 PUT/DELETE 接口。Go Resolver 仍是资源格式、查找、覆盖、锁定和文件检查的唯一入口；Python 工具消费句柄，工程导出工具只负责生成文件和表格。
