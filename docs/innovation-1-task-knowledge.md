# 制图语义规约与任务知识组织

更新：2026-09-25。

## 目的与入口

保留现有六张 CSV 作为 QGIS 渲染接口，以任务知识图谱统一保存主体、地点、事件、路径和原文依据，避免让模型重复维护坐标、样式与表格外键。

当前链路：

```text
原文 → 分段抽取 → 合并草稿 → 统一语义核对
     → 人工核对与补充 → 程序生成绘图字段 → Python 校验与编译 → 六表 → QGIS
```

编排智能体使用 `{"source_ref":"current_user_message"}` 委派一次 `knowledge_engineer`。运行时读取保存的原文，引用缺失时停止；也支持显式 `source_text` 和纯文本输入。知识模型及契约、编译工具是必要依赖，缺失时明确报错。

## 规则与协议的唯一职责

- `config/agent_configs/default/agent.yaml` 的 `knowledge_engineer.prompts.static_instructions`：可编辑的业务规则。Go 内置默认副本随发布同步。修改规则会改变缓存和已确认结果的兼容键。
- `carto_agent/internal/knowledge/prompts.go`：抽取、统一核对两种响应协议，不再放置另一套行军业务规则。
- `knowledge/extraction.py`：格式契约。保留显式传入规则的离线单次调用辅助入口，不替代 Go 生产流程。

示意路线中的“从 A 向 B 前进，中途受阻，折返 A”保留 **A→B→A**；B 表示行动指向，不因此生成抵达或占领 B 的事件。独立部队、计划行动、静态部署和地点并列不能自行串成已发生的移动。

## 抽取与核对

1. 按句子边界及模型预算分段。每个片段提供程序编号的原文证据，模型返回 `graph` 和 `unresolved`。
2. 事实与路径直接引用短句子编号 `source_evidence.ref`。模型输入不含字符偏移；程序校验编号，并以原文生成最终 `evidence` 和位置。
3. 每条路径通过 `actor_refs` 绑定移动主体，支持主力、支队分别行动。同名只作为核对候选，不自动合并。
4. 合并局部草稿后统一核对主体、地点用途、事件、路线、注记及疑问。核对可拆分路线、更正路径或归并实体，变动须有原文依据；实体归并保留双方证据。
5. 短文通常一次抽取、一次核对。长文先覆盖全部片段，再利用主体、地点、名称和别名索引组织相关上下文，支持非相邻片段。核对模型调用最多为最终片段数的两倍；超预算或失败保留诊断记录。
6. `unresolved` 保存在过程记录中，不再要求用户逐项写处理说明。制图前仍检查引用、图谱结构、路线适配和实际绘图地点的坐标。引用合法只证明依据可追溯，不等于语义判断必然正确。

模型把 `schema_version`、`task` 放到 `graph` 外时，程序仅在无冲突的情况下归位；格式或引用错误最多补充反馈重试一次。失败记录保留具体字段和原始响应。branch/incoming 若误把唯一 main 路径 ID 写作连接点，而首/末节点恰是主路上唯一共同地点，程序在制图副本中改为该地点 ID 并去掉重复的端点；其他节点不变。无法安全修正的路径结构显示具体错误。

局部抽取可因截断而有界细分。请求采用 UTF-8/JSON 字节保守估算预算，不把字节数宣称为精确 token 数；超长句和超预算关联仍可能需要人工处理。

## 制图准备与坐标

结果界面可直接开始制图，也可先编辑路径主体、地点、事件、路线和注记。用户修改后重新检查当前图谱；模型疑问保留在内部记录，不再以隐藏的人工处理步骤阻断制图。

未定位地点可保存在草稿中；真正用于路线、事件、点符号或注记的地点，编译前必须有坐标。不会补零坐标或为通过编译删除实际节点。允许估计坐标，但须标明 `llm_estimated` 与置信度；低置信度进入警告。经纬度使用 EPSG:4326。

历史人工决议仍随记录保存，后续相关修改会使旧决议失效。开始制图后使用现有签名和 Python 校验，恢复编译无需再次请求模型。历史记录继续可读；旧抽取协议不能冒充当前协议的新结果。

## 编译与过程记录

`knowledge/schemas/task_knowledge_graph_v1.schema.json` 维护最终图谱契约。程序从图谱生成绘图字段与六表，点、注记和路线共用地点坐标。重复经过同地保留顺序，自相交允许；六表适配器无法表达的拓扑明确报错。

会话抽取过程写入 `intermediate/route_knowledge_extraction/<runid>/` 的 `source.txt`、`state.json`。状态包含原文摘要、片段、模型响应、`semantic_reviews`、疑问和阶段标记；旧边界/路线记录仅用于读取历史。过程记录用于追溯，不表示支持从任意内部步骤自动续跑。

编译生成六张 CSV、`symbols/`、`source.txt`、`task_graph.json`、校验报告和编译清单；人工核对结果另存来源记录。先在临时目录生成并校验，再原子发布，失败不会覆盖成功成果。

## 维护位置与验证

- `carto_agent/internal/deepagent/knowledge_agent.go`：规则、模型、工具与会话入口。
- `carto_agent/internal/knowledge/pipeline.go`：阶段调度。
- `carto_agent/internal/knowledge/fragment.go`、`semantic_review.go`、`route_semantics.go`：抽取协议、核对分组与变更应用。
- `carto_agent/internal/knowledge/review_*.go`：人工草稿、决议、签名及恢复。
- `knowledge/validator.py`、`compiler.py`：引用和坐标校验、六表编译。
- `autocarto-web/src/features/knowledge-review/`：人工核对界面。

本次验证覆盖 A→B→A、跨段核对、失败阻断、有依据拆分、归并证据、规则缓存失效、人工恢复、真实 Python 六表编译及前端审核操作。按项目要求，验证完成后删除知识抽取相关测试文件。模拟模型测试不代表已测量真实史料抽取准确率，也未执行 QGIS 现场绘图。

修改后须按项目既有构建流程更新 Go 后端、前端和 QGIS 侧 Python 工具；仅刷新网页不会加载后端源码修改。
