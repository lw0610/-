# 03 获取执行与数据仓规范

本文件回答“怎样拿到数据、怎样把它变成流程能直接用的样子、怎样复用”。需求与来源选择见 `02`。

## 1. 总体

- **系统获取执行器** `data_acquisition`：系统自带的专用执行器，注册在 `internal/flowrun` 的执行器表中（与 `route_knowledge` 同一机制），**不需要方案中有对应角色**，不受 `01` 角色解析影响。
- **确定性优先**：除门户网站和联网搜索两类来源外，取数、转换、规范化、核验全部通过确定性的工具调用完成，不经过模型。
- **后台执行、按需等待**：获取任务在依赖就绪时立即在后台开始；需要该数据的步骤开始前等待它完成。例如行军路线图第 1 步（知识抽取，耗时较长）与底图获取可以同时进行。

## 2. 计划中的隐式获取步骤

- 每个数据需求，在本次运行中只要有条目的来源方式为 `auto` 或 `fill`，就在计划中插入一个系统步骤：
  - 编号 `acquire-<需求序号>`，标题“获取数据：<需求名>”，`Kind: "acquire"`，`Executor: "data_acquisition"`；
  - 位置：第一个引用其绑定输入或清单资源的步骤之前；“获取方式”指向自定义步骤时，插在该步骤之后（用于规范化与核验）；
  - 可达性：所有条目都是 `user`/`none` 时为 `never`（`01` §6.1）。
- 流程文件不出现这些步骤；预览中显示为“系统步骤（仅在自动获取或补齐时执行）”，并列出条目与计划来源。
- `run.json` 的 `steps` 中包含隐式步骤，旧前端按普通步骤显示即可。

## 3. 后台任务

| 项目 | 规则 |
|---|---|
| 开始时机 | 范围来自输入的条目：运行开始后立即开始；范围来自步骤产出的条目：该步骤完成后开始 |
| 上下文 | 进程生命周期上下文（`cmd/agent/main_deep.go` 的 `lifecycleCtx`），不使用请求上下文；运行取消时一并取消 |
| 并发 | 全局同时运行的条目数默认 2；同一主机同时请求数默认 1；可配置（§13） |
| 等待 | 隐式步骤开始时若任务未完成，步骤状态为“运行中”并持续推送进度；完成后再进入下一步 |
| 重启 | 进程重启后，未完成的条目重新开始；已入数据仓的条目按缓存键直接复用；半截下载丢弃 |

## 4. 条目管线

```text
① 查数据仓 ──命中──────────────────────────────────────────────► ⑧ 绑定
   │ 未命中
② 取数（适配器，§5）→ 原件写入数据仓临时目录（记录查询、地址、时间、字节数、sha256）
③ 解包与读取（安全解压；OSM XML/PBF 通过 GDAL 读取）
④ 规范化（§6：筛选、裁剪、字段映射、按比例尺取舍与简化、命名与格式）
⑤ 派生（需要时，§6.3）
⑥ 核验（§7）──失败──► 换下一个候选来源或等待用户选择（§11）
⑦ 入数据仓：原件 + 成品 + manifest，更新索引
⑧ 绑定到运行（§9），推送完成事件
```

每一阶段的结果写入 `run.json`（§10）。

## 5. 适配器

### 5.1 接口

```go
// internal/acquire（新建）
type Adapter interface {
	Kind() string
	Fetch(ctx context.Context, request FetchRequest) (FetchResult, error)
}

type FetchRequest struct {
	Source   *datasource.Source
	Provide  *datasource.Provide
	Item     flow.AcquisitionItem
	Extent   Extent // WGS84 外包范围与可选面
	WorkDir  string // 数据仓临时目录
	Progress func(Progress)
}

type FetchResult struct {
	Files       []string
	Format      string   // geojson、osm_xml、osm_pbf、shapefile、gpkg、zip、geotiff、csv…
	Query       string   // 查询语句或参数（不含密钥）
	URLs        []string // 已脱敏
	RetrievedAt time.Time
	Bytes       int64
	SHA256      map[string]string
	Notes       []string
}
```

网络访问由 Go 适配器完成（主机白名单、体量上限、脱敏都在这一层；OpenStreetMap 访问统一经过 `internal/osmdata`）；需要 QGIS/GDAL 的处理（离线提取、解包后读取、规范化、派生、GEE）通过“获取工具调用器”调用工具。获取工具调用器是新增的确定性调用通道，允许清单为：`admin_boundary_extract`、`archive_extract`、`data_normalize`、`data_derive`、`data_load_vector`、`data_load_raster`、`gee_run_script`（只运行系统模板）。现有 `InvokeFlowTool` 只允许两个只读工具（`internal/agentruntime/flow_builder.go:83`），不扩大它，另建 `InvokeAcquisitionTool`。

### 5.2 `local_folder`（本机数据源）

只读引用用户目录中的文件。字段与范围已满足时直接引用，不复制；需要裁剪或字段映射时生成派生副本。

### 5.3 `offline_asset`（内置离线数据）

调用随工具发布的离线数据工具。行政区边界使用 `admin_boundary_extract`，需要 F23 增加：

- 参数 `within`：上级行政区精确名称或六位代码，`全国` 表示全部；与 `name`/`code` 互斥；
- 按 `adcode` 前缀确定上下级（离线数据含 `name`、`adcode`、`gb`、`level` 字段），直辖市、省直辖县级行政区有专门测试；
- 输出一个 GeoJSON 与来源记录，沿用现有复用与不覆盖规则。

### 5.4 `http_file`（公开文件下载）

- Go 端流式下载，主机必须在来源 `hosts` 中；体量上限使用获取配置 `acquisition.max_download_mb`（默认 2048），与智能体使用的 `web_download_file`（默认 100 MB）分开——目录来源是系统审定的地址；
- 边下边算 sha256；服务端支持时可断点续传；
- 压缩包交给 `archive_extract`。

### 5.5 `overpass`（OpenStreetMap 在线查询）

- 直接调用 `internal/osmdata`（`07`）：多节点测速排序、固定健康节点与切换、三轮退避、1.1 秒节流、流式 200 MB 上限、`POST` 查询、`out geom` 逐要素组装、字段约定、去重、按几何拆分——与智能体使用的 `osm_get_features` 是同一套实现，不经过模型；
- 范围：获取范围（`02` §3.4）转为 `file:` 边界或 `bbox:`；边界面过于复杂时按“只多不漏”近似并标 `clipped=false`，由 `data_normalize` 精确裁剪；
- 体量：先用计数查询估计要素数，超过 `limits.max_features`（默认 3 万）时按内置行政区的下级单元拆分范围，一次最多 `limits.max_extents` 个，合并去重；
- 部分结果（失败范围、组装失败要素）记入条目说明；必需条目出现部分结果时按核验失败处理（`03` §7），可选条目只记说明；
- 全国范围或拆分后仍超限时，规划阶段就应选择 `source.osm.geofabrik-china`（区域提取包），不在运行时硬查；
- 每次请求的节点、查询语句与获取时间写入来源记录（不含任何密钥）。

### 5.6 `tianditu`（天地图）

- 复用 `internal/geocoding` 的天地图客户端和服务端 Key（`internal/config/tianditu.go`）；
- 县级驻地：先从内置行政区得到范围内的县级名单，再逐个查询“<县名>人民政府”等地名，按行政区代码和距离校验候选；查不到的条目回退为县域代表点并标“近似”；按服务配额限速（需核实配额）；
- 行政区划接口是否返回边界坐标需核实；不返回时不提供该类别；
- 在线底图（`basemap.tiles`）不下载数据，而是生成瓦片图层定义交给图层加载工具。Key 会出现在 QGIS 工程的图层地址中——加载前必须提示，并优先使用 QGIS 认证配置保存 Key；不能使用认证配置时，由用户确认后再加载。

### 5.7 `gee`（Google Earth Engine）

- 只运行系统模板（`autocarto/tools/system/data-acquisition/assets/gee/*.py`），参数来自条目（数据集、波段、时段、云量阈值、分辨率），不接受模型写的脚本；
- 栅格：沿用 `download_image`（已有分块下载与复用，`internal/geeruntime/worker.py:532`）；
- 少量矢量：新增 `download_features` 辅助，按体量上限导出 GeoJSON。

### 5.8 `portal` 与 `web_search`（模型参与的兜底）

- 由系统内置的“数据采集”角色执行（与 `01` 的系统默认执行器同一机制合成，工具包：网页与浏览器取数、文件操作；模型为方案主角色模型），**不依赖方案角色**；
- 任务消息是结构化的：类别、字段要求、范围、时间、门户地址（`portal`）或“只用公开来源，优先官方”（`web_search`），以及“只返回工具实际下载的文件路径和来源网址”；
- 需要登录、验证码或许可确认时，用现有 `hitl_request` 让用户在浏览器中完成；
- 结果文件进入同一条管线，从第 ③ 步开始做确定性的规范化与核验；核验不通过视为失败；
- `web_search` 默认关闭（README §8 第 13 项）；开启后每次使用前确认，并在来源记录中标“联网搜索获得”。

## 6. 规范化与派生（新工具，Python，`data-acquisition` 工具域）

### 6.1 `data_normalize`

| 参数 | 含义 |
|---|---|
| `input` | 原件路径；多图层数据（GPKG、OSM）附图层名 |
| `category` | 类别编号（用于几何检查） |
| `filter` | 筛选表达式：来源 `provides[].filter` 与类别 `generalize` 规则合并后的结果，由 Go 生成 |
| `clip` | 裁剪范围文件（GeoJSON 面）或外包范围 |
| `fields` | 输出字段 → 来源字段候选列表（按顺序取第一个存在且非空的值），例如 `NAME ← [name:zh, name]` |
| `simplify_tolerance_m` | 简化容差（米）；在地理坐标系数据上按范围中心纬度换算；为 0 时不简化 |
| `output` | 输出路径（数据仓成品目录 + 清单中的文件名），格式由扩展名决定 |

行为：不改坐标系（显示仍用 QGIS 动态投影）；输出 UTF-8（Shapefile 写 `.cpg`）；只保留字段要求中的字段（加上 `kind`、`ref` 等类别标准字段中来源有的）；返回要素数、几何类型、外包范围、各输出字段填充率、坐标系、警告和输出摘要。

需实测并写入 F22 验证记录：Shapefile 输出是否保留字段名大小写（样式集同时用到 `NAME` 与 `name`）；不保留时，清单该行改为 `.gpkg` 并同步样式匹配测试。

### 6.2 栅格

裁剪到范围（保留坐标系）、输出 GeoTIFF，返回范围、分辨率、波段数和无数据比例。

### 6.3 `data_derive`

| 方法 | 用途 | 质量说明 |
|---|---|---|
| `polygon_to_boundary_lines` | 行政区划面 → 行政界线：相邻面共享的边记 `kind=省界`（或对应层级），不共享的外边界记 `kind=外围界线` | 不能区分国界与海岸线；有海岸线数据时可进一步区分 |
| `point_on_surface` | 行政区划面 → 驻地代表点，继承名称 | 代表点不是驻地实际位置，来源记录标“近似” |
| `hillshade` | DEM → 晕渲 | — |

### 6.4 `archive_extract`

安全解压 zip / tar.gz：拒绝绝对路径、`..`、符号链接；限制文件数与解压后总大小；只解到数据仓临时目录。

## 7. 核验

| 类型 | 检查 | 失败 / 警告 |
|---|---|---|
| 矢量 | 要素数 ≥ `validate.min_features` | 失败 |
| | 几何类型与类别一致（允许多部件） | 失败 |
| | 外包范围与获取范围重叠比例 | < 0.3 失败；< 0.8 警告 |
| | 字段要求中的字段都存在 | 失败 |
| | 名称字段填充率 ≥ `validate.name_fill_ratio` | 低于阈值警告；低于一半失败 |
| | 坐标系已定义 | 失败 |
| 驻地类 | 点数与范围内对应行政区数量之比 | < 0.8 警告 |
| 栅格 | 坐标系、范围重叠、无数据比例 < 0.5 | 范围不重叠失败，其余警告 |
| 统计表 | 必需列（地区、年份、数值）、年份与参数一致、数值有效、地区与行政区名称匹配率 | 列缺失失败；匹配率 < 0.9 警告 |

警告写入条目说明，并在表单结果、进度和交付中显示。

## 8. 数据仓

| 项目 | 规则 |
|---|---|
| 位置 | `<AUTOCARTO_HOME>/data/acquired/<来源编号>/<缓存键前 16 位>/{raw/, out/, manifest.json}`，索引 `<AUTOCARTO_HOME>/data/acquired/index.json` |
| 缓存键 | sha256（来源编号与版本、类别与参数、查询或地址、范围外包框（保留 4 位小数）与面摘要、比例尺档位、规范化规格、适配器版本） |
| 复用 | 同键、未过期（来源 `refresh_days`）、文件摘要未变 |
| 范围包含复用 | 同来源同类别、已缓存范围包含本次范围时，从已缓存原件重新规范化，不再下载（例如先取过全国，再取某省） |
| 并发 | 按缓存键加文件锁，多个会话同时需要同一数据时只下载一次 |
| 容量 | 默认上限 20 GB（README §8 第 12 项）；超出时提示清理，不自动删除未过期数据 |
| 不传播 | 不随流程导出，不写入输入记忆；删除后，引用它的旧运行记录保留来源与摘要，但不能恢复文件 |

## 9. 绑定到流程

1. **单个文件输入**：有效值为成品文件路径。
2. **单个图层输入**：用 `data_load_vector`/`data_load_raster` 以唯一名称加载成品，有效值为图层编号。
3. **文件夹 + 清单**：不复制文件。资源解析器（`internal/resource/resolve.go`）的请求增加 `EntryOverrides map[string]string`（行名 → 绝对路径）。逐行解析顺序：用户在 `files` 中为该行指定的文件 → 用户文件夹中的文件（`user`、`fill`）→ 获取成品 → 缺失。每行在 `Extra["origin"]` 记录 `user`、`acquired` 或 `override`。`data_load_list` 只消费已解析条目，不需要修改；Shapefile 附属文件检查照常进行。
4. **有效输入**（`internal/flowrun/inputs.go` `EffectiveInputs`）：用户值与获取值合并；用于条件（`conditions.go:16`、`:87`）、步骤消息（`step_message.go:59`）、执行器输入（`executor_route_knowledge.go:32`）、恢复时的重链接（`resume_resources.go:81`、`:175`）。条件语义：“看的是流程此时能用的值”。
5. **重链接**：获取完成后用覆盖后的条目重新解析相关资源，写回 `run.Plan.Resources`，按运行开始时的方法更新 `ResourceFingerprint`。
6. **「数据来源说明」**：获取完成后，系统提供一个可被步骤引用的文本——逐项列出“图层：来源（许可或署名，获取日期；近似、取舍等说明）”。解析器把 `「数据来源说明」` 视为系统引用，不报未解析；内置流程的版面步骤在说明栏引用它（F40）。
7. **交付摘要**：`finish` 追加“自动获取的数据”一节，并在包含疆域类图层时附合规提示（`02` §5）。

## 11. 失败处理与用户选择

1. 条目失败后，若方案允许自动换源（README §8 第 8 项）且有下一个可用候选（层级 1–6），自动尝试并记录；
2. 下一个候选是门户网站或联网搜索，或已无候选时，隐式步骤进入等待，选项：**重试**、**换来源**（列出备选）、**我来提供**（选择文件；清单行写入 `files` 覆盖）、**跳过**（仅可选行）、**停止流程**；
3. 必需行不能跳过；清单中所有必需行完成后隐式步骤才算完成，可选行失败只记说明；
4. 用户选择“我来提供”的文件按该行的类别和字段要求同样核验（字段不符时给出提示，由用户决定继续或更换）。

## 12. 安全

- 适配器只访问来源 `hosts`；重定向到白名单外主机时中止。
- URL、日志、来源记录中的密钥参数（`tk`、`key`、`token`、`access_token` 等）一律脱敏。
- 下载内容不执行；解压遵守 §6.4。
- 用户目录与本机数据源只读；所有输出写入数据仓或会话目录。
- 遵守外部服务的使用规则（并发、退避、标识）；本系统不绕过验证码或登录。
- 模型参与的兜底获取不得上传本地文件；登录、验证码、付费或许可确认由用户完成。
