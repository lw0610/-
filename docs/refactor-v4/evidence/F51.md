# F51 离线验收记录

## 实际执行的链路

`TestBuiltinAcquisitionRealQGIS` 以真实内置行军路线图生成计划，使用 Go 获取规划器、HTTP 适配器和数据仓，再通过隔离 QGIS-LTR Python 执行内置行政区提取、规范化与共享省界派生。Go 正式资源解析器把结果逐行绑定成句柄，QGIS 实际执行 `data_load_list` 与国标底图样式集。

- 自动获取：8 项完成，实际加载 8 个同名图层；省域和地区界线来自内置行政区原件，其他 6 项来自仅监听回环地址的假 HTTP 服务器，属性明确写“合成验收数据”。没有将其作为真实下载成果。
- 补齐缺项：文件夹中保留用户提供的铁路 Shapefile，其他 7 项复用已验证数据仓；第二轮没有新增 HTTP 请求。两轮共 6 次回环下载。
- 两轮均实际应用国标 QML，并核对省域 `NAME`、县级城市驻地 `name`、河流线 `NAME` 标注字段；所有图层真实可读、非空、WGS84，来源文件与 Go 绑定的是同一文件。再次加载均复用原 8 层，不增加副本。
- Shapefile 的主输出首先返回 `.shp`，其余侧文件完整；数据仓记录有原件、产物、许可、署名、获取时间、下载/核验记录和每个文件的摘要。所有临时工程及测试运行目录独立，无真实用户配置、会话、模型调用和在线数据源请求。
- 最终运行：PASS，测试函数 9.52 秒，Go 包合计 10.15 秒（单点驻地与水平铁路回归）（当前机器 QGIS-LTR；不是其他机器/真实网络的性能承诺）。

复现：使用 `AUTOCARTO_QGIS_PYTHON=/Applications/QGIS-LTR.app/Contents/MacOS/python`，显式 QGIS 的 PROJ_DATA、GDAL_DATA、PYTHONPATH 与 offscreen；`go test ./internal/api -run '^TestBuiltinAcquisitionRealQGIS$' -count=1 -v`。未设置解释器时该项明确 skip，不计为通过。桥接脚本只允许本测试用到的操作。

## 验收中修复的问题

- macOS `/var` 与 `/private/var` 同一路径的别名导致原件被误判在工作区外，复制到自身后失败：获取管线已按真实路径判定。
- Shapefile 侧文件按字典序会把 `.cpg` 当主文件：管线改为主文件在先；验收显式断言。
- 全国县域提取逐县重扫 GeoJSON，形成 O(n²)：改为单遍索引再逐几何验证。2891 县提取函数实测约 1.04 秒，23 项边界/规范化回归通过；原件几何与来源校验保留。
- 点/线的要素外包框不代表查询覆盖面积。核验现在保留数量、几何、字段、坐标系和范围相交检查，只对面/栅格应用面积覆盖阈值。验收使用单点县驻地与水平铁路，零面积外包框可正常获取、加载和复用；显式断言不会回退到其他来源。范围外的点/线仍被拒绝。
