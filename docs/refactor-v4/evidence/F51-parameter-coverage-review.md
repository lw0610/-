# F51 补充审查：来源参数、缓存与点线范围

## 问题与修正

1. 方案 `02` 的 `provides[].params` 是固定约束，例如省级数据文件不能因用户填写“市”就被当作市级数据。原 GEE 目录却把分辨率、波段、年份等默认值存到该字段，导致无参数 DEM 和显式 2019 年人口请求都无法匹配。
2. 新增通用 `provides[].defaults`，不按 GEE 来源种类特判。GEE 资产迁移到该字段；`params` 的约束语义保留。合并顺序为来源默认值、用户参数、派生操作参数。编译和获取规划允许必填参数由来源默认值满足，再对每个候选来源的实际参数做类别校验。默认值留在来源候选中，不写回用户请求，所以更换来源和自动回退不会携带前一个来源的默认值。参数不合法时仍报错。
3. 缓存仅豁免联网扩展服务、密钥和下载体量前置条件。来源停用、试验状态、自动获取策略、流程排除、联网搜索授权、疆域、覆盖范围、比例尺、面积限制和本地目录检查均继续执行。
4. 点/线的外包框面积可能为零，或者仅覆盖查询区域的一小部分，不能以此推断未完整获取。此类数据保留范围相交、数量、几何、字段及 CRS 检查；面/栅格保留原面积覆盖阈值。真实性与点线完整性不能由这项包围框检查单独证明。

## 回归

- `datasource/planning_review_test.go`：真实 GEE 目录的无参数 DEM、2019 年人口、自定义分辨率；必填参数由默认值补齐；用户错误值不被覆盖；固定参数仍受限；13 类缓存政策与范围规则。
- `flow/requirements_defaults_test.go`：真实类别和来源目录上增加 required year 约束，保存分析允许默认 2020 或显式 2019，不捕获来源默认值。
- `acquire/planner_defaults_test.go`：实际 Plan → 候选选择 → GEE 参数构造 → 数据仓参数链路，包含无参数 DEM、显式人口年份和 required 默认年份。
- `acquire/validation_geometry_test.go`：单点、稀疏多点、水平/竖直线、短线、范围外点线及面/栅格不足覆盖对照。
- 真实 QGIS 离线 F51 已改为单点驻地和水平铁路：8 项自动获取 + 8 层补齐加载、6 次回环下载、7 项缓存复用、用户铁路保留、标注及来源一致，PASS 9.52 秒。

全包验证：`go test ./internal/datasource ./internal/acquire ./internal/flow -count=1` 全部 PASS（0.33 / 1.07 / 2.85 秒）。缓存规格和适配器请求共用同一个默认参数合并函数，数据仓键包含来源默认值与实际参数。

所有测试使用隔离 AUTOCARTO_HOME 与禁用系统 keyring；真实天地图/GEE/门户服务仍未执行。
