# 02 数据需求与数据源规范

本文件回答前两个问题：**要什么数据**、**能从哪里拿**，以及系统如何确定性地选出来源。怎样拿到、怎样变成能用的数据，见 `03`。

## 1. 分工与原则

| 问题 | 由谁回答 | 载体 |
|---|---|---|
| 要什么 | 流程作者 | `## 数据需求`、数据清单新列（类别、字段）、本次输入（区域、纸张、年份…） |
| 这是什么数据、需要哪些字段、可由什么派生 | 系统 | 数据类别词表（§2） |
| 能从哪里拿 | 系统与用户 | 数据源目录：系统内置 + 用户登记（§4） |
| 能不能用这个来源 | 系统 | 合规规则（§5）、扩展服务就绪、密钥与登录要求 |
| 这一次用哪个来源 | 系统给建议，用户可改 | 获取计划（§6） |

原则：

1. **确定性优先**：类别匹配、来源筛选、排序、可用性全部是本地确定性计算，不调模型、不联网；同样的输入得到同样的计划。
2. **模型只做兜底**：只有门户网站操作、联网搜索（`03` §5.8）和通用流程的需求分析（F41）使用模型。
3. **流程作者不写“去哪找”**：作者声明需求即可；需要指定时用“推荐来源”，系统仍按合规与可用性检查。
4. **一切来源可见**：表单中能看到每一项的计划来源、备选、体量、许可和不可用原因。

## 2. 数据类别词表

### 2.1 位置

新建工具域 `autocarto/tools/system/data-acquisition/`（工具包“数据获取”，`hidden: true`，由系统获取执行器使用）。词表放在 `assets/categories.yaml`，由 Go 新包 `internal/datasource` 加载与校验。本轮不开放用户自定义类别。

### 2.2 格式

```yaml
apiVersion: data_category/v1
categories:
  - id: admin.division
    name: 行政区划面
    geometry: polygon
    params:
      level: {values: [省, 市, 县], required: true}
    aliases:
      - {name: 省域, params: {level: 省}}
      - {name: 省级行政区, params: {level: 省}}
      - {name: 市域, params: {level: 市}}
      - {name: 县域, params: {level: 县}}
      - {name: 行政区面}
    fields:
      name: {meaning: 中文名称, required: true}
      code: {meaning: 六位行政区划代码}
    sensitivity: cn_territory
    validate: {min_features: 1, name_fill_ratio: 0.95}

  - id: admin.boundary_line
    name: 行政界线
    geometry: line
    aliases: [{name: 地区界线}, {name: 省界}, {name: 线状省界}, {name: 行政边界线}]
    fields:
      kind: {meaning: 界线类型（国界、省界、地级界、县界、海岸线）}
    derive:
      - {from: admin.division, method: polygon_to_boundary_lines, note: 不能区分国界与海岸线，需海岸线数据时另行获取}
    sensitivity: cn_territory

  - id: settlement.county_seat
    name: 县级驻地
    geometry: point
    aliases: [{name: 县级城市驻地}, {name: 县城驻地}, {name: 县级驻地}]
    fields:
      name: {meaning: 中文名称, required: true}
    derive:
      - {from: admin.division, params: {level: 县}, method: point_on_surface, quality: approximate, note: 代表点不是驻地实际位置}
    validate: {min_features: 1, name_fill_ratio: 0.95}

  - id: transport.road.major
    name: 主要公路
    geometry: line
    aliases: [{name: 公路}, {name: 干线公路}]
    fields:
      name: {meaning: 中文名称}
      ref: {meaning: 道路编号}
      class: {meaning: 道路等级}
    generalize:   # 按比例尺分母取舍，阈值需在 F24 实测后调整
      - {max_denominator: 1000000, keep_class: [motorway, trunk, primary, secondary]}
      - {max_denominator: 4000000, keep_class: [motorway, trunk, primary]}
      - {keep_class: [motorway, trunk]}
    simplify_mm: 0.2   # 派生副本按“图上 0.2 毫米”容差简化
```

| 字段 | 含义 |
|---|---|
| `id` | 稳定编号，FLOW.md 可写编号或任一别名 |
| `geometry` | `point`、`line`、`polygon`、`raster`、`table`、`tiles` |
| `params` | 类别参数（层级、年份、指标、时段、分辨率…） |
| `aliases` | 中文别名，可隐含参数（“省域”即 `level=省`）；与样式集对照表的“图层/别名”保持一致 |
| `fields` | 标准字段：数据源把自己的字段映射到这些语义上，需求再把它们输出为下游要求的字段名 |
| `derive` | 可由哪个类别、用什么方法派生，以及质量说明 |
| `generalize`、`simplify_mm` | 按比例尺的要素取舍与简化规则（只作用于派生副本） |
| `sensitivity` | `cn_territory` 表示涉及中国疆域表达，受 §5 约束 |
| `validate` | 核验阈值（`03` §7） |

### 2.4 与样式集的关系

类别别名与样式集对照表的“图层/别名”保持一致即可让获取结果按名称匹配样式：获取结果总是按清单中的名称命名，所以内置流程不需要额外改动。样式集按“类别”匹配样式（用户自带数据的图层名与样式不一致时）列入后续，不在本轮（`05` “不在本轮”）。

## 3. 流程中的数据需求

### 3.1 写法

新增一级章节 `## 数据需求`（别名：`数据来源`、`数据获取`），每项一个三级标题：

```markdown
## 数据需求

### 中国底图
- 清单：「中国底图」
- 范围：「路线数据集」外扩 20%
- 比例尺：自动

### 行政区数据
- 类别：行政区划面
- 层级：「行政区级别」
- 范围：「区域」

### 统计表
- 类别：年度统计指标
- 范围：「区域」
- 参数：年份=「统计年份」；指标=「指标」；层级=「行政区级别」
- 推荐来源：国家统计局国家数据
```

| 字段 | 必需 | 含义 |
|---|---|---|
| 清单 | 与“类别”二选一 | 绑定一份数据清单资源；清单的“文件所在文件夹”输入即本需求的输入 |
| 类别 | 与“清单”二选一 | 单个数据的类别（编号或别名）；三级标题必须与一个文件或图层输入同名 |
| 层级 | 否 | `admin.*` 等带层级参数的类别；可写固定值或 `「输入」` |
| 范围 | 是 | `全国`、`「输入」`（文本区域名、边界文件或图层）、`「输入或产出」外扩 N%`（取该数据的外包范围） |
| 比例尺 | 否 | `自动`（默认，§6.4）或 `1:N` |
| 参数 | 否 | `键=值`，分号分隔；值可引用输入 |
| 字段 | 否 | 单个数据需要的输出字段，写法同清单“字段”列（§3.3） |
| 推荐来源 | 否 | 数据源编号或名称，顿号分隔；只调整排序，不绕过合规与可用性 |
| 排除来源 | 否 | 同上 |
| 获取方式 | 否 | `系统`（默认）或 `「第N步」`：由流程自己的步骤获取，系统仍对其产出做规范化与核验 |

### 3.2 绑定规则

- **清单需求**：清单必须是 `data_list` 且关联了文件夹输入（`文件所在文件夹：「X」`）；该输入获得“自动获取 / 补齐缺项”能力。清单中每一行是一个获取条目。
- **单个数据需求**：标题与一个“文件”或“图层”输入同名。文件输入得到一个文件；图层输入得到“获取并加载到工程”的图层。
- **文件夹输入不能单独声明类别**：一组数据必须通过清单描述（`FLOW_REQ_FOLDER_NEEDS_LIST`）。
- 需求引用的输入（范围、层级、参数）在选择自动获取或补齐时变为必填。

### 3.3 数据清单新列（`internal/resource/formats/resource_formats.yaml` `data_list`）

| 列 | 键 | 含义 |
|---|---|---|
| 类别 | `category` | 类别编号或别名；空表示该行不能自动获取 |
| 字段 | `fields` | 输出字段要求：`NAME`（把标准字段 `name` 输出为 `NAME`）、`NAME=name;CODE=code`（目标=标准字段）；空表示保留来源字段 |
| 自动获取 | `acquire` | 是/否，默认是；“否”表示只能由用户提供 |
| 推荐来源 | `source_hint` | 同 §3.1 |

旧版本程序会忽略未知列（`internal/resource/table.go` `tableHeaders` 跳过无法识别的表头），新增列向后兼容。

### 3.4 范围

| 写法 | 解析 | 何时可知 |
|---|---|---|
| `全国` | 内置省级行政区合并后的外包范围（与面） | 计划时 |
| `「区域」`（文本） | 在内置行政区中按名称查找（省、市、县，含常见简称）；重名时表单让用户选 | 填写后 |
| `「边界」`（文件或图层） | 该数据的外包范围 | 填写后 |
| `「路线数据集」外扩 20%` | 路线格式数据集按 `places.csv` 坐标求外包范围；文件、图层按要素外包范围；再按比例外扩 | 用户提供时在开始时可知；由步骤产出时在该步完成后可知 |

范围依赖步骤产出时，该条目在计划中显示“第 N 步完成后确定范围”，获取任务在该步完成后才开始（`03` §3）。

### 3.5 解析结果与诊断

`FlowDoc` 增加 `Requirements []RequirementDoc`（名称、清单、类别、层级、范围、比例尺、参数、字段、推荐/排除来源、获取方式、行号）。

| 诊断码 | 级别 | 条件 |
|---|---|---|
| `FLOW_REQ_DUPLICATE` | 错误 | 需求重名 |
| `FLOW_REQ_BIND_MISSING` | 错误 | 单个数据需求没有同名输入，或清单未关联文件夹输入 |
| `FLOW_REQ_FOLDER_NEEDS_LIST` | 错误 | 文件夹输入直接声明类别 |
| `FLOW_REQ_CATEGORY_UNKNOWN` | 错误 | 类别不在词表中（清单行为警告，该行不能自动获取） |
| `FLOW_REQ_PARAM_INVALID` | 错误 | 参数或层级不符合类别定义 |
| `FLOW_REQ_EXTENT_INVALID` | 错误 | 范围写法无法识别或引用不存在 |
| `FLOW_REQ_FIELD_INVALID` | 错误 | 字段要求引用了类别没有的标准字段 |
| `FLOW_REQ_GEOMETRY_MISMATCH` | 警告 | 清单“类型”与类别几何不符（矢量/栅格） |
| `FLOW_REQ_STEP_INVALID` | 错误 | “获取方式”指向的步骤不存在、在消费步骤之后，或没有同名产出 |
| `FLOW_REQ_ROW_NOT_ACQUIRABLE` | 提示 | 清单行没有类别或标为不自动获取 |

## 4. 数据源目录

### 4.1 位置

- 系统内置：`autocarto/tools/system/data-acquisition/assets/sources/*.yaml`，随程序发布，只读。
- 用户登记：`<AUTOCARTO_HOME>/sources/*.yaml`（本机数据目录、单位内部服务等），由界面管理（F33）。用户项编号必须以 `user.` 开头，不能覆盖系统项。
- 由 `internal/datasource` 加载、校验、建立“类别 → 来源”索引；与资源解析一样，只在 Go 中解析。

### 4.2 格式

```yaml
apiVersion: data_source/v1
id: source.osm.overpass
name: OpenStreetMap（在线查询）
kind: overpass
version: 1.0.0
endpoints: osmdata          # 使用 internal/osmdata 内置的全量节点清单与测速排序（07 §3.1）
hosts: [lz4.overpass-api.de, z.overpass-api.de, overpass-api.de, overpass.osm.jp, overpass.kumi.systems, overpass.private.coffee, overpass.openstreetmap.fr, maps.mail.ru, api.openstreetmap.org]
coverage: {regions: [world]}
scale: {max_denominator: 4000000}
limits: {max_features: 30000, max_extents: 12, timeout_seconds: 120, max_mb: 200}
license: ODbL-1.0
attribution: © OpenStreetMap contributors
compliance: open
requires: [integration:osm]
refresh_days: 30
priority: 50
provides:
  - category: transport.railway
    tags: ['railway=rail']
    types: way
    fields: {name: ["name:zh", "name"], class: ["usage", "railway:class"]}
  - category: transport.road.national
    tags: ['["highway"~"^(trunk|primary|secondary)$"]["ref"~"(^|;)G[0-9]{3}(;|$)"]']
    types: way
    fields: {ref: ref, name: ["name:zh", "name"]}
  - category: hydro.river_line
    tags: ['waterway=river']
    types: way,relation
    fields: {name: ["name:zh", "name"]}
```

`tags` 与 `osm_get_features` 的标签写法相同（`07` §3.3）；方括号写法原样传入，可表达多个条件同时满足。

| 字段 | 含义 |
|---|---|
| `kind` | 适配器种类（§4.3） |
| `hosts` | 适配器允许访问的主机；不在其中的地址一律拒绝 |
| `coverage` | 覆盖区域（`CN`、`world` 或外包范围） |
| `scale` | 适用比例尺分母范围：`min_denominator`（不宜更详细）、`max_denominator`（不宜更概略） |
| `limits` | 单次面积、超时、体量上限；超出时适配器分块或报“超限” |
| `license`、`attribution` | 许可与署名，进入来源记录和版面的「数据来源说明」 |
| `compliance` | `cn_official`（国家官方平台）、`cn_reference`（来源声明为国内官方数据、未认证）、`open`（开放数据）、`unknown` |
| `requires` | `integration:browser|web|gee|osm`、`secret:<名称>`（如 `secret:tianditu`）、`login:user`（需用户登录） |
| `refresh_days` | 数据仓中结果的有效期；0 表示长期有效 |
| `priority` | 同一层级内的先后 |
| `provides[]` | 每个类别的访问细节：`tags`/`types`（OSM）、`url`/`path`/`tool`/`dataset`/`layer`、可选 `params` 约束、`filter`（规范化时的筛选表达式）、`fields`（来源字段 → 标准字段，可列多个候选） |
| `endpoints` | 只用于 `overpass`：`osmdata` 表示使用内置节点清单；不得填写区域节点 |
| `size_mb` | 预计体量（显示用，可省略） |

### 4.3 适配器种类

| `kind` | 取数方式 | 使用模型 | 典型前置条件 |
|---|---|---|---|
| `local_folder` | 读取用户登记的本机目录（只读） | 否 | 目录存在 |
| `offline_asset` | 调用随工具发布的离线数据（如行政区边界） | 否 | — |
| `http_file` | 下载公开文件（含压缩包），按需解压 | 否 | `integration:web` |
| `overpass` | OpenStreetMap 在线查询，复用 `internal/osmdata`（多节点测速排序、切换、节流、逐要素组装，`07`），按范围分块 | 否 | `integration:osm` |
| `ogc_wfs`、`arcgis_rest` | 读取要素服务（GDAL） | 否 | `integration:web` |
| `tianditu` | 天地图接口（地名、行政区划）与瓦片底图 | 否 | `secret:tianditu` |
| `gee` | Google Earth Engine 数据集模板（栅格下载、少量矢量） | 否 | `integration:gee` |
| `portal` | 门户网站：浏览器操作下载，可能需要登录或验证码 | 是（受限） | `integration:browser`，可能 `login:user` |
| `web_search` | 联网搜索公开数据（兜底） | 是（受限） | `integration:browser`，用户允许（README §8 第 13 项） |

### 4.4 初始内置数据源（F23–F25、F27 实现；标“需核实”的外部事实在实施前核实并写入验证记录）

### 4.5 本机数据源（用户登记）

用户可把自己电脑上的一套数据登记为来源，之后所有流程都会优先使用：

```yaml
apiVersion: data_source/v1
id: user.local.national-basemap
name: 我的全国基础数据
kind: local_folder
root: /Users/me/GIS/全国基础数据     # 只存在本机，不随流程导出
compliance: unknown                  # 用户声明；疆域类数据用户自负其责，系统提示
provides:
  - {category: transport.railway, path: 交通/铁路.shp, fields: {name: NAME}}
  - {category: admin.division, params: {level: 省}, path: 境界/省级行政区.shp, fields: {name: NAME, code: PAC}}
```

登记界面可从一个已有的数据清单或文件夹扫描生成草稿，由用户逐项确认类别（F33）。

### 4.6 目录诊断

| 诊断码 | 级别 | 条件 |
|---|---|---|
| `DS_SCHEMA_INVALID` | 错误 | 格式不符；该来源不进入索引 |
| `DS_ID_CONFLICT` | 错误 | 编号重复，或用户项不以 `user.` 开头 |
| `DS_CATEGORY_UNKNOWN` | 警告 | `provides` 引用未知类别；该项忽略 |
| `DS_HOST_MISSING` | 错误 | 需要联网的来源没有 `hosts` |
| `DS_SECRET_INLINE` | 错误 | 目录中出现疑似密钥值（只允许 `secret:<名称>`） |
| `DS_LOCAL_ROOT_MISSING` | 警告 | 本机目录不存在 |

## 5. 合规规则

1. 类别 `sensitivity: cn_territory`、且获取范围与中国区域相交时，只允许 `cn_official`、`cn_reference` 来源；`open` 与 `unknown` 来源从候选中排除，原因“境外开放数据的中国疆域表达可能与我国标准地图不一致”。
2. 用户自己提供的数据、用户登记的本机数据源不受第 1 条限制，但计划与交付中提示“疆域类数据由用户提供，请自行确认合规”。
3. 获取范围与中国区域相交、且结果包含疆域类图层时，交付摘要附“公开使用须依法送审；系统不认证地图合规性”。
4. 南海诸岛、钓鱼岛及其附属岛屿等是否完整表达，属于 F23 对内置行政区数据的核实项；核实前在来源记录中注明“未核实”。

## 6. 获取规划

### 6.1 输入

数据需求（含清单行）、本次输入与来源方式、数据类别词表、数据源目录、扩展服务就绪状态、已配置的密钥名称、数据仓索引、方案策略（README §8 第 7–9、13 项）。

### 6.2 条目展开

- 单个数据需求 → 一个条目。
- 清单需求 → 每行一个条目；没有类别或“自动获取=否”的行不可获取。
- 来源方式为 `fill`（补齐）时，只为用户文件夹中缺失的必需行（以及用户选择补齐的可选行）建立条目。

### 6.3 范围

按 §3.4 解析为外包范围（WGS84）与可选面；依赖步骤产出时标为“待定”。范围用于覆盖判断、在线查询分块和规范化裁剪。

### 6.4 比例尺

- `自动`：流程有“纸张”输入时，取版式主图宽度（无法得知时取纸张宽度 × 0.8）与范围实际宽度之比，`分母 ≈ 范围宽度（米） / 主图宽度（米）`。例：路线范围宽约 2000 公里、A1 横向（841 毫米）→ 约 1:300 万；全国宽约 5200 公里 → 约 1:770 万。
- 没有纸张输入时，按范围大小分级：全国 1:400 万，省级 1:100 万，地级 1:25 万，县级 1:5 万。
- 比例尺用于判断来源是否适用（`scale`）、选择取舍规则（`generalize`）与简化容差（`simplify_mm`）。

### 6.5 候选筛选（不满足即排除，并记录原因）

| 检查 | 不满足时的原因示例 |
|---|---|
| 来源提供该类别（含参数约束），或该类别可由某个可获取类别派生 | 无 |
| 覆盖范围包含获取范围 | “该来源只覆盖中国” |
| 比例尺适用 | “该来源过于概略，不适合 1:25 万” |
| 合规（§5） | “疆域类数据不能使用境外开放数据” |
| 扩展服务已启用 | “需要在“设置 → 扩展服务”启用网页取数” |
| 密钥已配置 | “需要配置天地图服务端 Key” |
| 体量在上限内 | “约 1400 MB，超过下载上限 1024 MB” |
| 方案未禁止自动获取、来源未被需求排除 | “当前方案已关闭自动获取数据” |

需要用户登录的来源不排除，标记“需要你登录”，排序靠后。

### 6.6 排序

先按层级，再按需求“推荐来源”、`priority`、比例尺贴合度（分母越接近越好）、预计体量：

1. 数据仓中已有、未过期的同参数结果
2. 用户登记的本机数据源
3. 内置离线数据
4. 官方在线接口（`cn_official` 的 `tianditu` 等）
5. 开放数据文件下载（`http_file`）
6. 在线查询（`overpass`、`ogc_wfs`、`arcgis_rest`）、GEE
7. 门户网站（`portal`）
8. 联网搜索（`web_search`，仅在用户允许时出现）

派生候选（例如由行政区划面派生行政界线）排在其基础类别所在层级之后，并带质量说明（“代表点为近似位置”）。

### 6.8 何时计算

| 时机 | 内容 |
|---|---|
| 执行计划（打开、保存、预览） | 不看输入：每个条目的类别、字段要求、候选来源类型与总体可用性 |
| 输入检查（`inputs/check`）与运行开始 | 按本次输入：范围、比例尺、选定来源、体量、数据仓命中；运行开始时的结果写入 `run.json`，此后不再变化（除“待定范围”条目在范围确定后补算） |

两处都不联网、不调模型；数据仓命中只查本机索引。

### 6.9 扩展服务就绪的判定

- `flow.Environment` 增加 `Integrations map[string]bool`（`browser`、`web`、`gee`、`osm` 是否在设置中启用），由 `internal/api/flow_environment.go` 读取 `GetIntegrationsConfig()` 填充；来源的 `requires: integration:<名称>` 按它判断。
- 工具层面的依赖关系由新文件 `internal/integrations/catalog.go` 的 `IntegrationFor(toolName) string` 给出，内部使用与调用时相同的判断（`browserruntime.Handles`、`webdata.Handles`、`geeruntime.Handles`、`osmdata.Handles`），各类 `*_check_environment` 工具不计入。工具包中所有非检查工具都依赖某项服务、且这些服务都未启用时，该工具包视为“未就绪”，供角色解析（`01`）与界面提示使用。
- “就绪”只表示设置中已启用；`npx`、浏览器、GEE 认证、OSM 节点可达性等真实环境由各自的检查工具在运行时确认，界面写“已启用，运行时检查环境”。
- 就绪状态参与 `CatalogRevision`，切换开关后计划随之更新。

## 7. 运行输入取值

### 7.1 取值形式

| 输入 | 取值 | 来源方式 |
|---|---|---|
| 文件 / 图层（有单个数据需求） | 路径或图层编号 | `user` |
| | `{"$acquire": true}` 或 `{"$acquire": true, "source": "<来源编号>"}` | `auto` |
| 文件夹（关联清单需求） | 路径 | `user`（缺必需文件时报错，可改为补齐） |
| | `{"path": "<路径>", "$fill": true}` | `fill`：只获取缺失项 |
| | `{"$acquire": true}` | `auto`：全部获取 |
| | 上两种可加 `"sources": {"<行名>": "<来源编号>"}`、`"files": {"<行名>": "<文件路径>"}` | 单行换来源 / 单行由用户提供 |

### 7.2 校验（`internal/flowrun/inputs.go`，表单检查与运行开始共用）

- `$acquire`、`$fill` 用于没有数据需求的输入 → `FLOW_INPUT_ACQUIRE_UNSUPPORTED`。
- 选定条目不可用 → `FLOW_INPUT_ACQUIRE_UNAVAILABLE`（附各条目原因）；`fill` 时缺失项中有不可获取的必需行 → 同上并列出行名。
- 必填检查把 `auto`、`fill` 视为已提供；可获取的必填输入未填时，消息为“请提供 X，或选择自动获取”，`StartupIssue.Acquirable=true`。
- 需求引用的输入（范围、层级、参数）在 `auto`、`fill` 时为必填 → `FLOW_INPUT_REQUIRED_FOR_ACQUIRE`。
- 指定的 `source` 必须是该条目的候选且可用；`files` 中的文件必须存在且类型相符。
- 二选一等约束把 `auto`、`fill` 计为已提供。
- 关联到 `auto` 文件夹的数据清单在开始时按“尚未提供”处理，不把对象当路径。

### 7.3 记忆

- 记住来源方式（`auto`、`fill`）和用户选择的来源，表单下次预选；不记住获取到的值。
- 用户选择的文件夹路径照旧记住；`fill` 时记住路径与“补齐”选择。
- 获取值通过数据仓复用（`03` §8），与输入记忆无关。

## 8. 诊断码汇总（运行输入）

| 诊断码 | 含义 |
|---|---|
| `FLOW_INPUT_ACQUIRE_UNSUPPORTED` | 该输入没有数据需求 |
| `FLOW_INPUT_ACQUIRE_UNAVAILABLE` | 选择了自动获取或补齐，但有条目不可用 |
| `FLOW_INPUT_REQUIRED_FOR_ACQUIRE` | 自动获取需要的输入（范围、层级、参数）未填写 |
| `FLOW_INPUT_SOURCE_INVALID` | 指定的来源不是候选或不可用 |
| `FLOW_INPUT_REGION_AMBIGUOUS` | 区域名称匹配到多个行政区，需要选择 |
