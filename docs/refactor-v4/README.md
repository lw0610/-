## 1. 目标

**一句话**：流程只声明“需要什么样的执行者”和“需要什么数据”；系统负责把执行者落到当前方案，也负责“从哪里拿数据、怎样拿、拿来后怎样改成流程能直接用的样子”，并留下来源。

1. **流程与方案解耦**（`01`）：流程声明参与角色及所需工具包；运行时按“方案映射 → 同名角色 → 工具包匹配 → 流程自带角色/系统默认执行器”解析，缺工具包时临时补齐；只有一定执行的步骤缺执行者才阻止运行。
2. **数据获取子系统**（`02`、`03`）：
   - **要什么**：数据需求用“数据类别”描述（例如“省级行政区面，标注字段 NAME”），不只是文件名；
   - **从哪里拿**：系统维护“数据源目录”（内置离线数据、用户登记的本机数据、开放数据下载、在线接口、GEE、门户网站），确定性地为每个需求选出候选来源；
   - **怎么拿、怎么用**：系统获取执行器按适配器下载或提取，再裁剪、筛选、映射字段、按比例尺取舍，输出成流程清单要求的图层名和字段，核验后入本机“数据仓”，下次复用；
   - **由用户决定**：每个数据可以“我来提供 / 自动获取”，文件夹可以“缺的自动补齐”，每个图层可以换来源；
   - **模型只做兜底**：只有门户网站操作、联网搜索和通用流程的“需求分析”使用模型，且结果必须经过同样的确定性核验。
3. **OSM 工具链**（`07`）：移植 GeoCode 的 OpenStreetMap 专用下载工具（查找、统计、按编号下载、按范围下载），补上“道路、铁路、河流、水域、站点、地名点”等矢量数据的确定性通道；智能体可直接用，获取子系统也用同一实现。
4. **会话工作区与文件区**（`08`）：对话页右侧改为“文件 / 任务 / 过程”三个页签的工作区，本会话导出的地图、下载的数据、流程成果集中列出，可预览、查看数据信息、加载到 QGIS、在文件夹中显示。

## 2. 现状问题（证据均来自当前代码）

**P1 负责角色按名字硬绑定当前方案**
- 步骤“负责”按显示名精确 → 编号 → 包含匹配（`carto_agent/internal/flow/diagnose.go:10`）；找不到、被禁用都是错误（`:28`、`:35`），运行入口拒绝（`internal/flow/compile.go:156`），`AvailablePlans` 直接跳过（`compile.go:239`）。
- 用户方案 `Zttzt` 启用了行军路线图和交通线路图，但缺“制图知识抽取专家”“质量反馈智能体”，“空间分析专家”已禁用，两个流程都被整体阻断；即使缺角色的步骤本次不会执行（行军路线图第 1 步、第 7–10 步都是条件步骤）也一样。
- 专用执行器是系统代码，却必须在方案里有对应角色。

**P2 能力检查名存实亡**：移除后台增强后 `SuggestedTools` 恒为空，`FLOW_CAPABILITY_MISSING_IN_ROLE` 不再触发；`kind=auto` 步骤实际落到第一个可用角色（`internal/flowrun/controller.go:365`）。

**P3 数据只能由用户提供**：必填输入缺失时表单禁止发送（`autocarto-web/src/features/flow-run/model.ts`）、运行入口报错（`internal/flowrun/inputs.go:84`）、编排提示要求先询问（`defaults/agent_configs/default/agent.yaml:23`）。

**P4 系统不知道“要什么数据”**
- 行军路线图的底图清单 `autocarto/flows/system/marching-route/resources/data/中国底图.csv` 只有“名称、路径、类型、必需、说明”五列，“说明”是自由文字；数据清单的列定义也只有这五项（`internal/resource/formats/resource_formats.yaml` `data_list`）。
- 下游步骤对数据有隐含的硬要求：样式集 `autocarto/resources/system/styles/国标底图样式/对照表.csv` 规定省域、河流线的标注字段为 `NAME`，县级城市驻地为 `name`。拿来一份字段不同的铁路或河流数据，符号化步骤就会缺标注或失败。
- 单个输入（如统计专题图的“行政区数据”）只有类型“文件”，没有“这是哪一级行政区面、需要哪些字段”的声明。

**P5 系统不知道“从哪里拿”**
- 现有取数能力是零散工具：浏览器（`browser_*`）、网页读取与下载（`web_*`，只支持 GET，默认上限 100 MB，`internal/webdata/tools.go:135`）、GEE（只有栅格下载辅助 `download_image`，`internal/geeruntime/worker.py:532`）、内置离线行政区边界（GeoCode 上游，声明数据来自天地图，只能按名称/代码取单个行政区，`autocarto/tools/system/admin-boundaries/`）、天地图地名查询（只用于路线知识抽取的坐标，`internal/geocoding/`，已有服务端 Key 配置 `internal/config/tianditu.go`）。
- 没有任何地方记录“铁路可以从哪里拿、什么比例尺合适、许可是什么、中国疆域表达是否合规”。如果只让作者在做法里写“去网上找”、让智能体带浏览器自己找，结果取决于模型临场发挥，不可预期、不可复现。

**P6 拿来的数据不能直接用、也不能复用**：没有统一的裁剪、筛选、字段映射、比例尺取舍；没有本机缓存，每次运行都要重新下载；没有来源署名进入版面的机制。

**P7 矢量底图数据没有可靠通道**：本机已启用浏览器、网页取数（上限 1000 MB）和 GEE 三项扩展服务（`autocarto_data/config/config.yaml` `integrations`）。浏览器每一步靠模型操作，网页取数只支持 GET 且必须先知道文件地址，GEE 以栅格为主——都拿不到可靠的道路、铁路、河流、站点等矢量数据。GeoCode v0.9.6 已有一套针对这一缺口、并在国内网络下加固过的 OSM 工具链（`07` §1–§3）。

**P8 会话产出没有统一入口**：右侧“详情与任务”只有任务、待确认与过程（`autocarto-web/src/components/chat/RightInspector.tsx`）；导出的地图、下载的数据散落在会话目录的 `exports/`、`output/`、`intermediate/`、`flows/` 中；只有流程成果卡片能点开路径（`features/flow-run/FlowOutputs.tsx`），没有“在文件夹中显示”和应用内预览（`08` §1）。

## 3. 目标设计

### 3.1 角色（`01`）

流程新增 `## 参与角色`（职责、工具包、执行器、模型要求），步骤可加 `能力`。解析顺序：方案映射 → 同名 → 工具包匹配 → 流程自带角色 / 系统默认执行器；缺工具包按策略临时补齐；按可达性分级阻断。合成角色只存在于运行快照。

### 3.2 数据获取子系统（`02`、`03`）

```text
流程：要什么                 系统：从哪里拿 → 怎么拿 → 怎么变成能用的
─────────────────            ──────────────────────────────────────────────────────────
数据需求（## 数据需求）       数据类别词表 ─┐
 + 数据清单新列（类别、字段）   数据源目录 ───┼─► 获取规划（确定性，表单即可看到）
 + 本次输入（区域、纸张…）      合规规则 ─────┘         │ 用户可换来源 / 改为自己提供 / 补齐
                                                       ▼
                               系统获取执行器（后台，依赖就绪即开始）
                                 数据仓命中？──是──► 直接复用
                                     │否
                                 适配器取数（离线 / 本机 / 下载 / 接口 / GEE / 门户 / 搜索兜底）
                                     ▼
                                 规范化（裁剪、筛选、字段映射、比例尺取舍、命名）→ 派生（面→界线等）
                                     ▼
                                 核验（要素数、几何、范围、字段填充率）→ 入数据仓（原件 + 成品 + 来源）
                                     ▼
                               绑定为输入值 ──► 后续步骤照常使用；版面获得「数据来源说明」
```

| 关键概念 | 说明 |
|---|---|
| 数据类别 | 词表中的稳定编号（如 `transport.railway`），带几何类型、标准字段、派生方法、核验阈值、敏感级别 |
| 数据需求 | 流程声明：绑定哪个输入或清单、类别、层级、范围（全国 / 某输入 / 某产出外扩）、比例尺、参数、推荐来源 |
| 数据源 | 目录项：提供哪些类别、访问方式、覆盖范围、适用比例尺、许可与署名、合规标签、前置条件（扩展服务、密钥、登录）、刷新周期 |
| 获取计划 | 每个需求条目的选定来源、备选、预计体量、注意事项、不可用原因；确定性计算，不联网 |
| 数据仓 | 本机已获取数据（原件、成品、来源记录），按来源与参数复用 |

### 3.3 OSM 工具链（`07`）

五个内部工具：`osm_check_environment`、`osm_search`、`osm_probe`、`osm_get_objects`、`osm_get_features`，工具包“开放地图数据（OSM）”。继承上游的关键做法：只用全量数据节点并首次测速排序、固定健康节点与切换、三轮退避、1.1 秒节流、流式 200 MB 上限、查询范围“只多不漏”、逐要素组装、固定字段约定、按几何拆分文件、部分结果明示。我方增加：默认写入会话目录且不覆盖、来源记录文件、疆域提示、产出登记、会话首次确认。

### 3.4 会话工作区与文件区（`08`）

右侧 40 像素图标栏（文件、任务、过程）+ 可调宽面板；文件页签按“成果、数据、流程运行、中间文件”分组，Shapefile 等多文件数据集合并为一行；单击预览（图片、PDF、表格、文本、数据信息与缩略图），预览时面板加宽或全屏；空间不足时面板以抽屉覆盖。后端以“登记 + 扫描”维护会话文件索引，接口只读、防越界。

### 3.5 一个例子（详见 `06`）

行军路线图的 8 个底图图层，在清单里加上“类别、字段”两列后，系统就知道：省域是“省级行政区面、需要 `NAME`”，县级城市驻地是“县级驻地点、需要 `name`”，河流线是“河流线、需要 `NAME`”……获取计划例如：省域与地区界线来自内置行政区边界（界线由面派生）、县级驻地来自天地图地名查询（无 Key 时用县域代表点并标“近似”）、铁路/公路/国道/河流来自 OpenStreetMap（按等级筛选、按比例尺取舍），中国疆域类图层不会使用境外开放数据。用户也可以把其中任一项改为自己提供，或选择自己的底图文件夹、只补齐缺的几项。

## 5. 整体验收标准

**角色**
1. **X1** Zttzt 结构夹具中，四个内置流程的计划没有错误；行军路线图提供路线数据集、质量审查为否时可以启动；交通线路图第 2 步由流程自带角色执行。
2. **X2** 只阻断一定执行的步骤；条件无法确定的步骤运行到时按失败策略询问。
3. **X3** 合成角色与临时补齐不写入方案文件，不出现在自由委派中；受限工具包不被补齐。

**数据**
4. **X4 知道要什么**：行军路线图底图 8 项在计划中都有类别、几何类型和下游要求的字段（省域 `NAME`、县级城市驻地 `name`、河流线 `NAME`）。
5. **X5 知道从哪里拿**：每项都有候选来源及不可用原因；中国疆域类数据（行政区面、界线）不出现境外开放数据来源；表单检查与计划生成不联网、不调模型。
6. **X6 拿来能直接用**：获取结果的文件名、图层名、字段与清单和样式集要求一致，行军路线图第 2、3 步不改一字即可加载和符号化。
7. **X7 由用户决定**：同一流程可“全部自动获取”“我来提供”“提供文件夹并补齐缺项”，以及单项换来源或单项改为自己提供；补齐时用户文件夹不被写入。
8. **X8 可追溯、可复用**：`run.json` 记录每项的来源、查询、获取时间、摘要与许可；交付和版面说明中有数据来源；第二次运行同一需求命中数据仓，不重复下载。
9. **X9 兜底受控**：目录覆盖不到时，只有在用户允许后才使用联网搜索，结果同样经过规范化与核验。

**整体**

## 6. 全局执行约束（所有执行智能体必须遵守）

在 v2 `README.md` §6 与 v3 `README.md` §6 全部约束基础上，增加：

1. **开工前确认工作区**：当前 `refactor/v3` 有用户尚未提交的改动；执行智能体不得替用户提交、暂存、丢弃或覆盖。F00 由用户先提交后再建分支。
2. **合成角色与临时补齐只存在于内存和运行快照**，不写方案文件，不进入自由委派与方案界面。
3. **请求路径不调模型、不联网**：角色解析、可达性、获取规划、表单检查全部是确定性的本地计算；网络访问只发生在运行中的获取任务里。
4. **数据只能来自真实来源**：不得用模型生成数值、几何或文件充当获取结果；每项获取结果都有来源记录、获取时间和摘要；模型参与的兜底获取也要经过同样的核验。
5. **适配器只访问数据源目录声明的主机**；密钥只按名称引用，不写入目录、来源记录、日志或 URL（含查询参数中的 `tk` 等，必须脱敏）。
6. **不写用户数据**：用户提供的文件、文件夹、本机数据源只读；规范化、裁剪、派生一律写入数据仓或会话目录的新文件。
7. **中国疆域类数据遵守合规规则**（`02` §5）；系统只提示“公开使用须依法送审”，不声称认证。
8. **获取结果不进入输入记忆、流程包或导出包**；复用通过数据仓完成。
9. **不得读写真实 `autocarto_data/`**：测试一律用临时运行目录；联网测试默认跳过，需显式开关，且不计入“通过”。
10. **验证记录写在 `docs/refactor-v4/evidence/`**，提交信息以任务号开头，在 `refactor/v4` 分支提交，不推送、不合并。
11. **遵守 OSM 公共服务的使用规则**：只使用全量数据节点；Overpass 与 Nominatim 两次请求间隔不少于 1.1 秒；请求带程序标识；不做批量地理编码；成果署名“© OpenStreetMap contributors”。
12. **会话文件区只读**：文件接口不提供删除、改名、写入；只读取会话文件索引中的文件，读取前重新确认路径在允许的根目录内。
13. **移植上游代码保留许可声明**：从 GeoCode 移植的逻辑与测试，在对应目录的 `UPSTREAM.md` 记录固定版本、文件摘要与本地修改，并保留 MIT 版权声明。

## 9. 术语

| 术语 | 含义 |
|---|---|
| 参与角色 / 方案角色 / 角色解析 / 临时补齐 / 流程自带角色 / 系统默认执行器 / 可达性 | 见 `01` |
| 数据类别 | 词表中的稳定编号与定义：几何、标准字段、派生方法、核验阈值、敏感级别 |
| 数据需求 | 流程声明的一项数据需要；绑定一个输入（单个数据）或一份数据清单（多个条目） |
| 获取条目 | 规划和执行的最小单位：单个数据需求，或清单中的一行 |
| 数据源 / 数据源目录 | 可获取来源的声明及其集合；系统内置 + 用户登记 |
| 适配器 | 一类数据源的确定性取数实现（离线、本机、下载、在线查询、天地图、GEE、门户、搜索） |
| 获取计划 | 规划器为每个获取条目给出的选定来源、备选、体量、注意事项与不可用原因 |
| 规范化 / 派生 | 把原件变成需求要求的样子（裁剪、筛选、字段、取舍、命名）/ 由一个类别生成另一个类别 |
| 数据仓 | 本机已获取数据的缓存与索引 |
| 补齐 | 用户提供的文件夹缺少清单条目时，只获取缺失项，写入数据仓，用户文件夹不变 |
| 来源方式 | 本次每个输入（及条目）的取值方式：`user`、`auto`、`fill`、`none` |
| 有效输入 | 用户值与获取值合并后的输入，供条件、步骤消息和资源链接使用 |
| OSM 工具链 | `internal/osmdata` 及五个 OSM 工具，移植自 GeoCode v0.9.6（`07`） |
| 会话工作区 | 对话页右侧的图标栏与面板，含“文件 / 任务 / 过程”三个页签（`08`） |
| 会话文件索引 | `<会话目录>/files.index.json`：登记与扫描合并得到的本会话文件清单及来源（`08` §5） |
