# 08 会话工作区与文件区规范

本文件规定对话页右侧如何从“详情与任务”改为“会话工作区”，加入“文件”区集中展示本会话产出的文件，以及后端如何登记、列出、预览这些文件。

## 1. 现状与问题

| 现状 | 证据 |
|---|---|
| 右侧只有“详情与任务”：上部（最多 40% 高）任务清单与只读待确认项，下部“智能体完整过程” | `autocarto-web/src/components/chat/RightInspector.tsx`，固定宽 380 像素 |
| 面板由顶栏“展开详情区”按钮或消息中的“查看详情”打开，默认关闭 | `stores/uiStore.ts` `inspectorOpen`；`components/layout/TopBar.tsx:273`；`hooks/useChatSession.ts:430` |
| 会话产出分散在会话目录：`exports/`（PNG、PDF 成果图与版面快照）、`output/`（GEE 栅格、下载数据、脚本、日志）、`intermediate/`（路线知识中间文件）、`flows/<运行编号>/run.json` | `internal/config/session_paths.go` `ResolveSessionDir`；`internal/websocket/handlers_session.go:28` 的子目录清单 |
| 只有流程成果卡片能点开路径；没有“在文件夹中显示”、没有应用内预览 | `features/flow-run/FlowOutputs.tsx`；Tauri 命令 `open_local_path`（`src-tauri/src/local_output.rs`，按扩展名白名单拒绝可执行文件与脚本） |
| 工具结果没有统一的“产物”字段；智能体可读的 `output_get_info` 只列出 `output/` 第一层 | `internal/toolresult/result.go`；`internal/runtimecontrol/tools.go` `getOutputInfo` |

结果：用户要找导出的地图、下载的数据，只能翻聊天记录或去磁盘里找。

## 2. 布局方案

### 2.1 可用宽度

窗口默认 1200 像素、最小 900 像素（`src-tauri/tauri.conf.json`）。左侧实例栏约 112 像素，会话栏展开 260 像素、收起 40 像素。默认窗口下再放 380 像素的右侧面板，聊天区只剩约 450 像素。

### 2.2 三种做法比较

| 做法 | 说明 | 结论 |
|---|---|---|
| A 页签式工作区（推荐） | 右侧保留一个面板，顶部或侧边切换“文件 / 任务 / 过程”；点开文件在面板内预览，可加宽或全屏 | 不增加栏数，默认窗口可用；与 Claude 桌面端、GeoCode 的“列表 + 预览”一致 |
| B 上下分区 | 面板上半文件、下半任务与过程 | 380 像素宽、上下再切分后每块都太小，不推荐 |
| C 独立第四栏 | 文件栏常驻，详情面板另开 | 默认窗口下聊天区不足 300 像素，不推荐 |

### 2.3 推荐布局

```text
┌ 顶栏 ─────────────────────────────────────────────────────────────────────────┐
│实例│ 会话 │                聊天（最小 420）                │ 工作区面板 │图│
│112 │260/40│                                                │ 360        │标│
│    │      │                                                │ ┌────────┐ │栏│
│    │      │                                                │ │文件列表 │ │40│
│    │      │                                                │ │或预览   │ │  │
│    │      │                                                │ └────────┘ │  │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **右侧图标栏**（40 像素，始终可见）：图标依次为“文件”（新文件数角标）、“任务”（进行中或待确认时显示角标，待确认为琥珀色）、“过程”（有活动时显示圆点）；底部“打开会话文件夹”。点击某个图标打开面板并切到该页签；再次点击当前图标收起面板。
- **工作区面板**：默认宽 360 像素，可拖动边缘调整（300–560）；预览时自动加宽到“预览宽度”（默认 520，可拖动调整，范围 420 到主区域的 60%），关闭预览恢复原宽度；宽度分别记住。
- **空间不足时**：主区域宽度减去面板宽度后小于 420 像素时，先自动收起会话栏；仍不足时面板改为覆盖在聊天区上方的抽屉（带遮罩，点击外部收起）。
- **全屏预览**：预览头部“放大”打开全屏对话框，适合 PDF 和大图。
- 顶栏原“展开详情区”按钮改为切换工作区面板（打开上次的页签），保留以兼容用户习惯；消息中的“查看详情”打开“过程”页签并定位到对应流程块（现有行为）。

## 3. 三个页签

### 3.1 文件

**头部**：标题“本会话文件”与数量；搜索框；类型筛选（全部、成果、数据、流程、中间文件）；排序（最新、名称、类型）；“显示全部”（包含日志、脚本与临时文件）；刷新；打开会话文件夹。

**分组**（默认顺序，空组不显示）：

| 分组 | 内容 | 默认 |
|---|---|---|
| 成果 | `exports/` 中的图片与 PDF；流程步骤已核验的文件产出；登记为成果的文件 | 展开，图片显示缩略图 |
| 数据 | 矢量、栅格、表格：GeoJSON、GeoPackage、Shapefile、GeoTIFF、CSV、XLSX；OSM 下载、自动获取的数据（可能位于数据仓或工程目录） | 展开 |
| 流程运行 | `flows/<运行编号>/run.json`，显示流程名、状态与时间 | 展开 |
| 中间文件 | `intermediate/` | 收起 |
| 其他 | 日志、脚本、临时文件 | 只在“显示全部”时出现 |

**一行**：类型图标、名称（多文件数据集合并为一行，见 §5.4）、来源（工具显示名 / 流程第 N 步 / 自动获取 / OSM 下载）、时间、大小、相对位置；新文件带圆点。悬停显示操作按钮。

**操作**：

| 类型 | 单击 | 其他操作 |
|---|---|---|
| 图片（PNG、JPG、WebP、GIF、SVG） | 预览 | 打开、在文件夹中显示、复制路径 |
| PDF | 预览（运行环境不支持时提示用系统程序打开） | 同上 |
| 矢量、栅格 | 数据信息与缩略图 | 加载到 QGIS、在文件夹中显示、复制路径 |
| CSV | 表格预览（前 200 行） | 打开、在文件夹中显示、复制路径 |
| XLSX、ZIP | 文件信息（工作表或文件清单） | 同上 |
| 文本、JSON、Markdown、YAML | 文本预览（不超过 1 MB） | 同上 |
| QGIS 样式（`.qml`）、版式（`.qpt`） | 文件信息 | 导入到模板与样式库（复用现有资源导入接口） |
| 流程运行记录 | 运行摘要：输入、各步状态、成果、自动获取的数据与来源 | 在文件夹中显示 |

非桌面运行（纯网页）时，“打开”“在文件夹中显示”改为复制路径（与 `FlowOutputs.tsx` 现有做法一致）。

**新文件提示**：按会话记住“上次查看文件页签的时间”，之后登记的文件计为新文件；图标栏显示数量。面板关闭时不自动弹出；流程结束且有成果文件时，在流程完成卡片中显示“在文件区查看”，面板若已打开则自动切到文件页签并高亮成果（README §8 第 21 项）。

**空状态**：“本会话还没有产出文件。导出地图、下载数据或运行流程后会出现在这里。”

### 3.2 任务

原面板上部内容：任务清单（`TaskListPanel`）与只读的待确认项；另加“当前流程”摘要（流程名、当前步骤、自动获取进度），点击跳到聊天中的流程进度卡片。

### 3.3 过程

原面板下部内容：智能体完整过程（`AgentBlockView` 列表），行为不变（自动折叠、展开全部、定位）。

## 4. 预览

| 类型 | 方式 | 限制 |
|---|---|---|
| 图片 | `<img>` 加载内容接口；可缩放、适应宽度 | 单个不超过 50 MB；SVG 只用 `<img>` 显示（脚本不会执行） |
| PDF | 内嵌显示 | 运行环境不支持内嵌 PDF 时显示提示与“用系统程序打开” |
| 文本类 | 等宽显示，自动识别 UTF-8 / GBK | 不超过 1 MB，超出只显示前 1 MB 并提示 |
| CSV | 表格（前 200 行、列宽自适应） | 不超过 5 MB |
| 矢量、栅格 | 信息卡：坐标系、范围、要素数或波段与分辨率、字段与前 5 条样本；缩略图（由 QGIS 渲染） | 需要已连接 QGIS；未连接时显示“连接 QGIS 后可查看数据信息”；结果按文件修改时间缓存 |
| 流程运行记录 | 结构化摘要 | — |

预览头部：文件名、来源、返回列表、放大、打开、在文件夹中显示、复制路径；矢量、栅格另有“加载到 QGIS”。在网页中交互式浏览矢量数据（GeoCode 用 OpenLayers 做了地图、表格、原始三种模式，超过 5000 个要素改为表格）列为后续可选项（README §8 第 22 项）。

## 5. 后端：会话文件索引

### 5.1 两个来源

1. **登记**：产生文件的环节主动登记，带上来源信息，可以覆盖会话目录之外的文件（工程目录、数据仓）。
2. **扫描**：读取时扫描会话目录的 `exports/`、`output/`、`intermediate/`、`flows/`，补上没有登记的文件（例如脚本直接写出的文件）。

两者按规范化后的绝对路径合并，登记信息优先。

### 5.2 登记点

| 环节 | 位置 | 记录 |
|---|---|---|
| 工具成功返回 | `internal/websocket/task_runner.go` `consumeEvents` 中工具消息判定为成功处（约第 581–596 行） | 从结果文本 JSON 与文件部件（`toolresult.AppendFileURL` 的 `extra.path`）中提取路径；工具名、显示名、调用编号、所属智能体 |
| 工具声明（可选，更精确） | 工具 YAML 新增可选 `spec.artifacts`，如 `[{field: path, role: deliverable}]` | 指定结果中的哪些字段是产物、是否为成果 |
| 流程步骤完成 | `internal/flowrun/controller.go` `handleResult` 核验通过后 | 文件、文件夹、数据集类产出；流程运行编号、步骤、产出名称；成果类产出标为成果 |
| 自动获取完成 | `03` §9 绑定时 | 来源编号、许可、数据仓位置 |
| OSM 下载 | `07` §4.3 | 来源记录文件一并登记 |
| 路线知识执行器 | 数据集目录 | 数据集（文件夹） |

只登记位于允许根目录下、真实存在的普通文件或目录：本会话目录、当前工程目录、`<AUTOCARTO_HOME>/data/acquired/`。用户提供的输入文件不登记为产出。

### 5.3 存储

`<会话目录>/files.index.json`：

```json
{
  "version": 1,
  "items": [
    {
      "id": "f_3b1c…",
      "path": "/…/exports/成果图.pdf",
      "kind": "pdf",
      "group": "deliverable",
      "members": [],
      "origin": {"type": "tool", "tool": "export_layout_pdf", "label": "导出版面 PDF", "call_id": "…", "agent": "cartographer"},
      "flow_run_id": "fr-…",
      "step_id": "s11",
      "registered_at": "2026-10-24T08:00:00Z"
    }
  ]
}
```

- `id` 为规范化路径的 sha256 前 16 位，加 `f_` 前缀。
- 写入用临时文件替换，按会话加锁；损坏时备份后重建（扫描结果仍可用）。
- 不随会话导出包携带绝对路径之外的任何数据；会话导出（`/sessions/{id}/export`）是否附带此文件按现有导出规则处理，路径为本机绝对路径，导入时只作参考。

### 5.4 分类与合并显示

- **类型**按扩展名：`image`、`pdf`、`vector`、`raster`、`table`、`text`、`json`、`qgis_style`、`qgis_layout`、`archive`、`run`、`folder`、`other`。
- **分组**按登记角色与位置：成果（登记为成果，或位于 `exports/` 的图片与 PDF）、数据（矢量、栅格、表格）、流程运行（`run.json`）、中间文件（`intermediate/`）、其他（`logs/`、脚本、`temp/`）。
- **多文件数据集合并**（参考 GeoCode `utils/geo-tree-filter.ts`）：同一目录、同名主文件存在时，把附属文件并入主文件一行——Shapefile（`.shx`、`.dbf`、`.prj`、`.cpg`、`.qix`、`.sbn`、`.sbx`、`.fix`、`.shp.xml`）、栅格（`.tfw`、`.ovr`、`.aux.xml`、`.hdr`）、MapInfo（`.dat`、`.map`、`.id`；`.mid`）、GML（`.gfs`）、GeoPackage（`-wal`、`-shm`）、QGIS 附带的 `.qml`/`.qmd`、本系统的 `.source.json`。主文件不存在时附属文件单独显示。
- **排除**：`session.json`、`runtime_snapshot.json`、事件序号文件、`snapshots/`、`*.lock`。

### 5.5 接口（`project_path` 参数与现有会话接口一致）

| 接口 | 作用 |
|---|---|
| `GET /api/sessions/{id}/files?project_path=&all=0` | 列表（登记 + 扫描合并、分类、分组、数据集合并、存在性、新文件判断所需的登记时间） |
| `GET /api/sessions/{id}/files/{file_id}/content?project_path=` | 预览内容流；`?download=1` 时作为附件 |
| `POST /api/sessions/{id}/files/{file_id}/inspect?project_path=` | 调用 QGIS 端 `geodata_inspect` 返回数据信息 |
| `POST /api/sessions/{id}/files/{file_id}/thumbnail?project_path=` | 调用 QGIS 端 `geodata_thumbnail` 生成缩略图，写入 `<会话目录>/temp/previews/`，返回内容地址 |
| `POST /api/sessions/{id}/files/{file_id}/load?project_path=` | 在会话绑定的 QGIS 实例中加载（`data_load_vector`/`data_load_raster`，复用已加载的同源图层） |

WebSocket 新增消息 `session_files_changed`（`{session_id, added, updated}`），登记后去抖 500 毫秒推送；前端收到后重新拉取列表。

### 5.6 安全

- 只接受索引中存在的 `file_id`；读取前重新规范化路径（解析符号链接），确认仍在允许根目录内。
- 内容接口按类型白名单与大小上限返回；响应头 `X-Content-Type-Options: nosniff`、`Content-Security-Policy: default-src 'none'`、`Cache-Control: private`（与知识审查素材预览接口 `handlePreviewKnowledgeReviewAsset` 相同）。
- 不提供删除、改名、写入接口（本轮文件区只读）。
- “打开”继续使用 `open_local_path`；新增 Tauri 命令 `reveal_local_path`（macOS `open -R`、Windows `explorer /select,`、Linux 打开所在目录），复用 `local_output.rs` 的同一套路径校验。

### 5.7 智能体侧

`output_get_info` 改为返回会话文件索引的摘要（按分组的文件清单与来源），不再只列 `output/` 第一层；参数与返回结构向后兼容（保留原字段）。

## 6. QGIS 端工具（F61）

| 工具 | 作用 | 说明 |
|---|---|---|
| `geodata_inspect` | 读取矢量或栅格文件信息：格式、图层（GeoPackage 列出全部图层）、坐标系、范围、要素数或尺寸与波段、字段类型、前 N 条样本、无数据值 | 不加载到工程；对应 GeoCode 的 ReadGeoData 元数据模式；也供 OSM 下载与自动获取核验使用 |
| `geodata_thumbnail` | 用 QGIS 渲染一张 PNG 缩略图（默认 512 像素，简单默认符号；栅格按 2%–98% 拉伸） | 不修改工程；输出到调用方给定的会话临时目录 |

## 8. 验收要点

1. 默认 1200 像素窗口：打开工作区后聊天区不少于 420 像素；900 像素窗口：面板以抽屉方式出现，不挤压聊天区。
2. 导出 PDF、下载 OSM 数据、流程产出的成果，都在文件页签出现在正确分组，并显示来源；Shapefile 只显示一行。
3. 图片、PDF、CSV、文本可在应用内预览；矢量、栅格在连接 QGIS 时显示信息与缩略图，可一键加载到 QGIS。
4. 内容接口拒绝索引外的文件、越界路径与不在白名单的类型；响应头符合 §5.6。
5. 新文件角标计数正确；流程结束时的切换规则符合 §3.1。
6. 原“详情与任务”的任务、待确认与过程功能在“任务”“过程”页签中全部保留，原有测试改写后通过。
