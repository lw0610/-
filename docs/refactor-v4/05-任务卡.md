# 05 任务卡

每张卡可以单独交给一个执行智能体。交付时附上本卡、`README.md`，以及卡中“必读”列出的文档。

通用要求（每张卡都适用，不再重复）：
- 遵守 `README.md` §6 与 v2、v3 `README.md` §6 的全局约束；开工前对照 §3 文件归属表，确认要改的文件没有被进行中的任务占用。
- 完成后写 `docs/refactor-v4/evidence/<任务号>.md`（格式见 `docs/refactor-v3/evidence/README.md`），在 `refactor/v4` 分支提交（提交信息以任务号开头，不推送）。
- 命令约定：Go 命令在 `carto_agent/` 下执行；前端命令在 `autocarto-web/` 下执行；Python 命令在仓库根执行，`$PYTHON_BIN` 指能导入 QGIS 的解释器（见 `build.sh`），`test_*_qgis.py` 每个模块单独进程运行。
- 测试一律使用临时运行目录，不读写真实 `autocarto_data/`；不访问真实网络——网络适配器用本地假服务器和小样例数据测试。真实联网测试只在设置 `AUTOCARTO_LIVE_ACQUIRE=1` 时运行，默认跳过，跳过不算通过。
- “Zttzt 结构夹具”：测试中新建的方案，角色与工具包与用户方案 `Zttzt` 相同——编排智能体（主角色）、数据工程专家（`data-loading`）、制图布局专家（`cartography-styling`、`print-layout`、`route-cartography`）、脚本与高级数据专家（已禁用）、空间分析专家（已禁用）；共享工具包 `vector-selection`；没有知识抽取执行器和质量反馈角色。由 F00 建立在 `carto_agent/internal/testutil/`，后续卡只追加。
- 新增兼容层时在 `carto_agent/defaults/architecture/removal_ledger.yaml` 追加条目，并跑 `go test ./internal/control -run TestCompatLayerRequiresRemovalCriteria -count=1`。
- 方案中标“需核实”的外部事实（网址、主机、许可、字段名、配额、体量），由负责该来源的卡在实施前核实，结果写入验证记录；无法核实的来源在目录中标 `status: experimental`，规划器在说明中显示“实验性来源”。

## F00 分支、基线与测试夹具

- **目标**：建立 v4 分支、基线，以及复刻问题现场和离线获取测试所需的夹具。
- **必读**：`README.md`
- **涉及范围**：git 操作；`internal/testutil/`；`docs/refactor-v4/evidence/F00.md`。
- **步骤**：
  1. 确认用户已提交 `refactor/v3` 上的未提交改动；未提交时停止并报告。
  2. 从 `refactor/v3` 最新提交新建 `refactor/v4`；运行 `./build.sh check` 并记录。
  3. 夹具：Zttzt 结构方案、只含主角色的最小方案；本地假 HTTP 服务器（可按路径返回文件、模拟 429/超时/重定向）；小样例数据（一个小 `.osm` 文件、一个小 Shapefile 压缩包、一个小统计 CSV），全部为合成或可再分发数据并注明来源。
  4. 记录基线：四个内置流程在 Zttzt 结构夹具下的计划诊断码。
  5. 打本地标签 `v4-baseline`。
- **验收**：分支、标签存在；夹具可被其他包导入；记录写明 check 结果与基线诊断。
- **测试**：`./build.sh check`；`go test ./internal/testutil/... -count=1`
