# 04 界面与编排规范

本文件规定用户在哪里看到角色解析与数据获取、怎样修改，以及编排智能体在对话中的行为。后端结构见 `01`、`02`、`03`。对话页右侧“会话工作区”（文件、任务、过程三个页签）与会话文件接口见 `08`；OSM 工具链及其扩展服务开关见 `07`。

## 1. 接口（字段只增不删，`X-AutoCarto-Contract-Version` 仍为 `v1`）

| 接口 | 变化 |
|---|---|
| `GET /api/flows?scheme=` | `FlowSummary` 增加 `roles`（方案角色、临时补齐、流程自带、系统执行器、未解析、仅条件未解析的数量）与 `data`（数据需求数、可自动获取条目数） |
| `GET /api/flows/{id}?scheme=`、`PUT /api/flows/{id}` | 计划带 `role_slots`、`flow_roles`、步骤角色字段（`01` §5）、`requirements` 与静态获取计划（`02` §6.8），隐式获取步骤 |
| `POST /api/flows/{id}/inputs/check` | 接受 `02` §7.1 的取值形式；返回问题项（含 `step`、`acquirable`）和按本次输入计算的获取计划 `acquisition_plan` |
| 新增 `GET/PUT /api/flows/{id}/roles?scheme=` | 角色对应（`01`）；写入方案 `flow_policy.role_mapping` |
| 新增 `GET /api/data-sources` | 内置与用户数据源、可用性与原因、提供的类别 |
| 新增 `POST/PUT/DELETE /api/data-sources/user/{id}` | 用户登记的本机数据源（只允许 `user.` 前缀） |
| 新增 `POST /api/data-sources/scan` | 扫描一个文件夹或数据清单，生成本机数据源草稿（只读扫描，不保存） |
| 新增 `GET /api/data-store`、`DELETE /api/data-store/{key}` | 数据仓条目、体量、来源、获取时间、被哪些运行使用；删除需确认 |
| 新增 `GET /api/data-categories` | 类别词表（显示名、别名、几何、标准字段） |
| 方案、模型、配置读写接口（现有） | 透传 `flow_policy`、模型 `vision`、`acquisition` 配置 |
| 会话文件接口 | 见 `08` §5.5（列表、预览内容、数据信息、缩略图、加载到 QGIS） |
| 扩展服务配置（现有） | 增加 `integrations.osm`（`07` §4.4），设置页“扩展服务”增加“OpenStreetMap 数据”一行与连通性检查 |

写方案、写配置必须经过现有设置变更服务；不得直接写 YAML。上述接口都不联网、不调模型。

## 2. 对话页流程表单

涉及 `autocarto-web/src/features/flow-run/FlowComposer.tsx`、`useFlowComposer.ts`、`model.ts`、`types.ts`、`src/features/flows/types.ts`、`api.ts`。

### 2.1 来源方式

| 输入 | 选项 |
|---|---|
| 有单个数据需求的文件或图层输入 | 我来提供 / 自动获取（可选输入另有“不提供”） |
| 关联清单需求的文件夹输入 | 我来提供 / 提供文件夹并补齐缺项 / 自动获取 |
| 没有数据需求的输入 | 不变 |

- 默认来源方式按 README §8 第 6 项；记忆中上次选了自动获取或补齐时预选该方式（`02` §7.3）。
- 选择“提供文件夹”后，即时检查发现缺失必需文件时，不只报错，同时提示“缺少 3 项，可自动补齐”，一键切到补齐。
- 有两个及以上可获取输入时，顶部提供“没有的数据都自动获取”。

### 2.2 获取计划面板

选择自动获取或补齐后，在该输入下展开获取计划（来自 `inputs/check` 的 `acquisition_plan`），形式见 `06` §6：

- 每个条目一行：名称、计划来源、注意事项（近似、需登录、署名、取舍）、数据仓命中（“将复用 10 月 24 日获取的数据”）；
- “换来源”下拉列出备选及其层级、许可、体量；不可用的备选灰显并显示原因；
- “我来提供”为该行选择文件，提交到 `files`；
- 范围与比例尺显示在面板顶部；范围待定时写“第 N 步完成后确定范围”；
- 整个面板底部显示预计下载体量（估计值）；
- 条目不可用时，显示原因与修复入口（“去启用扩展服务”“配置天地图 Key”“改为我来提供”）。

### 2.3 提交

- `prepareFlowSubmission` 按 `02` §7.1 生成取值：`{"$acquire": true}`、`{"path": "...", "$fill": true}`，以及 `sources`、`files`；
- 自动获取所需的输入（范围、层级、参数）标为“自动获取需要”，未填即时报错；
- 发送前检查与即时检查使用同一接口；切换来源方式、换来源、单项提供都属于输入变化，沿用 v3 的过时发送防护。

### 2.4 运行进度

涉及 `FlowProgressCard.tsx`、`model.ts` `applyFlowEvent`：

- 系统获取步骤显示为“获取数据：<需求名>”，展开后逐条目显示状态（等待范围、下载中 xx%、规范化、核验、已复用、已完成、失败）和来源；
- 处理事件 `flow.acquire_planned`、`flow.acquire_progress`、`flow.acquire_item_done`、`flow.acquire_failed`；
- 条目失败等待用户时，显示 `03` §11 的选项：重试、换来源、我来提供（文件选择）、跳过（仅可选行）、停止；
- 完成摘要中的“自动获取的数据”与合规提示原样显示。

## 3. 流程中心

涉及 `autocarto-web/src/features/flows/FlowWorkspace.tsx`、`PreviewPanels.tsx`、`api.ts`、`types.ts`。

### 3.1 步骤预览

- 负责角色显示“名称 + 来源标记”：方案角色 / 方案角色（已指定）/ 按工具包匹配 / 临时补齐：<工具包> / 流程自带 / 系统默认执行器 / 无法执行：<原因>（条件步骤加“仅在条件满足时需要”）。
- 系统获取步骤显示为“系统步骤：获取数据（仅在自动获取或补齐时执行）”。

### 3.2 数据需求页签

只读展示每个数据需求：绑定的输入或清单、范围、比例尺、条目（类别、几何、字段要求）、各条目的候选来源类型与当前可用性。清单行没有类别时提示“该行只能由用户提供；填写类别后可自动获取”，并链接到清单编辑说明。

### 3.3 角色对应页签

按当前方案列出参与角色、所需工具包、当前对应、选择（自动 / 方案角色 / 流程自带角色）；保存调用 `PUT /api/flows/{id}/roles`。修复动作 `map_role` 打开此页签。

## 4. 方案设置

涉及 `autocarto-web/src/components/settings/AgentFlowSelection.tsx` 与方案类型：

- 每个流程行显示状态：“可运行”“自动补齐 N 项”“部分步骤有条件限制”“有错误”，以及“可自动获取数据”；点击打开流程中心对应页签。
- 方案策略（写入 `flow_policy`）：

| 设置 | 选项 | 默认 |
|---|---|---|
| 流程缺少角色或能力时 | 自动补齐（推荐）/ 使用流程自带角色，不改方案角色 / 不补齐，提示我修改方案 | 自动补齐 |
| 对话中流程缺少数据时 | 先问我 / 自动获取 / 不自动获取 | 先问我 |

“不自动获取”同时关闭表单中的自动获取与补齐。

## 5. 模型设置

`ModelConfigWorkspace.tsx`：每个模型增加“支持读图（图片输入）”。

## 6. 数据获取设置（新页面，F33）

位于“设置”中，与“扩展服务”相邻。

### 6.1 数据源

- 内置数据源列表：名称、种类、提供的类别、合规标签、许可、当前可用性与原因（未启用扩展服务、缺 Key、需登录）。只读。
- 本机数据源：新增、编辑、删除。新增时选择一个文件夹或已有数据清单，`/api/data-sources/scan` 生成草稿，用户逐行确认类别和字段映射后保存。
- 获取配置：下载上限、数据仓容量、自动换源、联网搜索（默认关闭，开启时说明“每次使用前确认”）。

### 6.2 数据仓

列表：类别、来源、范围摘要、获取时间、体量、过期时间、被哪些运行使用；支持删除与按过期清理；顶部显示已用容量与上限。

## 7. 编排智能体

### 7.1 可用流程摘要（`internal/websocket/flow_runtime.go:463` `injectAvailableFlows`）

- 每个输入摘要增加 `acquirable`（有数据需求）、`acquire_available`（当前至少一种方式可用）、`modes`（可用的来源方式：`auto`、`fill`）。
- 系统消息按方案的 `flow_policy.auto_acquire` 追加规则：

| 策略 | 规则要点 |
|---|---|
| `ask` | 可获取的输入缺失、且用户没有明确表态时，只问一次“由您提供，还是由我自动获取”；用户表示没有数据、让系统找、无所谓时，传 `{"$acquire": true}`；用户给了文件夹但不完整时，传 `{"path": …, "$fill": true}` |
| `allow` | 可获取的输入缺失时直接传 `$acquire`，启动后说明哪些数据将自动获取、来自哪里 |
| `deny` | 不传 `$acquire`、`$fill`；缺失的必填输入照常询问 |

- 所有策略共同：`acquire_available=false` 的输入不得传 `$acquire`；不得编造路径；不得自行指定来源编号（`sources` 只由表单设置）；用户已给出数据时优先使用用户数据。
- 规则由系统消息和 `flow-control` 工具包说明提供，不依赖用户方案里的编排提示词，因此对已有方案同样生效。

### 7.2 预览与启动

- `flow_preview` 返回各输入的数据需求、按本次输入计算的获取计划摘要（每项来源与不可用原因）以及缺失项（带 `acquirable`）。
- `flow_start` 透传取值形式（`internal/runtimecontrol/flow_tools.go`、`flow_runtime.go` `StartFlow`）；返回结果增加 `acquire`（将自动获取的条目与来源摘要），供编排智能体在回复中说明。
- 更新 `autocarto/tools/system/runtime-control/flow_start.yaml` 参数说明、`autocarto/skills/system/flow-control/SKILL.md` 规则段；默认方案编排提示中“必填输入缺失时，先询问用户”改为“必填输入缺失时，可自动获取的按可用流程说明处理，其余先询问用户”。
