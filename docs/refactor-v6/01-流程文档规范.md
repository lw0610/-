# 01 流程文档规范

## 1. 定位

流程是一份写给大模型看的 Markdown 文档：做什么图、需要哪些图层、每层怎么处理、用哪个样式和版面、出什么成果、要注意什么。它像一份给同事的制图说明，而不是一张需要程序逐格解析的表。

程序只从流程中读两样东西：

1. **头部**：名称、说明、版本——用于列表、搜索和让大模型判断是否使用这份流程；
2. **`「名称」` 形式的样式与版面引用**——用于在详情页显示引用的资源及预览、生成依赖锁定、导出时附带资源、做引用检查。

其余内容全部交给大模型理解。

## 2. 存放

| 项目 | 规则 |
|---|---|
| 位置 | 内置 `autocarto/flows/system/<编号>/`，用户 `<AUTOCARTO_HOME>/flows/<编号>/`（沿用现有存储、导入导出、版本管理） |
| 文件 | `FLOW.md`（README §8 第 1 项）；系统生成的 `flow.lock` |
| 不再有 | `resources/` 子目录（数据清单、符号、路线样式、参考文档按 `02` §6 迁走）；数据文件 |

## 3. 写法

### 3.1 头部

```markdown
---
名称: 行军路线图
说明: 根据史料或已整理的路线数据集，制作带路线、专题符号、图文标注和完整版面的行军路线专题图。适用于“行军路线图”“战役路线示意图”“长征路线图”等请求。
版本: 5.0.0
---
```

`说明` 写清“什么请求适用”，不超过 300 字。编号取目录名。

### 3.2 正文（建议结构，不强制）

```markdown
# 行军路线图

## 什么时候用
……

## 需要的图层与处理
- 省级行政区（面）：作为底图，显示省名，样式「省域面」。
- 河流线（线）：显示河名，样式「河流线」。
- 路线：从史料抽取路线数据集后绘制，保留主线、分支和汇入方向；路线样式用“红蓝对比”。
……

## 做法
1. ……
2. ……

## 版面
使用版面「四角对齐版式」，纸张默认 A1 横向……

## 成果
导出以地图标题命名的 PDF……

## 注意事项
……
```

### 3.3 写作要求

| 要做 | 不要做 |
|---|---|
| 把需要的每个图层写清楚“是什么数据”（行政区面、河流线、道路……）和大致范围，便于自动获取 | 不写文件路径、数据清单、数据来源编号——数据在运行时确定（`03`） |
| 写清每个图层怎么处理、用哪个样式、标注什么 | 不写负责角色、步骤负责人 |
| 样式与版面用 `「名称」`，名称与资源库一致 | 不写工具名与工具参数 |
| 可选部分写清何时需要（“用户要求质量检查时才做”） | 不写执行条件语法、失败策略 |
| 默认值直接写在正文（“纸张默认 A1 横向”） | 不做输入表单 |

可以用 Markdown 表格帮助阅读（例如列出底图图层），但程序不会解析它。

## 4. 程序如何读取

### 4.1 头部与引用

- 解析头部 YAML；缺 `名称` 或 `说明` 时提示。
- 引用识别：`样式「X」`、`版面「X」`、`版式「X」`，以及任何与资源库中样式或版面同名的 `「X」`。按名称在资源库中查找（内置与用户，名称唯一）。

### 4.2 提示（只提示，不阻止保存和使用）

| 代码 | 条件 |
|---|---|
| `FLOW_META_MISSING` | 头部缺少名称或说明 |
| `FLOW_RESOURCE_NOT_FOUND` | `样式「X」` / `版面「X」` 在资源库中找不到 |
| `FLOW_RESOURCE_AMBIGUOUS` | 同名资源有多个（导入时应已避免，`02` §4） |
| `FLOW_ROLE_MENTION` | 出现“负责”“参与角色”等写法 |
| `FLOW_PATH_MENTION` | 出现本机绝对路径（数据位置不写进流程） |

内置流程必须没有任何提示（L50 守卫）。

### 4.3 锁定与导出

- 保存时根据识别出的引用自动生成 `flow.lock`（资源编号、版本、摘要），沿用现有锁定逻辑，只是来源从“使用的资源”章节改为正文引用。
- 导出时附带被引用的样式与版面（含预览）；导入时同编号同摘要复用本机资源，否则保留随包副本并提示（沿用 v3 规则）。

### 4.4 交给大模型

沿用 v5 的指南技能后端（`internal/deepagent/subagents/guide_backend.go`）：

- 列表只给名称与说明；
- 读取全文时，在正文后附“引用的样式与版面”摘要：名称、类型、适用几何（点 / 线 / 面）、样式的标注字段说明、版面的纸张与元素说明。

## 5. 界面

“流程”页（v5 的指南库）：

| 区域 | 内容 |
|---|---|
| 列表 | 名称、说明、版本、内置 / 用户、是否停用；搜索 |
| 详情 | **只有一页**：渲染后的正文；右侧“引用的样式与版面”，每项一张缩略图，点开看大图与说明；提示列表（如有） |
| 编辑 | Markdown 编辑与实时预览，下方显示提示；内置流程只读，可复制为用户流程 |
| 操作 | 在对话中使用（带上 `/流程` 标签跳到对话）、复制、导出、导入、停用、删除（用户流程） |

删除 v5 详情页的七个页签（适用任务与信息、数据、图层处理、制作要点、版面要求、产出与检查、资源）。

## 6. 迁移

### 6.1 v5 结构化指南 → 流程文档

| v5 章节 | 改写为 |
|---|---|
| 头部 | 头部（版本主号加一） |
| `## 适用任务` | `## 什么时候用` |
| `## 需要明确的信息` | 写进相关段落的默认值说明（如“纸张默认 A1 横向”） |
| `## 数据` 表 + `## 图层处理` 表 | 合并为 `## 需要的图层与处理`：每个图层一条，写清是什么数据、范围、怎么处理、样式、标注；“由某能力产生”的数据写清产生方式 |
| `## 制作要点` | `## 做法`（保留原文，删去“需要的能力”“本阶段产出”的固定写法，改成自然语句） |
| `## 版面要求` | `## 版面` |
| `## 产出与检查` | `## 成果`（检查项写成自然语句） |
| `## 使用的资源` | 删除；样式与版面在正文中以 `「名称」` 出现即可；数据清单、符号、路线样式按 `02` §6 处理 |
| `## 注意事项` | 保留 |

### 6.2 执行

- **内置流程**：四份由 L11 按 `05` 范本手工改写。
- **用户流程**：启动时自动转换（v5 `GUIDE.md` 或 v4 `FLOW.md` 均可），原文件备份为 `*.bak`，详情页提示“已自动转换，请检查”；可重复执行。
- 转换时，流程 `resources/` 中的数据清单内容写入“需要的图层与处理”（文件名不写入，只写图层名与说明），符号与路线样式按 `02` §6 迁走后在正文中按名称引用。
