# 04 任务卡

每张卡可以单独交给一个执行智能体。交付时附上本卡、`README.md`，以及卡中“必读”列出的文档。

通用要求：
- 遵守 `README.md` §6 及 v5 `README.md` §7 中仍适用的约束；开工前对照 §3 文件归属表。
- v5 新增文件的实际名称以用户工作目录中的代码为准；与本卡不同时照实际修改，并在验证记录中写明对应关系。
- 完成后写 `docs/refactor-v6/evidence/<任务号>.md`（格式见 `docs/refactor-v3/evidence/README.md`），在 `refactor/v6` 分支提交（提交信息以任务号开头，不推送）。
- 命令约定：Go 命令在 `carto_agent/` 下执行；前端命令在 `autocarto-web/` 下执行；Python 命令在仓库根执行，`$PYTHON_BIN` 指能导入 QGIS 的解释器，`test_*_qgis.py` 每个模块单独进程运行。
- 测试使用临时运行目录，不读写真实 `autocarto_data/`，不访问真实网络；模型行为用脚本化测试模型模拟。

## L00 基线

- **目标**：在可回滚的基础上开始 v6，并记录 v5 实际实现的文件位置。
- **必读**：`README.md`
- **步骤**：
  1. 请用户确认提交 v5 的实施结果（或明确授权本卡提交）；未确认时停止。
  2. 从该分支建 `refactor/v6`；运行 `./build.sh check` 并记录。
  3. 记录：v5 指南解析、指南接口、指南页面、资源库页面、计划卡、数据服务的实际文件路径（供后续卡对照）；资源库现有资源清单（按类型统计，内置与用户分别列出）；四份内置流程引用了哪些资源。
- **验收**：分支存在；记录完整。
- **测试**：`./build.sh check`

## L10 后端：流程只读头部与引用

- **目标**：程序只从流程读取头部和样式、版面引用。
- **必读**：`01` §2–§4
- **涉及范围**：v5 指南解析（`internal/flow/guide*.go` 等）：删除对固定章节、数据表、图层处理表、“需要明确的信息”、产出与检查的解析与诊断，只保留头部与引用识别、`01` §4.2 的五种提示；`store.go`（文件名按 README §8 第 1 项，兼容读取 `GUIDE.md`）；`lock.go`、`export.go`、`import.go`（锁定与导出依赖改由正文引用生成）；`guide_backend.go`（全文后附引用的样式与版面摘要）；指南接口返回正文、引用列表（含资源编号、类型、预览地址）与提示；测试。
- **验收**：`05` §1 全文零提示；五种提示各有正反测试；保存时 `flow.lock` 只含正文引用的样式与版面；导出包附带这些资源；读取全文时附引用摘要；接口不调模型、不联网。
- **测试**：`go test ./internal/flow/... ./internal/deepagent/... ./internal/api/... -count=1`

- **验收**：详情页无页签；引用资源可点开；编辑保存后提示即时更新；内置流程只读、可复制。

## L20 资源只留样式与版面并迁移

- **目标**：资源库只剩样式与版面；其他类型有明确去处。
- **必读**：`02` §1、§2、§6
- **涉及范围**：`internal/resource/formats/resource_formats.yaml`（只保留 `style`、`layout` 供资源库）；资源清单增加说明字段（适用几何、标注字段、版面元素）；迁移程序：拆分内置“国标底图样式”为 11 个样式、拆分用户样式集、路线样式与符号迁为工具预设（内置迁入 `autocarto/tools/system/route-cartography/assets/resources/`，用户迁入 `<AUTOCARTO_HOME>/presets/route-cartography/`）、数据清单与参考文档的内容交给 L12 写入流程正文；名称唯一性检查；资源库接口只返回两类；迁移报告；`removal_ledger.yaml` 登记旧类型；测试。
- **验收**：资源库接口只有样式与版面；11 个拆分样式的名称、标注字段说明正确；路线工具能按名称找到“单色”“红蓝对比”“军标”“图例”；迁移前有完整备份、可重复执行；名称冲突按 `02` §4 处理。
- **测试**：`go test ./internal/resource/... ./internal/api/... ./internal/control -run TestCompatLayerRequiresRemovalCriteria -count=1`

## L30 数据确定规则与 `data_find` 对应用户文件夹

- **目标**：用户给了就用，没给才获取；数据需要由大模型从流程正文读出。
- **必读**：`03` 全文
- **涉及范围**：`internal/dataservice/`（描述为主的 `need`、`provided` 对应、删除清单模式）；`internal/plan/validate.go`（`data[].layer`、`data[].style`，`PLAN_STYLE_NOT_FOUND`、`PLAN_FLOW_STYLE_UNUSED`、几何不符提示）；`internal/websocket/plan_runtime.go`（注入 `03` §4 的规则，替换依赖结构化章节的规则）；默认方案编排提示；测试（脚本化模型）。
- **验收**：
  1. 用户消息给出路径、附件、@图层时，计划中对应数据为用户提供，没有获取步骤。
  2. 用户给出文件夹时，`provided` 对应结果正确，未对应项进入自动获取；用户文件夹不被写入。
  3. 流程引用的样式在计划中没有图层使用时，计划校验退回警告。
  4. `data_find` 不联网、不调模型。
- **测试**：`go test ./internal/dataservice/... ./internal/plan/... ./internal/websocket/... -count=1`
