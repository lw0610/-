## 统一后的执行链

1. 首轮直接读取已安装 flow-control 手册作为唯一规划契约，注入精简的能力 ID 和数据类别约束；不把全部执行工具名混进能力目录。目录或契约缺失时在模型调用前明确失败。
2. data_find 返回已有、可直接获取、待探索、需补输入或无来源的状态。真实探索候选可写入原有 acquire 步骤；不要求在提交计划前另行下载。
3. 选择冻结为 Selection，包含同次查询、参数、范围与候选。需要上游数据确定范围时，先通过同一范围解析器解析并保存 bbox，HITL/重启不重新读取已变化的上游文件。已有本地文件和图层仍允许不指定下载范围。主模型不重复发现，执行器把同一份选择、事实和已核验的上游输入交给系统数据专家。
4. 直接获取与探索获取共用原有 flowrun 控制器、步骤结果、等待与恢复。探索结果必须 data_register；控制器按查询和行核对回执与文件哈希，模型消息中的路径不能冒充完成。
5. 探索无登记时明确进入失败处理，不自动再拉起同一个专家。模型的计划输入修正最多 3 次；成功退出规划回合，新回合有独立预算，HITL 恢复保留本回合预算。
6. 修订计划注销旧等待；尝试编号包含计划版本；旧断点在恢复前、旧完成回调在锁内均核对身份。

## 清理与兼容

- 删除从整个指南文本推导“全部样式都必须使用”的逻辑，只校验本次计划实际引用。
- 分离 Data.name（显示名称）与 Data.output（上游产出标识）。统一引用规范化：旧 name 引用兼容；单产出可以确定性绑定；获取步骤引用展开为明确的数据 ID；多产出缺少选择、未知引用或前向依赖仍报具体诊断，不猜测。
- 统一 HITL 回答解析，删除各处对 option / selected / value 的手工不一致判断。
- 去掉“会话最新查询”隐式绑定；独立数据专家用 data_get 明确绑定，计划执行使用被冻结的查询。
- 查询 TTL 只约束未绑定的发现；已确认计划和暂停恢复沿用原查询，避免为了续期重新发现。
- 浏览器、网页传输和搜索分别判断。已知门户可通过浏览器探索；网页读取/下载可服务于该门户；关闭搜索仍不允许 web_search。
- 门户目录的 experimental 表示缺少确定性自动适配器；明确的浏览器探索可使用它，其他目录前提仍需满足，禁用来源不能被重新标为可用。
- 去掉 what.category 与 description 的无谓互斥：至少一项，允许共存，显式 category 为分类权威，description 保留说明，未知类别不被静默替换。探索结果使用 DATA_EXPLORATION_REQUIRED，避免一边提供可用门户、一边报告“没有可用来源”。
- 前端来源摘要、详情和编辑统一解析，探索途径明确标为“探索获取”。
- DeepSeek 官方端点显式发送 thinking.type，并使用 max_tokens；未改变用户模型配置，未推测其他兼容端点协议。
