## 1. 三个概念，各管一件事

| 概念 | 管什么 | 是什么 | 谁来理解 |
|---|---|---|---|
| **流程** | 做什么、怎么做 | 一份 Markdown 文档：做什么图、需要哪些图层、每层怎么处理、用哪个样式和版面、出什么成果 | 大模型阅读 |
| **资源** | 画成什么样 | 只有两类：**样式**（单个图层的 QML）和**版面**（打印版面模板），带预览，在流程里用 `「名称」` 引用 | 工具按名称加载 |
| **数据** | 画什么 | 不是资源，也不写进流程包。每次运行时由大模型从流程读出“需要哪些图层”，先找用户给的，没给才自动获取 | 大模型判断，数据服务获取 |

这三条边界之外的东西都不需要：流程里不再有数据清单、数据表、图层处理表、“需要明确的信息”、产出检查表；资源库里不再有样式集、数据清单、数据文件夹、路线样式、符号、参考文档。

## 2. 运行逻辑（核心）

```text
用户：“做一张河南省人口密度图，市界在 D:/data/henan_city.shp”
         │
① 选流程   大模型按流程的名称与说明匹配（或用户用 / 指定）→ 读取流程全文
         │
② 读需要   大模型从流程中读出需要的图层：市级行政区面、人口统计表（流程里写了“需要……”“加载……”）
         │
③ 找来源   对每个图层依次判断：
           a. 用户这次明确给了吗？（消息中的路径、附件、@图层）           → 市级行政区面：用户给了 D:/data/henan_city.shp
           b. 用户说用已有的吗？（“用工程里的”“用上次的”）              → 否
           c. 用户给的是文件夹吗？（交给 data_find 自动对应文件夹里的文件）→ 否
           d. 都没有 → 自动获取（data_find 查候选、按固定顺序选来源）     → 人口统计表：国家统计局（门户网站，需确认）
         │
④ 出计划   计划卡逐项写明来源：“市级行政区面：您提供”“人口统计表：自动获取（国家统计局）”；用户可一句话改
         │
⑤ 执行     用户提供的直接加载；需要获取的由数据服务获取（记录来源）；之后按流程处理图层、套用「样式」、按「版面」出图
```

要点：

1. **“需要什么”由大模型从流程正文读出**，程序不解析流程里的表格。流程作者把需要的图层写清楚即可（`01` §3 给出写法建议）。
2. **“用户给没给”由大模型从本次对话判断**，工具负责核验（文件是否存在、是不是需要的几何类型）。
3. **只有用户没给的才自动获取**，而且一律经过数据服务：候选与排序是确定性的，选择有理由，结果有来源记录（沿用 v5 方案 `docs/refactor-v5/03-统一数据服务规范.md`）。
4. **计划卡是唯一需要用户看的地方**：每个图层的来源一目了然，改来源只需一句话或点一下。

## 3. 相对 v5 的改动

| v5 | v6 |
|---|---|
| 指南按 7 个固定章节组织，程序解析数据表、图层处理表、需要明确的信息、产出与检查；指南详情页 7 个页签 | 流程是一份自由书写的 Markdown；程序只读头部（名称、说明、版本）和 `「名称」` 引用；详情页只有一页正文，旁边列出引用的样式与版面（带预览） |
| 数据表中的“可以来自”“范围”“字段”决定数据来源与获取 | 大模型从正文读出需要的图层，按 §2 的顺序确定来源；计划校验做轻量交叉检查（`03` §5） |
| 资源 8 类：样式、样式集、版式、数据清单、数据文件夹、路线样式、符号、参考文档 | 资源 2 类：样式、版面；都有预览；样式集拆成单个样式；路线样式与符号改为路线工具自带的预设；数据清单、数据文件夹、参考文档取消 |
| 标注字段写在数据清单或样式集对照表里，靠获取时改字段名对上 | 样式自带“标注字段”说明；套用样式时可指定实际标注字段（`layer_load_style` 增加 `label_field`），不再要求数据改字段名 |
| 文件名 `GUIDE.md`，界面叫“指南” | 界面统一叫“流程”；文件名见 §8 第 1 项 |

不变的部分：v5 的制图计划、计划卡、计划执行器（按能力选角色、回执与核验、失败重规划）、统一数据服务（`data_find` / `data_get` / `data_register`）、系统数据获取智能体、对话输入（附件、@图层、/流程）、会话工作区。

## 5. 验收标准

1. **Z1 流程是一份 md**：四份内置流程都是自由书写的 Markdown，没有数据表、图层处理表、角色与表单；流程详情页只有一页正文与引用资源列表。
2. **Z2 资源只有样式与版面**：资源库只显示这两类，每项都有预览，可按点、线、面、版面筛选与搜索；“国标底图样式”拆成 11 个单独样式，名称、标注字段说明齐全。
3. **Z3 用户给了就用**：消息中给出路径、附件、@图层或说明“用工程里的”时，计划中该图层来源为用户或工程，不发起获取。
4. **Z4 没给才获取**：流程需要、用户没给的图层，计划中来源为自动获取，并能说明选择理由；获取结果有来源记录。
5. **Z5 文件夹自动对应**：用户给一个文件夹时，能按名称与几何类型对应到需要的图层，对应不上的才获取，用户文件夹不被写入。
6. **Z6 引用一致**：流程中 `「名称」` 引用的样式与版面都能在资源库中找到；计划漏掉了流程中提到样式的图层时给出提示。
7. **Z7 不退化**：行军路线图真实 QGIS 离线验收（v3、v5 同口径）在新流程与新资源下复现，标注字段正确。
8. **Z8 门禁**：`./build.sh check` 通过。

## 6. 全局约束

在 v5 `README.md` §7 的约束基础上：

1. **开工前**：v5 的实施结果由用户确认提交后，从其分支建 `refactor/v6`；不替用户丢弃或覆盖未提交改动。
2. **程序不解析流程正文的结构**：除头部与 `「名称」` 引用外，不从流程中抽取表格或固定章节作为执行依据。
3. **数据不进资源库、不进流程包**：数据只来自用户、工程、会话或数据服务获取，并记录来源。
4. **资源迁移不丢内容**：样式集拆分、旧资源类型移出时，原文件备份保留；用户流程引用的旧资源有对应的新去处（`02` §6）。
5. **验证记录写在 `docs/refactor-v6/evidence/`**，提交信息以任务号开头（例如 `L20: 资源只留样式与版面`），在 `refactor/v6` 分支提交，不推送、不合并。
