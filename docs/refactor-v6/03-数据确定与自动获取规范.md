# 03 数据确定与自动获取规范

## 1. 原则

1. **需要什么，由大模型从流程正文读出**。程序不再从流程中解析数据表或数据清单。
2. **用户给了就用**：本次对话中明确给出的路径、附件、`@图层`，或明确说“用工程里的 / 用上次的”，一律优先。
3. **没给才自动获取**：只有找不到用户给的数据时，才经数据服务获取（v5 方案 `docs/refactor-v5/03-统一数据服务规范.md` 的 `data_find` / `data_get`，候选与排序确定、有理由、有来源记录）。
4. **结果一目了然**：计划卡逐个图层写明来源与样式，用户一句话或点一下就能改。

## 2. 四步

### 2.1 读出需要的数据（大模型）

大模型读完流程正文与用户消息后，列出本次需要的每一项数据：

| 项目 | 示例 |
|---|---|
| 名称（流程中的叫法） | 河流线 |
| 是什么 | 线状河流；需要显示河名 |
| 几何 | 线 |
| 范围 | 路线范围外扩 20%（来自流程）/ 河南省（来自用户） |
| 用途与样式 | 底图图层，样式「河流线」 |
| 是否由处理产生 | 否（路线数据集这类“由史料抽取”的写“是”） |

要求：流程中提到要加载、绘制、关联、裁剪的每一项数据都要列出，不能遗漏；流程写明“可选”“用户要求时才需要”的，按本次对话判断是否需要。

### 2.2 确定来源（大模型判断，工具核验）

对每一项依次判断，命中即停：

| 顺序 | 情况 | 来源 | 核验 |
|---|---|---|---|
| a | 用户本次明确给出：消息中的路径、附件、`@图层` | 用户提供 | 文件用 `geodata_inspect`、工程图层用 `get_layers_info` 核验存在与几何类型；不符时问用户 |
| b | 用户说“用工程里的”“用上次的”“用刚才生成的” | 工程图层 / 数据记忆 / 本会话文件 | 同上 |
| c | 用户给的是一个文件夹 | 文件夹中对应上的文件 | `data_find` 的 `provided` 参数自动对应（§3）；对应不上的项继续往下 |
| d | 用户没提，但工程里已有同类图层 | 工程图层（默认使用，计划卡注明） | 同 a；README §8 第 4 项 |
| e | 由流程中的处理产生（如“从史料抽取路线数据集”） | 由某一步产生 | 执行时核验产出 |
| f | 以上都没有 | 自动获取 | `data_find` 给出推荐候选与理由；不可用时说明原因并请用户提供 |

不确定用户的话是否指向某个数据时（例如只说“用我那份河流数据”但没有路径），问一次，不猜。

### 2.3 出计划（v5 计划卡）

每个数据一行：

```text
河流线      自动获取 · OpenStreetMap 在线查询（覆盖所需范围；适合 1:300 万）   样式「河流线」[缩略图]   [改]
省域        您提供 · D:/底图/省域.shp                                          样式「省域面」[缩略图]   [改]
路线数据集  由第 1 步产生（从史料抽取）
```

“改”的菜单与 v5 相同：换来源（`data_find` 候选）、我来提供（选文件）、用工程图层（选图层）。

### 2.4 执行

- 用户提供、工程、会话中的数据：直接使用，不复制，不写入用户目录。
- 自动获取：执行时经 `data_get` 获取，写入数据仓，登记到会话文件区，进入「数据来源说明」。
- 由处理产生：按计划步骤执行并核验产出。

## 3. `data_find` 的调整

在 v5 方案 `docs/refactor-v5/03-统一数据服务规范.md` §3 的基础上：

| 调整 | 内容 |
|---|---|
| 接收大模型的描述 | `need.what` 以 `{"description": "线状河流，需要河名"}` 为主要写法，配合 `geometry`、`extent`；按类别别名识别，识别不了时返回相近类别供大模型改写（类别词表沿用 v4） |
| 新增 `provided` | 传入用户给出的文件或文件夹路径；对文件夹中的每个数据文件读取名称、几何类型（GeoJSON、Shapefile、GeoPackage 读头部信息；必要时调用 QGIS 端 `geodata_inspect`，属本机调用，不联网），按“文件名 / 图层名与需要的名称或类别别名相近、几何类型一致”对应到各项需要；返回对应结果、置信说明与未对应项 |
| 不再接收 | `{"list": …}`（数据清单取消） |
| 不变 | 确定性、不联网、不调模型；结果保留 30 分钟供计划校验与获取引用 |

示例：用户给出 `D:/底图`，其中有 `省级行政区.shp`（面）、`河流.shp`（线）、`湖泊水库.shp`（面）。需要“省级行政区面、河流线、河流面、铁路”时，返回：省级行政区面 → `省级行政区.shp`；河流线 → `河流.shp`；河流面 → `湖泊水库.shp`（名称相近度低，标“请确认”）；铁路 → 未对应，继续自动获取。

## 4. 编排规则（替代 v5 中依赖结构化章节的部分）

由系统消息注入（对所有方案生效），并写入默认方案的编排提示：

1. 选定流程后读全文，按 §2.1 列出需要的数据。
2. 按 §2.2 的顺序确定每项来源；用户没给出位置的，不假设位置。
3. 用户给了文件夹，先用 `data_find` 的 `provided` 对应；对应结果中标“请确认”的，在计划卡中提示。
4. 需要自动获取的，用 `data_find` 查候选，计划中只能使用其候选。
5. 只在用户给出的数据核验不通过、或指代不清时提问；其余信息用流程中的默认值，并写进计划。
6. 计划中每个图层写明样式（流程中写了的），供计划卡显示缩略图与交叉检查。

## 5. 计划校验的补充（轻量，确定性）

在 v5 方案 `docs/refactor-v5/02-计划与执行规范.md` §4.2 的校验之外：

| 检查 | 级别 | 说明 |
|---|---|---|
| 计划 `data[]` 增加可选字段 `layer`（图层名）与 `style`（样式名） | — | 计划卡据此显示缩略图 |
| `style` 必须存在于资源库 | 错误，退回大模型修正 | `PLAN_STYLE_NOT_FOUND` |
| 流程正文中引用的每个样式，计划中都有图层使用它 | 警告，退回大模型确认 | `PLAN_FLOW_STYLE_UNUSED`：“流程提到样式「河流线」，计划中没有使用它的图层，是否遗漏了河流线？”——用来发现漏列的图层，不阻止计划 |
| `from=user` 的路径存在且几何类型与 `data_find` / `geodata_inspect` 结果一致 | 错误 | 沿用 v5 `PLAN_DATA_MISSING`，增加几何不符的提示 |

## 6. 不再需要的部分

| 部分 | 处理 |
|---|---|
| 流程中的 `## 数据` 表、`## 数据需求`、数据清单资源及其“类别”“字段”列、“文件所在文件夹”关联 | 删除（迁移内容写入流程正文，见 `01` §6） |
| 输入来源方式（我来提供 / 补齐 / 自动获取）的表单 | v5 已删除，保持 |
| 清单逐行合并（v4 `EntryOverrides`） | 由 `provided` 对应替代；引擎中逐行合并逻辑在无调用后删除 |
| 获取时为了对上样式而改字段名 | 改为套用样式时指定标注字段（`02` §5） |

## 7. 例子

### 7.1 统计专题图

流程正文写：“需要所选区域的行政区面（按用户要求的层级）和对应年份的统计表；两者按地区名称关联后按指标分级设色；版面用「统计专题版式」……”

| 用户说 | 结果 |
|---|---|
| “做河南省各市 2023 年常住人口分级图” | 行政区面：自动获取（内置行政区边界，河南省 · 市）；统计表：自动获取（国家统计局门户，需要确认） |
| “市界在 D:/data/henan_city.shp，人口表 D:/data/pop.csv，做人口分级图” | 两项都是用户提供，不获取，自动开始 |
| “工程里有河南市界，人口数据你去找” | 行政区面：工程图层；统计表：自动获取 |
