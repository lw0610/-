# D21 取数智能体、合格检查与统计库

## 结论
统计检查、SQLite 复用、需求交接与登记回执的离线实现完成。按 README §9 的决定，本轮不预置仍有识别错误的完整历史统计表；真实取数通过检查后入库。

## 改动摘要
- 新增 AcquisitionNeed：目标、语义需求、期望行政单元、验收标准、手册、已有台账及预算。上下文由系统传入；注册只接本次 need_id 与实际文件/来源，不要求模型复制冻结查询标识。
- data_register 经内容检查后登记；注册回执按 plan_id/data_id 标识持久化，可恢复后读取。模型文字宣称完成不会替代成功回执。
- 新增 internal/stats：CSV/TSV/XLSX 入口，地区代码/精确别名对应、重复与缺项、有限数值、空值与零区分、年份/单位/口径一致性、来源信息及合计校验；期望单元来自内置行政区，河南市级包含济源，支持排除。
- SQLite 位于运行目录 data/stats/stats.sqlite，按地区/层级/年份/指标/口径/单位复用；官方优先，未指定年份选择已有最新年份。用户上传表走同一检查，并保存规范 CSV，原件不改写。
- fallback 授权改为设置/会话统一授权，取消冻结来源候选限制。
- 取数专家增加 document_extract，默认没有 shell_execute，设置允许时才挂载；已配置的 GEE 工具可在取数专家使用。补充检索方式手册与提示词。
- 新增 flowrun/ledger.go 独立台账类型，字段与 UI 对齐，实际调度/预算计数由 D31 接入。

## D51 真实回放发现后的收敛
专家仍挂着旧 data_find/data_get，加上 osm-data 手册仍要求先查询，使模型在已得到 AcquisitionNeed 后重新发起旧查询，并把省级下载失败转为省级 Overpass。现在系统专家只接需求和成功登记，移除旧查询/调度工具；osm-data 手册同步现行区域与比例尺路由，明确省级任务不能改为超 2 万平方千米 Overpass 或分片绕过。旧工具仍供开发/独立工具调用，但说明不得将查询编号放入 v2 计划。相关材料传递与专家工具测试按此契约通过。

## 合计容差的实际规则与真实回放

02§6.3第5项允许“单元数×0.5个取整单位，或者合计的0.5%”。当前实现有明确取整单位 RoundingUnit 时采用前者；没有声明取整精度时采用全省合计的0.5%，不会从整数数值自动推断取整单位。

河南 D51 真实回放没有声明 RoundingUnit，因此实际采用 9815×0.5%=49.075 万的容差；真实18单元合计9817与全省9815相差2万，既满足实际采用的49.075万，也满足 README Z5 样例提出的9万。二者不能混同：本次真实数据符合9万，但当前系统没有对所有未声明精度的表强制9万。离线夹具的9万来自显式 RoundingUnit=1。收尾核对此处仅补充事实说明，没有变动实现或回放数据。

## 最终只读核对后补齐的两处统计接线

2026-10-29。此前底层 `stats.Need.Exclude` 和检查器支持排除行政单元，但 v2 计划类型/工具 schema 没有公开该字段，执行入口也未传递；因此不能将底层支持等同于用户流程已支持。现已在 `plan.Need`、两份计划工具 schema 公开 `exclude`（用户明确排除的行政区代码或完整名称），并由用户文件和自动取数两个入口传入统计需求。没有新增自然语言猜测或第二套过滤器，仍由既有统计检查入口处理。

此前用户表分支直接调用 `ValidateStatistics`，没有执行自动取数分支已有的 `PrepareAcquisitionNeed`，会以空 `RegionCode` 入库。现仅在用户表入口补上同一个准备调用，统一地区身份后进入原有内容检查和入库；不重复检查、不迁移旧运行记录、不改用户原文件。
