# D31 延迟准备、内容交接、修复和预算

## 修改
- v2 不再插入获取步骤：每步消费输入之前才准备，`extent.from` 按实际产物 ID 解析路线数据集、文件或工程图层，多个产物合并范围后统一外扩。
- 独立确定性获取并行；全部结果先持久化再处理失败。一项失败不会丢掉同组成功项，之后继续复用成功项。
- 确定来源按路由顺序获取；暂时错误同方法退避最多两次。需要研究的来源交取数智能体，传 AcquisitionNeed、合格标准、台账、预算，无需 find_id。
- 指定 web_search/portal 等研究方式可以进入取数智能体；明确指定的确定方式失败不会静默替换。
- 步骤按实际文件、表格字段、数据集必需文件、图层几何和字段、版面核验。图层回执支持单个值、数组和对象。
- 内容不符交同一 Agent 修复，保留先前工具调用与结果，最多两次；确定性错误不盲目重试，402/401 等服务问题暂停。
- 追踪本次新增图层。失败清理新层，成功保留声明产物及成功版面的地图/图例依赖；用户已有层与文件不删除。纯抽取/表格步骤不依赖 QGIS；连接失败进入明确暂停状态。
- 单项取数、单步骤、整次运行分别有时间/调用预算；修复共享当前步骤额度，显式继续开启新额度。只统计实际获准工具调用，拒绝调用不计数。暂停可继续或真正取消并持久化。
- v2 抽取执行器传递本步选中的真实 source_ref/source_refs，支持文件夹子文件、多文件和前序产物。消息原文使用 current_user_message；旧活动任务保留旧输入方式。
- 数据项状态只更新数据项，不再覆盖整体计划状态。

- 修复累计额度用例：额度两次，首轮用完但缺成果时，修复不再领取新额度，直接暂停。

## 真实回放追加修正
- 重启后的开始/取消依据已落盘 RunState，旧计划卡的 running 不再遮住 interrupted；真实工厂回归覆盖暂停后重新创建控制器，再继续或取消。
- 同一范围跨服务传递只外扩一次；多次 PrepareExtent 的实际 bbox 保持一致。
- 主模型的 task 不再暴露内部取数专家；计划控制器仍通过 BuildRole 构建并传递 AcquisitionNeed。真实工厂工具绑定验证两条边界。
- 唯一上传文件名可直接解析为已提供文件；同名多个附件明确报需选择，不猜目录。用真实临时文件覆盖这两个情况。
- QGIS 工具的结构化失败保留部分成功与逐项失败明细，模型能够看到确切路线编号，错误摘要保持简短。

- 图层内容检查读取生产 `layer_inspect` 的 `data` 对象；名称回执从同次 `get_layers_info` 快照解析唯一 ID，同名则给出实际 IDs，不把名称直接作为 ID 调工具。真实外壳回归通过。
- 已下载原件后的本地转换失败用 `ProcessingError` 区别于取数失败；保留原件路径并停止来源回退/专家重复下载。
- 下载排队也计入单项截止时间；准备状态发布开始时间，前端本地秒表显示预算用量，无后端秒级心跳。
- 执行步骤明确复用来源说明中已经完成的裁剪、合并和尺度取舍，避免重复概化；真实模型仍可能偏离，需要结合 D51 记录评价。


## 2026-10-29 更新方案后的重复抽取修正

真实用户测试 `08eb0b80-4008-4f3b-a2f0-ca24efb1e26e`：首次计划缺少 `route_style/symbols`，固定执行器重复提交同一输入三次；随后的重规划调用 Build 主智能体，在计划外完成并确认了一次抽取。修订计划仍保留抽取步骤，控制器没有收到此前抽取的完成状态，于是又执行了一次。这是两条执行路径不一致，不是界面重复卡片。

本次修改：
- 计划提交时把缺少执行参数作为一项可修正诊断返回模型，尚不启动抽取。已完成步骤由真实运行状态保留，不因新增参数要求被重新判错；依赖关系仍核验。
- 重规划使用现有受限 PlanAgent，只有查询与计划修订能力，不会委派执行任务，也不回退 Build。
- v2 专用执行器返回失败后交回计划修订，停止重复发送不可变化的固定参数；其内部抽取重试和普通步骤原有修复流程保持原职责。
- 公开计划工具补足 `layout` 产出类型；明确的 `file + format:layout` 在入口规范为版面，以真实版面名称核验。PDF/QPT 文件仍按文件核验。详见 `layout-output-contract.md`。
