# D30 简化计划契约、规范化与本地预检

## 修改
- 新提交采用 `carto-plan/v2`，模型声明 data 的 source/ref/need/extent 和步骤 inputs/produces。系统生成编号、版本和执行角色，不要求模型抄查找编号、冻结候选或重复声明前序产物。
- 规范化唯一名称引用、步骤 ID 引用、非法/重复 ID、产出标签与缺省能力；抽取自动绑定唯一原件或消息原文。前向/循环依赖等真正不能执行的内容集中诊断。
- 预检使用已提供文件、工程元数据、图层清单与本地路由目录，不调用模型或下载。保存逐项可用/请确认/不可用及理由；不可用不能开始。
- 用户文件夹按实际图层匹配，注册的数据集和具体子文件保持身份；几何/字段从文件头补充。用户在来源编辑入口选文件后登记一次，内部使用已确认引用。
- 明确指定获取方式时保持该方式；自动来源记录方法顺序、已知取舍规则和目录中的典型耗时。内置来源保留清单样式、标注、署名和合规备注。
- 规划上下文限制为 8 KiB（所选完整流程另行读取）；flow-control 手册约 1.8 KiB。目录摘要不携带重复资源环境和完整工具 schema。
- 旧 v1 快照仍可显示，只有已开始的旧运行可以继续；新入口不接受 v1，不自动转换。

## 验证
定向 plan/planexec/flowrun/websocket 用例通过，包括真实计划提交、前序产物无需重复 data、前向引用在保存前拒绝、缺失文件保存明确 needs_data 且不能启动、既有会话数据集复用、能力推断和旧计划显示边界。目录性能与模型可见 schema 的检查另见 D50。

## 边界
预检不把外部网络可用性作为已验证事实。目录中配置存在、凭据存在不等于服务可用；真实调用在 D51 记录。UI 上的预估来自目录参数，不是现场测速。

## 实际模型回放后的能力契约修正
真实人口图的设色步骤声明了合法但不完整的 `data-loading/project-state/vector-fields`。原方案 §03 仅要求缺省或无效编号才推断，此条件不足以覆盖这类现场错误。本轮据此扩展：保留合法声明，并补齐步骤做法/产出可明确识别的职责；没有识别到额外职责时不乱加脚本能力。专用知识执行器保持独立角色。

同时发现旧推断规则使用 `cartography/statistical-data`，实际工具包 ID 是 `cartography-styling/statistical-data-tools`；已修正，回归直接读取项目真实包目录，避免自造可用目录掩盖问题。合并/去重/几何清理补 `vector-geometry`，过滤补 `vector-selection`。这是基于实际失败的职责修正，不对模型执行效率作保证；郑州测试中已有空间工具却仍手写 WKB，不能归因于工具未挂载。

`GeoPackage` 与 `gpkg` 统一为文件格式 `gpkg`，旧持久化声明也可核验同一真实 `.gpkg`，不再因驱动名与扩展名差异要求重新导出。
