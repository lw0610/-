# D13 流程点名图层

## 结论
完成。两种图层引用语法都可保存、锁定、导出导入与提供给模型；前端插入入口见 D12。

## 改动摘要
- `图层「名称」`、`内置图层「名称」` 进入独立图层引用列表；其他自然语言不强制按此格式解析。
- 按图层库名称/别名规则解析，不存在、歧义、摘要变化产生提示，不阻止保存流程。
- `flow.lock` 增加 `layers`（ID、名称、摘要），已有锁保留，避免资源变化时自动悄悄重锁。
- 导出流程只携带图层引用，不把用户地理原件打进流程 ZIP。导入到缺图层环境后显示缺失项。
- 读取流程全文时在已有 GuideStore.ReadContext 末尾附名称、ID、类别、几何、覆盖、标注字段、默认样式和状态；GuideBackend 复用该入口，没有另起一套提示构造器。
- 更新五份内置流程的测试：系统图层+China_map 名称夹具零提示；只有系统图层时允许明确报告缺少点名数据。夹具不用于 GIS 正确性结论。

## 运行的命令与结果
| 命令 | 结果 |

| `go test ./internal/flow/... -count=1` | 通过 |
| `go test ./internal/flow/... ./internal/api/... -run 'TestGuideLayer\|TestFlowLayer\|TestBuiltinGuides' -count=1` | 解析、锁、导出导入、内置流程夹具通过 |

## 计数与耗时
保存/读取图层引用模型调用为 0；没有重新引入编译、体检或警告计数 UI。

## 与方案不一致之处
图层摘要在已有流程读取入口构造，避免直接在 GuideBackend 重复实现同一读取逻辑。导出/导入的通用 lock 传递已经适用新增 layers 段，不为其增加第二套 ZIP 逻辑。

## 遗留问题
图层重命名后已有流程仍保留原文，重新打开/保存时会提示缺失引用；不会替用户批量改写流程文字。
