# D22 读表工具与读图能力

## 结论
网页、PDF 文本表格、扫描 PDF、图片输入链路完成。真实河南年鉴原图的 2023 年列 19 个数全部正确。当前用户默认 python3 未安装 OCR；本次只在临时虚拟环境验证，不能将临时依赖可用说成应用默认已安装。

## 改动摘要
- document_extract 接本地原件或 HTTP(S) 地址；地址复用已授权 web_download_file，通过同一网络策略和会话输出目录取得原件。支持 PDF 页码范围和表格提示，提示仅标记匹配表格，不丢弃未匹配内容。
- HTML 支持 rowspan/colspan；PDF 优先读取文本表格，无文本层时按真实页面渲染图片。识别来源通过内容签名兼容无扩展名下载。
- 视觉模型收到实际图片媒体；非视觉模型自动调用配置的本机 OCR。保存 CSV、格子位置/置信度、不确定格、原件摘要，保留空格而非补零。统计结果仍由 D21 合格检查后入库。
- 配置增加 OCR 引擎、解释器、Tesseract 路径/语言、shell 开关和取数/步骤/全程预算。GET acquisition/config 的 reading_status 报告选中模型和本机实际可用状态；设置界面证据见 D22-设置界面.md。
- build.sh 对 OCR 缺失给安装提示，不让现有门禁失败。

## OCR 选型
| 选项 | 本次观察 | 决定 |
|---|---|---|
| RapidOCR + ONNX Runtime | Python 包可在 Windows/macOS/Linux 安装；本机临时环境安装成功，无独立系统可执行文件需求；中文数值识别通过目标列验收 | 默认引擎 |
| Tesseract + chi_sim/eng | 三平台可安装，需要额外程序与中文语言包；本机未安装，因此未声称已完成同图精度比较 | 保留设置选项 |

官方安装依据：https://github.com/RapidAI/RapidOCR ，https://tesseract-ocr.github.io/tessdoc/Installation.html 。依赖清单位于 file-operations/requirements.txt。临时验证解释器 /tmp/autocarto-v7-ocr-env/bin/python；真实用户配置未改。

中文名称可能被拆分或漏字（如郑州的郑），因此工具不是独立的可信表格生成器；原图、原始格子和期望单元都提供给取数模型，登记时检查缺项/未知名称/合计。

## 与方案不一致之处
没有修改用户机器的默认 Python，也没有把临时环境路径写入用户配置。要在实际应用使用非视觉模型读图，需要为其配置安装好的 OCR 解释器；缺失会明确显示“不可用”，不会伪装已识别。

## 计数与耗时
HTML/PDF 文本层/OCR 均为本机工具，无模型调用。视觉分支返回真实媒体供后续模型消费；本次未发真实视觉模型请求。真实图 OCR 耗时以单独测试日志为准。
