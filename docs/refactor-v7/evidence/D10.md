# D10 内置图层库后端

## 结论
完成。图层登记、匹配、只读文件清单和 API 已落地；真实图层加载见 D11。没有改写用户原始数据。

## 改动摘要
- 新增 `internal/layers`：layer/v1 清单、系统/用户两个根目录、全库名称唯一、名称优先于别名、别名歧义、原件和 Shapefile 配套文件内容摘要、状态检查、覆盖率和匹配排序。
- 匹配先处理流程点名，再名称，再类别与参数；过滤几何、字段、覆盖不足及变化文件。同级优先用户登记，再适用比例尺与覆盖率。明确点名但不符合要求时，替代候选带确认原因。
- 新增 `/api/layers` 列表、详情、扫描、确认、修改、删除、预览接口。删除仅删除登记目录；系统登记不可修改。
- `ReadableFiles()` 提供原始数据及配套文件的精确只读清单；数据来源与 fileops 接入由 D20 完成，不开放整个原件父目录的写权限。
- 新增 `AdministrativeUnits`，按真实内置行政区代码/名称和层级给出行政单元，包含济源等省直管单元，供统计完整性核验使用。
- 未新增兼容层。

## 运行的命令与结果
| 命令 | 结果 |
|---|---|
| `go test ./internal/layers/... -count=1` | 随定向 Go 门禁通过 |
| `go test ./internal/api/... -run TestLayer -count=1` | 扫描→确认→预览→删除登记契约通过；QGIS 调用边界为夹具，文件扫描/清单/HTTP 为实际实现 |

## 计数与耗时
列表、登记和匹配不调用模型，模型调用为 0。未用夹具执行时间推算真实大数据导入耗时。

## 跳过的测试及原因
全量 API 与总体门禁统一在 D50 执行，避免与同步修改计划测试的任务重复运行。

## 与方案不一致之处
覆盖率函数就近放在 `match.go`，未单独新建只有一个函数的 `coverage.go`。行政区字段辅助接口独立于统计库类型，避免包循环依赖。

## 遗留问题
每次列表会核对内容摘要；大型数据的实际耗时应通过真实使用观察，尚未增加缓存及其失效机制。
