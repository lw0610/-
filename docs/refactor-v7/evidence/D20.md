# D20 检索方式路由、取舍与数据仓语义键

## 结论
代码与离线验收完成；真实网络取数交 D51 单列，不把路由测试当成真实下载成功。

## 改动摘要
- categories.yaml 按详细、区域、概略三档声明方式顺序、标签取舍、合并字段、最小图上长度/面积及同名站点合并距离；来源声明 method、比例尺档、中文名能力及典型耗时。新增地铁站点类别，共 24 类。
- 按主图框宽度与地面范围估算比例尺；候选依次为当前明确输入、内置图层、已登记数据仓、路由表中的可用方式。Overpass 超过 2 万平方千米排除；区域河流要求中文名时排除不含中文名的 GEE 来源；显式指定方式不静默改道。
- data_normalize 按 name/ref 合并相连线，按地面度量剔除图上小要素，同名站点在 300 米内合并。输出规则、输入数、合并后数、删除小要素数。
- 数据仓采用 v7 语义键，不含显示名/输出文件名；按 0.5 度外扩范围存储，同类别/参数/比例尺档且覆盖范围可命中，再按本次实际范围与比例尺派生输出。外扩导致 Overpass 面积超限时保留精确范围，避免突破服务限制。原始下载与缓存不被本次派生覆盖。
- 旧缓存可读，新语义查找只选择 v7 条目。过期条目不删除，显示刷新说明。在线瓦片定义不作为可分析的实际地理数据命中。
- 内置原件精确文件/sidecar、数据仓和统计库目录向文件工具只读开放；会话输出仍是写入边界。

## D51 真实回放发现后的收敛
首次湖南任务按正确的区域档选择 OSM 中国提取包，但直连源站 TLS 失败。HTTPAdapter 原来吞掉底层原因，本次改为保留可诊断且已脱敏的底层错误。macOS 当前系统 HTTP/HTTPS 代理已启用；应用原来只读取环境代理，未使用系统设置。新增小型共用 networkproxy.Transport，显式代理设置优先，其次环境，最后读取 macOS 已启用的系统 HTTP/HTTPS 设置；不修改用户配置，不固定端口。HTTP 原件下载与 OSM 客户端接入，公网网页工具原有边界不改。

真实 HEAD 经系统代理返回 200，当前中国 PBF 为 1,618,217,864 字节。河流与铁路原来会分别重复下载同一文件；现在以来源 URL 与版本复用一个原件条目，使用已有 Store.Materialize 的跨进程锁与容量管理，再各自按类别处理。并行两类别夹具验证只发生 1 次 HTTP 下载。

补充验证：go test ./internal/networkproxy ./internal/acquire ./internal/dataservice ./internal/osmdata ./internal/deepagent -count=1 全部通过。真实整条获取结果仍由 D51 记录，不把 HEAD 可达视作完整下载/出图成功。

### 官方省级包与缓存覆盖
2026-10-29 查验 [Geofabrik 中国官方目录](https://download.geofabrik.de/asia/china.html)，当前已列出 33 个省级地区 PBF 链接；[湖南省包](https://download.geofabrik.de/asia/china/hunan.html)为 48.8 MB。源配置新增 region_urls 元数据，按精确地区身份选省包；跨省和未知范围仍用来源全包，不按包围框中心猜地区。程序没有写死湖南特例。缓存额外记录省包的覆盖身份；即使省级包围框和相邻省有重叠，也不会把该原件误用到相邻省。

省、市、县所属区域的选择、跨省退回全包、相邻省/无区域身份不得命中省包均有离线测试。现场网络仍慢，短范围传输探测约 22–24 KB/s，整次下载能否在预算内完成由 D51 单独判断。

### 原件规范化实测
湖南省官方 PBF 51,162,608 字节已成功下载（约 61 秒），两个类别复用同一原件。发现并修复两个具体问题：headless QGIS 启动缺少 GDAL_DATA，导致 OSM 驱动找不到 osmconf.ini；实际 OSM other_tags 为 hstore，原来误当 JSON 解析，遇到合法换行时报错。worker 初始化随包 GDAL 数据目录，规范化按 hstore 转义解析；已知矢量失败保留矢量读取错误，不再误试栅格后给出无关错误。

使用真实缓存原件与 QGIS 直接验证，河流 292,766 条原始线中筛选 1,499 段、按名称合并为 494 条，32.3 秒；铁路筛选 12,599 段、合并为 435 条，34.1 秒。后续实际需求还会按比例尺去小要素及简化；这些数值只代表缓存基础层，不冒充最终导出验收。完整模型执行见 D51。

无 China_map 的真实全国包下载还暴露了每个网络块发送进度的高开销；HTTP 下载出口现就地限制为 250 毫秒最多一次，结束立即发送最终字节数。未改变下载数据和终结状态。新增回归核对节流次数和最终字节数，acquire 全包通过（1.523 秒）。

### GeoPackage 主键与失败阶段
地铁真实下载后的二次归一化暴露 `UNIQUE constraint failed: data.fid`：同名线合并再分离后保留了重复的来源 fid。最终处理为将原 fid 属性明确改名为 source_fid（保留原值并返回 field_renames），让新 GeoPackage 使用唯一的规范 fid。最初“另建主键但同名保留 fid”的做法仍被后续 QGIS 原生算法当主键，已替换为上述完整方案。真实地铁基础文件归一化输出 881 个要素，再经 native:savefeatures 写出仍为 881 个，日志 `/tmp/v7-real-metro-fid-final.log`；新增合成回归同时核对来源字段保留、唯一要素 ID 和后续原生写出。

已经取得原件/基础层后的确定性转换错误现为 ProcessingError（DATA_PROCESSING_FAILED），携带可复用的已发布路径，保留底层 cause。Engine 不因此切换来源；计划控制器收到后请求修正，不委派专家重复下载。测试实证仅尝试一个来源、原件仍存在且底层错误可识别。数据内容本身不合格仍走原有内容检查，不混为网络失败。
