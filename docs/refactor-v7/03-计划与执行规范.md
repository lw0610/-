# 03 计划与执行规范

## 1. 计划格式 `carto-plan/v2`

模型只写“要做成什么、用哪些数据、每步做什么”。编号、版本、来源核验和引用对齐由系统完成。

```json
{
  "goal": "根据史料制作红二十五军长征路线图，A1 横向，导出 PDF",
  "guide": "marching-route",
  "facts": [{"name": "纸张", "value": "A1 横向", "from": "流程默认"}],
  "assumptions": [{"text": "标题拟为“中国工农红军第二十五军长征路线图”", "impact": "low"}],
  "data": [
    {"id": "src", "name": "史料原文", "kind": "file", "source": "user", "ref": "附件:史料.txt"},
    {"id": "province", "name": "省域", "kind": "layer", "geometry": "polygon", "source": "builtin", "ref": "省域", "style": "省域面"},
    {"id": "rivers", "name": "河流线", "kind": "layer", "geometry": "line", "source": "retrieve",
     "need": {"category": "河流线", "fields": ["name"], "description": "主要河流，需要河名"},
     "extent": {"from": "route", "expand": 0.2}, "style": "河流线"}
  ],
  "steps": [
    {"id": "extract", "title": "从史料抽取路线数据集", "inputs": ["src"],
     "instructions": "按流程第 1 步的要求抽取；用户核对后再继续",
     "parameters": {"route_style": "红蓝对比", "symbols": "军标"},
     "produces": [{"id": "route", "kind": "dataset", "format": "route_dataset"}]},
    {"id": "basemap", "title": "加载底图并套样式", "inputs": ["province", "rivers"],
     "instructions": "图层名与流程表格一致；按表格套样式和标注",
     "produces": [{"id": "basemap_layers", "kind": "layer"}]}
  ],
  "deliverables": ["export.pdf"],
  "checks": ["主图覆盖全部路线与地点"]
}
```

### 1.1 数据项

| 字段 | 说明 |
|---|---|
| `id`、`name` | 计划内编号、显示名称 |
| `kind` | `layer`、`table`、`dataset`、`file` |
| `geometry` | 图层必填：`point`、`line`、`polygon`、`raster` |
| `source` | 四选一：`user`（您提供：路径、附件、消息原文、本会话以前的产出）、`project`（工程里已有的图层）、`builtin`（内置图层）、`retrieve`（自动检索） |
| `ref` | `user`：路径、`附件:<名称>`、`消息原文` 或会话文件编号；`project`：图层 ID 或名称；`builtin`：内置图层名称；`retrieve`：不写 |
| `need` | `retrieve` 必填，其他来源可选（用于核验）：`category`（类别编号、名称或别名）、`params`、`fields`、`description`；统计表另写 `region`、`level`、`year`、`indicator`、`caliber`、`unit` |
| `extent` | `{"region": "河南省"}`，或 `{"bbox": [西, 南, 东, 北]}`，或 `{"from": "<更早的数据或产出 id>", "expand": 0.2}`。`retrieve` 需要；内置、用户、工程数据可以不写 |
| `method` | 可选。只在用户点名检索方式时写，例如 `osm_extract`、`tianditu` |
| `style`、`label_field` | 样式库名称、实际标注字段 |

**步骤产出的数据不需要在 `data` 里重复声明**：`produces` 里的 `id` 就是数据 id，后面的步骤直接在 `inputs` 里引用。

### 1.2 步骤

| 字段 | 说明 |
|---|---|
| `id`、`title`、`instructions` | 编号、标题、做法 |
| `inputs` | 用到的数据 id（`data` 里的，或更早步骤 `produces` 里的） |
| `produces` | 产出：`id`、`kind`（`layer`、`table`、`dataset`、`file`、`layout`）、可选 `format` |
| `parameters` | 执行器需要的参数，例如路线抽取的 `route_style`、`symbols` |
| `capabilities` | 可选。省略或填了不存在的编号时，由系统推断 |
| `optional` | 可选步骤 |

### 1.3 相对 v6 去掉的内容

find_id、choice；`from` 的 6 个取值（`conversation`、`user`、`project`、`session`、`step`、`acquire`）；`uses` 与 `data` 两种引用并存；产出 `label` 与成果 `label/type/format` 的对齐；`kind: acquire` 的获取步骤；`conversation_text` 输入绑定。

### 1.4 工具参数

`plan_propose` 与 `plan_revise` 的参数按上面的结构定义，嵌套不超过三层，并附一个完整示例（`autocarto/tools/system/runtime-control/plan_propose.yaml`、`plan_revise.yaml`）。`plan_revise` 提交完整的新计划，系统自动保留已完成的步骤和产出。规划智能体不再挂载 `data_find`、`data_get`；数据服务保留这两个函数，供系统内部预检和解析使用。

## 2. 系统自动修正（不退回给模型）

| 情况 | 系统怎么做 |
|---|---|
| 缺少计划编号、版本、`api_version` | 自动补上 |
| `id` 含非法字符或重复 | 规范化，重复的加后缀 `_2` |
| 引用写成名称而不是 id | 按数据名称或产出 id 唯一匹配 |
| `inputs` 写了步骤 id | 展开为该步骤的全部产出 |
| `capabilities` 缺省或不存在 | 按步骤做法和输入输出推断（规则表放在 `carto_agent/internal/plan/capabilities.go`） |
| 抽取步骤没有原文输入 | 自动绑定本次消息原文或唯一的附件 |
| 内置、用户、工程数据缺 `kind`、`geometry` | 按实际数据补上 |
| 缺 `source` | 有路径时按 `user`；名称对得上内置图层时按 `builtin`；否则按 `retrieve` |
| 成果写成产出的名称或标签 | 对到产出 id |

修正内容记在计划快照的 `notes` 里，计划卡可以展开查看。

只有以下情况才返回诊断给模型：前向或循环依赖；步骤用了尚未产出的数据；`extent.from` 指向不存在或更晚的数据；`retrieve` 项连需要什么都推断不出来。诊断一次列全，并附修正示例。

## 3. 提交预检（不联网、不调用模型）

每个数据项给出一个状态：**可用**、**请确认**、**不可用**，并附原因和建议。

| 来源 | 检查 | 不可用时的建议 |
|---|---|---|
| 您提供 | 文件存在、可读；读文件头核对几何与字段；给的是文件夹时，按名称和几何对应到需要的图层（沿用 v6 的文件夹对应） | 给出正确路径；或改为内置图层、自动检索 |
| 工程图层 | 图层存在；几何与字段 | 改为其他来源 |
| 内置图层 | 名称存在且唯一；几何一致；需要的字段存在；范围已知时覆盖率不低于 90%；比例尺超出建议范围时只提示。流程点名的图层本机没有时，按 `01` §5 第 1 条改用其他来源，状态为“请确认” | 导入该图层；或接受计划卡给出的改用来源 |
| 自动检索 | 类别能识别、参数齐全；范围能确定（地区名能解析、bbox 合法、`extent.from` 指向更早的数据）；路由表中至少有一种可用方式；统计表还要求取数智能体可用（模型可用、设置允许联网） | 启用某种方式；补齐参数；提供数据 |
| 步骤 | 输入都已定义，且在本步之前产生；产出 id 唯一；成果指向某个产出 | — |

- 有“不可用”时不能开始执行；计划卡上写明怎样处理，模型也会收到一份汇总，据此修订。
- “请确认”（例如文件夹弱对应、多个内置候选）：设置 `plan.confirm` 为 `never` 时按首选执行，并在计划卡注明；否则等用户确认。
- 预检结果写进计划快照，前端直接显示。实现位置：新建 `carto_agent/internal/plan/precheck.go`；内置图层与路由查询由 `internal/layers` 与 `internal/dataservice` 提供。

## 4. 计划卡

数据部分一行一项：

| 列 | 内容 |
|---|---|
| 名称 | 例如“河流线” |
| 来源 | 您提供 / 工程图层 / 内置「河流线」（China_map） / 上一步产出 / 自动检索·OSM 提取包 |
| 理由 | 例如“流程点名”“名称与几何一致，覆盖本次范围”“内置没有，区域档河流按路由表首选 OSM 提取包” |
| 范围 | 地区名、bbox，或“路线数据集外扩 20%（执行时计算）” |
| 预检 | 可用 / 请确认 / 不可用，附原因 |
| 样式 | 样式名与缩略图 |

- 点来源可以直接改：选您提供的文件、选工程图层、选其他内置图层、换检索方式。也可以在对话里一句话改。
- 自动检索项展开后显示方式顺序、取舍条件和预计耗时。
- 步骤部分只显示标题、输入和产出；数据准备不作为单独的步骤显示，而是在执行进度里出现。
- 计划里的 `checks` 显示为“成图后请核对”，不再作为“有待处理问题”报告。

## 5. 执行

### 5.1 用到之前再取

执行器逐步推进。执行第 N 步之前，先准备它的 `inputs` 中还没有就绪的数据：

1. 您提供、工程图层、内置图层：直接解析为“加载方式”（内置图层用 `layer_load_builtin`，文件给路径和坐标系，工程图层给 ID），需要时按范围裁剪。
2. 自动检索：
   - 计算范围：`extent.from` 指向的数据此时已经就绪，按它的实际外包框加外扩比例计算；
   - 查数据仓；
   - 按路由表的方式顺序执行确定的方式（不调用模型）；
   - 统计表、专题资料或所有方式都失败的，交给取数智能体（`02` §5）；
   - 合格检查通过后存入数据仓，绑定到计划。
3. 互不依赖的检索可以并行，并发数沿用 `acquisition.concurrency`。

准备好的数据以统一的说明交给步骤的执行智能体：名称、来源、加载方式、坐标系、样式和标注字段、来源说明。执行智能体不需要自己去找数据。

实现位置：`carto_agent/internal/flowrun/carto_plan.go`（替换 `advancePlanData` 的获取步骤逻辑）、`internal/websocket/plan_acquisition.go`（范围计算改用 `extent.from` 与数据 id，不再按显示名作键）、`internal/planexec/build.go`（不再生成 `kind: acquire` 步骤）。

### 5.2 错误分类与处理

| 类别 | 例子 | 处理 |
|---|---|---|
| 确定性错误 | 范围算不出来、类别不认识、内置图层不存在、方式未启用 | **不重试**。状态改为“需要处理”，计划卡给出修正办法；用户一句话改来源，或由模型修订计划 |
| 暂时性错误 | 网络超时、429、5xx | 同一方式退避重试，最多 2 次，然后改道 |
| 内容不合格 | 0 个要素、缺少字段、统计合计不符 | 记入台账；地理数据改道下一种方式，统计表交回取数智能体修正一次 |
| 模型服务错误 | 402 余额不足、401 密钥无效、上下文超限 | **暂停运行**，保留全部进度，提示原因；处理后可以从当前步骤继续 |
| 步骤核验未通过 | 产出不存在、字段不是数值 | 同一执行智能体修复（§5.3），最多 2 次；仍不通过，重规划或询问用户 |

`flowrun/carto_plan.go:49` 那种对所有错误都再试一次的循环，改为按上表分类处理。`llm.IsNonRecoverableServiceError` 命中的错误改为暂停，不再判失败。

### 5.3 修复回路与工程变更追踪

- 核验未通过时，把具体问题（“产出 `joined` 的字段 `pop` 不是数值”）作为新消息发给**同一个**执行智能体，让它只修这一点，而不是另起一个智能体从头再做。
- 每次步骤尝试之前和之后各取一次工程图层清单。尝试失败或要重做时，先移除该尝试新建的图层（文件保留），避免像 10-28 22:58 那样在工程里堆出多份同名图层。
- 步骤完成后，只保留 `produces` 声明的图层；其他临时图层移除或移入“中间结果”分组。

### 5.4 内容核验

| 产出种类 | 核验 |
|---|---|
| `layer` | 回执可以是字符串、数组或对象，系统统一解析；图层在工程里存在，或文件存在且非空；几何类型与声明一致；下游需要的字段存在 |
| `table` | 文件可读，行数大于 0；统计表另做合格检查 |
| `dataset` | 按 `format` 检查必需文件，例如 `route_dataset` 的六张表 |
| `file` | 文件存在、非空，扩展名与 `format` 一致 |
| `layout` | 版面存在；读取版面警告，元素越界或重叠时作为核验问题 |
| 底图符号化 | `layer_set_symbology` 读回的设置与调用参数一致（`06` §4）；引用样式的图层读回渲染器类型与标注开关 |

实现位置：`carto_agent/internal/flowrun/verify_outputs.go`。

### 5.5 预算与暂停

- 默认上限（README §9 第 6 项，设置里可改）：单项取数 15 分钟、80 次工具调用；单个步骤 10 分钟、60 次；整次运行 60 分钟。
- 达到上限时暂停，询问“继续、换方式还是停止”，不直接判失败。
- 进度里显示已用时间和调用次数。

### 5.6 重规划

步骤修复两次仍不通过，或数据被判“不可用”时，才请模型修订。交给模型的内容：失败原因、取数台账、已完成的步骤和产出。模型只修订未完成的部分；已完成的步骤由系统保留，不需要模型照抄（解决 10-29 02:34“已完成的步骤不能改写”的问题）。

## 6. 文件访问

- 数据仓目录和内置图层的原文件，加入文件工具的只读范围（`carto_agent/internal/fileops/workspace.go`）；写入仍然只限当前会话的 `output`。
- 取数智能体默认不挂载 `shell_execute`，读表一律用 `document_extract`；需要时在设置里开启。

## 7. 旧计划兼容

- v6 保存的 `carto-plan/v1` 计划可以显示，但不能直接执行；计划卡提供“按新格式重新生成”，用原请求和原流程重新规划。
- 正在执行的 v6 运行可以继续到结束，或者取消；不做自动转换。
