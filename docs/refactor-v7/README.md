## 1. 思路

一句话：**流程写要加载哪些图层；内置有就用内置的；流程没点名、内置也没有的，系统按数据类别和比例尺选对检索方式，自动去取。**

| 你的说法 | 方案里的做法 |
|---|---|
| 流程里写一下加载什么图层 | 流程仍是一份自由书写的 Markdown（v6 不变），照常写“需要的图层与处理”，模型读出图层清单 |
| 内置有这些图层就用 | 新增**内置图层库**：系统自带省、市、县行政区；你的 China_map 一键导入；全国水系交通可以导入 1:100 万公众版。每个图层有名称、预览、覆盖范围、适用比例尺、标注字段和默认样式 |
| 或者流程里直接说用内置的哪个图层 | 流程里写 `图层「省域」`，和 `样式「省域面」`、`版面「四角对齐版式」` 一样识别、锁定。本机没有这个图层时，保存流程会提示；运行时按别名、其他内置图层、自动检索的顺序改用，并在计划卡上写明改用了什么、为什么 |
| 没说的、内置找不到的，自动检索 | 每个图层按固定顺序确定来源：用户给的 → 工程里已有 → 流程点名的内置 → 内置库对得上的 → 数据仓里取过的 → 自动检索 |
| 流程里应写对图层怎么操作，而不是只写用哪个内置样式 | 底图改回逐层写“怎么画”：颜色、线宽、线型、标注什么、怎么放、上下顺序；只有铁路保留 `样式「铁路」`。数值取自现有样式，图面不变；新增按参数设置符号与标注的工具（`06`） |
| 有好几种检索方式，它应该知道用哪一种 | 一张**检索方式路由表**：按数据类别、比例尺、区域和方式是否可用，排出方式顺序（例如河流：省级图是内置 → OSM 中国提取包，全国图是内置 → Natural Earth；城市地铁只用 OSM 在线查询；人口格网只用 Earth Engine）。确定的方式由系统直接执行，计划卡写明用哪种、为什么；只有统计表这类没有固定方式的，才交给取数智能体 |

另外两点：

1. **统计表不是图层，同一套顺序也适用。** 先查统计库，没有再自动检索；取数智能体要能读年鉴图片和 PDF，取到后由系统做“地区齐全、合计吻合”等合格检查，入库复用。
2. **数据在用到之前才取，不在规划时冻结来源。** 范围依赖上游的情况（例如“底图覆盖全部路线外扩 20%”）在计划里写成正式字段。

## 2. 为什么要改

10-15 之后你一共执行了 20 次任务，完成 5 次。专题图 14 次只完成 1 次（详见 evidence/00）：

| 任务类型 | 次数 | 完成 | 主要问题 |
|---|---:|---:|---|
| 单纯要图层或影像（广东河流、湖南河流铁路 3 次、河南高速与市域、固始影像） | 6 | 4 | 每次 9–43 分钟；同是河流，一次用 GEE、一次用 OSM；省级 OSM 查询超时或 0 要素；不按比例尺取舍（河南高速 62,826 段）；你选的 ESRI 影像在裁剪时被换成 Sentinel-2 |
| 统计专题图（河南人口） | 11 | 1 | 4 次启动或接口故障；其余卡在人口表：来源冻结在国家统计局门户、搜索被拦；年鉴是 JPG，模型不能读图又没有 OCR；关联做完却因回执格式被判失败，重跑 4 遍到余额耗尽；唯一成功那次靠临时写的 macOS OCR 脚本，而且没有复用 45 分钟前登记过的同一张表 |
| 行军路线图 | 3 | 0 | 8 个底图都走自动获取，规划时范围待定，执行时报 DATA_EXTENT_UNRESOLVED；数据查询的嵌套 JSON 写错 7/15 次；史料原文的绑定校验失败 |

根因（按影响排序）：

1. **内置底图丢了。** 9 月的行军路线图直接从 China_map 加载 8 层，约 55 秒。v6 删掉“数据清单/数据文件夹”后，系统不再知道这套底图（`autocarto/flows/system/marching-route/resources/data/中国底图.csv` 已删除，路径只残留在 `autocarto_data/config/flow_input_memory.yaml`）。10-25、10-26 的数据请求里，模型 10 次用 `resource_get` 找“河流”“铁路”“底图”这类数据，全部失败。
2. **来源在规划时冻结。** 执行时补范围只认未公开的 `「名称」外扩N%` 写法（`carto_agent/internal/dataservice/find.go:19`），而工具说明写的是“尚未确定可省略”（`autocarto/tools/system/data-service/data_find.yaml:46`）；兜底只放行冻结候选里的方式（`dataservice/fallback.go:35-50`）。
3. **检索方式没有路由规则。** 候选排序只看来源种类（`dataservice/candidates.go:245-266`），不看比例尺、是否需要中文名、方式自身的范围和速度限制；自由取数时每次凭模型临场决定。
4. **统计数据没有可靠路径。** 统计类只有一个实验状态的国家统计局门户（`source.portal.nbs.yaml:23`），它不覆盖全部地级市；地市数据在省年鉴里，常常是图片；没有读图工具，也没有系统级合格检查；登记结果按文件名作键，下次用不上。
5. **计划契约太重，核验卡格式，失败就整步重来。** 模型要抄 find_id/choice、在 6 种 `from` 中选、对齐产出 label（`carto_agent/internal/plan/validate.go:96-206`）；回执格式不符就整步重跑；确定性错误也照样重试（`flowrun/carto_plan.go:49`）；余额不足直接判失败。
6. **验收没走真实链路。** v6 的行军路线图验收通过环境变量直接把 China_map 交给脚本（`autocarto/tests/integration/acceptance/run.py:29`），完全绕开了数据确定与获取。

模型读流程、列出需要的图层这一步，在所有记录里都没有出错。所以本方案不改“流程是一份 md”，改的是数据从哪来、什么时候取、怎样交接与核验。

## 3. 目标设计

### 3.1 每个图层怎样确定来源（第一项命中就用）

```text
① 用户这次给的        消息里的路径、附件、@图层、文件夹（文件夹按名称和几何对应）
② 工程里已有的        名称、几何、字段核验通过
③ 流程点名的内置图层   图层「省域」：本机有、且覆盖本次范围就用它；否则按别名、其他内置图层、自动检索依次改用，计划卡写明原因
④ 内置图层库对得上的   名称/别名或类别参数一致、覆盖本次范围、适用当前比例尺
⑤ 数据仓里取过的       同一类别、参数、比例尺档并覆盖范围（统计表：同一地区代码、年份、指标、口径）
⑥ 自动检索            按路由表的方式顺序执行；统计表、专题资料或所有方式都失败时交给取数智能体
```

用户随时可以一句话改来源（“河流用我的 D:/data/river.shp”“铁路用 OSM”），也可以在计划卡上直接选。

### 3.2 什么时候取

- 规划时只确定“需要什么、准备从哪来”，并做一次不联网的可执行预检；不下载，也不冻结查询编号。
- 执行到第一个用到该数据的步骤之前才去取。这时上游已经完成，“路线外扩 20%”“市域范围”这类范围可以直接算出来。
- 内置、用户和工程数据不需要范围就能加载；需要时按范围裁剪成派生副本，原件只读。

### 3.3 计划卡

每个图层一行：名称 · 来源（您提供 / 工程图层 / 内置「省域」 / 上一步产出 / 自动检索·OSM 提取包） · 理由 · 预检状态（可用 / 请确认 / 不可用及原因） · 样式预览。自动检索会写明方式和取舍条件，例如“OSM 提取包，铁路只取干线和支线，按约 1:110 万取舍”。

### 3.4 执行与核验

- 确定的检索方式由系统执行，不调用模型。取数智能体只处理统计表、专题资料和路由失败的项，带着目标、合格标准、方式手册、预算和取数台账，不再受冻结候选的限制。
- 核验看内容：图层在不在、几何和字段对不对、统计表单元齐不齐、合计吻不吻合。格式上的差异由系统统一处理。
- 核验没过，就把具体问题交回同一个执行智能体修，最多两次。每次尝试新建的图层都有记录，重试前先清理。
- 确定性错误不重试，直接给出修正办法；余额不足、限流等服务错误让运行暂停，之后可以恢复。

### 3.5 底图怎么画

- 流程逐层写画法；系统按参数设置符号与标注，设置后读回核对（`06` §4）。
- 标注写“省名”“河名”这类含义，字段由数据决定（内置图层清单的 `label_field`）。
- 尺寸按 A1 写，其他纸张按比例缩放；字体自动选系统里可用的中文黑体。
- 复杂的标准符号（铁路）仍引用样式；流程没写画法的图层，用内置图层的默认样式。

### 3.6 总图

```text
流程 FLOW.md（写需要的图层；可以点名 图层「省域」）
      │ 模型阅读
      ▼
计划 carto-plan/v2：每项数据 {名称, 几何, 来源, 范围规则, 样式}；步骤 {做法, 输入, 产出}
      │ 系统规范化 + 预检（不联网、不调模型）
      ▼
计划卡（来源、方式、预检状态；可以一句话修改）
      │ 执行
      ▼
步骤 N 之前：准备它要用的数据
      ├─ 用户 / 工程 / 内置：直接加载（需要时裁剪）
      └─ 自动检索：按路由表的方式顺序 → 统计与专题资料交给取数智能体 → 合格检查 → 存入数据仓
      ▼
步骤 N（执行智能体）→ 内容核验 → 没过就原地修复 → 下一步
```

## 4. 相对 v6 的改动

| v6 | v7 |
|---|---|
| 资源库只有样式和版面；“数据不进资源库” | 增加内置图层库（资源库第三个页签）。它存放的是本机长期可用的地理数据，有预览，流程可以点名；任务数据仍不进流程包 |
| 模型对每个图层调 `data_find`，find_id/choice 写进计划并冻结 | 计划只写来源类型、需求和范围规则；提交时系统预检；执行前才解析；不再需要 find_id/choice |
| 范围依赖上游靠隐藏写法 `「名称」外扩N%` | 计划里的正式字段 `extent.from` 加 `extent.expand` |
| 兜底只放行冻结候选里的方式 | 路由表决定方式顺序；取数智能体可以使用设置允许的全部取数工具 |
| 统计类只有门户兜底 | 统计库、取数智能体、读表工具（网页表格、PDF、图片）、合格检查 |
| 6 种 `from`；产出 label 与成果要对齐；capabilities 必填 | 4 种来源；步骤产出的 id 就是数据 id；capabilities 可省略；能确定的引用由系统自己修正 |
| 获取写成计划里的步骤（`kind: acquire`） | 数据准备是系统阶段，在用到它的步骤之前自动进行，进度里能看到 |
| 按回执格式核验；失败整步重来；确定性错误也重试；余额不足直接失败 | 按内容核验；同一智能体修复；记录并清理失败尝试新建的图层；确定性错误不重试；服务错误暂停、可恢复 |
| 数据仓按来源编号和文件名作键 | 按数据含义作键（类别、参数、比例尺档、范围；统计表用地区代码、年份、指标、口径） |
| 每个底图图层引用一个样式；标注字段、字体（macOS 专用的 `.AppleSystemUIFont`）、尺寸都写死在样式文件里 | 流程逐层写画法；标注字段按数据确定；字体自动选可用的中文黑体；尺寸随纸张缩放；复杂符号（铁路）仍引用样式 |

不变的部分：流程是一份 md；样式和版面库；计划卡加执行器的总体分工；取到的数据必须登记来源；用户原文件只读。

## 6. 验收标准

1. **Z1 内置优先**：导入 China_map 之后，行军路线图的 8 个底图全部来自内置图层，不发起任何联网检索；加载加套样式合计不超过 2 分钟。
2. **Z2 流程点名**：流程写 `图层「X」` 时，X 已安装且覆盖本次范围，计划里该图层的来源必定是 X；X 没有安装或不覆盖范围时，保存流程即提示，计划卡把该项标为“请确认”，写明改用了什么（别名对应的图层、其他内置图层或自动检索）以及原因，不悄悄替换。
3. **Z3 方式选得对、选得稳**：同一需求（例如“湖南省河流线和铁路，A4 横向”）连续运行三次，选择的方式和取舍条件相同，计划卡写明理由；省级及更大范围不使用 Overpass；结果按 `02` §3 取舍、合并（河南省高速公路应是数百条以内，而不是 10-26 的 62,826 段）。
4. **Z4 范围依赖**：在没有导入 China_map 的临时环境里，行军路线图的底图范围在执行时按“路线数据集外扩 20%”算出并完成检索，不出现 DATA_EXTENT_UNRESOLVED。
5. **Z5 统计表**：在统计库为空的环境里，“河南省各市 2023 年常住人口”由取数智能体取得官方数据，通过合格检查（18 个单元齐全，各市合计与全省数之差不超过 9 万人）后入库；第二次运行直接命中统计库，不再联网。全程不依赖 macOS 专有工具。
6. **Z6 不白跑**：把 10-28、10-29 出现过的失败（回执格式、确定性错误重试、余额不足、史料原文绑定、兜底拦截、登记文件读不到）做成回放测试，全部按新规则处理：不整步重跑，不重复重试，余额不足时暂停并可恢复。
7. **Z7 计划简单**：`plan_propose` 的数据项不含 find_id/choice；D51 回放中计划一次提交通过的比例不低于 90%。
8. **Z8 真实回放**：D51 的 5 个真实任务（真实模型、真实网络、真实 QGIS）全部出图，记录耗时、模型调用、工具调用和失败次数，并与 evidence/00 对比。
9. **Z9 门禁**：`./build.sh check` 通过。
10. **Z10 底图画法**：行军路线图的底图按 `06` 逐层写画法，只有铁路引用样式；A1 成图时，逐层读回的颜色、线宽、线型、标注字段与放置方式和 v6 样式一致；选 A4 时尺寸按比例缩放；Windows、macOS 上标注中文都正常显示。

## 7. 全局约束

1. 开工前由用户确认 v6 的提交；从 `refactor/v6` 建 `refactor/v7`。不替用户丢弃或覆盖未提交的改动。
2. 程序仍不解析流程正文的结构，只识别头部和 `样式「」`、`版面「」`、`图层「」` 引用。
3. 用户数据和内置图层的原文件只读。裁剪、规范化、坐标系修正要么写成派生副本，要么写在图层清单里，不改原件。
