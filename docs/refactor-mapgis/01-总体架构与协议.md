# 01 总体架构与协议

## 1. 组件与职责

| 组件 | 位置 | 负责 | 不做 |
|---|---|---|---|
| 前端与桌面壳 | `autocarto-web/` | 对话、计划卡、流程与资源页；启动宿主、选择工程；按宿主描述显示名称、扩展名、设置项 | 不写死宿主名称；不直接调用宿主 |
| Go 控制面 | `carto_agent/` | 配置、契约装载、计划与执行器、数据服务、会话；工具分发；geo 输入物化与输出发布；按宿主描述判断可用性 | 不写 `if mapgis`；不操作 GIS 对象 |
| MapGIS 插件 | `autocarto_mapgis/plugin/` | MapGIS 进程内的宿主工具：工程、地图、图层、选择集、专题与标注、版面、导出、路线绘制、预览 | 不做文件级分析；不写死场景内容 |
| geo 运行时 | `autocarto_mapgis/geo/` + `carto_agent/internal/georuntime/` | 文件进、文件出的地理计算：几何、字段、栅格、GDAL、网络、点云、图表、取数处理、统计与路线知识 | 不连接宿主；不访问网络（脚本工具另有策略） |
| GEE、浏览器、网页、OSM | `carto_agent/internal/{geeruntime,browserruntime,webdata,osmdata}` | 原样沿用 | — |
| 质量审查脚本 | `tools/system/quality-feedback/scripts/` | 原样沿用（`execution.cli`） | — |

## 2. 宿主描述 `host.yaml`

每个宿主包的根目录放一份，Go 启动时从 `AUTOCARTO_ASSETS_ROOT` 读取。缺失时按 QGIS 处理，以兼容旧包。

```yaml
apiVersion: host/v1
kind: mapgis                       # qgis | mapgis
display_name: MapGIS               # 界面与提示文字中的宿主名称
product: MapGIS Desktop 10         # 关于页、诊断页显示
project:
  noun: 工程
  extensions: [.mapx]              # 选择器过滤、会话文件分类
  default_extension: .mapx         # 新建工程
  open_mode: bridge                # args：启动参数直接打开（QGIS）；bridge：先启动，实例注册后经 open_project 打开（MapGIS）
launch:
  platforms: [windows]
  executable_names: [AutoCarto-MapGIS.exe]
  default_paths:
    - 'E:\MapGIS 10\Program\AutoCarto-MapGIS.exe'
    - 'D:\MapGIS 10\Program\AutoCarto-MapGIS.exe'
  requires_elevation: true         # 经 ShellExecute 启动，由系统弹出 UAC 确认
plugin:
  deploy: reference                # reference：Ribbon 工程 .dcprj 引用插件 DLL；copy_to_profile：复制到 QGIS profile
  config_file: autocarto-mapgis.config   # 插件 DLL 同目录；启动前由桌面壳写入运行目录，绕开提权后环境变量丢失
runtimes:
  host: mapgis                     # 宿主类 runtime 名
  compute_python: geo              # qgis：需能 import qgis.core；geo：使用 geo 环境
resources:
  style_formats: [style.yaml]
  layout_formats: [layout.yaml]
  capture: {style: style.yaml, layout: layout.yaml}
  preview_renderer: mapgis-offscreen/v1    # M02 不通过时为 geo-sketch/v1
capabilities:                      # 由 M02 探查结论填写；Go 与前端据此提示，不据此改变工具契约
  multiple_layouts: false
  layer_blend_modes: false
  online_tiles: false
  layout_svg_export: via_pdf
  item_rotation: text_only
fonts:
  cjk_candidates: [Microsoft YaHei, SimHei, Noto Sans CJK SC]
```

QGIS 包的 `autocarto/host.yaml` 用同一格式写出现状：

- `kind: qgis`，`open_mode: args`；
- 扩展名 `.qgz`、`.qgs`；
- `plugin.deploy: copy_to_profile`，`compute_python: qgis`；
- 样式格式 `qml`，版面格式 `qpt` 与 `layout.yaml`；
- `multiple_layouts: true`。

对外接口：

- `GET /api/runtime/descriptor` 增加 `host` 段，内容即上面的 YAML，去掉本机路径。
- WS 的 `runtime_snapshot` 增加 `host.kind`、`host.display_name`。
- 前端只读这两个来源，不再推断宿主（`05` §2）。

## 3. 运行时与分发

| runtime | 后端实现 | 可用条件 | 不可用原因码 |
|---|---|---|---|
| `qgis`、`mapgis`（统称宿主 runtime） | `skill.HostBackend`（由 `QGISBackend` 泛化，按 runtime 名实例化），经反向 WS 桥接 | 有已连接、`host_type` 与 runtime 相同的实例；实例上报了 `implemented_tools` 时，工具名在其中 | `host_disconnected`、`host_kind_mismatch`、`tool_not_implemented` |
| `geo` | `skill.GeoBackend` → `internal/georuntime` 进程池 | geo 环境自检通过，且工具所需依赖都在（例如点云需要 PDAL） | `geo_env_missing`、`geo_dependency_missing:<包名>`、`geo_disabled` |
| `internal` | Go 进程内 | 原有规则 | 原有原因码 |
| `cli` | `execution.cli` 子进程 | 原有规则；`python3` 解析为 `host.yaml` 指定的计算环境 | 原有原因码 |

规则：

1. `NormalizeRuntime`：
   - `bridge`、`interactive` 归一为当前宿主描述的 `runtimes.host`；
   - `compute` 归一为 `cli`；`pyqgis` 归一为 `qgis`；
   - `qgis` 与 `mapgis` 不互相归一。
2. 宿主包里只会出现本宿主的宿主 runtime。另一宿主的契约若出现在用户目录中，显示为不可用，原因 `host_kind_mismatch`，不报错退出。
3. “这一步是否需要宿主”改为看步骤可用工具中有没有宿主 runtime 的工具（`IsHostRuntime`），不再按工具包名列表判断（现为 `flowrun/attempt_layers.go:96-102`）。
4. `geo` 工具的依赖声明写在契约 `metadata.requires`，例如 `[pdal]`、`[pysheds]`。geo 运行时启动自检时返回已安装依赖，目录据此标注可用性。

## 4. 握手与事件

`instance_connect` 在 QGIS 版字段的基础上增加以下字段，旧字段保留：

| 字段 | QGIS 插件 | MapGIS 插件 | 说明 |
|---|---|---|---|
| `instance_id` | `qgis_…` | `mapgis_{机器指纹}_{pid}_{unix秒}` | 原规则 |
| `host_type` | 不发（视为 `qgis`） | `mapgis` | 新增 |
| `host_version` | 不发 | 宿主程序集版本 | 新增；`qgis_version` 仍按旧字段读取 |
| `plugin_version` | 不发 | 插件程序集版本 | 新增，用于诊断 |
| `implemented_tools` | 不发（视为契约全部可用） | 已注册的工具名数组 | 新增，用于目录可用性 |
| `capabilities` | 不发 | M02 探查项的运行时结论，例如 `{"layer_blend_modes": false}` | 新增，只用于诊断与提示 |
| `plugin_path`、`skills_dir`、`python_path`、`project_id`、`project_path`、`machine_fingerprint`、`start_time`、`source` | 原样 | 原样（`python_path` 为空串） | 不变 |

其他消息：

- `instance_heartbeat`：每 10 秒一次，格式不变。
- `instance_project_event`：`project_opened`、`project_saved`、`project_closed`。另存为时，`data.previous_path` 带旧路径，后端先迁移会话目录，再更新实例的工程路径。移植自 enio-mapgis 的 `provider.go:783-844` 与 `session_project_move.go`。
- `instance_disconnect`：不变。断连时，后端立即让该实例上挂起的工具调用失败（移植 `failPendingRequestsForInstance`），不让调用方干等到超时。
- `tool_engine_contract`：插件把收到的执行清单与 `implemented_tools` 比较，缺少实现的写日志，不阻断连接。

实例记录用新表 `host_instances` 存储，含 `host_type` 与 `host_version` 列。启动时把旧表 `qgis_instances` 的行复制过来（`host_type=qgis`），旧表保留只读一个版本（H12）。

## 5. 工具调用与回执

调用消息与 QGIS 版相同：

```json
{"type": "tool_invoke", "data": {"request_id": "…", "tool_name": "layer_set_symbology", "params": {"items": [], "target_instance_id": "mapgis_…"}}}
```

- `params` 已经过 Go 处理：
  - 默认值已补齐；
  - 资源参数已展开为资源句柄（`resource_args.go`）；
  - 输出路径已按会话目录补齐（`applyExecutionOutputDefaults`）。
- 插件读出 `target_instance_id` 后，把它从参数中剔除。

回执外层与 QGIS 插件一致：

```json
{"type": "tool_result", "data": {
  "request_id": "…", "success": true,
  "output": {"success": true, "output": "已设置 3 个图层", "info": {}, "data": {}},
  "error": "", "error_code": "", "output_layers": [],
  "status": "succeeded", "terminal_state": "succeeded", "progress": 1.0, "message": ""}}
```

- **`output` 字段**：放处理器结果对象，键名与 QGIS 版同名处理器一致（`success`、`output`、`info`、`data`、`layer_id` 等），与 `core/tool_engine/runtime.py` 中 `execute_tool` 的外层结构相同。Go 侧现有解析不改。例如 `extractProjectPathFromToolResult` 读 `info.project_path`；质量审查读 `data.layout_snapshot_path`。
- **失败回执**：`success=false`，`error` 写可读原因，`error_code` 取下表之一。

| `error_code` | 含义 | 可重试 |
|---|---|---|
| `invalid_params` | 参数不合法或引用对象不存在 | 否 |
| `unsupported_tool` | 本宿主未实现 | 否 |
| `unsupported_parameter` | 已实现，但该参数值或组合属于降级范围之外 | 否 |
| `host_not_ready` | 宿主未就绪，例如没有文档或正在打开工程 | 是 |
| `native_failure` | 原生层访问冲突或 SDK 返回失败；不保证原生状态可安全重试 | 否（报告用户，建议保存后重启宿主） |
| `execution_failed` | 其他执行异常 | 是 |
| `cancelled` | 已取消 | 否 |

- **超时与取消**：
  - 单次调用的超时取契约 `execution.timeout`，缺省 240 秒，与 QGIS 插件相同；
  - 正在执行的调用收到取消时不中断，跑完后回真实结果；
  - 排队中的调用直接丢弃，并回 `canceled`。

  沿用第一版语义（`ToolInvokeRouter.cs`）。

## 6. 图层引用、物化与发布

### 6.1 图层引用

工具参数里的图层可以写成：

1. **图层 ID**：插件分配的稳定 ID，格式 `ml_` 加 12 位十六进制（§7.1）；
2. **唯一图层名**；
3. **文件路径**：相对路径按项目根解析，与 QGIS 版相同。

同名图层多于一个时，按名称引用返回 `invalid_params` 并列出候选 ID。不像第一版那样取第一个。

### 6.2 geo 工具的输入物化

契约参数类型为 `layer`、`raster_layer`、`vector_layer`、`multi_layer`，且值不是文件路径时，Go 在调用 geo 之前：

1. 调宿主 `layer_export`（系统内部工具），参数为 `{layer_id, format: gpkg|tif, fields: all, selected_only: false}`，得到会话临时目录中的文件路径与 `data_revision`；
2. 以 `(layer_id, data_revision)` 为键缓存，同一步骤内重复引用不重复导出；
3. 把参数值替换为文件路径，并在调用上下文中记下原图层 ID 与坐标系，供输出发布与重投影校验使用。

矢量物化为 GeoPackage，栅格直接给原始文件路径；栅格没有文件源时导出为 GeoTIFF。物化文件写 `<会话>/temp/materialized/`，会话结束时按现有清理规则删除。

### 6.3 geo 工具的输出发布

geo 处理器把结果写成文件，回执列在 `output_layers`：

```json
{"path": "…/output/work/buffer-3.gpkg", "layer_name": "学校500米缓冲", "kind": "vector", "auto_load": true, "replace_layer_id": null}
```

Go 收到后按以下规则发布：

| 情况 | 处理 |
|---|---|
| `auto_load=true`，没有 `replace_layer_id` | 调宿主 `data_load_vector` / `data_load_raster` 加载，图层名取 `layer_name` |
| 有 `replace_layer_id` | 调宿主 `layer_replace_source`，保留原图层的名称、ID、顺序和样式，只换数据。用于字段计算这类“沿用业务名称、替换工程显示”的工具（QGIS 版 `field_calculator` 的 `OUTPUT=memory:` 语义） |
| `auto_load=false` | 不加载，只登记成果 |

- 发布结果的 `layer_id` 写回处理器回执，键名与 QGIS 版相同（`layer_id`、`output_layer_id`、`OUTPUT`），后续步骤直接使用。
- 契约 `OUTPUT` 的取值：
  - `memory:` 或省略：输出到 `<会话>/output/work/<工具>-<序号>.gpkg`，并自动加载；
  - 给了路径：按路径写出。
- 发布失败时，工具整体判为失败，错误中写明文件已生成及其路径，便于恢复。

这些规则只在 Go 的 `GeoBackend` 中实现一次（H16）。geo 处理器只负责写文件、返回描述。

### 6.4 宿主工具的前置处理

有些宿主工具在落图之前，先要做文件级处理。QGIS 版在同一个 Python 进程里完成；MapGIS 版把这一步交给 geo，避免在 C# 里再实现一遍：

| 宿主工具 | 前置处理（geo 内部处理器） | 交给宿主的参数 |
|---|---|---|
| `route_draw`、`route_points_build`、`layout_add_callouts` | `route_dataset_resolve`：复用 `autocarto.knowledge.dataset_handoff.resolve_marching_route_dataset`，解析 `dataset_source`、`dataset_dir`，核对 `expected_table_counts`、`expected_task_id` | `dataset_resolved`：数据集目录、六表路径、行数、任务编号、坐标系 |
| `layer_load_builtin`（带 `clip` 或 `extent`） | `builtin_clip`：按范围或边界裁出派生副本 | 替换为派生文件路径 |
| `layer_set_symbology`、`layer_load_style(s)` | 不需要 | — |

契约写法（MapGIS 包）：

```yaml
execution:
  backend_tool: route_draw
  prepare:
    handler: autocarto_geo.knowledge:route_dataset_resolve
    when: always              # always | {param: clip, present: true}
    output_param: dataset_resolved
```

- Go 的 `HostBackend` 在调用宿主前执行 `prepare`：参数物化规则同 §6.2。
- 前置处理失败时，工具直接失败，错误码沿用 geo 的回执，不调用宿主。
- 宿主工具只读 `output_param` 中的结果，不再自行解析数据集或裁剪。

### 6.5 选择集

- `selection_*` 由宿主执行：插件用 C# 表达式引擎（P34）在要素记录上求值，再设置选择集。
- `extract_selected_features` 这类 geo 工具需要选中的要素时，Go 先调宿主 `layer_selected_ids` 取得 OID 列表，与物化文件一起交给 geo。

## 7. 标识与约定

### 7.1 图层 ID

- 插件为每个由它创建或首次见到的图层分配 `ml_<12 位十六进制>`。
- 持久化方式由 M02 第 1 项决定：
  - 优先写入图层可持久的自定义属性；
  - 没有时写工程旁的 `<工程名>.mapx.autocarto.json`，键为“地图序号 + 图层 URL + 图层名 + 同名序号”，`save_project` 时一并写出。
- 打开工程后按同一键重新关联。关联不上的图层分配新 ID，并在 `get_layers_info` 中标注 `id_reassigned: true`。
- 用户在 MapGIS 界面里手工改名、移动图层后，插件在下一次工具调用前重新关联：按 URL 与同名序号匹配，不按顺序猜测。

### 7.2 版面元素 ID

- 元素 ID 即 MapGIS 元素名（`LayoutElement.Name`），在版面内唯一。
- 第一版发现 `Layout.Append` 可能重置元素名（`LayoutAddLabelTool.cs:349`），所以每次追加后都要重新赋名并回读确认。
- 复合元素（图例框加标题、图文标注组）按“组长名”加 `组长名_` 前缀归组，规则沿用第一版 `LayoutSupport.GetElementGroup`。

### 7.3 坐标与单位

| 对象 | 对外约定（与 QGIS 版相同） | MapGIS 内部 | 换算位置 |
|---|---|---|---|
| 版面元素位置 | 毫米；页面左上角为原点，y 向下；参考点为元素左上角 | 毫米；左下角原点，y 向上 | `Core/LayoutCoordinates`：`y_out = 页高 − (y_mapgis + 高)` |
| 地图坐标 | 图层坐标系下的地图单位 | 同 | — |
| 坐标系 | `EPSG:xxxx` 或 WKT | `SRefData` | `Core/CrsMapper`：先 `SRefData.EPSGToSRS`，再 `WKTToSRS`；无法映射时报错，不猜 |
| 颜色 | `#RRGGBB`，可带透明度 | 系统库色号 | `ColorLibrary`：按 RGB 查找色号，找不到就 `AddColor` 并记住；回读时把色号转回 RGB 比较 |
| 尺寸 | 毫米；字号可用 pt，按 0.3528 毫米/pt 换算 | 毫米；符号尺寸受“跟随缩放”和基准比例尺影响 | 写入时关闭跟随缩放，或对齐基准比例尺（第一版 `ApplyPointSymbolOptions` 的做法） |
| 字体 | “系统可用的中文黑体”（微软雅黑优先） | 字体库字体号 `Ifnt`（中文）、`Chnt`（西文） | `FontLibrary`：按候选名查字体号，都缺时用库内第一个黑体并给出警告 |

## 8. 会话与本地库

- 会话目录结构与 QGIS 版相同（`<home>/data/sessions/<工程>/<会话>/{output,temp,exports,uploads,…}`），由 Go 决定，插件和 geo 只写 Go 给出的路径。
- **本地库**：
  - 插件使用专用本地库 `gdbp://MapGISLocalPlus/AutoCarto`，不存在就创建。第一版写入默认库 `database`（`DataLoadVectorTool.cs:24-26`），容易与用户数据混在一起。
  - 导入的要素类名为 `<会话短号>_<数据名>_<几何>`，同源复用按源文件指纹判断（路径、大小、修改时间、前 1 MB 的 SHA-1），不按类名，避免第一版“同名类直接复用旧数据”的问题。
- **清理**：工程关闭后不删除本地库中的类，因为工程仍引用它们。提供系统内部维护命令，列出没有任何工程引用的类，经用户确认后删除（W20 的诊断页入口）。

## 9. 失败与恢复

| 场景 | 处理 |
|---|---|
| 插件断连 | 挂起的调用立即失败，原因码 `host_disconnected`；执行器按 v7 规则暂停，可恢复 |
| 宿主卡在模态对话框 | `UiDispatcher` 同步等待，工具悬挂；超时后后端发取消，插件回 `canceled`，但已在 UI 线程开始的执行不会中断（沿用第一版语义）。诊断页提示用户关闭对话框 |
| 原生访问冲突 | 工具回 `native_failure`；插件记录当前工具与参数；后续调用照常排队，但在回执中提示建议保存工程并重启 MapGIS |
| geo 进程崩溃或超时 | 该次调用失败，原因码 `geo_crashed`、`timeout`；进程池补起新进程；会话目录中已写出的文件保留，供排查 |
| 图层 ID 失配 | 见 §7.1；失配的引用返回 `invalid_params` 并给出候选 |

## 10. 安全

- **geo 脚本工具**（`geo_execute_script` 等，G57）：
  - 在独立子进程中运行，工作目录为会话目录；
  - 默认禁止网络（不设代理，并拦截 `socket` 模块）；
  - 文件写入限定在会话目录与用户指定的输出目录；
  - 沿用 QGIS 版 `pyqgis_*` 的确认规则（`hitl/guard.go:47` 对 `pyqgis_submit_script` 的守卫改为同样作用于 `geo_submit_script`）。
