# 抽取结果的坐标补全

知识抽取完成后，后端必须为 `spatial_entities` 中的地点补齐坐标：先分析现代检索名称和行政区，再查询天地图；无法取得可用匹配时，调用模型结合原文、路线和区域信息估算位置。天地图坐标标为 `gazetteer`，模型估算坐标标为 `llm_estimated`。两类坐标都直接写回地点的 `lon`、`lat`，自动进入显示和制图，不要求逐地点人工确认。原文名称、ID、路线关系和箭头样式不变。

抽取过程文件、核对界面和后续编译使用同一份回填后的图谱。抽取阶段只抄录原文明确给出的坐标；允许中间草稿暂缺坐标，是为了交给后续定位步骤处理，不代表最终可以交付缺坐标的结果。

已有草稿可以在“知识结果核对”中点击“自动补全坐标”。查询前先保存修改；查询结果保存为新草稿版本。查询期间若其他窗口保存或确认了草稿，本次请求返回版本冲突，不覆盖新版本。

地点下面显示已填坐标、来源及定位说明。名称沿革、同名地点和近似名称由定位流程自动处理；查库无法可靠选出匹配项时转为模型估算。区域及方向性描述也由模型给出用于绘图的代表位置，保留“伏牛山区”“西安南部”等原始名称，不把名称改成附近县城。估算位置与查库位置在来源字段中明确区分，估算置信度低也不会触发逐地点确认。

## 数据与凭据

- 每个地点的 `geocoding` 保存查询、匹配或估算状态与理由。它不是独立结果表，也不包含服务 Key。
- 已有合法的原文、人工、地名资料或制图控制点坐标保留。模型估算也必须提供成对、有限且范围合法的经纬度；`coordinate_source` 不得冒充原文或地名资料来源。
- 自动定位的坐标变化由后端单独记录，不会冒充人工核对，也不会借此放宽历史事实的证据校验。
- 编译后的 `task_graph.json` 保留定位信息，`places.csv` 使用回填的坐标。模型估算坐标可直接编译；如果模型不可用、结果不合法或任务被取消，系统报告定位失败，不把缺坐标结果作为补全成功。
- 天地图原始 `lonlat` 以经度、纬度顺序读取，元数据记录 `coordinate_system: tianditu_lonlat`。此实现没有增加坐标基准转换或改变现有 `EPSG:4326` 输入契约。

天地图 Key 只在后端使用。读取顺序为 `TIANDITU_API_KEY` 环境变量，然后是现有本机 `SecretsManager` 中名为 `tianditu` 的密钥（系统钥匙串或加密存储）。不写入前端、提示词、抽取 JSON 或代码。当前机器已配置用户提供的服务器端 Key。

`POST /api/sessions/{session_id}/knowledge-reviews/{review_id}/geocode` 接收 `{"base_revision": 1}`，返回保存后的 `ReviewDocument`。后端定位总预算为 240 秒，前端请求超时为 300 秒。模型按 6 个地点分批、最多并行 4 次，并压缩重复原文片段；名称分析、天地图查询、候选选择分别设定阶段预算，为最终估算保留处理时间。天地图单次请求最多 12 秒、最多并行 4 次，所有请求均匀限速为每秒 4 次，同次重复查询共用响应。HTTP 429 在查询阶段预算内按 `Retry-After` 延迟重试一次；认证失败不重复请求。查询失败由模型估算兜底；取消或超时的手动请求不提交半份草稿。

查询只返回具体地点的上级乡镇、县市中心时，该位置只能作为估算参考，不会直接冒充这个村庄、桥梁或渡口的查库坐标。

支持切换思考模式的 Qwen 模型在这些定位请求中显式使用非思考模式，以免默认深度思考耗尽批量查询时间；该选项仅作用于定位调用，不修改全局模型配置或知识抽取请求。

本次没有接入网页搜索或地方志资料库。模型提出的名称沿革用于检索；没有查库依据而由模型生成的位置始终标为估算，不声称是经史料证实的历史驻地。服务不是道路规划，不会把长征路线改成现代道路。

## 旧稿与验证

新 schema 新增可选 `geocoding` 属性。紧邻前一版本的旧审核稿通过原有 HMAC 审核认证后可使用这项增量兼容，仍按当前 schema 全量校验。任意其他旧 schema、伪造契约或被篡改的原文/图谱不接受。

相关验证覆盖后端回填、持久化复读、并发版本冲突、原始记录保护、自动/人工来源区分、Key 安全错误、同名与历史名称处理、旧契约的真实编译，以及前端补全、保存与显示。Python 编译测试包含天地图来源地点、低置信度模型估算区域和方位性地点，验证它们无需人工审核凭据即可生成数据，且坐标、来源和定位说明完整保留。

2026-09-25 使用现有 72 地点长征抽取稿的副本进行真实接口验证：72 个地点全部回填，48 个使用天地图候选坐标、24 个使用模型估算，全程约 63 秒。测试未修改原始草稿；该结果验证流程完整性，不代表逐地点历史位置已经过人工或史料认证。

代码更新后需重新构建后端并重启 AutoCarto，重新载入 QGIS 插件以使用新的 Python 校验逻辑。

前端并行预览必须使用独立构建缓存，例如在 `autocarto-web` 中运行 `AUTOCARTO_NEXT_DIST_DIR=.next-preview npx next dev -p 3100`。不要让临时预览与正在运行的桌面开发服务共用 `.next`；否则页面引用的脚本可能被覆盖而返回 404。
