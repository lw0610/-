# 04 编译与链接规范

实现任务：R40（编译/链接分离）、R41（方案环境与可用流程缓存）、R50（链接时写锁定）。

## 1. 现状

- `internal/flow/cache.go:20` 的 `fingerprint` 把 FLOW.md、方案、能力目录**和**全部资源（含数据清单引用的每个数据文件的完整内容）一起哈希，作为编译缓存键。
- 缓存未命中就调用 `compilePlan`，其中 `inferFlow`、`inferStep` 会调模型（`compile_llm.go`）。所以改一个 shp、换一次绑定，都会整份重新调模型编译。前端的绑定请求因此给了 300 秒超时。
- 每次规划/执行，`internal/websocket/flow_runtime.go:437` 的 `injectAvailableFlows` 调 `AvailablePlans`：先 `LoadEnvironment` 一次，再对每个启用流程 `EnsureCompiled`，后者调两次 `source`（各一次 `LoadEnvironment`——读取全部工具包与约 319 份工具定义——再加一次全量哈希）。
- 缓存文件按键命名（`flow_cache/<流程>/<方案>/<键>.plan.json`），没有清理。
- 只哈希清单列出的 `.shp`，改 `.dbf` 不使缓存失效（D8）。

## 2. 拆成两步

| | 编译 compile | 链接 link |
|---|---|---|
| 做什么 | 解析 FLOW.md；调模型推断输入、产出、条件、建议能力；绑定角色 | 解析全部资源声明；检查文件、附属文件、绑定、锁定、执行器资源契约；生成资源快照与资源诊断 |
| 是否调模型 | 是（配置了编译模型时） | 否 |
| 输入 | FLOW.md 原文；方案修订号、能力目录修订号、角色、工具包、能力；编译器版本与模型名；**资源声明身份** | 编译计划；资源库；绑定；`flow.lock` |
| 缓存 | 落盘，键为编译键 | 不落盘；进程内按链接指纹记忆 |
| 何时执行 | 编译键变化时 | 每次预览、详情、运行前、可用流程注入时（命中记忆则直接返回） |

### 2.1 编译键

`compileKey = sha256(` 以下内容的规范 JSON `)`：
- FLOW.md 原文；
- `SchemeRevision`、`CatalogRevision`、角色、工具包、能力（与现状相同）、启用流程列表；
- `CompilerVersion`（本次升为 `"2"`，旧缓存自动失效）、模型名；
- 每个资源声明的 `{类型词, 标签, 位置}`，以及解析出的**身份** `{id, type, version, owner}`——不含条目、存在性、绑定、文件内容。

资源身份进入编译键是因为模型推断会看到资源名称与类型（`compile_llm.go` 把 `plan.Resources` 放进提示）。**编译提示中只放资源的标签、类型和条目数量**，不放路径和条目，R40 同步修改 `compile_llm.go`。

### 2.2 链接指纹

`linkFingerprint = sha256(` 编译键 + 对每个资源：`Root`、`Entry`、清单内容、`Digest`；数据清单与数据文件夹的每个条目及其附属文件的 `(路径, 大小, 修改时间纳秒)`；绑定值；`flow.lock` 内容 `)`。

- 不读取数据文件内容；元数据变化（大小或修改时间）即视为变化。
- 进程内记忆：`map[flowID+scheme]{fingerprint, linkedPlan}`；指纹一致直接复用。计算指纹本身只做 `stat`，代价与条目数线性相关。

### 2.3 计划结构

`FlowPlan` 保持 `flow-plan/v1` 的对外形状，增加：

```go
type FlowPlan struct {
    // … 现有字段 …
    CompileKey      string       `json:"compile_key"`
    LinkFingerprint string       `json:"link_fingerprint"`
    LinkedAt        time.Time    `json:"linked_at"`
    Lock            *resource.Lock `json:"lock,omitempty"`
    // Diagnostics = 编译诊断 + 链接诊断（读取时合并，便于前端不改）
    CompileDiagnostics []Diagnostic `json:"compile_diagnostics"`
    LinkDiagnostics    []Diagnostic `json:"link_diagnostics"`
}
```

- 落盘的编译计划不含 `Resources[].Entries`、`ResolvedPath`、`BaseDir` 和链接诊断；这些由链接填充。
- `CacheKey` 保留为 `CompileKey` 的别名（兼容现有前端与 `run.json` 读取），R61 之后删除。

### 2.4 入口函数

| 现函数 | 新行为 |
|---|---|
| `Compile(ctx, id, scheme, force)` | 编译（命中缓存则读盘）→ 链接 → 返回合并后的计划。`force` 只强制重新编译。预览接口使用 |
| `EnsureCompiled(ctx, id, scheme)` | 改名 `EnsureRunnable`（保留旧名包装一个版本）：编译 → 链接 → 有错误返回 `ValidationError`；编译期间 FLOW.md 被修改（编译键变化）或链接指纹在返回前变化 → `ErrPlanChanged` |
| `AvailablePlans(ctx, scheme)` | 只 `LoadEnvironment` 一次；每个启用流程走编译缓存 + 链接记忆；**不再调用两次 `source`** |

运行开始时，`flowrun.Controller.Start` 把链接后的计划完整写入 `run.json` 的 `plan`（现已如此），作为本次运行的资源快照；恢复运行时使用快照中的资源，并重新做一次链接校验：资源已变化时提示用户"资源在暂停期间发生变化"，由用户选择继续（用快照）或重新开始。

### 2.5 缓存清理

每个 `flow_cache/<流程>/<方案>/` 目录写入新计划后，只保留最近修改的 3 个 `.plan.json`。

## 3. 绑定与保存的接口变化

- `PUT /api/flows/{id}/bindings`、`PUT /api/resources/bindings`：保存后只做链接，**不触发编译**；响应返回新的链接诊断。前端 `autocarto-web/src/features/flows/api.ts` 的 `bind` 去掉 300 秒的编译超时（R40 一并修改）。
- `PUT /api/flows/{id}`（保存 FLOW.md）：编译键变化才调模型；只改了资源文件时只链接。

## 4. 方案环境缓存（R41）

`internal/api/flow_environment.go` 的 `loadFlowEnvironment`：

- 结果按 `(方案名, 方案文件修改时间与大小, 工具定义目录修订号, 工具包目录修订号)` 在进程内缓存。修订号可用目录树中文件 `(路径, 大小, 修改时间)` 的哈希，按 1 秒节流计算，或订阅现有的资产变更通知（若有）。
- 方案保存、工具包导入/删除、工具目录刷新时主动清除缓存。
- `injectAvailableFlows` 每轮调用 `AvailablePlans`，在环境缓存与链接记忆命中时不读任何工具 YAML、不做任何内容哈希。

## 5. 验收用的计数

R40/R41 的测试通过可注入的计数器验证：

- 修改数据文件内容（大小或修改时间变化）后再次 `Compile`：模型调用次数 0，链接诊断更新。
- 修改绑定后：模型调用 0，`FLOW_RESOURCE_UNBOUND` 等诊断消失或出现。
- 修改 FLOW.md 正文：模型调用次数 > 0。
- 连续两次 `AvailablePlans`（无变化）：`LoadEnvironment` 实际加载 1 次，内容哈希 0 次。
- 修改 `.dbf`：链接指纹变化。
