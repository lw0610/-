# R40 编译与链接分离

## 实现

- 编译版本升为 2；结构键仅覆盖 FLOW、环境与声明身份。结构缓存落盘剔除已展开条目、绑定、路径、摘要与链接诊断。
- 模型资源上下文只含标签、类型、条目数量；资源变化仅重新链接，含 shp 附属文件的大小与纳秒修改时间，数据文件不读内容。
- 进程内链接计划按指纹记忆，返回副本；AvailablePlans 每次只加载一次环境。每个流程/方案只留最近三个结构缓存。
- EnsureRunnable 检查生成期间的结构与资源变动；旧 EnsureCompiled 为一版包装。绑定 HTTP 即使没有结构缓存也不会请求模型，返回当前资源诊断。
- 暂停恢复使用 `EnsureRunnable`：结构身份或结构诊断有错时阻止恢复；链接指纹变化时显示明确的资源选择。`Start` 用 CompileKey 保存运行身份，旧计划读取回退 CacheKey。
- 资源变动后的两个操作为“继续使用运行快照”和“使用当前资源重新开始”。继续只记住用户确认的当前链接指纹，不修改 `run.Plan`；重新开始保留并取消旧运行，创建新运行并删除旧 ADK checkpoint。
- 选择携带用户看到的链接指纹；再次变化时要求重新选择。`interrupted`、原 `waiting_user`、跨服务重启的原 ADK checkpoint 均在执行前检查，检查期间保留原断点，不重复执行旧步骤。
- 界面说明“继续使用本次运行保存的资源引用；已修改的文件内容不会恢复”，并指出文件缺失或内容变动仍可能导致执行失败。
- 为让真实交互可达，task admission 只允许当前暂停流程的恢复请求通过占用检查，其他任务保持拒绝。原人工确认被资源检查拦住后，同一 checkpoint 再推送仍可确认；恢复上下文重新注入旧运行的资源 Scope。

## 重启确认竞态补充

- 自审发现 Restart 的确认校验与最终 Start 曾各自重新解析，可能在用户确认后无提示使用更晚的一版资源。
- Start 拆出私有 `startPlan`；Restart 在第二次校验结构键、所见链接指纹后才结束旧运行，随后直接使用刚验证的同一计划，不再进行第三次解析。资源再次变化时重发确认，结构变化时拒绝恢复，旧运行仍保留为暂停。
- 新增两次调用间资源变化和结构变化测试；确认未一致前执行次数为零，重新确认后只执行一次。focused race 通过，日志 `/tmp/enio2-r40-restart-race.log`；flowrun/websocket 全包回归见 `/tmp/enio2-r40-restart-full.log`。
- 与 R70 清理对齐后，`compileKey` 只读取 `CompileKey`；旧 `cache_key` 的读取由 FlowPlan JSON 解码统一转换，运行记录的 `PlanCacheKey` 继续保留兼容。
- R70 删除旧输出字段后再次 focused race 通过：flowrun 2.139s、websocket 4.736s，日志 `/tmp/enio2-r40-restart-post-cleanup.log`。

## 恢复子项涉及范围扩展

- 新增 `flowrun/resume_resources.go` 和测试，修改 `controller.go`、`types.go`、`restore_waiting.go`；Compiler 接口改调用 EnsureRunnable。
- WebSocket 的真实恢复发生于 `resumeTask`，因此需要调整 `flow_runtime.go`、`flow_restore.go`、`task_runner.go` 并新增 `flow_resume_resources.go`；只改 Controller 会漏掉普通人工暂停。
- 前端 `flow-run` 卡片/模型/类型、`useChatMessaging` 和 `MessageList` 增加两个明确选择及指纹传递，避免仅返回错误文本而没有用户可执行操作。
- 资源管理的真实 HTTP 联调（R60/R61）仍等待 R50 修复接口完成，本卡没有用前端模拟测试替代那部分验收。

## 恢复边界补充

编译键按 04 §2.1 包含实际资源的 id/type/version/owner。实际使用的资源替换升版本、选用生效覆盖等身份变化也会使键改变，CheckResume/Restart 均保守拒绝，要求普通新建运行。只有编译键不变、链接指纹变化时才提供继续快照/重新开始。未引用资源或不影响随包资源的本机覆盖不受此限制；继续快照也不恢复文件字节。已有单元测试分别覆盖编译键变化拒绝、重启二次确认、替换升版与覆盖身份，没有宣称已做替换/覆盖连同暂停恢复的专门端到端测试。
