# R11 资源清单、编号与名称解析

## 结论
完成。资源库与流程资源统一通过 `Resolver.Resolve(ctx, Ref, Scope)` 解析，返回稳定身份、版本、摘要、规范化条目与诊断。错误级诊断阻止句柄生成；警告随句柄传递。

## 改动摘要
- 支持单文件与文件夹资源清单、合法编号/名称/版本/入口校验、同目录同名主文件冲突、同库重复编号检查。
- 旧式资源保留临时推断编号并提示升级；7 项内置公共资源加入规范清单，真实资源测试验证编号与清单。
- 同名用户/内置资源返回歧义及结构化候选；明确 `overrides` 后执行解析采用用户项；多个覆盖冲突时回落内置项；资源列表保留双方，按编号管理详情返回确切项。
- 摘要按规范计算，缓存文件内容哈希；数据清单不纳入外部数据内容，数据文件夹仅记录数据文件路径与大小。资源库索引缓存仍检查元数据以感知外部修改。
- 句柄携带完整规范化字段、QML 几何类型、样式标注模式和诊断。Scope.Linked 返回隔离的快照；流程计划的往返转换保留数组、数字和诊断字段类型。
- `NewLibrary` 注入同一绑定存储；API 默认资源库只创建一次，保留索引缓存。已有列表与详情返回身份/来源/覆盖/摘要，新加 `/resources/by-id/{id}`。
- 兼容层登记：`resource_manifest_inference`、`flow_resource_absolute_path_code`、`resource_plan_legacy_fields`。

## 与方案不一致之处
- 增加 `Ref.BaseDir` 单次调用覆盖。既有 `data_load_list.base_dir` 必须在 Go 检查文件前生效，不能交给 Python 再解析一次；覆盖不写入绑定。Linked 数据清单命中时同样重解析并保留原身份与标签。
- 数据路径支持已有 GeoPackage provider 选项（例如 `regions.gpkg|layername=regions`）：句柄完整保留选项，文件检查与指纹只针对物理路径。
- 保留旧绑定键至 R31，`Ref.Key` 仅承接现有编译器生成键；新身份字段已独立提供，R31 负责迁移存储与诊断。

## 修改了涉及范围以外的文件
- `api/api.go` 增加互斥锁，保证惰性创建资源服务不会每请求产生新实例。
- `api/handlers_resource_preview.go` 在资源无效时拒绝旧预览入口继续读取。
- `flow/executors.go`、`flow/cache.go` 分别适配 Resolver 与数据 URI 的物理路径；测试和 acceptance 构造入口按新的绑定存储注入签名调整。
- 流程计划增加 `FlowDir`/`Lock` 承接 R21 的运行 Scope（由 B 泳道协作落地），三份编译快照同步新字段。
- 新增 `flow/resource_conversion_test.go` 验证快照往返无损且不共享可变字段。
