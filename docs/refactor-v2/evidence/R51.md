# R51 资源库管理接口

## 结论
完成。资源库具备导入生成清单、复制与显式覆盖、校验后替换、版本备份、引用查询、受保护删除及旧式升级接口，返回格式与 R60 前端一致。

## 改动摘要
- 导入接受可选名称，生成 `<type>.u-<8 位>` 编号与 `resource/v1` 清单；同名同类型返回 409，附 `details.existing_id`，便于明确选择替换目标。
- 复制保留内容与来源元信息，分配新编号；仅 `override=true` 对内置资源建立显式覆盖，重复覆盖返回冲突。
- 替换先在隐藏临时目录复制并校验；成功后旧资源整体移至 `.backup/<id>/<UTC 时间戳>/`，补丁版本递增。发布中断回滚，校验失败不修改原资源。
- 同一用户资源目录共享管理读写锁；公开 List、Resolve、GetByID 与管理事务相互协调，避免读到主文件和清单的中间状态。
- 引用查询只读扫描内置/用户流程声明与 `flow.lock`，识别名称歧义、显式编号与覆盖后的影响；`bundled` 锁不当作公共库依赖，已锁定其他资源时不回落同名猜测。
- 删除默认有引用即 409，并返回 `details.references`；`force=true` 才删除，内置始终只读。主文件与旁置清单一起删除，覆盖删除后恢复内置解析。
- 旧式资源升级保留内容并生成新清单；响应同时返回 `old_id` 与新 `id`，使后续锁定/绑定迁移可显式处理身份变化。
- 按编号的预览读取确切管理项；符号预览以资源根检查边界，支持自定义对照表入口。
- 旧按类型/名称管理入口保留一个版本，并登记 `resource_type_name_management_routes`；旧删除入口同样执行引用保护。

## 与方案不一致之处
- API 管理详情和预览采用已商定的 `/resources/by-id/{id}`；执行 Resolver 按覆盖关系取生效资源，管理详情保留指定原项。
- 数据清单仅缺外部数据或待绑定目录时允许导入/替换，诊断保留；结构错误仍拒绝。这保留“先导入清单、再选择数据目录”的现有操作与验收，避免导入前必须建立绑定的循环。
- 引用扫描已读取锁定，不必等待 R50 才识别；R50 可复用并扩展。

## 修改了涉及范围以外的文件
- `resource/resolver.go` 为管理替换提供公开读取锁及内部无锁解析，避免嵌套调用死锁。
- `api/handlers_resource_preview.go` 增加按编号确切项预览，并修正自定义映射表入口下的符号边界根。
- 新增 API 管理与流程引用测试文件，避免与 R31 的原绑定测试修改冲突。

## 遗留问题与后续任务需要知道的事
- 升级改变 legacy 编号，资源响应明确给出 `old_id`；本卡不静默重写流程锁。R31/R50 负责可编辑锁与绑定迁移，内置锁仍只读。
- R51 的 `Library.Delete(kind,name)` 是旧内部兼容方法；HTTP 两种删除路由均经引用保护，不能绕过确认影响。
- 本卡仅保证应用管理接口与 Resolver 的事务可见性；用户直接从外部文件管理器修改资源属于下一次解析的重新校验范围。
