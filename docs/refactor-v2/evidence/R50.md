# R50 流程资源锁定与可携带依赖

## 结论
完成。用户流程持久保存公共资源身份，版本或内容变化有独立诊断；导出可携带公共依赖；导入按本机有效资源的编号与摘要去重，保留差异副本且不自动安装到用户库。六种资源修复动作已接入真实 HTTP 路由。

## 改动摘要
- 新增严格的 `flow-lock/v1` 读写：校验版本、摘要、重复项和随包路径，拒绝多文档 YAML、越界路径和符号链接；用同目录临时文件原子替换，内容未变化时不重写。
- 编译/链接取得同一份流程、声明、锁定和资源快照。用户流程只补齐未锁定的公共引用，保存或链接时清除被删声明对应的锁；原有编号、版本和摘要保留，内置流程不在运行时写锁。
- 按名称和显式 `公共资源库/<id>` 的引用均先查锁；找不到锁定编号时给出错误及结构化候选。相同编号发生内容变化时同主版本为提示，跨主版本为警告；`update_lock` 才更新快照。
- 导出 HTTP 参数 `include_library_deps` 缺省为 true，复制资源文件夹的全部内容，单文件连同旁置清单。导出副本的锁记录实际打包资源，原流程锁保持不变。多个标签或显式覆盖最终指向同一编号、摘要时只保留一份副本；导出期间同编号内容发生分歧则报错。
- 导入先在临时包处理依赖，再发布整个用户流程。同编号、同摘要且实际生效资源相同则去重；缺失、内容不同或本机覆盖改变身份时保留副本，解析显示 `FLOW_RESOURCE_BUNDLED_DIFFERS`。校验随包清单编号和摘要，拒绝被篡改的副本；多标签共享副本时只处理一次。
- `POST /api/flows/{id}/resources/repair` 接受 `{action, resource_key, resource_id?}`，返回完整 `FlowDetail`：支持选择编号、更新锁、升级清单、改写类型、安装副本、改用本机资源。修复后只重新链接，不调用模型。共享稳定键的多个同类型标签一起更新。
- 安装随包资源生成新编号，用户库同名时生成明确的“流程副本”名称；已有副本仍保留在流程包内，避免失败中途丢文件。
- 旧式用户公共资源升级后，迁移用户流程锁、精确匹配的显式资源位置、共享绑定和流程单独绑定；不改内置锁。流程内旧式数据清单升级后迁移 `path:` 绑定到稳定编号。已有目标绑定优先保留，迁移使用同一个 bindings.Store 原子写入。
- 类型改写与流程资源升级先在临时包操作，再同时发布 FLOW.md、清单和锁。公共编号迁移只修改解析器定位的资源声明行，不改正文、前缀相似编号或其他用户文本。
- 内置 4 个流程和验收 2 个流程提交锁文件。`TestBuiltinFlowLocksUpToDate -args -update` 可显式重建；日常测试只比较。编译计划夹具同步记录锁定。

## 与方案不一致之处
- 缓存结构要求一致快照，因此锁定补写与资源解析在编译器取得来源时一次完成，链接阶段直接消费该快照；行为仍是首次保存/体检补锁，后续不静默重锁。
- 同编号同摘要去重还要求本机实际生效编号一致。若该内置编号已被用户显式覆盖，保留随包副本，避免去重之后被覆盖资源悄悄替代；用户仍可显式选择 `use_library`。
- 导出只在压缩包副本中更新为实际打包的版本与摘要。否则内容已变化但原锁未更新时会生成自身摘要不符的包；原流程继续保留漂移诊断。
- 旧式公共资源沿用 R11 已登记的兼容推断；携带时以锁内 legacy 编号保持身份，不自动修改公共资源。用户选择安装后才生成正规编号和清单。

## 修改了涉及范围以外的文件
- `resource/bundle.go`：共用资源包复制、定位、安装与流程资源清单升级，避免 flow 包重新定义格式解析。
- `resource/resolver.go`、`manifest.go`：显式 ID 的随包锁定、漂移诊断、随包 overrides 元数据保留但不参与库覆盖、legacy 便携身份与结构化修复字段。
- `resource/bindings/store.go`：原子迁移稳定键，复用原配置保存/备份逻辑。
- `api/handlers_resource.go`：公共资源升级后迁移可编辑流程和绑定；R51 管理测试手写锁补齐 v1 所需摘要。
- `flow/compile.go`：读取包含锁的统一来源快照；同文件 R30 的默认资源删除由 R30 负责。
