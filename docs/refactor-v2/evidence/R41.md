# R41 方案环境缓存与对话开销

## 结论
完成。方案环境与流程编译器由 API 实例共享；未变化时对话注入流程不重复加载工具 YAML，不新增资源内容哈希或模型调用。

## 改动摘要
- `FlowCompiler()` 惰性创建并保存唯一实例，互斥保护并发初始化；HTTP 与 WebSocket 使用同一个编译/链接缓存。
- 方案环境按方案、方案文件元数据、工具/工具包目录元数据修订和配置服务修订缓存。方案文件逐次 stat；目录树修订按一秒节流，只读取路径、大小、mtime、模式。
- 环境快照复制角色/工具包/能力/启用流程的可变切片，调用方修改不会污染后续会话；模型实例作为服务依赖复用。
- HTTP 方案创建/克隆/保存/迁移/删除/激活和工具包写入/导入/删除/启停后主动失效。
- 生产装配将 WebSocket 方案应用、工具目录监视和扩展导入的刷新请求包装为“先失效，再排队刷新”；目录刷新成功再次失效，覆盖异步刷新窗口。
- 资源层提供 `ContentHashCount()`，只统计真正打开文件并读取内容计算哈希的次数，元数据摘要不计入。
- R40 已完成 `AvailablePlans` 单次环境加载和单次 source；本卡沿用该实现。WebSocket 原有每轮 `injectAvailableFlows` 调用链无需增加第二套缓存。

## 与方案不一致之处
- 环境缓存实现独立放在 `flow_environment_cache.go`，保留 `flow_environment.go` 的环境装配职责。
- 主动清缓存覆盖刷新请求发生时与刷新成功后，避免现有 capability 刷新防抖造成短暂旧缓存。
- 编译器实例也缓存，确保已有链接记忆能被 HTTP 与对话链路复用。

- `api/handlers_agent.go`、`api/handlers_skill.go` 在成功变更点调用失效接口；失败与仅预览路径不清缓存。

- `cmd/agent/flow_environment_hooks.go` 与对应测试封装刷新请求时序。
