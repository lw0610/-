## 门禁发现和修复

1. 第一次完整运行在 Go API 测试停下：旧管理接口测试仍读取已退休的 `resolved_path`。改为断言 `owner/entry`，并明确断言旧字段不存在；定向通过，随后全量通过。初次日志 `/tmp/enio2-R73-build-check-initial.log` 保留。
2. 第二次运行在普通 Python 检查发现隐藏旧预设包缺少 `domain/system` 元数据，且测试仍要求所有工具进入可见或系统包。补齐元数据、保持隐藏和禁用；测试按 G4 检查每个工具具有唯一可见归属或明确隐藏登记，拒绝可见/隐藏混用，保留未知引用与元数据检查，没有加入工具名白名单。初次日志 `/tmp/enio2-R73-build-check-python-initial.log` 保留。
3. 最终重新执行全部门禁，包含真实 HTTP 契约，退出码 0。没有修改黄金基线或用跳过替代上述失败。

## 跳过与保留边界

- 普通 Python 的 3 项发行产物检查需要尚未生成的对应工件（含 Linux staging）；在当前 macOS 开发检查中显式跳过。没有据此声称 Linux/Windows 发行包通过。
- `AUTOCARTO_LIVE_E2E`、`AUTOCARTO_PACKAGED_SMOKE` 未启用：没有实际运行中的桌面 QGIS 界面联调或已安装发行包验收。QGIS Python 实际工具测试与 headless 浏览器测试已执行，二者不能替代上述范围。
- 未调用在线模型；未将固定审查夹具当作真实多模态审查。
- G1 知识子系统场景隔离、G3 WebSocket 分层按推荐范围未开展。兼容层的删除条件见 `removal_ledger.yaml`，仍保留旧方案/绑定/运行记录读取及隐藏预设等明确登记项。
- v1 资源绑定读取时在内存转换，首次成功写入才备份并保存 v2；本轮验证使用临时文件，没有替用户迁移真实绑定文件。
- 尚未实现图形化逐行数据清单编辑器。换数据存放目录可在界面绑定；新增/删除清单行仍需要外部编辑器后导入或替换。
- 按方案，编译键包含资源编号、类型、版本与归属；这些身份变化仍会使编译缓存失效。零模型增量承诺适用于身份不变的数据、资源内容及绑定变化，不适用于资源替换后升版本等情况。
- 暂停恢复也按编译键保守校验。实际使用的资源替换升版本或生效覆盖引起身份变化时，需要普通新建运行；不能通过继续快照/重新开始按钮绕过。编译键未变的链接变化才提供该选择。此边界已与当前用户指南同步。
- 资源摘要基于内容；数据文件的链接指纹基于路径、大小和修改时间，不读取所有数据字节。继续旧运行快照不会恢复被外部修改的文件内容。
