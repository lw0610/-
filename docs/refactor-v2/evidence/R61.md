## 结论

## 改动摘要
- 流程资源页先展示声明的资源名称、类型、来源、版本、状态与目录；包内文件列表折叠为次要信息。
- 数据绑定从资源卡或诊断进入，自动持有稳定资源键；用户只看到数据清单名称、当前目录与文件夹选择，不再填写编号。
- 绑定 API 使用普通 15 秒超时，保存后刷新详情；前端不再强制重新编译。此项对应 R40 的前端子项。
- 导出默认勾选附带公共资源依赖，可取消；实际数据文件仍单独选择。
- 六类资源修复动作均有可见入口：选择资源、更新锁定、升级、修正类型、安装随包依赖、改用本机公共资源。
- 选择资源展示候选的名称、来源、版本、编号，选中后把确切编号提交给修复接口。内置流程需要复制后才能修改声明与锁定。
- 类型修正仅改当前草稿对应声明，保留其他修改、围栏示例与步骤正文，不静默保存。
- 独立读取 `/api/flows/bindings/status`，即使流程列表为空也显示无法迁移的旧绑定数。
- 移除前端对 `resolved_path` 的依赖；生产代码和 E2E 不再引用 `resolved_path`、`cache_key`、`FLOW_RESOURCE_ABSOLUTE_PATH`。
- 新登记兼容层：无。已通知后端旧字段与诊断码可在 R61 联调完成后移除。

## 与方案不一致之处
- 与主代理约定资源修复接口 `POST /api/flows/{id}/resources/repair?scheme=<当前方案>`，体为 `{action, resource_key, resource_id?}`，响应为 `FlowDetail`。
- 公共旧式资源升级走资源管理 API；用户流程自带旧式资源升级走流程资源修复 API，避免把流程文件误当公共库资源。
- 旧绑定提示改为独立状态接口，避免在每条流程摘要重复计数，也覆盖空列表情形。
- 定向 headless E2E 使用独立构建目录，Next 自动生成的 tsconfig 变化已清理，不污染用户开发配置。

## 修改了涉及范围以外的文件
- `editor.ts` / `editor.test.ts`：新增可验证的局部资源类型改写，R61 诊断修复需要。
- `request.test.ts`：验证绑定恢复普通超时，模型编译请求仍保留较长超时。
- `ResourceLibrary.tsx` / 测试：选中资源时一并传递本次已加载的类型目录，避免工作区另一请求失败时引用插入异常；适配删除旧路径字段后的测试数据。

## UI 自审
- 每个新增资源诊断动作都有中文入口和对应处理分支；同名候选需要用户明确选择，没有猜测资源编号。
- 绑定目录只用于用户查看、选择和后台结构化参数；前端没有要求用户或模型抄写清单内绝对路径。
- 内置流程写操作转为复制入口；有未保存内容时锁定修复不覆盖草稿；资源类型修复保留草稿修改。
- 绑定保存成功但详情刷新失败会明确说明已保存，避免重复提交。
