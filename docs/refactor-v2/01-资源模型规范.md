# 01 资源模型规范

实现任务：R11（清单、编号、名称解析、覆盖、摘要）、R31（绑定）、R50（`flow.lock`、导出导入）、R51（管理操作）、R30（内置资源归属）。

## 1. 资源由什么组成

一个资源 = **主文件或资源文件夹** + **资源清单**。

### 1.1 清单的位置

| 资源形态 | 适用类型 | 清单位置 | 例子 |
|---|---|---|---|
| 文件夹型 | `data_folder`、`style_set`、`symbols` | 文件夹内的 `resource.yaml` | `styles/国标底图样式/resource.yaml` |
| 单文件型 | `data_list`、`style`、`route_style`、`layout`、`doc` | 主文件旁的 `<资源名>.resource.yaml` | `layouts/四角对齐版式.layout.yaml` + `layouts/四角对齐版式.resource.yaml` |

- **资源名** = 主文件名去掉类型扩展名（`.layout.yaml` 整体去掉；`.qml`、`.qpt`、`.csv`、`.xlsx`、`.md`、`.txt`、`.pdf` 去掉一层）。
- 同一目录下一个资源名只能对应一个主文件。例如同时存在 `四角对齐版式.qpt` 和 `四角对齐版式.layout.yaml` 时，两者都报 `RESOURCE_NAME_CONFLICT`（错误），都不可用。这从根上消除 D3 这类"同名不同格式"的歧义。
- 公共资源库的分组目录不变：`data/`、`styles/`、`layouts/`、`symbols/`、`docs/`。流程自带资源放在 `<流程目录>/resources/` 下，建议使用同样的分组目录，但不强制（引用时写明路径）。

### 1.2 清单字段（`resource/v1`）

```yaml
apiVersion: resource/v1
id: layout.four-corner            # 稳定编号
type: layout
name: 四角对齐版式                 # 显示名，FLOW.md 中按它引用
version: 1.0.0
entry: 四角对齐版式.layout.yaml    # 主文件，相对清单所在目录
description: 标题在装饰框上方居中，综述右上，图例左下，比例尺右下，指北针左上
overrides: ""                      # 仅用户公共资源：被覆盖的内置资源编号
source:
  author: AutoCarto
  license: ""
  upstream: ""
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `apiVersion` | 是 | 固定 `resource/v1` |
| `id` | 公共资源必填；流程自带可省略 | 正则 `^[a-z][a-z0-9_]*\.[a-z0-9][a-z0-9.-]*$`，不超过 64 字符；第一段必须等于 `type`（如 `layout.`、`style_set.`）；同一根目录内唯一。用户导入时由系统生成 `<type>.u-<8 位小写字母数字>` |
| `type` | 是 | `data_list`、`data_folder`、`style`、`style_set`、`route_style`、`layout`、`symbols`、`doc` 之一 |
| `name` | 是 | 1–64 字符，不含 `/ \ : 「 」` 和控制字符 |
| `version` | 否 | `MAJOR.MINOR.PATCH`，缺省 `1.0.0`；"替换内容"操作自动把补丁位加一 |
| `entry` | 单文件型必填；文件夹型可省略 | 资源内相对路径，不得含 `..`、不得为绝对路径；文件夹型省略时按 `03` §2.3 的候选名找对照表 |
| `description` | 否 | 不超过 500 字符 |
| `overrides` | 否 | 只允许出现在用户公共资源中，值必须是同类型的现有内置资源编号，见 §3 |
| `source` | 否 | 作者、许可、上游来源；资源库详情中展示 |

清单格式错误（缺必填字段、编号不合规、类型与主文件扩展名不符）时，该资源报 `FLOW_RESOURCE_INVALID`，不参与名称解析。

### 1.3 旧式资源（没有清单）

为了兼容现有用户资源和流程：

- 类型按"分组目录 + 扩展名"推断（扩展名表见 `03` §1），名称为文件名去扩展名或文件夹名。
- 编号推断为 `legacy.<type>.<根目录内相对路径的 sha256 前 10 位>`，版本 `0.0.0`。
- 体检报 `FLOW_RESOURCE_MANIFEST_MISSING`（提示），修复动作 `upgrade_resource`（R51 提供，一键生成清单）。
- **内置资源必须有清单**，由测试 `TestBuiltinResourcesHaveManifests` 保证。
- 该推断属于兼容层，R11 登记到 `removal_ledger.yaml`；删除条件：R51 的升级入口发布后的下一个版本，且启动时已自动把用户库中的旧式资源升级。

## 2. 资源的三层归属

| 归属 | `owner` 值 | 位置 | 是否进资源库列表 | 是否可被用户覆盖 |
|---|---|---|---|---|
| 工具资产 | `tool` | `autocarto/tools/system/<工具域>/assets/` | 否 | 否（需要可替换的部分应改为正规资源） |
| 流程自带 | `flow` | `<流程目录>/resources/` | 否（在流程详情的资源页展示） | 不适用（按路径引用） |
| 随包依赖 | `bundled` | `<流程目录>/resources/_deps/<编号>/`（导入的流程包） | 否 | 不适用 |
| 内置公共资源 | `library_builtin` | `autocarto/resources/system/<分组>/` | 是，只读 | 可被用户资源显式覆盖 |
| 用户公共资源 | `library_user` | `$AUTOCARTO_HOME/resources/<分组>/` | 是 | — |
| 外部路径 | `external` | 流程外的绝对路径或项目根相对路径 | 否 | 不适用；体检警告 |

放置原则：
- 只被一个工具使用、用户不应替换的数据或配置 → 工具资产。
- 只被一个流程使用的内容（包括场景专用的符号、配色、版式） → 流程自带。
- 被多个流程复用、且不含具体场景的内容 → 公共资源。

## 3. 编号、名称与覆盖

### 3.1 按编号查找

以下位置使用编号：`flow.lock`、FLOW.md 写法 `公共资源库/<编号>`、工具 YAML 的 `default_resource`、绑定键、资源库接口。

### 3.2 显式覆盖

- 用户公共资源在清单写 `overrides: <内置编号>` 后，**按该内置编号或其名称的所有查找都返回这个用户资源**，并附 `FLOW_RESOURCE_OVERRIDDEN`（提示）。
- 同一个内置编号只能被一个用户资源覆盖；多于一个时这些用户资源都报 `RESOURCE_OVERRIDE_CONFLICT`（错误），查找回落到内置资源。
- 删除覆盖用的用户资源后，查找恢复为内置资源（删除前接口会返回受影响的流程，见 R51）。
- 资源库界面同时显示两者：用户项标"覆盖内置「X」"，内置项标"已被用户资源覆盖"，不再隐藏。

### 3.3 名称解析规则

适用于 FLOW.md 的 `类型「名称」：公共资源库`，以及流程外的工具调用中模型直接写的资源名称（流程内先查流程作用域，见 `02` §4）：

1. **锁定优先**：流程的 `flow.lock` 有 (类型, 名称) 对应条目时，按锁定的编号查找；编号已不存在 → `FLOW_RESOURCE_LOCK_MISSING`（错误，修复动作 `choose_resource`）。
2. **候选集合**：
   - 名称为该名称、类型匹配的用户公共资源；
   - 名称为该名称、类型匹配、且**未被覆盖**的内置资源；
   - 覆盖了"名称为该名称的内置资源"的用户资源（即使它自己的名称不同）。
3. 候选恰好一个 → 使用它。多于一个 → `FLOW_RESOURCE_AMBIGUOUS`（错误），诊断中列出各候选的编号、来源、版本；修复动作 `choose_resource` 把选择写入锁定（或把位置改写为 `公共资源库/<编号>`）。
4. 没有候选 → `FLOW_RESOURCE_NOT_FOUND`。

与现状的差别：同名的用户资源与内置资源不再"用户静默优先"，而是要么显式覆盖，要么报歧义让用户选（待确认事项 4）。现有开发运行目录中没有用户公共资源（`autocarto_data/resources/` 不存在），不需要迁移。

### 3.4 类型校验

- 有清单时以清单 `type` 为准；FLOW.md 类型词只表示"期望类型"。
- 期望类型与实际类型不同 → `FLOW_RESOURCE_TYPE_MISMATCH`（错误）。
- 兼容例外：期望 `style` 实际为 `style_set`（或相反）时按实际类型解析，报 `FLOW_RESOURCE_TYPE_ADJUSTED`（警告，修复动作 `rewrite_type` 改写类型词）。此例外由 R01 引入，登记为兼容层。

## 4. 版本与摘要

- **摘要** `digest` = `sha256:` + 十六进制，对以下内容按顺序计算：规范化后的清单 JSON；资源根内每个文件（按相对路径排序，跳过以 `.` 开头的文件和目录）的相对路径、大小、内容 sha256。
  - 数据清单：只覆盖清单文件与资源清单，**不含**清单引用的数据文件（那是外部数据，变化由链接指纹体现，见 `04`）。
  - 数据文件夹：覆盖每个数据文件的相对路径与大小，不读内容。
  - 其他类型：全部内容。
  - 计算结果按（路径、大小、修改时间）在进程内缓存。
- **版本比较**（链接时，锁定版本 vs 当前版本）：
  - 编号相同、主版本相同、摘要不同 → `FLOW_RESOURCE_CHANGED`（提示）；
  - 主版本不同 → `FLOW_RESOURCE_CHANGED`（警告）；
  - 修复动作 `update_lock` 把锁定更新为当前版本与摘要。

## 5. `flow.lock`

位置：`<流程目录>/flow.lock`（YAML）。

```yaml
apiVersion: flow-lock/v1
resources:
  - type: layout
    name: 四角对齐版式           # FLOW.md 中的名称（标签）
    id: layout.four-corner
    version: 1.0.0
    digest: sha256:...
    source: library_builtin      # library_builtin | library_user | bundled
    bundled: ""                  # source 为 bundled 时：resources/_deps/<编号>/
```

规则：
- 只记录**公共资源**引用（`公共资源库`、`公共资源库/<编号>`）和随包依赖；流程自带资源按路径引用，不进锁定。
- 用户流程：保存或体检时由链接步骤补写**尚未锁定**的引用；已锁定条目只在用户执行 `update_lock` / `choose_resource` 时改变；FLOW.md 删除了某个声明时，对应锁定条目随之删除。
- 内置流程：锁定文件随仓库提交，由测试 `TestBuiltinFlowLocksUpToDate` 校验（提供 `-update` 方式重写）。内置流程只读，链接时发现漂移只报提示。
- 复制流程时复制锁定文件；删除流程时一并删除。

## 6. 导出与导入

**导出**（`POST /api/flows/{id}/export`）新增参数 `include_library_deps`（缺省 `true`，待确认事项 5）：
- 对锁定中每个公共资源，把资源（清单 + 全部文件；单文件型连同旁边的清单）复制到压缩包内 `resources/_deps/<编号>/`，并在压缩包内的锁定条目写 `bundled: resources/_deps/<编号>/`。
- `include_data_files`（现有参数）的含义不变：是否附带 `resources/data/` 下的数据文件。

**导入**：对锁定中带 `bundled` 的条目逐个处理：

| 本机情况 | 处理 | 诊断 |
|---|---|---|
| 公共资源库有同编号、同摘要的资源 | 删除包内副本，锁定 `source` 改回 `library_*` | 无 |
| 有同编号、不同摘要 | 保留包内副本，`source: bundled`，解析使用包内副本 | `FLOW_RESOURCE_BUNDLED_DIFFERS`（提示），动作 `install_resource`（以新编号安装为用户资源）或 `use_library` |
| 没有该编号 | 保留包内副本，`source: bundled` | 同上，动作 `install_resource` |

- 导入**从不自动写入用户公共资源库**。
- 锁定条目没有包内副本、本机也没有 → `FLOW_RESOURCE_LOCK_MISSING`。

## 7. 绑定

### 7.1 键

| 资源 | 绑定键 |
|---|---|
| 流程自带数据清单（有清单编号） | `flow:<流程编号>/<资源编号>` |
| 流程自带数据清单（无清单编号） | `flow:<流程编号>/path:<相对 resources/ 的路径>`，例如 `flow:marching-route/path:data/中国底图.csv` |
| 公共数据清单 | `library:<资源编号>`；流程对公共清单的单独绑定为 `flow:<流程编号>/library:<资源编号>` |

键不再包含哈希，改 FLOW.md 中的标签不影响绑定。

### 7.2 值

- 基准目录在项目根之内 → 保存不含 `..` 的项目根相对路径；在项目根之外 → 保存绝对路径。
- 现有越界相对值（如 `../数据/底图数据/China_map`）在迁移时按项目根解析为绝对路径。

### 7.3 文件（`resource-bindings/v2`）

```yaml
apiVersion: resource-bindings/v2
bindings:
  "flow:marching-route/path:data/中国底图.csv": /Users/<用户>/研究生/QGIS-agent/数据/底图数据/China_map
orphaned:                         # 迁移时无法对应到任何资源的旧键，原样保留
  "flow:old-flow/resource_0123456789ab": /some/dir
```

- 文件路径只由 `config.ResolveResourceBindingsFile()` 给出；`resource.Library` 和 `flow.Store` 共用同一个 `bindings.Store` 实例（启动时创建并注入）。
- 读取 v1（无 `apiVersion`）时在内存中按 §7.4 转换；首次写入时落盘为 v2（写前备份）。

### 7.4 从 v1 迁移

1. 备份原文件到 `config/backups/resource_bindings-<时间戳>.yaml`。
2. `flow:<流程>/resource_<哈希>`：读取该流程（内置或用户）当前 FLOW.md 的资源声明，对每个声明按旧算法 `"resource_" + hex(sha256(类型 + "\x00" + 标签))[:12]` 计算旧键；匹配到的转换为 §7.1 的新键；匹配不到的放入 `orphaned`。
3. `library:<名称>`：按名称在公共资源库查找唯一资源，转换为 `library:<编号>`；找不到或有歧义的放入 `orphaned`。
4. 值按 §7.2 规范化。
5. 迁移幂等：对 v2 文件再次执行不产生变化。
6. 体检中，`orphaned` 非空时在流程中心顶部提示"有 N 条旧绑定未能对应，请重新选择文件夹"。

### 7.5 数据清单基准目录的取值顺序（不变）

流程单独绑定 → 公共清单的共享绑定（仅公共清单）→ 清单文件所在目录；已绑定但条目在绑定目录下不存在、而在清单目录下存在时，使用清单目录下的文件。

## 8. 新增与调整的诊断码

在 `docs/refactor/02-流程包规范.md` 的诊断码表基础上：

| 码 | 级别 | 含义 | 修复动作 |
|---|---|---|---|
| `FLOW_RESOURCE_TYPE_MISMATCH` | 错误 | 声明类型与资源实际类型不同 | 无（改类型词） |
| `FLOW_RESOURCE_TYPE_ADJUSTED` | 警告 | 样式 / 样式集写反，已按实际类型解析 | `rewrite_type` |
| `FLOW_RESOURCE_AMBIGUOUS` | 错误 | 同名公共资源多于一个 | `choose_resource` |
| `FLOW_RESOURCE_OVERRIDDEN` | 提示 | 使用了覆盖内置资源的用户资源 | 无 |
| `FLOW_RESOURCE_CHANGED` | 提示 / 警告 | 锁定的资源版本或内容已变化 | `update_lock` |
| `FLOW_RESOURCE_LOCK_MISSING` | 错误 | 锁定的资源编号不存在 | `choose_resource` |
| `FLOW_RESOURCE_BUNDLED_DIFFERS` | 提示 | 使用了流程包附带的资源副本 | `install_resource`、`use_library` |
| `FLOW_RESOURCE_MANIFEST_MISSING` | 提示 | 旧式资源没有清单 | `upgrade_resource` |
| `FLOW_RESOURCE_PATH_EXTERNAL` | 警告 | 引用了流程外的路径（替代原 `FLOW_RESOURCE_ABSOLUTE_PATH`） | `import_resource` |
| `FLOW_DATA_SIDECAR_MISSING` | 错误 / 警告 | shapefile 缺 `.shx`/`.dbf`（必需条目为错误）或缺 `.prj`（警告） | `bind_base_dir` |
| `FLOW_EXECUTOR_RESOURCE_MISSING` | 错误 | 专用执行器要求的资源没有在该步骤引用 | `import_resource` |
| `FLOW_EXECUTOR_RESOURCE_AMBIGUOUS` | 错误 | 执行器步骤引用了多个同类资源（原为运行时错误） | 无 |
| `FLOW_RESOURCE_CONTRACT_UNSATISFIED` | 错误 | 资源缺少使用方要求的条目（如符号集缺 `waypoint`） | 无 |
| `RESOURCE_NAME_CONFLICT` | 错误 | 同一目录内两个主文件资源名相同 | 无 |
| `RESOURCE_OVERRIDE_CONFLICT` | 错误 | 多个用户资源覆盖同一个内置资源 | 无 |

`FLOW_RESOURCE_ABSOLUTE_PATH` 在 R61 完成前仍由后端同时输出（便于旧前端显示），R61 之后删除。
