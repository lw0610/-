# 06 整体治理（资源之外的问题）

本文处理与公共资源无直接关系、但属于整体设计的问题。对应任务 G1–G5，作为独立泳道，优先级低于 R 系列；G1、G3 需用户确认后再开工（README 待确认事项 6）。

## G1 路线知识子系统的场景隔离（需确认）

**现状（证据）**
- `autocarto/knowledge/`：`schema.py:26` 写入 `map_type = "marching_route"`；`vocabulary.py:9` `MAP_TYPES = {"marching_route"}`，事件类型与符号类型词表（`battle`、`meeting`、`rendezvous`、`start_flag`）写在代码里；`validator.py:605`、`:850`，`handler.py:110`，`dataset_handoff.py:181`、`:193` 的提示文案写"行军路线"；`compiler.py:177` 按"会师"字样判断事件。
- `autocarto/tools/system/marching-route-knowledge/`：工具名 `marching_route_get_extraction_contract`、`marching_route_compile_dataset`。
- `carto_agent/internal/knowledge/`：约 7.9K 行非测试 Go 代码；`carto_agent/internal/deepagent/knowledge_*.go`。
- 场景词守卫把以上目录整体排除（`autocarto/tests/test_scene_word_guard.py:31` 起的 `EXCLUDED_ROOTS` 与 `excluded_source`），而且只扫中文字面量；`include_military_arrow`、`marching_route_*` 这类英文标识不受约束。

**问题**：界面上"路线知识抽取"是通用的专用执行器，代码上是行军专用子系统；核心代码因此长期豁免守卫，"场景知识只在流程包和资源里"的规则在这里失效。

**方案 A（推荐）：作为场景扩展隔离**
1. 标识中性化：工具改名 `route_knowledge_get_extraction_contract`、`route_knowledge_compile_dataset`（旧名作为别名保留一个版本并登记）；地图类型取值、提示文案中的场景词移入扩展自带的词表文件。
2. 目录隔离：Python `autocarto/knowledge/` → `autocarto/extensions/route_knowledge/`；Go `internal/knowledge/` → `internal/extensions/routeknowledge/`；工具定义随之移动。
3. 执行器注册：`internal/flow/executors.go` 的 `ExecutorSpecs()` 改为注册表（`flow.RegisterExecutor(spec)`），扩展在装配时注册，核心包不 import 扩展包（`cmd/agent` 负责装配）。
4. 守卫：核心目录零豁免；扩展目录单独豁免，违规逐条写入债务清单。

**方案 B（不在本轮）**：做成通用的"事件—路线抽取"执行器，事件类型、符号类型、地图类型全部来自流程资源（新增词表资源类型）。工作量大，单独立项。

**前置**：R23、R30 完成（执行器输入已改为句柄，资源契约已上线）。

## G2 内置 FLOW.md 去补丁

**现状**：`autocarto/flows/system/marching-route/FLOW.md` 146 行、约 15 KB，"不要 / 不能 / 必须 / 禁止 / 不得 / 只能"共 20 处；`statistical-choropleth/FLOW.md` 16 处。例如第 81 行用文字重述了四角对齐版式的元素位置（版式资源已定义）、比例尺外框、字号锁定；第 87 行规定注记元素编号的记录方式；第 102 行是审查细节。

**问题**：上一版要消除的"提示词补丁循环"转移到了 FLOW.md——工具行为细节和版式规则仍然靠文字约束模型。

**方案**
1. 对两份流程的步骤正文逐句分类：
   - 业务意图与交付要求 → 保留；
   - 工具行为细节（比例尺外框、字号锁定、只创建一套元素、元素编号记录、审查分辨率等）→ 核对工具是否已有确定性保证（返回结构、校验、拒绝修改）：已有则删除该句；没有则写入验证记录的"工具待补能力"清单，由后续工具卡补齐，补齐前保留原句；
   - 版式规则重述 → 删除，以版式资源为准。
2. 体检新增提示 `FLOW_STEP_TOOL_DETAIL`（提示级）：步骤"做法"超过 600 字，或出现能力目录中的工具参数名时，提示"这一步写得像工具说明，建议精简"。
3. 不改变步骤结构、负责角色与产出声明（`test_builtin_flows.py` 的结构断言保持）。

**验收**：行军流程约束词不超过 8 处、正文体积减少不少于 30%；统计专题流程同口径；上一版 T53 五项离线验收不退化。

**前置**：R23、R30。

## G3 `websocket` 包分层（需确认）

**现状**：`carto_agent/internal/websocket` 约 1.5 万行非测试代码（`handlers_session.go` 2596 行、`task_runner.go` 1818 行、`server_core.go` 1675 行），承担会话管理、任务运行、流程运行（`flow_runtime.go`、`flow_restore.go`）、上下文压缩、自动标题、知识审查恢复等应用层职责；可用流程列表也在这一层以系统消息注入。

**方案**：新建 `internal/app/`，按职责迁出：
- `flowsvc`：流程步骤运行绑定、可用流程注入、运行恢复；
- `taskrun`：任务运行与阶段执行；
- `sessionsvc`：会话状态、投影、持久化；
- `compression`：上下文压缩。

`websocket` 只保留协议解析、连接管理与消息收发。依赖方向 `websocket → app → 领域包`，`app` 不依赖 `websocket`。按文件逐步迁移，每一步对外行为不变，现有 `websocket` 测试作为回归。

**前置**：R41 完成（避免与 R21、R41 改同一文件）。建议单独立项。

## G4 工具目录与遗留契约

**现状**：工具有三套分类：
- `autocarto/tools/system/<工具域>/`：代码与工具定义（如 `cartography`、`misc-tools`、`statistical-data`）；
- `autocarto/skills/system/<工具包>/`：工具包（如 `cartography-styling`、`charts`、`statistical-data-tools`），目录名仍叫 `skills`；
- `carto_agent/defaults/tool_contracts/system/`：11 份遗留契约，由 `internal/tool/loader.go` 的 `loadLegacyCanonicalDefinitions` 兜底加载；显示名已与正本分叉（如"添加字段到属性表"与"添加属性字段"），且未登记为兼容层。

**方案**
1. 遗留契约：查清 `LoadCanonicalDefinitions` 的调用方。只用于兜底的 → 删除 `tool_contracts/` 及其 embed，相关测试改用正本；仍有用途的 → 改为从正本生成，并登记兼容层。
2. 工具域与工具包的对应：新增测试 `TestToolsBelongToToolkits`——每个公开工具恰好属于一个非隐藏工具包，或被明确列入隐藏包；在 `docs/新增工具与工具包.md` 增加一张"工具域 → 工具包"对照表。
3. `skills/` 改名为 `toolkits/` 牵涉 `internal/config/paths.go` 的资产根标记、构建脚本、插件部署与大量测试，收益主要是可读性——本轮不做，记录为后续事项。

**前置**：R23（工具定义参数已改完，避免冲突）。
