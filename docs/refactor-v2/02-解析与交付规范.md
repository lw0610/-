# 02 解析与交付规范

实现任务：R11（解析器与句柄）、R20（工具资源参数与展开）、R21（流程作用域、步骤消息、`resource_get`）、R22、R23（Python 消费句柄）、R30（执行器资源契约）。

## 1. 唯一解析器（Go `internal/resource`）

系统中只有这里把"引用"变成"文件与条目"。体检、链接、工具调用、执行器、资源库接口都调用同一个实现。

```go
package resource

// Ref 是一次资源引用。Name、ID、Location 至少给一个。
type Ref struct {
    Type     string // 期望类型；来自 FLOW.md 类型词或工具参数的 resource_type；可为空（resource_get）
    Name     string // FLOW.md「」中的名称，或模型在工具调用中写的名称
    ID       string // 编号：flow.lock、公共资源库/<编号>、default_resource
    Location string // FLOW.md 位置原文；或工具调用中模型传入的路径
}

// Scope 是解析的上下文。流程外的工具调用使用零值。
type Scope struct {
    FlowID  string
    FlowDir string
    Lock    *Lock               // 流程锁定，可为 nil
    Linked  []*ResolvedResource // 流程运行时已链接的资源（按标签、键、编号匹配）
}

type Resolver interface {
    // Resolve 永不返回 nil；所有问题写入 Problems，调用方按级别决定是否继续。
    Resolve(ctx context.Context, ref Ref, scope Scope) *ResolvedResource
}

func WithScope(ctx context.Context, scope Scope) context.Context
func ScopeFromContext(ctx context.Context) (Scope, bool)
func (r *ResolvedResource) Handle() map[string]any // 生成 §2 的句柄
```

`ResolvedResource` 在现有字段基础上增加：

```go
type ResolvedResource struct {
    Key          string // 作用域键：流程自带为清单编号或 path:<相对路径>；公共资源为 library:<编号>
    ID           string
    Label        string // FLOW.md 标签；公共资源为名称
    Name         string
    Type         string
    Version      string
    Owner        string // tool | flow | bundled | library_user | library_builtin | external
    Location     string
    Root         string // 资源根：文件夹型为文件夹，单文件型为主文件
    ResolvedPath string // 兼容字段，等于 Entry（文件夹型无对照表时等于 Root），R61 后删除
    Entry        string // 主文件绝对路径（文件夹型为对照表）
    Format       string // layout: layout_yaml | qpt；style: qml；doc: md | txt | pdf
    BaseDir      string
    BindingKey   string
    Digest       string
    Overrides    string
    OverriddenBy string
    Entries      []ResourceEntry
    Problems     []Diagnostic
}

type ResourceEntry struct {
    Name   string            `json:"name"`
    Path   string            `json:"path"`
    Kind   string            `json:"kind"`
    Exists bool              `json:"exists"`
    Extra  map[string]string `json:"extra"`  // 原始单元格，仅供界面展示
    Fields map[string]any    `json:"fields"` // 规范化字段，见 §2.2；句柄只使用它
}
```

- `Library` 实现 `Resolver`。进程内只创建一个 `Library`（启动时创建，注入 API、编译器、执行引擎、`resource_get`），不再每个请求 `NewDefaultLibrary()`。
- 公共资源库列表按目录修改时间缓存，变更（导入、替换、删除）后失效。

## 2. 资源句柄（`resource-handle/v1`）

### 2.1 结构

句柄是解析器交给工具与执行器的唯一形式：

```json
{
  "api_version": "resource-handle/v1",
  "id": "style_set.gb-basemap",
  "type": "style_set",
  "name": "国标底图样式",
  "version": "1.0.0",
  "owner": "library_builtin",
  "root": "/abs/autocarto/resources/system/styles/国标底图样式",
  "entry": "/abs/autocarto/resources/system/styles/国标底图样式/对照表.csv",
  "format": "",
  "base_dir": "",
  "digest": "sha256:…",
  "entries": [
    {
      "name": "省域",
      "path": "/abs/…/省域面.qml",
      "kind": "style",
      "exists": true,
      "layer": "省域",
      "aliases": ["省级行政区", "省界面", "省域外框", "省域面"],
      "style_path": "/abs/…/省域面.qml",
      "label_mode": "field",
      "label_field": "NAME",
      "geometry": "polygon",
      "description": "由原预设导出的符号和标注"
    }
  ],
  "total_entries": 11,
  "truncated": false
}
```

- 所有路径都是绝对路径；句柄里不出现需要工具再解析的相对路径。
- 句柄只在出现错误级问题时不生成；警告与提示放在 `warnings` 数组（`[{code, message}]`）中随句柄一起交给工具，工具可原样写入结果。
- `entries` 上限 10 000 条，超过时解析报错（数据文件夹过大应改用数据清单）。

### 2.2 各类型的条目字段

每个条目都含公共字段 `name`、`path`、`kind`、`exists`，再加下表字段：

| 类型 | `name` 取值 | `kind` | 额外字段 |
|---|---|---|---|
| `data_list` | 清单"名称"列 | `vector` / `raster` | `required`（布尔）、`description`、`sidecars_missing`（数组，如 `[".dbf"]`） |
| `data_folder` | 文件名去扩展名 | `vector` / `raster` | `sidecars_missing` |
| `style` | 资源名 | `style` | 条目为空数组；句柄级 `format: qml`，另给 `geometry` |
| `style_set` | 对照表"图层"列 | `style` | `layer`、`aliases`（数组）、`style_path`、`label_mode`（`keep` 空值保留 QML / `off` 写"无"关闭 / `field` 覆盖字段）、`label_field`、`geometry`（`point`/`line`/`polygon`/`unknown`，读 QML 的 `layerGeometryType`）、`description` |
| `route_style` | `<topology>/<side>` | `route_style` | `path` 为空；`topology`、`side`、`route_type`、`draw_type`、`style_id`、`width_scale`（数字或 null）、`legend_label`、`preset_ref`、`default_sides`（数组）、`reference_style_id`、`label_paths`（布尔）、`auto_width_group`（布尔） |
| `symbols` | `symbol_type` | `symbol` | `symbol_type`、`format`（`svg`/`png`）、`size`（毫米，缺省 4）、`priority`（缺省 0）、`anchor_x`、`anchor_y`（缺省 0）、`description`、`event_types`（数组） |
| `layout` | 资源名 | — | 条目为空数组；句柄级 `format: layout_yaml` 或 `qpt` |
| `doc` | 资源名 | — | 条目为空数组；句柄级 `format: md`/`txt`/`pdf` |

字段名、取值规范化（如 `标准 → standard`、`是 → true`）由 `03` 的格式规范定义；Go 是唯一实现者。

## 3. 工具参数类型 `resource`

### 3.1 YAML 写法

```yaml
- name: style_set
  type: resource
  resource_type: style_set              # 必填，8 种类型之一；layout 可写 layout:layout_yaml 或 layout:qpt 限定格式
  required: true
  default_resource: style_set.gb-basemap # 可选，内置资源编号
  description: 样式集资源名称（例如「国标底图样式」），也可以填写样式集文件夹路径
```

- `internal/tool/types.go` 的 `ToolParameter` 与 `internal/skill/types.go` 的 `SkillParameter` 增加 `ResourceType`、`DefaultResource`，`internal/skill/registry.go` 的参数转换同步复制。
- 工具定义加载时校验：`type: resource` 必须有合法 `resource_type`；`default_resource` 的第一段必须与类型一致（是否存在由测试 `TestToolDefaultResourcesExist` 用真实资源库检查）。
- 给模型的 JSON Schema 中类型为 `string`（`internal/skill/adapter.go` 的 `skillParameterJSONSchemaType` 默认分支已满足）。

### 3.2 执行引擎展开

位置：`internal/skill/engine.go` 的 `Execute`，在 `applyParameterDefaults` 之后、`validateExecutionArgs` 之前，新增 `expandResourceArgs`（新文件 `internal/skill/resource_args.go`）。引擎通过 `SetResourceResolver(resource.Resolver)` 注入解析器（`cmd/agent/main_deep.go` 创建引擎处）。

```text
对每个 type: resource 参数：
  value := args[参数名]
  若 value 为空：
      有 default_resource → ref = {Type, ID: default_resource}
      参数必填 → 报"缺少资源"；否则跳过
  若 value 是字符串：
      看起来像路径（含 / 或 \、以 ~ 开头、或以该类型的主文件扩展名结尾）→ ref = {Type, Location: value}
      否则 → ref = {Type, Name: 去掉「」与空白后的 value}
  若 value 已是句柄（map 且 api_version = resource-handle/v1）→ 只允许来自执行器的内部调用，按 id 重新解析校验
  scope := resource.ScopeFromContext(ctx)（流程外为零值）
  r := resolver.Resolve(ctx, ref, scope)
  r 有错误级问题 → 返回 ExecutionValidationError：
      "资源「名称」无法使用：<问题列表>。可用的同类资源：<最多 10 个名称>"
  否则 args[参数名] = r.Handle()
未注入解析器而工具含 resource 参数 → 返回"资源服务未就绪"
```

- 对话历史中保留模型写的原始参数；展开后的句柄不写入对话，避免上下文膨胀。工具结果中由工具返回 `resource: {id, version}` 摘要。
- 数组参数中的资源引用本轮不支持（图例额外条目改用单独的符号集参数，见 §6.4）。

## 4. 作用域

### 4.1 流程步骤

- `internal/flowrun/types.go` 的 `StepRequest` 增加 `FlowID`、`FlowDir`、`Lock`、`Resources []*resource.ResolvedResource`（本次运行链接计划中的全部资源；步骤消息另按引用过滤）。
- `internal/flowrun/controller.go` 构造 `StepRequest` 时填充。
- `internal/websocket/flow_runtime.go` 的 `flowRuntimeBinding.Run` 在调用 `runAgentPhase` 前执行 `ctx = resource.WithScope(ctx, resource.Scope{FlowID, FlowDir, Lock, Linked: request.Resources})`。
- 流程作用域内的名称匹配顺序：已链接资源的标签 → 已链接资源的编号 → `01` §3.3 的公共资源名称解析（`Linked` 已包含本次运行链接的全部声明资源）。
- 专用执行器不经过模型：`executor_route_knowledge.go` 直接用已链接资源的 `Handle()` 组装输入（§5.2）。

### 4.2 流程外的对话

没有作用域：名称按 `01` §3.3 在公共资源库解析；路径按外部路径解析（`owner: external`，附 `FLOW_RESOURCE_PATH_EXTERNAL` 警告）。

## 5. 默认资源与资源契约

### 5.1 工具默认资源

- 工具 YAML 的 `default_resource` 是唯一的默认资源声明方式；默认值经过解析器，用户覆盖照常生效。
- 删除 `autocarto/resources/system/styles/route-defaults.json` 中的 `route_style_table`、`symbol_table` 指针（R30 删除整个文件），删除 Python `visual_presets.resource_table()` 的默认分支。

### 5.2 专用执行器的资源契约

`internal/flow/executors.go` 中 `ExecutorSpec.DefaultResources` 改为：

```go
type ExecutorResourceRequirement struct {
    Type          string   `json:"type"`           // symbols | route_style
    Label         string   `json:"label"`          // 中文说明，用于诊断
    RequiredNames []string `json:"required_names"` // 规范化条目 name 必须包含的值
}
// 路线知识抽取：
// {Type: "route_style", Label: "路线样式"}
// {Type: "symbols", Label: "专题符号", RequiredNames: ["start_flag", "waypoint"]}
```

`RequiredNames` 以知识编译器实际依赖为准（当前 `autocarto/knowledge/compiler.py` 读取 `symbol_presets["start_flag"]`、`symbol_presets["waypoint"]`），R30 核对后写入。

编译期检查（替代原运行时报错）：
- 执行器步骤没有引用该类型资源 → `FLOW_EXECUTOR_RESOURCE_MISSING`；
- 引用了多个同类资源 → `FLOW_EXECUTOR_RESOURCE_AMBIGUOUS`；
- 资源条目缺少 `RequiredNames` → `FLOW_RESOURCE_CONTRACT_UNSATISFIED`。

执行器输入：`{"source_ref": "current_user_message", "force_refresh": …, "rules": …, "route_style": <句柄>, "symbols": <句柄>}`。知识编译器从句柄条目构建路线预设与符号预设，把符号文件复制进数据集的 `symbols/` 目录（与现行为一致）。

### 6.2 `resource_get` 内部工具

- 位置：`carto_agent/internal/runtimecontrol/resource_get.go`；工具定义 `autocarto/tools/system/runtime-control/resource_get.yaml`（`runtime: internal`）；加入系统基础包"运行控制"（`autocarto/skills/system/runtime-control/SKILL.md` 的 `tools`）。

### 6.3 `reference_read`

### 7.2 规则

- 生产代码不打开资源表（数据清单、样式集对照表、路线样式表、符号对照表）；数据集六表、注记表等**运行产物**不属于资源，仍用 `table_io.py` 读取。
- 生产代码不出现 `resources/system`、`get_plugin_root() / "resources"` 等资源路径拼接（R70 守卫）。
- 工具私有资产通过 `autocarto/tools/system/_shared/tool_assets.py` 的 `tool_asset_path(domain: str, *parts: str) -> Path` 读取（相对工具包目录定位，不经过插件根常量）。

### 7.3 测试用句柄

- 句柄样例由 Go 生成：`carto_agent/internal/resource/handle_fixtures_test.go`（R20 建立）在 `AUTOCARTO_UPDATE_FIXTURES=1` 时把样例资源解析结果写入 `autocarto/tests/fixtures/resource_handles/*.json`，路径中的仓库根写成 `${REPO}`；不带该变量运行时比较内存结果与已提交文件，不一致即失败。
