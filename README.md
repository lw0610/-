# AutoCarto AI

AutoCarto 将自然语言制图任务与 QGIS 连接起来。**流程（FLOW.md）**用自由书写的 Markdown 描述制图要求；主智能体根据具体任务提出**制图计划**，系统按实际能力选择角色执行。工具包由开发人员维护，资源库只复用样式与版面。

当前开发副本是 `enio2`，原 `Eino` 保留。当前架构见 [v6 方案](docs/refactor-v6/README.md)，实施与验证范围见 [v6 执行状态](docs/refactor-v6/evidence/00-执行状态.md)。v2–v5 文档保留作历史说明，旧流程编译、输入表单和角色位策略不再是当前运行入口。离线测试使用真实控制器与 QGIS、固定模型/角色动作，不能证明在线模型理解和视觉审查的质量。

## 使用入口

启动 QGIS 并启用 AutoCarto 插件，打开桌面应用，确认工程连接并配置模型。直接在对话中描述任务，可添加文件/文件夹、使用 `@` 引用当前图层、使用 `/` 指定流程。缺少必要信息时由问题卡补充；已知信息和流程默认值进入计划卡。需要确认时点“开始”，其余任务按设置直接执行。

简单的加载、查看和样式修改可以直接委派；适用流程、需要获取数据或较复杂的任务先给出计划。Plan 使用同一主模型与规则，只读取信息、生成计划；切到 Build 后可执行同一计划。任务进度与过程保留在同一区域，文件页签展示真实产出。

流程页只有一页正文和引用的样式与版面预览。可以导入、编辑、复制、导出和停用流程。保存只检查头部与资源引用，**不调用模型、不重新编译**。旧 GUIDE.md 和结构化 FLOW.md 备份转换为自由书写的 FLOW.md；内置流程只读，复制后可编辑。

## 从源码启动

需要 QGIS、Go（仓库要求 `go 1.24.0`，声明工具链 `go1.24.11`）、Node/npm、Rust/Cargo 和所在平台的 Tauri 构建依赖。真实 Python 制图测试必须使用能够导入 QGIS 的解释器。脚本预检会指出缺少的组件；不会自动安装系统依赖。Ubuntu 的显式环境准备脚本为 `bootstrap-ubuntu.sh`，它会安装或下载依赖，使用前先检查其范围。

在项目根目录执行：

```sh
./build.sh help
./build.sh deps
./build.sh dev
```

Windows 对应 `build.bat help`、`build.bat deps`、`build.bat dev`。

`deps` 根据锁文件准备前端依赖；`dev` 构建 Go sidecar、**替换当前 QGIS profile 中的 `autocarto` 插件目录**，再启动 Tauri 和本地前端（开发地址 `http://localhost:3000`）。先保存 QGIS 工程，确认插件部署目标，重新加载插件后连接。仅在 `autocarto-web/` 执行 `npm run dev` 只启动网页，不负责完整系统和插件部署。

准备好上述开发工具链并安装前端依赖后，也可直接沿用桌面开发入口：

```sh
cd autocarto-web
npx tauri dev
```

它会自动构建当前 Go 后端，再启动 Tauri 和前端，无须预先准备 sidecar 或额外执行 `./build.sh go`。后端构建失败会停止桌面构建，避免启动旧二进制。`./build.sh dev` 还负责完整的 QGIS 插件部署；macOS 开发模式从应用新建 QGIS 实例时会同步已安装的开发插件，但仍需存在可用的 QGIS profile 与 AutoCarto 插件。不要保留指向旧 `Eino` 的 `AUTOCARTO_*` 环境变量，否则可能读到旧资产或运行目录。

其他入口：

| 命令 | 实际作用 |
| --- | --- |
| `./build.sh go` | 仅构建 sidecar，保留运行中的前端缓存 |
| `./build.sh check` | 隔离运行目录，执行 Go、Web、Python、E2E、Next 和 Rust 门禁；不部署插件 |
| `./build.sh build` | 构建桌面应用并部署 QGIS 插件，省略命令时也会执行此操作 |
| `./build.sh plugin` | 打包 QGIS 插件 ZIP |
| `./build.sh dist` | 生成当前平台的桌面与插件发行产物，整理到 `dist/` 并执行发行包 smoke |

平台专属的 `app`、`dmg`、`deb`、`appimage` 和已有发行包检查以 `./build.sh help` 为准。以上是现有命令说明，不表示本次验收安装或部署了发行包。

## 项目内运行目录与路径

默认运行目录为**固定项目根下的 `autocarto_data/`**，相对配置路径按项目根解析，不按进程启动时的工作目录解析。

```text
autocarto_data/
├── config/                   设置、智能体方案、加密凭据、指南开关和数据记忆
├── data/
│   ├── logs/                 后端日志
│   ├── sessions/             会话、plans/ 计划版本、flows/ 执行记录和成果
│   └── acquired/             已核验的获取数据、来源清单与摘要
├── sources/                  本机数据源清单
├── flows/                    我的 FLOW.md、锁定及随包样式/版面依赖
├── presets/                  迁移保留的用户路线样式、符号预设
└── resources/                用户样式与版面
```

内置资产仍位于 `autocarto/{tools,skills,flows,resources}/system/`。流程正文由模型理解，程序只读取头部和样式/版面引用。用户直接提供文件、文件夹或工程图层；缺少的数据才自动获取，不需要维护 CSV 清单。

样式与版面可导入文件或文件夹，也可从 QGIS 工程保存；文件夹和多图层分别生成独立资源。资源名在内置与用户库中唯一，内置只读。预览由独立 QGIS 工程生成，断连时排队，内容变化后更新。流程导出只附带所引用样式与版面，不含任务数据；差异依赖保留随包副本，不覆盖本机用户库。数据记忆不随包导出。

需要显式定位时，在启动进程前设置：

```sh
export AUTOCARTO_PROJECT_ROOT="/项目的绝对路径/enio2"
export AUTOCARTO_HOME="autocarto_data"
export AUTOCARTO_ASSETS_ROOT="autocarto"
```

`AUTOCARTO_PROJECT_ROOT` 必须是绝对路径；另外两项可相对于它。项目根通常从显式环境、资产、可执行文件或源码位置定位；桌面便携应用按自身位置定位，必要时明确覆盖。本机输入记忆使用绝对路径，配置中的相对运行路径从固定项目根解析。运行目录必须可写。

开发启动 `npx tauri dev` 时，如果未显式设置项目根，但终端遗留的 HOME/ASSETS 两项指向另一个完整源码副本的默认 `autocarto_data` / `autocarto`，程序会纠正为当前源码项目并打印路径说明。自定义目录、独立资源库和发行版的覆盖规则不变。若确实要使用另一个源码副本，请同时显式设置它的 `AUTOCARTO_PROJECT_ROOT`。

数据服务统一使用 `data_find` 选择来源、`data_get` 获取并核验、`data_register` 登记兜底工具取得的数据。候选包含可用条件、选择/排除原因和来源手册；工程图层、用户目录、会话文件与数据仓可以复用。只允许系统数据获取智能体及计划执行器取数的设置默认开启；普通角色不因缺工具而获得下载权限。用户方案文件不会被临时能力分配改写。

按用户选择，联网策略默认 `direct`，不再每个会话询问下载授权；设置可改为确认或禁止。浏览器、自定义查询等兜底另受兜底策略控制。OSM、天地图、GEE 等服务仍需满足各自启用与凭据条件；门户来源未就绪时，统计表需由用户提供。离线测试不表示任意地区的真实网络来源都已可用。

需要把密钥写入工程的在线瓦片定义，目前不作为统一数据服务可自动完成的候选；界面会说明排除原因。已经加载的真实工程图层可复用，已有下载文件不受该限制影响。待加载的定义文件不会被当作获取成功的数据。

计划卡逐项展示数据来源及理由、样式预览和待确认匹配，同时展示事实、默认值、假设、步骤与成果；数据选择可直接修改，也可在对话中要求调整。常规步骤执行失败会自动重试一次，再进入计划修订或用户决定；最多三次修订。已完成部分保留，未完成部分可以修订。每步产出和可机器检查的最终条件由真实工具核验；无法自动判断的要求明确留作人工检查。

计划版本存于会话 `plans/`，执行快照仍存于 `flows/<运行编号>/run.json`，记录版本、回执、来源与结果。中断恢复会验证原文、能力和资源；资源变化需要明确选择继续原快照。旧 v4 运行记录仅供查看，不能按新计划直接续跑。快照不备份外部数据字节。

会话文件区登记真实产出与来源，可预览图片、表格、文档及地理数据。下载展示已知的进度和速度；来源不提供总大小时展示已下载量和阶段，不伪造百分比。修正同一产物时替换原产物，不新增“移到历史”入口。

## 备份与验证

迁移、批量编辑方案或更换运行目录前，先停止相关服务，再完整备份运行目录，包含隐藏文件。加密配置与其密钥必须一并保留；备份不要提交到仓库或分享到日志。只备份方案 YAML 不能替代完整配置备份。已有迁移的保留范围和原始备份见 [T51 记录](docs/refactor/evidence/T51.md)。

日常门禁为 `./build.sh check`，报告位于 `.sisyphus/evidence/`；真实 QGIS 与黄金样例的解释器、外部数据要求及明确跳过规则见 [黄金回归说明](autocarto/tests/golden/README.md)。只读开发验收成果位于 `autocarto/tests/golden/.runs/T53/`，不会写入工作运行目录。

[上一版 T53](docs/refactor/evidence/T53.md) 保存当时通过的完整门禁与跳过范围；不把它作为当前修改后的通过证明。当前改动测试以 [refactor-v6 证据](docs/refactor-v6/evidence/) 为准，跳过项不算通过，桌面编译也不等同于已安装发行包或实时 QGIS 界面联调。
