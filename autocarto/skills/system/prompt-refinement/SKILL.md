# 用户需求精炼与提示词优化

## 概述

本 skill 指导编排智能体在调度子智能体之前，对用户输入进行系统化的需求分析和提示词优化。通过补全缺失信息、消除歧义、结构化输出，确保下游子智能体收到清晰、完整、可执行的任务描述。

## 触发判断

在处理用户请求时，先进行快速评估（不超过 2 秒思考）：

**直接调度**（不触发本 skill）：
- 用户明确指定了输入图层、操作类型和输出要求
- 请求匹配单一工具调用（如"将 A 图层导出为 GeoJSON"）
- 用户引用了之前对话中已确认的参数

**触发精炼**（启用本 skill）：
- 用户使用模糊动词（"分析"、"处理"、"看看"）且未指定具体方法
- 缺少 2 个以上关键参数
- 涉及多步骤但未说明顺序或优先级
- 请求可能匹配多个不同的工作流 skill

## 适用场景

当用户输入存在以下情况时，应优先触发本 skill：
- 需求描述模糊或过于笼统（如"帮我分析一下这个数据"）
- 缺少关键参数（坐标系、输出格式、分析范围、阈值等）
- 涉及多步骤但未明确执行顺序
- 使用非专业术语描述 GIS 操作

## 工作流步骤

### 1. 意图识别

- 从用户输入中提取核心操作意图（数据处理/空间分析/制图输出/查询筛选）
- 识别是单步操作还是多步工作流
- 判断是否匹配已有的工作流 skill（如选址分析、变化检测等）

### 2. 上下文采集

- 使用 `get_layers_info` 获取当前工程中已加载的图层
- 使用 `get_active_layer_info` 获取活动图层的详细信息（字段、CRS、要素数）；如果当前没有活动图层，优先按图层名查询，不要直接假设不存在数据
- 使用 `get_project_info` 获取工程级别信息，并优先检查工程目录下的 `data_files`
- 使用 `get_map_extent` 获取当前视图范围
- 将上下文信息与用户需求关联，自动推断缺失参数
- 在向用户索取文件路径之前，必须先检查 `get_project_info.info.data_files`、`get_layers_info` 和当前工程目录；如果工程目录中已有与任务地理范围/主题匹配的数据文件，应直接使用而不是追问用户

### 3. 缺失信息补全

按以下清单检查并补全关键参数：

**数据相关：**
- 输入数据源（图层名/文件路径）— 若未指定，从已加载图层推断
- 数据类型（矢量/栅格）— 从图层信息自动判断
- 坐标参考系 — 从图层 CRS 自动获取

**分析相关：**
- 分析方法和参数（缓冲距离、分类数、权重等）
- 空间范围（全图层/当前视图/自定义范围）
- 筛选条件（属性条件/空间条件）

**输出相关：**
- 输出格式（图层/文件/地图）
- 输出路径
- 命名规则

### 4. 歧义消解

- 当存在多种合理解读时，调用 `hitl_request` 工具暂停执行并向用户确认
- 对于可从上下文推断的参数，给出推荐值并说明理由

### 5. 结构化输出

将精炼后的需求组织为标准格式，传递给后续调度：

```
【任务目标】一句话描述最终目标
【输入数据】图层名、类型、CRS、要素数
【处理步骤】按序列出每步操作及对应子智能体
【关键参数】分析参数、阈值、方法选择
【输出要求】格式、路径、命名
【风险评估】数据量级、潜在精度损失、不可逆操作标记
【回退方案】失败时的替代策略或降级方案
【确认要点】需要用户确认的关键决策（触发 HITL 中断的依据）
【约束条件】性能要求、精度要求、特殊限制
```

### 6. 优化策略

- **简单任务**（单步操作）：快速补全参数，直接调度，不过度展开
- **复杂任务**（多步工作流）：拆分为有序步骤，标注依赖关系和中间产物
- **重复任务**：识别与历史任务的相似性，复用已验证的参数配置
- **中断控制**：单次任务中最多发起 2 次 HITL 中断（1 次歧义消解 + 1 次执行确认），避免过度打扰用户

## 与用户确认的交互方式

当需要向用户确认时，统一调用 `hitl_request` 暂停执行：

### 歧义消解中断

当存在多种合理解读时，调用 `hitl_request`，携带以下信息：
- 检测到的歧义点描述
- 可选方案列表（最多 3 个）
- 每个方案的推荐理由
- 默认推荐方案标记

`hitl_request` 参数示例：
```json
{
  "type": "clarification",
  "title": "请确认您的意图",
  "description": "检测到的歧义描述",
  "options": [
    {"label": "方案A（推荐）", "value": "option_a", "reason": "推荐理由"},
    {"label": "方案B", "value": "option_b", "reason": "理由"},
    {"label": "方案C", "value": "option_c", "reason": "理由"}
  ],
  "default": "option_a"
}
```

### 执行计划确认中断

完成需求精炼后、调度子智能体前，调用 `hitl_request`，携带：
- 完整的结构化任务描述（使用增强模板）
- 将要调度的子智能体列表
- 预估的操作影响（涉及的图层、可能的数据修改）

`hitl_request` 参数示例：
```json
{
  "type": "plan_confirmation",
  "title": "执行计划确认",
  "description": "即将执行以下操作",
  "plan": {
    "objective": "任务目标",
    "steps": [
      {"agent": "子智能体名", "action": "操作描述", "impact": "影响说明"}
    ],
    "risks": ["风险点1", "风险点2"],
    "fallback": "回退方案描述"
  }
}
```
