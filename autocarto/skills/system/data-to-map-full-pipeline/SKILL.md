# 从原始数据到成品地图全流程

## 概述

本 skill 描述从原始数据到最终成品地图的完整工作流，orchestrator 据此调度各子智能体完成端到端的地图制作。适用于项目交付、报告制图、数据可视化展示等场景。

## 前置条件

- 原始数据文件已准备（矢量/栅格，可为多种格式）
- 已明确地图主题和用途
- 已明确输出格式和规格要求（纸张大小、分辨率、文件格式）

## 工作流步骤

### 1. 需求分析 [orchestrator]

- 确认最终地图主题和用途（展示/分析/打印）
- 确认输入数据源（文件路径、格式、数量）
- 确认输出格式和规格要求
- 评估是否需要空间分析环节（纯展示 vs 分析+展示）
- **中间产物命名规范**：
  - 数据准备阶段：`prep_{原始名}`（如 `prep_roads`）
  - 分析阶段：`analysis_{方法}_{输入}`（如 `analysis_buffer_schools`）
  - 最终输出：`map_{主题}_{日期}`（如 `map_population_20240101`）
- **数据传递**：将数据源列表、分析需求、输出规格传递给后续步骤
- **判断标准**：需求明确，数据源可用，输出规格已确定

### 2. 数据准备 [data_processing]

- 优先读取 `get_project_info` 返回的工程目录 `data_files`，先消费当前工程目录里已经存在且与任务主题匹配的数据文件，不要默认要求用户再提供路径
- 数据加载：用 `data_load_vector` / `data_load_raster` 加载所有数据
- 格式检查：用 `get_layers_info` 确认加载成功
- CRS 统一：用 `reproject_layer` 将所有图层统一到同一坐标系
- 属性表清洗：用 `check_validity` + `fix_geometries` 修复几何，清理空值字段
- 数据格式转换（按需）：如 SHP → GPKG
- 若当前工程中已经存在可直接满足任务的数据图层（例如行政区划面图层已带业务字段），优先复用现有图层，不重复导出、重算、连接或创建中间副本
- **数据传递**：输出清洗后的图层列表（含图层名和 CRS）
- **判断标准**：所有图层加载成功，CRS 一致，几何有效

### 3. 空间分析 [vector_spatial / raster_terrain]

- 根据地图主题执行必要的空间分析：
  - 矢量分析：叠加（`intersection`/`union`）、缓冲（`buffer`）、查询（`extract_by_expression`）
  - 栅格分析：地形衍生（`slope`/`hillshade`）、插值（`idw_interpolation`）、重分类（`raster_reclassify`）
- 每步分析后验证输出：
  - 矢量：检查要素数和属性完整性
  - 栅格：检查值域和 NoData
- **数据传递**：输出分析结果图层列表
- **判断标准**：分析结果合理，无异常值

### 4. 制图输出 [cartography_layout]

- 专题地图符号化：
  - 根据数据类型选择渲染方式（分级/分类/热力图）
  - 添加标注
- 标准打印布局制作：
  - 创建布局 → 设置页面 → 添加主图
  - 添加完整地图要素（图例、比例尺、指北针、标题）
  - 对齐调整
- 仅导出用户明确要求的成品格式；如果需求是打印地图或未特别指定图片格式，默认只导出 PDF，不额外导出 PNG/JPEG
- **数据传递**：输出导出文件路径
- **判断标准**：布局完整，导出成功

### 5. 成果汇总 [orchestrator]

- 汇总输出文件清单（地图文件、中间数据文件）
- 记录处理参数和分析方法
- 输出完整的工作流报告：
  - 输入数据列表
  - 处理步骤摘要
  - 分析方法和参数
  - 输出文件路径和格式

## 常见问题处理

- 数据加载失败 → 检查文件路径和格式，尝试指定编码
- CRS 统一后数据偏移 → 检查原始 CRS 是否正确定义
- 分析结果不符预期 → 检查输入数据质量和参数设置
- 布局导出失败 → 检查布局完整性，确认所有要素已正确添加
- 流程中断需恢复 → 从最近成功的中间产物继续

## 输出检查清单

- [ ] 所有数据已加载并清洗
- [ ] CRS 统一
- [ ] 空间分析结果合理（如适用）
- [ ] 符号化效果清晰
- [ ] 布局包含完整地图要素
- [ ] 成品地图已导出
- [ ] 工作流报告已输出
