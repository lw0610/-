# 数据服务

数据准备由当前智能体方案中负责数据的角色执行，默认方案为数据工程专家。它负责查找、获取、整理、登记和接入；不额外创建系统取数智能体。工具按方案分配，模型也使用该角色的配置。

Build 模式由编排智能体交接目标、输入材料和已有结果。数据角色先用 data_find 查找用户给定数据、工程已有图层、内置图层和数据仓，再按类别与比例尺选择来源。用 data_get 取得选定数据。返回 exploration_required 时，同一角色沿用 find_id 和完整 preparation，用已分配的取数工具继续查找原件并登记，不重新发现或重复下载已有成果。

Plan 模式只声明数据需求、来源偏好与范围规则；执行器准备确定性来源，未解决的需求交给当前方案中具备数据获取和登记能力的角色。沿用当前 need、Selection、handbook 和 ledger，不重建查询。

`data_find` 是本地发现工具，不联网。返回 `state=needs_input` 时先按 diagnostics 更正需求，此时没有可用查询编号，不能继续登记。`need.scale` 是地图比例尺（auto 或 1:500000），不是“100米”像元分辨率；已取得边界文件时，extent 直接传真实边界文件绝对路径。一个 need 表达一类数据，不把地铁线路、站点、背景和人口拼成同一类“地铁”。`data_get` 按返回的 find_id 和候选选择取得数据。用户明确指定的来源、年份、口径或方式不可静默替换。具体方式与约束见 `data-service/references/检索方式手册.md`，需要时用 reference_read 读取。

取得原件后按实际格式处理：下载链接取得文件；网页文字表格读取真实单元格；需要选择地区或年份时先用浏览器筛选再导出。图片和 PDF 使用 `document_extract`，实际角色的视觉模型可读取图片；不支持视觉时使用本机 OCR。仅有文件名或截图记录不代表已读到数据。

统计表按任务要求整理为 CSV 或 Excel，地理数据保留正确几何、坐标系与字段。保留原件，记录来源网址、标题、表号或页码和读取方式；不凭记忆补数，不把缺失值写成 0。对照任务指定的行政单元、年份、指标、口径和单位整理，全省合计存在时同时保留；无法识别的内容明确列出。

用 `data_register` 提交真实 path、source_title、url、method、license、attribution；原件为文档或表格时补 table_ref、original_path。登记有三种明确入口：

- 已绑定计划需求：直接提交文件与来源，不另填新 need 或查询编号。
- Build 按查询获取：沿用 data_get 的 preparation 中 find_id、row 与可用 kind，不把 needs_input 的诊断当成功查询。
- Build 已由 OSM/GEE/浏览器等专用工具取得文件：直接填写 `need`（与 data_find 相同的 name、what、geometry、extent、scale、fields、params 结构）及文件与来源。说明准确类别和实际研究区边界；不用补造 find_id、不为登记重下文件。登记会复用现有内容核验与入仓逻辑。

只有文件的来源说明还不等于登记回执；已有真实文件优先用以上对应入口登记。登记反馈有具体问题时修正同一成果，不重复下载或重做已经正确的部分；以真实文件和登记回执交接后续步骤。

同一需求再次执行优先复用数据仓、统计库和已下载原件。用户原件与内置数据只读，整理结果写本会话 output 目录。失败时区分网络请求、数据内容与文件保存错误；修正实际失败操作，不重复同样请求，不把命令退出正常当作数据已取得。

图层的来源与画法分别处理：内置登记提供字段及默认样式，流程明确的颜色、线宽和标注要求由符号工具执行；不能为了套用默认样式换数据。计划步骤保留已有数据绑定，系统准备一次后复用；上游产出由后续步骤输入引用，不再作为待获取数据重复声明。
